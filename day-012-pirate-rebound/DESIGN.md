# Day 012 設計 — ユーザーストーリーと UX 5階層

実装に入る前に戦略層から順に書き下ろした。**この工程で実装方針が6か所変わった**（末尾に一覧）。

## ユーザーストーリー

> **音ゲーが得意ではない人**として、
> **音を聞いて返すだけの短いゲーム**で遊びたい。
> なぜなら、**譜面を目で追う音ゲーはいつも置いていかれる**から。

補助のストーリー2本。

> **100日チャレンジを見ている人**として、**画像も音源も1つも読み込まずに音ゲーが成立している**ことを確かめたい。ソースを開けば全部コードだと分かるから。
>
> **スマホで開いた人**として、**イヤホンだと音がずれる**ことを先に知らせてほしい。ずれを自分のせいだと思わずに済むから。

## UX 5階層

### 1. 戦略層 — 何のために作るか

- **利用者の目的**：45秒で「自分にもリズム感がある」と思えること
- **作り手の目的**：Day 11–20 の「4状態」を、飾りでなく必然として実装すること／音と3Dを外部素材ゼロで成立させること
- **ここから出る一番強い制約**：**上手い人のためのゲームにしない。** ミスしても曲は止まらず、音も汚れない。下手なまま最後まで到達できる

### 2. 要件層 — 何があれば成立するか

| 要件 | 戦略層のどれから来たか |
|---|---|
| 操作は1ボタンだけ | 置いていかれない |
| 合図は必ず**音が先**（映像は後追い） | 目で追う音ゲーにしない |
| **押してはいけないもの**（カモメ）を混ぜる | これが無いと音を聞かずに連打で通せてしまう |
| ミスしても伴奏が止まらない | 下手なまま最後まで到達できる |
| イヤホン注意を開始前に出す | ずれを自分のせいだと思わせない |
| 補正（キャリブレーション）を持つ | 端末差30〜100msを利用者の責任にしない |

### 3. 構造層 — 画面と遷移

```
タイトル(empty) ──押す──> カウントイン(loading) ──> プレイ(playing) ──> 結果(result)
     │                                                   │                  │
     └──「音のズレを直す」──> 補正(calibrating)          └─タブが裏へ──> エラー(error)
```

- 補正は**タイトルから開くサブ画面**にする。プレイ中には出さない（プレイ中に触れると拍が壊れる）
- 結果からタイトルへは戻さず、**その場でもう一度**始められるようにする

### 4. 骨格層 — 画面の骨格

```
┌─────────────────────────┐
│ Day 012 / 海賊船の打ち返し係     │ ← プレイ中は消す
├─────────────────────────┤
│        空・水平線・敵船(奥)      │
│                                 │
│        ● 飛んでくる砲弾          │
│                                 │
│      ドンピシャ！  ← 打点のすぐ上  │
│   ▲ 自分（船首・手前）           │
├─────────────────────────┤
│  のこり ●●●●○○   [ 打つ ]      │
└─────────────────────────┘
```

- 判定の文字は**打点のすぐ上**に出す。視線は常に船首にあるので、画面上部に出しても読まれない
- プレイ中は見出し・説明・シェアを消す。残すのは海と、進み具合と、押すところだけ

### 5. 表層 — 見た目と音

- **夜明けの海**。空は上が藍、下が橙のグラデーション。敵船は逆光のシルエット
- **色で意味を分けない**。判定は色ではなく**文字と動き**で伝える（赤と緑の対比は使わない）
- 判定音は効果音ではなく**伴奏の一部**として鳴らす。ドンピシャだけ和音のトップが乗る
- ミスは不協和音にしない。**船体に当たる鈍い音**だけで、曲は続く

## 5階層を通して変わったこと（6件）

1. **カモメ（押してはいけないもの）を足した。** 当初は砲弾と二連弾だけの予定だったが、要件層で「音を聞かずに連打で通せる」ことに気づいた
2. **判定表示を画面上部から打点のすぐ上へ移した**（骨格層）
3. **ミスの音を不協和音から鈍い衝突音へ変えた**（戦略層の「下手なまま到達できる」から）
4. **プレイ中はヘッダとシェアを隠す**ことにした（骨格層）
5. **補正をプレイ画面の常設スライダーから、タイトル配下のサブ画面へ分離した**（構造層）
6. **判定の色分けをやめた**。当初は成功=緑・失敗=赤にする想定だった（表層）

## 追記（2026-08-19）：敵船が壊れていく演出

本人の指示「ドンピシャだったら船が崩れていく。打ち返せば打ち返すほど崩れる」を受けた追加。
**この追加でも設計を先に通し、実装方針が6か所変わった。**

### 戦略層から出た制約

このゲームの報酬は今まで「ドンピシャ」という**文字**しかなかった。文字は1回0.7秒で消えるので、
**60秒遊んだ痕跡がどこにも残らない**。壊れていく船は「自分がここまでやった」という積み上げの記録になる。
だから演出ではなく、**進捗の表示そのもの**として設計する。

### 通して変わった6点

1. **ダメージは打った瞬間ではなく、弾が敵船に届いた瞬間に入れる。** 打つ→飛ぶ→当たる→崩れる、の
   因果が目で追えないと、ただ画面が変わっただけになる
2. **おしいでは壊れないことにした。** 当初は判定に応じてダメージ量を変える案だったが、
   量の差は遠くの船では見えない。**届く／届かないの二択**にして、おしいの弾は海に落とした
3. **壊し方を「部品が欠ける」から「輪郭が変わる」へ変えた。** 敵船は82m先の小さなシルエットなので、
   細かい欠けは見えない。帆→マスト→船体の傾き、という**シルエットが変わる順**にした
4. **沈めないことにした。** 海は線で描いているだけで前後関係を持たないので、水面下へ沈めると
   海の上に浮いて見える。傾きで代替した
5. **画面下の帯に「敵船 いまの状態」を出した。** 崩れたことに気づかないまま終わる人が出るため
6. **段のしきい値を「半分当てても3段目までは見える」配りにした。** 上手い人しか変化を見られないと、
   いちばん演出を必要としている人に届かない
