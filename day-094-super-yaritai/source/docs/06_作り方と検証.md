# 06 作り方と検証

## 部品の分け方：シミュレーションを画面から切り離す

```
src/shared/   純TS。DOM・three・Rapier・Workerを使わない（端末とWorkerの両方が読む）
  rules/      misdeeds.ts（悪事の定義）・scoring.ts（点と称号）・tuning.ts（数値）
  layout/     store.ts（店の純データ）
  view.ts     描画とHUDが読む「店の見え方」の型（WorldView）
  protocol/   連絡の型とバイナリの符号化
src/game/     シミュレーション。DOMとthreeを使わないので、Nodeのテストでそのまま回せる
  sim/        Simulation（Rapierの世界）・entities・systems（悪事ごと）・nav（経路）・ai（店員・客・CPU）
  session/    Local（ひとり）・Host（部屋の主）・Guest（参加者）
src/client/   ブラウザ側
  render/ input/ ui/hud/ ui/screens/ ui/share.ts audio/ net/ app.ts main.ts
src/worker/   Worker と Durable Object
```

- **見え方を1つの型にそろえる**：描画とHUDは `WorldView`（`src/shared/view.ts`）だけを読む。ひとりでも部屋の主でも参加者でも、同じ描画のコードが動く
- 部品間の型を変更したときは、`src/shared/view.ts`、`src/shared/rules/misdeeds.ts`、`src/client/contracts.ts` の利用箇所を確認する。通信形式の変更は [ネット対戦の設計](05_ネット対戦.md#やりとりの形) に反映する。
- **乱数は機能ごとに別の系列**にする（商品の並び・客・店員・CPU・効果）。あとから足した機能で既存の配置が変わらないようにする
- ゲーム内の調整値は `src/shared/rules/tuning.ts` に集める。

## 試験用の窓口 `window.__SY__`

試験と撮影に使う。開発中に有効になり、本番ビルドでもURLに `?debug=1` を付けると有効になる。

- `state()`：段階・残り時間・全員の点・コンボ・目立ち度・達成・位置、店員の状態、店の被害率、毎秒の描画数
- `teleport(slot, x, z)`・`face(slot, yaw)`・`setTimeScale(n)`・`forceEnd()`・`seed(n)`
- `shot(name)`：固定ショットの構図に切り替える（04）
- `camera(pose)`：撮影用にカメラの位置・見る点・画角（度）を指定する（`null` で標準の追従カメラに戻す）

## ビルドと動作を確認する

- `npm run build` で型とビルドを、`npm test`（Vitest）と `npm run e2e`（Playwright）でルールと操作を確認する。ネット対戦に関わる変更では `npm run e2e:online` と `npm run e2e:split` も実行する。
- **単体試験（ロジック必須）**：点数・コンボ・称号・同点の決め方／店のデータ（棚が重ならない・全部の場所に歩いて行ける）／シミュレーション（Nodeで Rapier を回し、なぎ払いで商品が落ちて点が入る・缶ピラミッドの8割判定・カートの距離・ベル・試食・放送・冷凍・バナナ・駄々・ボウリング・店員の確保・目立ち度の減り方）／CPUが2分で4種類以上を達成する（ふつう）／符号化の往復／部屋の規則
- **E2E**：ひとりで1試合（タイトル→強さ→試合→結果→シェアのURL）／スマホの縦と横（スティックで動く・はみ出さない）／ネット対戦（`wrangler dev` に2つのブラウザでつなぎ、部屋を作る→あいことばで入る→始める→互いのキャラが動いて見える→両方の点が結果に出る）／OGP・canonical・CSP・外部への通信0件・コンソールのエラー0件
- 画面ロック中は Chromium が起動しないので、E2E と撮影は WebKit に切り替えられるようにする（`SY_BROWSER=webkit`）
