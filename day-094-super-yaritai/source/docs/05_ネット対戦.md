# 05 ネット対戦の仕組み

## 構成：画面は Pages、ネット対戦は Worker、物理は部屋の主の端末

- **画面と部屋**。画面は Cloudflare Pages から静的ファイルとして配信し、ネット対戦の `/api/*` は Cloudflare Worker が受け持つ。Worker も同じ静的ファイルを配信する。Worker から画面を開いた場合は、同じオリジンの API に接続する。
- **許可する画面**：`src/shared/hosts.ts` が接続先と Origin 許可リストの共通の置き場。別 origin の部屋づくりの結果は、許可した画面だけに CORS で読ませる。ビルドは1種類
- **部屋**。部屋ごとに Durable Object（`RoomDO`）を1つ、相手探しに全体で1つ（`LobbyDO`）、1日の使用量を数えるために1つ（`UsageDO`）を置く。部屋管理の一部は同じ作者の「名所バトル」の Worker をもとに実装した。
- **物理は部屋の主の端末で回す**：最初に部屋へ入った人（部屋の主）のブラウザが、商品・カート・店員・CPU・点数のすべてを計算する。ほかの人は「自分のキャラの位置と動き」とボタンの意図だけを送る。部屋の主は店全体の様子を毎秒15回配る。Durable Object は中継と部屋の管理だけをする
- **選んだ理由**：商品が数百個ある物理を Durable Object の中で回すと、無料枠の時間をすぐ使い切る。端末どうしの直接通信（WebRTC）は、携帯回線でつながらない人のために中継サーバーが別に要る。中継を Durable Object の WebSocket にすれば、どの回線でも443番でつながる
- **捨てた案**：全員が同じ物理を回して入力だけを交換する方式（ロックステップ）は、端末ごとに浮動小数点の結果がずれて店の状態が食い違う

## 部屋の決まり（名所バトルを引き継ぐ）

- **あいことば**：4文字。読み違えやすい文字（0・O・1・I・L など）を除いた英大文字と数字
- **人数**：友だちの部屋は2〜4人、相手探しは2人。始まったら途中からは入れない
- **名前**：友だちの部屋は本人が入れた名前（8文字まで、制御文字と改行は消す）。相手探しは「試食ハンター」「カート番長」のような自動の仮名だけを使う
- **部屋の主**：最初に入った人。試合の長さを選び、「はじめる」を押せる。待合室で主が抜けたら、次に入った人が主になる
- **切断**：待合室は60秒、ゲーム中は20秒、席を残す。同じ札（接続時に配る使い捨ての文字列）で戻れる。ゲーム中に部屋の主が切れて戻らなければ、最後に届いた点数で結果を出す
- **片付け**：全員が抜けて10分たった部屋は状態を消す

## やりとりの形

**操作の連絡（JSON）**

| 向き | 種類 | 中身 |
|---|---|---|
| 端末→部屋 | `hello` | 名前（友だちの部屋だけ）・キャラ・再接続の札 |
| 端末→部屋 | `config` / `start` / `rematch` | 部屋の主だけ。試合の長さ・開始・もう一回 |
| 端末→部屋 | `final` | 部屋の主だけ。最終結果（全員の点・内訳・達成） |
| 端末→部屋 | `ping` / `bye` | 時計合わせ／自分から抜ける |
| 部屋→端末 | `welcome` | 自分の番号・札・あいことば・サーバー時刻 |
| 部屋→端末 | `room` | 段階（待合室・カウントダウン・試合中・結果）・顔ぶれ・主・開始時刻・試合の長さ |
| 部屋→端末 | `result` / `pong` / `error` | 最終結果／時計合わせの返事／断る理由 |

**試合中のデータ（バイナリ。1文字目が種類）**

| 種類 | 向き | 中身 | 頻度 |
|---|---|---|---|
| 1 自分の様子 | 参加者→主 | 位置・速度・向き・動きの種類・乗っているカート・持っている物 | 毎秒15回 |
| 2 店の様子 | 主→参加者 | 全員の位置と状態・動いている商品・店員と客・点数・残り時間 | 毎秒15回 |
| 3 出来事 | 主→参加者 | 点が入った・達成・滑った・捕まった・効果音 | 起きたとき |
| 4 意図 | 参加者→主 | アクションを押した／離した・相手（棚や台の番号） | 押したとき |

- 部屋の中継は、種類1と4を主にだけ、種類2と3を参加者全員に送る。主以外が2・3を送ったら捨てる。送り主の番号は部屋が書き込む（なりすまし防止）
- 店の様子は**前回から動いた物だけ**を送る。2秒に1回は動いたことのある物を全部送る（つなぎ直した人がそろえられるように）
- 参加者の画面は、届いた店の様子を約100ms遅らせて補間する。自分のキャラだけは手元で即座に動かす
- 「捕まった」「滑った」は主が決めて、出来事で本人へ伝える。本人の端末はそれに従ってキャラを動かす

## Cloudflare の無料枠とゲームの開始上限

- **Cloudflare の無料枠**。Durable Objects は1日10万リクエストと13,000 GB秒。WebSocket の受信メッセージは料金計算上、20通で1リクエストに換算される。 [Cloudflare Durable Objects の料金表](https://developers.cloudflare.com/durable-objects/platform/pricing/)
- **試算**。2人で2分の試合は受信約3,600通（180リクエスト）、実行時間は約15 GB秒。試合中の使用量だけで計算すると1日約500試合に相当する。部屋づくりや相手探しなどの使用量は試算から除いている。
- **ゲーム側の上限**。1日につき友だちの部屋づくり300回、相手探し600回、試合開始250回まで。上限に達したら「きょうのネット対戦はいっぱいです」と表示し、「ひとりで」へ案内する。
- 受付の流量制限：部屋づくり5回/分、相手探し6回/分、接続30回/分（IPと拠点ごと）。1つの接続から毎秒40通を超えたら切る。1通は16KBまで
- 静的ファイルだけで動く「ひとりで」は Worker の処理を呼ばない。ネット対戦が止まっても1人では遊べる

## ずるへの考え方

部屋の主は点数を自由に書き換えられる。ランキングも成績の保存も作らず、ずるをして守るものを置かない。参加者が瞬間移動の位置を送ってきたら、主が速さの上限で丸める。

## 公開

- 手元では `npm run build` の後に `npm run cf:dev` を実行し、同じ URL を2つのブラウザで開いて対戦を試す。
- 画面と Worker を別のオリジンで配信する場合は、Worker の HTTPS オリジン、画面の Origin 許可リスト、CSP の接続先を設定する。手順は [自分の環境に配信する](../README.md#自分の環境に配信する) を参照。
- `npm run e2e:split` で、別のオリジンから部屋を作って対戦できることを確かめる。
