# 第三者のURLへ接続するAPIの落とし穴（Day74）

脅威と対策の全体は `.kiro/specs/day-074-link-dokumi/threat-model.md`。ここには、コードを読んでも分からない、**実行環境の癖**と、実在のサイトで測った事実だけを残す。
新しく「利用者が決めたURLへ接続する」APIを足すときは、先にこれを読む。

## Cloudflare Workers の `fetch`
- `redirect` に使えるのは `follow` と `manual` だけ。`'error'` は例外になる（「実装しない」と明記）。DoHに指定したため、本番では全診断が `resolver_unavailable` になるところだった。**Node上の単体テストの偽fetchはこの制約を知らない**ので、`tests/observer-runtime.test.mjs` が同じ制約を模している。観測コードのfetchの呼び方を変えたら、これが落ちるか確かめる。
- 証明書の期限切れ・自己署名・名前の不一致も、名前が引けない場合も、**同じ `Error: internal error; reference = …`** が投げられる。メッセージでは分類できない。名前が引けるかは先にDoHで決め、HTTPSのfetchが投げたら、同じホストの `http://` へ1回だけ取りに行き、応答があれば `tls_failed`、なければ `connect_failed` と推定する。断定せず「推定」と書く。
- IPアドレス直指定のfetchは、ローカルのworkerdでは通った（本番の網は断ると公式にある）。宛先の検査は、基盤に頼らず自前で行う。
- 無料枠のCPUは1回10ms。`extractHtmlFacts` は、実在ページ（GitHub・楽天・Wikipediaなど）を速いMacで測ると、160KiBで4〜6ms、初回で最大16msだった。64KiBに絞り、走査を文字コード比較にして、64KiBで約1ms（初回で最大4ms）になった。ネットワーク待ちはCPUに数えない。

## 独立レビューで見つかった落とし穴（2026-10-22）
- **相手が決める値（`Location`など）は、検査を通してから計算に使う。** 長大なホスト名を登録ドメインの計算に渡すと、ラベル数の二乗で時間を使わされた（4096ラベルで約176ms）。検査（`validateTarget`）→計算の順にし、計算側にも入口の上限を置く。
- **相手に断られたら、そのサイトへの追加のアクセスもやめる。** 「403などで断れば、もう取りに行かない」と運営者へ約束するなら、画面が追加の確認（`http://`側・`security.txt`）も省く（`around`の`site=0`）。説明と動きを一致させる。
- **取得した文字列は、写し（報告書・要約）に入れる前に1行へ直し、URLの`?`以降を落とす。** 大文字のスキーム・`//host/…`・空白での分断・C1制御・U+2028を使った抜け道がある。
- **登録ドメインの境界は、公開サフィックスリスト（PSL）の本物で引く。** 手書きの表は、利用者ごとのサブドメイン（`sakura.ne.jp`・`s3.amazonaws.com`）を表せず、偽のページを公式扱いで見逃した。`tools/gen-psl.mjs` で生成し、公式の試験データと変異試験で確かめる。

## 実在の大手サイト
- NHKは、ブラウザ以外の名乗りだけ約10秒遅らせる（ブラウザの名乗りなら約0.1秒。`Mozilla/5.0 (compatible; …)` でも同じ）。楽天はブラウザでも約5秒。
- ブラウザになりすますのは、診断先への誠実さと方針に反するので採らない。正直に名乗り、待つ時間だけを延ばし（1ホップ7秒・全体12秒）、時間切れは「時間切れ」と表示する。
- 本番確認に使うのは、速くて無害な試験用サイト：`example.com`・`github.com`・`httpforever.com`（HTTPだけ）・`*.badssl.com`（TLS試験用）。

## ローカルで実機に近く確かめる
リポジトリ直下で、空のディレクトリを渡して起動すると `functions/` が動く：
`wrangler pages dev <空のディレクトリ> --port 8799 --compatibility-date=2026-08-01 --binding LINK_DOKUMI_RATE_LIMIT=1000`
その状態で `node day-074-link-dokumi/tools/api-check.mjs --base http://127.0.0.1:8799 --no-pace` が、実在の試験サイトと、拒否されるべき宛先（内部アドレス・DNSが私設を指す名前・転送先が私設）を約40ケース確かめる。レート制限は `--ratelimit`（既定の12/分のサーバーに対して。新しい1分の窓まで待つ）。本番は `--base https://hundred-days.pages.dev`（間隔を空けて流す）。
wranglerはCIの `4.115.0` と別に、手元の確認用に入れた版でよい。ただし**公開から2週間以上経った版**を使う（`npm install --before=<2週間前の日付>`）。
