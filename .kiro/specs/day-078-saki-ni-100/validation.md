## 実装と判断（実装担当の記録から要点）

- 12面の表・先攻・ミス率は設計どおり。`lib/` の関数名は推奨どおり。
- `?seed=整数` で、あいての乱数を固定できる（整数以外は無視）。E2E と動画用。
- 飛び飛びの数（8・9面）では、目標未満で足せる数がなくなることがある。その側の負けとし、探索と実際の勝敗を同じ規則にした。
- 保存は3項目（クリアした面・ヒントなしでクリアした面・音）だけ。ヒントなしの記録は一度得たら失わない。
- 状態は `app.js` の1か所で持つ。面の切り替え・もう一度・ページを離れる・タブを隠すときに、待ち中のあいての手を取り消す。

## 評価・レビューの指摘と対応

| 出どころ | 指摘 | 対応 |
|---|---|---|
| 体験評価A | 8面で合計29になると、足せる数がなく、理由が盤に出ずに負けになる | ルール文に「足せる数がなくなった人も負け」を出し、終わった理由を一文で出す。試験で固定 |
| 体験評価B | 分かれ目が、最初の失敗しか指さない | その場の勝ちの見逃しを先に、最初の分かれ目をあとに伝える。盤にも金の枠と「ここ」 |
| 体験評価C・D・F | 勝った手応えが弱い／スマホで面を選ぶと盤が画面の外／1280×800で最初の画面が収まらない | 勝ちの印（朱の「勝」）・面を選ぶと盤の先頭へ戻る・画面の高さに合わせて縮める |
| 体験評価E | 7面以降のからくりが数の並びだけ | 「p ずつ同じ形がくり返す」を説明に足し、独立の計算でテスト |
| 見た目 1周目 | スマホで数字ボタンが画面の下／ヒントで数字ボタンが動く／768pxの丸が楕円／折り返し／端のずれ | 盤を先頭へ／ヒントを数字ボタンの下へ／丸を真円に／文ごとに折る／端をそろえる |
| 見た目 2周目 | 金の枠が朱の上で見えにくい／文字が小さめ／折り返し | 紙の色のすき間つきの枠＋「ここ」／文字を大きく／文ごとのかたまり |
| 独立レビュー | タブを隠してもあいてが打つ／負けても「次の面」が出ない／時間に頼る試験 | 隠している間は取り消し・戻ると再予約／次の面が開いていれば出す／ページの時計を止める試験に変更 |
| 独立レビュー | 足せない数キーの理由が読み上げられない／通り過ぎたヒントの数字のコントラスト不足／条件つきで空振りする試験／最初から隠れたタブの扱い | 読み上げ用の領域を追加／薄めず破線に／確実に勝てる手順で必須の検査に／最初の状態を `document.hidden` から決める |
