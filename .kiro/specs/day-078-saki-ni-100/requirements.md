# Day78 先に100

本人が2026-10-27、Day100の提案から「先に100（誰でもできて頭を使うゲーム）」を選び、番号はDay78・規模はふつう（12面）、公開まで依頼した。Xの投稿は本人が行う。

## ユーザーストーリー

ふだんパズルをしない人が、友だちと暇つぶしに始める。ルールは10秒で分かる。2〜3回負けるうちに「相手が足した数に合わせて足すと、いつも勝てる」と気づき、誰かに「これ先攻なら必ず勝てるよ」と教えたくなる。

## 受け入れ条件

- R1 ルール：あなたとあいてが交代で、許された数のどれか1つを合計に足す。合計を目標ちょうどにした側が勝つ（ふつう）。さかさまの面では、目標ちょうどにした側が負ける。目標を超える数は選べない。先攻・後攻は面ごとに決まっている。
- R2 面：12面・4章（design.md の表）。どの面も、あなたの側に必ず勝てる打ち方がある（全面をユニットテストで確かめる）。面はクリアした次の面まで選べ、クリア済みの面はいつでも遊び直せる。
- R3 あいて：面ごとのミス率で、勝てる局面でもその確率で勝てない手を選ぶ。負けている局面では、あなたが間違えやすい手を選ぶ。乱数は外から渡せて、同じ乱数で同じ対局が再現できる。
- R4 操作：数字ボタンのタップ・クリックと、キーボード（数字キー、1〜9と0＝10）で足せる。選べない数は押せない状態で、理由が読み上げられる。あいての番は操作を受け付けない。
- R5 表示：合計を大きく出す。目標までの積み木バーに、足した数を誰が足したかで色分けして並べる。直近の手の履歴、いま誰の番かを出す。番や結果の変化は読み上げられる（aria-live）。
- R6 ヒント：1回目で「勝ちの合計」を、数字ボタンの下の欄とバーの点線で示す。2回目で、いま勝てる手があればその数を金の太い枠で示し、勝てる手がないときは、あいてのミスを誘う手を示す。ヒントを出しても数字ボタンの位置は動かない。ヒントを使った面は、記録に残る。
- R7 結果：勝ちでは、からくり（勝ちの合計の並びと、等間隔・くり返しの形の説明）を出す。勝ち筋を外したのに勝ったときは、あいてのミスに助けられたことも伝える。負けでは、勝ち筋を外した手に金の枠と「ここ」を付け、その場の勝ちを見逃したならそれを先に、最初の分かれ目をあとに伝える。足せる数がなくなって終わるときは、その理由を盤に出す（ルール文にも書く）。どちらも同じ画面で「もう一度」「次の面」を選べる（負けのとき「次の面」は、すでに開いている場合だけ）。
- R8 保存：端末の localStorage に、クリアした面・ヒントなしでクリアした面・音の設定だけを保存する。壊れた値や想定外の形は読み捨てて初期値で始める。個人情報・外部通信・アカウントはない。
- R9 音：Web Audio の効果音（足す・あいて・勝ち・負け）とミュート。初期は無音で、ボタンで入れる。
- R10 共有・OGP：共通の shared/ を `<div id="share"></div>` に据え付ける（独自のダイアログは作らない）。canonical・OGP・`share:text` は Day78 の正規URLと題名に揃える。
- R11 品質：390・768・1440px で崩れない。タップ領域は44px以上。`prefers-reduced-motion` に従う。文字と背景のコントラストは AA。初回の遊び方の説明が主操作（数字ボタン）を覆わない。
- R12 公開：`npm run check`・`npm run publish:check -- --day 78`・Day78 の E2E・独立レビューが通ってからPRを出す。外部依存と配信ヘッダーの例外は増やさない。
