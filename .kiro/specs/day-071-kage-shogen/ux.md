# 操作と画面の設計：影証言

## ユーザーストーリー
| ユーザー | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| 本命：休憩中にスマホで頭を使いたい人 | 灯りを動かして影を証言のスケッチに重ね、人影の正体を暴きたい。手を動かして分かるほうが、長い文を読むより楽しい。 | 説明を読まなくても、夜1の最初の30秒で「灯りを上下に動かすと影が動く」と分かる。夜1が1分以内に解ける。 |
| このアプリが救う相手：文章の多い推理ゲームで疲れる人 | 推理は短く、根拠は1つの計算（灯りの高さ÷0.6）で済ませたい。 | 手がかりは1夜3つ以内、1つが1〜2文。推理は3択で、誤りには理由が返る。 |
| 補助：キーボードだけ・動きを減らしたい人 | 同じ内容を、マウスなし・演出なしで遊びたい。 | 全操作が矢印キーとボタンでできる。reduced-motionでは印や移動の演出が瞬時に切り替わる。 |

## UX5階層
| 層 | 判断と画面への反映 |
|---|---|
| 戦略 | 差別化は「影の物理が推理の根拠になる」こと。足跡が立ち位置を、影が灯りの高さを、高さが身長を教える。1夜1〜3分、5夜で約10分。壁の上で手を動かす時間を最優先にする。 |
| 要件 | 載せる：5つの夜・影の再現・現場図・推理・星・共有。載せない：ランキング・音・ログイン・課金・3D・事件の追加。 |
| 構造 | home → briefing → stage → solved → deduction → verdict →（次の夜 または epilogue）。迷う所は「灯りと道具のどちらを動かすか」。選択チップとヒントで戻れる。推理で詰まれば「考え方」を見られる。どの画面からも事件簿へ戻れる。 |
| 骨格 | 縦に、証言ストリップ（スケッチと証言。開閉できる）→ 壁（最大の要素は1つ）→ 状態（読み出し・近さ）→ 注記（一言・ヒント）→ 灯り・道具の操作 → 補助（ヒント・ガイド・はじめから）。PCは右の列に状態・注記・操作・手がかりを置く。主操作は常に壁の直下。 |
| 表層 | 停電の夜の下宿。暗い舞台、紙色の壁、琥珀の灯り、朱の印。影は濃い藍。ガイドの輪郭は朱の破線とラベルで、色だけに意味を持たせない。 |

**この5階層を通して実装が変わった数：10。** ①灯りを2次元の自由移動から縦レールだけに。②スケッチを壁の隅に重ねる案を、壁の上の証言ストリップに。③ガイドは夜1だけ初期ON、以降は選択制で星の減点を画面に明記。④邪魔な道具の置き場を作らず、棚の端へ寄せる形に。⑤近さを%でなく4段階の文に（足りない理由も添える）。⑥指の精度を補う微調整ボタンと矢印キー。⑦成功後に現場図を必ず出し、灯りから身長を読む計算を文で見せる。⑧画面を作って確かめた結果、再現した壁を solved にも出し、印をそこへ移した。⑨推理の手がかりを4項目に絞った（7項目では容疑者に届かなかった）。⑩誤答の理由を、押したカードの中へ出すようにした。

**改修1（独立評価の指摘。体験12/20・画面14/20）で、さらに変わったもの：**⑪近さのメーターを、各段の中でも連続して満ちるものに。⑫指示文と近さの文が同じ欄を奪い合って操作列が動いていたのを、近さの文（1行）と注記（2行分）に分けて高さを固定。⑬ヒントを、一般論の繰り返しから、いまいちばんずれているものの名指しと考え方の交互に。注記の欄に出して、スマホでも見えるように。⑭壁の上の灯りの数値の札をやめ、身長計に琥珀の目印だけを描く。⑮証言ストリップを開閉式にして、全文とスケッチを1タップで見られるように。⑯事件簿で、次に開く夜だけを琥珀の枠と「はじめる →」で示す。⑰結末とエピローグの判子が横にはみ出さないよう、始めの倍率を下げて入れ物で切る。エピローグはボタンを振り返りの前に。⑱推理を、夜3は身長が同じ2人をアリバイで1人に絞る形、夜5は身長178cmと180cmを灯りの高さの小数まで読んで分ける形に。夜2以降は身長まで書かない。夜4の踏み台の手がかりは事実だけにして、式は書かない。⑲数字・単位・式の途中で行が割れないよう、折り返さない範囲（`span.nb`）を作った。

## 画面と流れ
`#app[data-phase]` が現在の画面を示す。phase は `home / briefing / stage / solved / deduction / verdict / epilogue`。

| phase | 内容 | 次へ |
|---|---|---|
| home | 題名・一文の紹介・5つの夜のカード（題名・一文・星・鍵）・遊び方・共有・進行のリセット | 夜を選ぶ → briefing |
| briefing | 場所・事件の概要・目撃者の証言・スケッチ | 「再現室へ」→ stage |
| stage | 証言ストリップ・壁・状態・注記・操作・補助・手がかり | 再現成功 → solved |
| solved | 「再現」の印・現場図・再現の文・読みの文（夜1だけ身長の計算まで。夜2以降は灯りの高さまで） | 「推理する」→ deduction |
| deduction | 手がかり・再現の結果・3人の容疑者 | 正解 → verdict／誤り → 同じ画面に理由 |
| verdict | 「解決」の印・解決の文・星 | 次の夜 または epilogue／事件簿へ |
| epilogue | 文・星の合計・共有 | 事件簿へ／最初から |

## 壁と操作
- 壁（`#wall`）は、VIEW（x −10〜250、y 0〜180）を、表示領域に均等に拡大して描く。比率は260:180（約1.44:1）。左に身長計（10cmごとの目盛り、50・100・150cmに数字。数字は壁の色で縁取る）。灯りの現在の高さは、身長計の左に琥珀の三角、目盛りの上に短い線で示す（文字は描かない。数値は壁の下の `#lamp-readout`）。
- 灯りは、レール（足跡の位置の縦の線）の上の琥珀の玉。道具は紙色の切り絵で、棚（その道具の高さの破線）の上にある。すべれる道具にだけ棚の破線を出す。
- 描画順：壁の紙色と灯りの明るい円 → ガイド（有効時）→ 影 → 棚の破線 → 道具 → 選択の枠 → 身長計と灯りの目印 → 灯りの玉 → 選択した道具の名前の札（身長計の数字と灯りの玉を避けて、枠の上・下・横から選ぶ。`placeTag`）。影は濃い藍、道具は紙色に茶の縁。邪魔な道具を色で見分けられるようにはしない。
- **選択**：初期は灯り。灯りの玉・レールの近く（半径22px）または道具の輪郭の外接矩形（44px以上に広げる）でポインターを押すと、それを選んでドラッグできる。壁のそれ以外の場所では何も起きない（`touch-action: none`）。
- **ドラッグ**：押した位置からの移動量を、そのままcmに変換する相対移動。灯りは縦だけ、道具は横だけ。ポインターキャプチャを使い、up・cancel・lostpointercaptureで終了する。最初の1本の指だけを使い、2本目以降は無視する。
- **キーボード**：`#wall` に焦点が当たるとき、選択が灯りなら↑↓、道具なら←→で動く。1回1cm、Shiftで5cm。
- **選択チップ**（`#item-select`、`role=radiogroup`）：「灯り」と、すべれる道具の名前。すべれる道具が無い夜（夜1・2）は「灯り」だけを固定表示する。
- **微調整**（`#nudge-minus`・`#nudge-plus`）：選択が灯りなら「下げる／上げる」、道具なら「左へ／右へ」。1回1cm、400ms以上の長押しで60msごとに繰り返す。ポインターを離す・外す・焦点が外れると止める。
- **読み出し**：1行目に `#lamp-readout`（「灯り 99cm」）、すべれる道具を選んだときは同じ行に `#item-readout`（「帽子 横 120cm」）。値は小数を丸めて整数cmで出す。`#item-readout` が出入りしても行の高さは変わらない。
- **注記**（`#note-text[data-kind=coach|hint|notice]`。notice は、動かない向きの矢印キーを押したときの4秒の案内）：近さの行の下。最初はその夜の `coach`（何をすればよいかの1文。星は減らさない。夜1でガイドを消しているときは `coachNoGuide`）。ヒントを押したら、そのヒントの文（`ヒントN：…`）に替わり、操作・道具の選び替え・ガイドの付け外しでは消えない。はじめからで `coach` に戻す（`hintsUsed` は戻さない）。高さは2行分を予約し（幅900px以上は3行分）、2行以内の文なら操作列を動かさない。
- **近さ**（2行目。左に `#band-text`、右に `#meter`）：文は far「遠い」／warm「すこし似ている」／near「近い」／全体は合うが条件が足りないとき「あと少し」＋理由（「ずれている道具がある」「関係ない道具の影が残っている」。小さく添える）。success は「再現できた」。`#meter` の4つの目盛りは、`describeAssessment` の `fills`（0〜1）を `--fill` に入れて、各段の中の位置まで連続して満たす。`data-band` と `aria-label` は段の言葉のまま。
- **ガイド**（`#guide-toggle`、`aria-pressed`）：ねらいの面を朱で薄く塗り、輪郭を朱の線で描く。夜1は練習用で、何度出し入れしても星を減らさない（文言は「ガイドを重ねる」「ガイドを消す」）。夜2以降は「ガイド（★−1）」と明記し、付けた時点で使用とする。使った補助（ガイド・ヒント・誤答・考え方）は、夜を出て入り直しても、解決するまで星の計算に残す（ページを開いている間だけ。端末には保存しない）。
- **ヒント**（`#hint`）：押すたびに、まだ出していない文を1つ、注記の欄へ出す。いまの配置でいちばんずれているものの名指し（例「灯りが、少し高い。下げてみよう。」。配置が変わって文が替わったら先に）→ その夜の考え方 → 「ヒントはここまで」（番号なし）の順。ボタンは「ヒント（★−1）」、使ったあとは「次のヒント」（`title` と読み上げに「最初の1回で星が1つ減る」を持たせる）。
- **はじめから**（`#reset-stage`）：配置だけを開始へ戻す。

## 成功の演出と現場図
合格が `SOLVE_HOLD_MS`（350ms）保たれ、操作が止まっていれば成功。灯りと道具を `SNAP_MS`（420ms）で正解へそろえ、輪郭を朱で強く光らせる（stage の壁の上で）。reduced-motionでは、そろえるのも光らせるのも瞬時。
その後 solved の面板を出す。上から、再現した壁（`#wall-result`。ガイドの輪郭付き）と、その右下に朱の印「再現」（`#stamp`。CSSのアニメーションで現れる）、現場図（`#side-view`）、再現の文（`reveal`）、読みの文（`readingOf`）、「推理する」。
現場図は横から見た図：右が壁、左が灯りと足跡。床、壁、灯りの高さの目盛り、足跡〜壁の距離、各道具の位置（奥行き）、灯りから道具の上端・下端を通って壁へ届く光の筋。踏み台がある夜は足跡の下に四角い台を描く。「灯り 99cm」と道具の名前は、線をすべて描いたあとに横書きの札で重ねる（破線が文字を横切らない）。

## 推理
- 推理の手がかり（`#deduction-clues`）は、決まり（rule）→踏み台（stool。夜4だけ）→アリバイ（alibi）→再現（result）の順。足跡・現場・証言は stage の「現場メモと手がかり」（`#stage-clues`）にあり、ここには出さない（長くなって容疑者に届かない）。再現の項目の文は `readingOf(caseDef)` そのもの（夜2以降は「灯りの高さは96cm。これを提げた人の身長は？」で、身長は書かない）。
- 夜3は、灯りの高さに合う身長の人が2人いて（容疑者のカードに同じ身長が2つ並ぶ）、アリバイが外すのは同じ身長のもう1人だけ。身長だけを見て選ぶと、半分は外れる。夜5は、身長178cmと180cmの2人を、灯りの高さの正確な読み（6割で計算した106.8cmと108cm）で分け、アリバイは身長が大きく違う別の1人を外す。誤答の理由は、非整数を小数1桁で出す（「106.8cm」）。
- 容疑者は3枚のカード。名前（明朝体）・職と身長・証言。各カードに「外す ✕」（自分用の印。`aria-pressed`。押すと「✕ 外した（戻す）」に変わる。判定に使わない。外した人も「この人だ」で選べる）と「この人だ」。外した人のカードは、全体を薄くせず（文字のコントラストを保つ）、取り消し線と点線の枠で分ける。
- 誤りのとき、選んだカードに「ちがう」の印（`.suspect-badge`）を付けて「この人だ」を無効にし、`#deduction-message` を**押したカードの末尾へ移して**理由を出す（押した場所の近くに出すため）。他の人は選び続けられる。推理の画面を出るとき、メッセージを元の位置（容疑者の一覧の後ろ）へ戻して隠す。
- 「考え方を見る」（`#deduction-hint`）は `deductionHint` を出す。ヒントとして数える。一度出したら無効にする。

## 見た目
- 色は `app.css` の `:root` のトークンだけに書く。舞台 `#12102a`、面 `#1b1840`、壁 `#efe6cf`、影 `#1d1a3a`、道具 `#e8d2a2`（縁 `#6b4f2a`）、灯り `#ffb84d`、朱 `#d6402f`、本文 `#f1ecff`、補助 `#b9b2d8`、焦点 `#ffd36e`。ダークの1テーマで、`color-scheme: dark`。
- 外部フォントを使わない。見出しと事件名は明朝系（Hiragino Mincho ProN, Yu Mincho, serif）、本文はsystem-ui。数字は `tabular-nums`。
- 本文は `word-break: normal`（対応するブラウザーでは `auto-phrase`）、見出しは `text-wrap: balance`。数字・単位・式の途中で行が割れないよう、`lib/text.js` の `nowrapSegments` が決めた範囲を `span.nb`（`white-space: nowrap`。textContent は変わらない）で包む。行頭に数字・単位・「＝」「−」を置かない。
- 動き：印のスケールイン・そろえる移動・輪郭の点滅。reduced-motionでは全て瞬時。装飾の点滅や粒は付けない。
- 44px以上の操作、見える焦点（焦点色の2px輪）、状態を色だけで表さない（選択は輪＋太字、ちがうは文字の印、ロックは鍵と文）。

## レイアウト
- 幅899px以下：1列。上から、ヘッダ → 題 → 証言ストリップ → 壁 → 読み出し・近さ → 注記 → 選択チップと微調整 → ヒントとガイド → 手がかり。壁は幅いっぱい（余白16px）。幅719px以下かつ高さ760px以下では、題を見た目だけ隠し（読み上げには残す）、縦を詰める。幅360×高さ640でも、夜1〜5のすべてで、壁・近さ・注記・選択・微調整と、ヒント・ガイド・はじめからの行までが最初の画面に入る（高さ700px以下では、スケッチを72×54pxにして引用を隠し、道具の選ぶ札を1段の横スクロールにする）。
- 幅900px以上：左に証言ストリップと壁、右に状態・注記・操作・手がかり（1画面に収まる）。solved も2列（左に再現した壁、右に現場図・説明・読み・「推理する」）で、1440×900なら見出しと「推理する」が同じ画面に入る。
- 導入・推理・結末・エピローグ・現場図（幅900px未満）は、読む列を680px（現場図は640px）に抑えて中央に置く。結末とエピローグは、判子・見出し・本文・星・ボタンを中央揃えにそろえる。
- 高さ560px以下の横画面：壁を左いっぱいに、スケッチ・近さ・操作を右へ。証言の文は隠す（スケッチは残す）。
- 配置は `app.css` のCSS Grid（`grid-area`）で決め、DOMの順序は変えない。
- 幅360〜1440で横スクロールを出さない。

## 焦点と中断
phase が変わったら、その画面の見出し（`tabindex=-1`）または主ボタンへ焦点を移す（stageは `#wall`、solvedは `#to-deduction`、verdictは `#next-case`）。
dialogは開いた操作へ焦点を戻す。dialogを開く間は、ポインターの操作と長押しの繰り返しを止める。
`visibilitychange`・`blur` で、ドラッグと長押しの繰り返しを止める。時計は使わないので、中断で進行は変わらない。

## 確認する画面
幅360 / 390 / 768 / 1440 で、home・briefing・stage（夜1のガイド付き、夜3の途中、夜5の邪魔な道具）・solved・deduction（誤り・正解）・verdict・epilogue・各dialogを確認する。
壁とスケッチが重ねて比べられるか、影が読めるか、近さの文が次の操作を教えるか、日本語の行分けと44px以上の操作、横はみ出し、焦点を、実画像と実操作で評価する。
