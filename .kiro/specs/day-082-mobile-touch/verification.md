## 4. 実装の独立レビュー（読み取り専用・別のAI・API 経由）

遊びの正しさを壊す不具合は無し。直すべきは主に試験の穴で、すべて対応した。

| 指摘 | 対応 |
|---|---|
| 画質の試験が軽くなったことを確かめていない（`__quality.ao` は表の値、`isMobile` の画素比は1） | `ao` を実際の `post.ao.enabled` から読み、画素比3の端末で 1.25・1.5・1・0.75 を確かめる試験にした |
| 最初のタッチで切り替えたとき画質が下がる試験がない | 段階が1（やや軽い）・AO なしになることと、読み込み直さないこと（`window` の目印）を確かめる試験を足した |
| 押した瞬間・離した瞬間の単体試験が、効かない手順で書かれている | 「物理で押す→タッチで押す→押した印が1回だけ」「しゃがみが物理とタッチで2回切り替わらない」に直した |
| 狙い中に窓を離れた（blur）経路の試験がない | 狙っていれば投げずにやめ、止めはしない試験を足した |
| ペンでもタッチ操作に入る・`?adaptive=1`・「1.4倍を越えたら」と `>=` | 実装に合わせて要件を直した（1.2 ペン、10.3 例外、2.4 の文言） |
| 物理の C を押したままタッチのしゃがみを押すと切り替わらない | 変更なし（設計どおり。ほぼ起きない） |
| 軽微：時計が rAF と `performance.now` で混在／コンテキスト喪失の案内が重なる／デスクトップでも `visualViewport` の再サイズ | 時計を揃えた／案内を1つに／タッチのときだけ再サイズ |

試験が見逃す変異を、実際にソースを壊して確かめた（どちらも元に戻した）。A：`setAoEnabled` の呼び出しを消す → ブラウザ試験2件が落ちた。B：`touchKeyDown` の物理キー判定を消す → 単体試験2件が落ちた。C（NaN を通す）は NaN・Infinity を入れる単体試験を足した（変異は未実施）。`consumeRelease` が本体で未使用なのは元からで、変更していない。

### 4b. 実装の独立レビュー 第2回（最終・読み取り専用・別のAI・API 経由）
