# 要件: ふたりの着地点

「なんでもいい」から、答えに応じて食べたいものを絞り、近くの行き先を見つける。2026-11-05の追加依頼により質問を分岐し、具体的な店名から地図案内までを完了点にする。

## 1 同行者と段階的な質問
- 1.1 When 利用者が開始するとき, アプリはパートナー・友達・家族・ひとりを選べるようにする。
- 1.2 When 同行者を選ぶと, アプリは気分を尋ね、食事・カフェ・一杯ではジャンル→具体的な料理や飲み物→空間→徒歩圏へ絞り、外出では空間→徒歩圏へ進む。進行表示は実際の質問数に合わせる。
- 1.3 When 利用者が前の問へ戻ると, アプリは回答を保持して修正できるようにする。
- 1.4 While 必要な回答が未選択の間, アプリは次の問や検索へ進めない。

- 1.5 When 上位の回答を変えると, アプリは依存する下位の回答をリセットし、前の枝の料理を混ぜない。
- 1.6 While 質問に答えている間, アプリは選択済みの食事ジャンル・料理を見える形で示す。

## 2 探す場所
- 2.1 When 利用者が現在地を使う操作をすると, アプリは検索先へ座標を送ることを説明したうえで、一度だけ位置を取得する。
- 2.2 If 位置情報を拒否・取得失敗した場合, アプリは理由・再試行・駅名や場所から探す導線を示し、回答を保持する。
- 2.3 When 利用者が駅名や場所を検索すると, アプリは候補名・住所を提示し、選ばれた場所を検索の中心にする。
- 2.4 While 位置や場所を取得中の間, アプリは状態を表示し、重複操作を防ぎ、取り消せるようにする。

## 3 着地点と道案内
- 3.1 When 必要な質問と場所が揃うと, アプリは選んだ料理・飲み物と希望の徒歩圏を優先して施設を最大3軒に絞り、1軒を大きく表示する。
- 3.2 When 結果を表示すると, アプリは施設名・カテゴリ・住所・距離・徒歩時間の目安・選んだ条件を示す。
- 3.3 When 別の場所にする操作をすると, アプリは再検索なしで別候補を示し、最後の候補では条件の見直しへ案内する。
- 3.4 When 道案内を開くと, アプリは選んだ施設座標をGoogleマップの徒歩案内へ渡す。
- 3.5 If 0件・通信失敗・待ち時間超過の場合, アプリは状況を区別し、回答を保持して条件修正や再試行を可能にする。
- 3.6 When 結果を示すと, アプリは徒歩時間が経路計測でないことと、雰囲気・営業状況は地図で確認することを伝え、未知の評価や写真を捏造しない。

- 3.7 When 料理・飲み物を選んで検索すると, アプリはその名称で店を探し、0件なら半径1.5km、5kmへ段階的に広げる。それでも0件なら選んだジャンル内の候補を探し、料理の一致を保証しない別案と明示する。回答は変更しない。
- 3.8 If 0件または通信失敗の場合, アプリは料理を選び直す・場所を変える・Googleマップで探す導線を提供する。
- 3.9 When 料理名で施設を提案すると, アプリは実際の提供メニューを保証せず、メニュー確認へ案内する。

- 3.10 When 候補が見つかると, アプリは「あなたにおすすめのお店」と実在データの店名を示し、その近くにGoogleマップの徒歩案内ボタンを置く。希望圏外の候補には範囲を広げた事実と実距離の目安を示す。
- 3.11 While 段階的に検索する間, アプリは検索範囲を表示し、最大4回・合計12秒以内に完了またはエラーとする。通信失敗は範囲拡大で隠さない。

## 4 品質・公開への統合
- 4.1 While 利用している間, アプリは位置・回答・検索結果を永続保存せず、共有リンクに含めない。
- 4.2 When アプリを共有すると, アプリはX・LINE・リンクコピー・対応端末の共有シートを提供する。
- 4.3 When 390・768・1440px幅で使うと, アプリは横はみ出しなく表示し、44px以上の操作領域・キーボード操作・見えるフォーカス・状態の読み上げ・動きの軽減を提供する。
- 4.4 When 公開用にビルドすると, サイトは一覧・canonical・OGP・データ出典・必要な通信先の制限を揃え、公開ゲートを通す。

## 対象外と隣接する責任
施設の営業・空席・静かさ・実際の経路は施設情報や地図側で確認する。予約・認証・履歴・口コミ・課金・SNSへの投稿は含めない。
