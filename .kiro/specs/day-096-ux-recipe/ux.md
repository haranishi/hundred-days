# ユーザーストーリーとUX5階層（実装の前に書いた・2026-11-20）

## ユーザーストーリー
| ユーザー | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| **本命**: 自分の店のページを作りたい人（デザインの経験なし） | 何を載せてどの順に並べればいいか知りたい。迷って手が止まるから | 目的を1つ選ぶだけで、使える下書きが出る。30秒以内に、自分の店の名前に変えられる |
| **本命**: 同上 | 触った結果が良いか悪いか、理由つきで知りたい。ただ並べても良し悪しが分からないから | 部品を動かすと点と項目が変わる。各項目に理由があり、1タップで直せる |
| **本命の相手**: 共有リンクを受け取った人 | 編集画面ではなく、まずページを見たい。道具の使い方は後でいい | リンクを開くと、ページがそのまま見え、気に入ったら1タップで自分用に作れる |
| **救う相手**: そのページを見に来る「お客さん」 | 迷わず、安心して、行動したい | 診断の言葉は、お客さんの立場から書く（「来た人が〜」）。誇張した期限・残り枠を促さない |
| 受託制作者（本人） | クライアントに構成の理由を説明したい | 書き出したHTMLと共有リンクを、説明の叩き台に使える |

## UX5階層
- **①戦略**: 目標=「構成の迷い」を無くし、触りながら理由を学べる。差別化=**部品の種類でなく目的から順序と理由が決まる**こと
  （他にも目的を伝えてページを生成するサービスはある。ここでは「並べ替えた瞬間に、その目的に照らした理由が出る」体験を磨く）。
- **②要件**: 8目的・19部品・診断・共有・書き出し。対象外は requirements.md（画像・自由配置・AI生成・アカウント）。
- **③構造**: 目的画面 → 編集画面（構成・プレビュー・パネル）→ 共有／保存のダイアログ。受け取る側は、見るだけ画面 → 「もとに作る」で編集画面。
  迷う分岐=「目的を変える」→確認＋元に戻せる。壊れたリンク→理由を出して入口へ。
- **④骨格**: 一番大きい要素は**プレビュー**（1つ）。スマホでは、編集パネルを画面下に非モーダルで置き、触りながらプレビューが見えたままにする。
  並べ替えは「つまみ」だけがドラッグ（スクロールとぶつからない）。▲▼ボタンとキーボードでも並べ替えられる。
- **⑤表層**: 道具の画面は無彩色寄りにして、ユーザーが選ぶテーマと喧嘩しない。段階の色は色覚に配慮した配色＋記号（気・わ・信・動・安）。
  診断は色でなく、アイコンと文字（✓／！）で示す。動きは短く、動きを減らす設定で止める。

## 5階層を通して実装が変わった点（実装前の記録）
1. 差別化が「理由」だと分かり、部品の「なぜ」パネルと、根拠リンクつき診断を要件に足した（当初は部品箱＋診断点だけだった）。
2. 診断の言葉を「お客さん視点」に統一した（作る人への叱責にならない）。
3. 「本当の数字です」チェックを、期限・残り枠の部品に必須で入れた（Day063の解約ボタンの学びを持ち込み）。
4. 共有リンクの受け手のために「見るだけ画面」を足した（編集画面で開くと、受け手が迷う）。
5. 並べ替えを「つまみだけドラッグ＋▲▼」に決めた（プレビューの中のドラッグは、スクロールと衝突する）。
6. 編集パネルをモーダルにしない決まりにした（モーダルだと、直した結果が見えない）。
7. 数値の目安は「このアプリの目安」と明記し、根拠リンクを出す方針にした（調査で数値の閾値が確認できなかったため）。
