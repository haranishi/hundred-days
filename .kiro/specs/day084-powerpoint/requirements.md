# Day84：PowerPointを直接選んで発表する

## 目的と承認の根拠
2026-11-06の本人指示により、初期SDDのPDF/PPTX/PPT選択をWeb版へ継承する。
ブラウザ版でPDFのみとした制限は本仕様で置き換える。毎回の手動PDF書出しを通常手順にしない。
既存の暗号化接続・プレビュー採用・差し替え・全画面・公開URLはday084-browserの仕様を引き継ぐ。

## 1. 直接選択
- 1.1 PCのブラウザでPDF・PPTX・PPTを選択またはドロップできる。利用者へアプリやサーバーの導入を要求しない。
- 1.2 PPTX/PPTはアプリ内で表示用データへ自動変換し、同じプレビュー・採用・スマホ操作へ進める。
- 1.3 元ファイルの背景・フォント指定・XMLを推測で変更しない。順序・縦横比と元の背景を維持する。
- 1.4 アニメーション・動画は静止画になること、利用可能なフォントで見た目が変わり得ることを事前に説明する。全ページの確認を必須にする。
- 1.5 PowerPoint本体を遠隔操作する機能は含めない。元PowerPointからPDFを作る方法は、再現に問題がある場合の補助手段とする。

## 2. PC内での処理と待ち時間
- 2.1 元資料・PCから読み取ったフォントを外部へ送らない。スマホへ渡す現在ページ画像・カンペ・状態は既存仕様で暗号化して中継し、原本とフォントは送らない。
- 2.2 変換エンジンと日本語の通常/太字フォントを同一originから必要時だけ取得する。スマホのリモコンにはエンジンを読み込ませない。
- 2.3 初回取得・エンジン初期化・変換・ページ描画を文字と経過時間で示す。未計測の残り時間や処理率を作らない。
- 2.4 処理中も旧資料を維持する。実行を取り消せ、失敗・時間切れでも旧資料とリモコンを継続できる。再選択で再試行できる。
- 2.5 原本25MiB・100ページ、同時処理1件を守る。初回取得/初期化は180秒、変換は120秒を上限とし、停止時は変換用フレームとそのWorkerを終了して資源を解放する。
- 2.6 キャッシュするのは固定版の公開エンジン/フォントのみ。資料と変換結果はメモリだけで扱い、採用前の取消・差し替え・終了で解放する。

- 2.7 対応PCブラウザでは本人の明示操作とブラウザの許可で、PC内の代表的な英日フォントを任意に使用できる。同じ書体のWindows/Mac名だけを対応付け、未許可/未対応でも標準日本語フォントで処理できる。

## 3. 配信と検証
- 3.1 通常画面のJS評価制限を維持する。変換専用フレーム/Workerだけに必要なCSPを設定し、外部originへの通信を許さない。
- 3.2 公開原本の取得先・固定版・ハッシュ・ライセンス・ソースを記録する。25MiB超のアセットを配信に入れず、私的資料はGit/配信/宣伝に含めない。
- 3.3 自作の日本語/英語・通常/太字・白/色背景を含むPPTXとPPTで、直接読込→全ページ確認→採用→スマホの送り/戻りを実ブラウザで検証する。
- 3.4 指定された実資料はローカルだけで別途確認する。文字抽出のみで描画成功と判断しない。検証範囲と差異を記録する。
- 3.5 不正形式・空/過大・ページ上限・取得失敗・取消・再選択と、PDF/暗号化接続/全画面の既存動作を回帰検証する。
- 3.6 本人から許可されているPR・全必須CI・マージ・公開後の実接続確認まで進め、案内文と宣伝素材を実際の対応形式に合わせる。SNSへの投稿はしない。
