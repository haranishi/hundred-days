# 要件定義：トップページの作り直し

## Introduction
`https://hundred-days.pages.dev/`（`scripts/build.mjs` が生成する一覧ページ）は、機能は足りているが、見た目が量産品に近い。
等幅の見出し・青いボタン・同じ形のカードが77枚並ぶだけで、「毎日1本、77本続けた」という最大の強みが一目で伝わらない。
スマホでは、最初のアプリまで3,500px以上あり、その大半は225個のタグのチップが占める。
この仕様は、一覧ページを「作品として見せられるページ」に作り直す。アプリ本体と `meta.json` は変えない。

## Boundary Context
- 対象：一覧ページの見た目・構成・絞り込み・OG画像・同梱書体。
- 対象外：各Dayのアプリ、`meta.json` の項目、計測の種類（GA4の既存イベント名と送る値）、タグの付け方、ライトテーマ、英語版。
- 接続先：`scripts/build.mjs`、`tests/e2e/`（外部Day・Day 007〜010・050・051が一覧のDOMを見ている）、`static/assets/`。

## ユーザーストーリー
| ユーザー | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| 初見の訪問者（Xやプロフィールから来る学生・開発者）★本命 | 3秒で「何のページか・何日続いたか・新しいのはどれか」を知り、すぐ最新を触りたい。続いている証拠を見て、触る価値を決めるため | ファーストビューに題名・77/100・最新アプリの実画面・「最新のアプリを開く」がある |
| 依頼を考える人・採用側 | 作り手の腕と作法（AIの使い方、失敗の書き方）を数分で見たい | 実画面の一覧と制作メモで判断でき、ページ自体が整っている |
| 特定のアプリを探す人 | 77件から10秒で見つけたい（Day番号・題名・テーマのどれでも探せるように） | 検索・タグ・Dayのマップのどれでも辿り着ける。0件のときは戻る手段が出る |
| スマホで見る人 | 長い一覧でも、迷わず、疲れずに進みたい | 最初のアプリまで約2画面（旧ページは約4画面）。タグで押し出されない。一覧の途中から検索へ戻れる |
| このチャレンジに励まされる人（毎日続けられずにいる人） | 続けた結果の具体的な形を見たい | 100マスの埋まり方・制作時間・失敗の記録が見える |

## UX5階層
| 階層 | 決めたこと |
|---|---|
| ①戦略 | 目標＝アプリを触ってもらう・Xで追ってもらう・信頼される。差別化の源泉は「規模を一目で見せる（100マス）」「実画面を先に見せる」「失敗も書く（制作メモ）」。 |
| ②要件 | 載せる：100マスのマップ、最新アプリのプレビュー、検索、よく使うタグ、タグ一覧、並べ替え、ルールと解禁の段階、Xへの入口（ヘッダー・ヒーロー・ルール欄）、スマホの「検索へ戻る」。外す：「公開中」の印（73/77が同じで情報がない）、225個のチップの全展開、青い主ボタンの量産。 |
| ③構造 | 入口＝題名と進捗。次＝マップで日を選ぶ／検索で探す。マップのマスはその日のカードへ飛ぶ（フィルタ中でも解除して飛ぶ）。0件のときは「条件をクリア」で戻る。 |
| ④骨格 | 最大の要素は題名（1つ）。右にマップ＋プレビュー（触ると変わる、唯一の動く要素）。絞り込みの帯は画面上端に追従（PC）。カードは画像が主、文は従。 |
| ⑤表層 | 暖かい黒に象牙色の文字、朱色は「いま・選択・押せる」だけ。縦長の看板書体（数字と題名）＋等幅の小さな札。動きは1つの目的に1つ。`prefers-reduced-motion` で止まる。 |

## 受け入れ条件
1. 77件すべてが新しい順に出る。外部公開・制作記録のみのDayも従来どおり。進捗の数字・制作時間・制作日数は `meta.json` の実値。
2. マップは `ceil(max(100,最新日)/10)*10` 個。公開済みのマスは `#day-NNN` へのリンクで、触る・フォーカスすると下のプレビューがその日に変わる。JSが無くても、マスのリンクとプレビュー（最新）は動く。
3. 検索は題名・説明・タグ・Day番号（`34`・`034`・`Day34`）に当たり、全角半角・大小・カタカナとひらがなの差を無視する。タグと併用でき、0件のときは理由と「条件をクリア」を出す。
4. よく使うタグは12個以内。全体の40%を超えて付くタグ（現状 vanilla-js・no-dependencies）は絞り込みに効かないので、ここに出さずカードのタグ表示でも後回しにする。大小・空白・記号だけが違うタグ（3D/3d、Web Audio/web-audio）と、意味が同じ英日の5組（game/ゲーム・puzzle/パズル・security/セキュリティ・image/画像・music/音楽）は1つに数え、いちばん多い綴りで見せる。全タグは「タグ一覧」から選べる。
5. 既存の約束を壊さない：下の「DOMの約束」と、GA4の既存イベント（app_open・demo_play・tag_filter・profile_click・memo_open）の名前と値。
6. アクセシビリティ：スキップリンク、見出しの順、キーボードだけで全操作、`:focus-visible`、文字のコントラスト4.5:1以上（大きい文字は3:1）、主な操作の大きさ44px以上（チップは40px以上）、`prefers-reduced-motion`、390〜1920pxで横スクロールなし。
7. 外部へ新しい通信をしない。書体は同梱（2ファイル・計60KB以下・先読み）。制作メモは全文のまま載せる（削って軽くしない）。HTMLは現行（約484KB・gzip 138KB）の1割増し以内（gzipで160KB以下）。
8. OG画像（1200×630）を新しい見た目に合わせて作り直す。件数など日々変わる数字は入れない。
9. `npm run check` と、一覧を見る既存のブラウザテストが通る。新しい単体テストとブラウザテストを足す。
10. 見た目は、別セッションの採点（スクショのみ・10項目20点）で16点以上かつ0点なし。（実績：第1周14点→第2周18点で合格。記録は `.agent-harness/runs/top-page-redesign.md`）
11. スクショは切り抜かず全体を表示する（76枚中16枚が16:10でなく、Day 70〜77はOGP型の1.905）。余白は暗い面。
12. 同じ行のカードは、見出し・サムネ・題名・説明・タグ・ボタンの段がそろう（`subgrid`）。題名の行数が違っても動かない。
13. 追従する検索の帯（900px以上）は不透明で、画面の上端に付き、高さ約120px。マップのプレビューは、題名が1行でも2行でも高さが変わらない。

## DOMの約束（既存テスト・計測が見ている。変えるときはテストと一緒に直す）
- カード：`article.card` に `data-day`（3桁）・`data-title`・`data-tags`。カード内の `img` は1つだけ（スクショ。`loading="lazy"`）。
- `a.btn[href="./day-NNN-…/"]` は、そのDayのカードの「アプリを開く」だけ（ほかの場所で `.btn` を使わない。新しいDayのテストが厳密一致で見る）。外部Dayは「紹介ページを開く」でカード内の `.badge` は1つ（「外部で公開」）。
- `.thumb__link`（サムネの `a`）・`.thumb__play`（`data-demo`・名前に「Day NNN」「題名」「再生」）・`.card__title`・`.progress__now`（数字だけ）・`.pill`・`.footer__links a`・`.about__link a`・`.memo`。
- `<link rel="canonical" href="https://hundred-days.pages.dev/">`。
