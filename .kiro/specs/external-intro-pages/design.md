# 設計

## ユーザーストーリー

- 画像や動画を1つずつ保存する手間に困っている人が、検索で見つけたページで、PageCrate が何をするものか、いま何ができるか、権利の注意は何かを30秒で知り、デモを試したい。
- 100日チャレンジを追う人が、Day081 の作り方（AIに任せたこと・自分でやったこと・失敗）を読みたい。

## UXの5階層

| 層 | 決めたこと |
|---|---|
| 戦略 | 検索で見つけた人を、アプリの試用か、制作記録の閲読へ送る。検索の評価を `rairakku.com/100days/` に集める。成功は Search Console の表示回数とクリックで、数週間後に見る |
| 要件 | requirements.md の8点 |
| 構造 | ヘッダー → 題名と一文 → 主ボタン → 画面と動画 → できること → 注意 → 制作メモ → 共有 → 一覧へ戻る |
| 骨格 | 1カラム・最大幅 720px・スマホが先。主ボタンは高さ 48px 以上で、最初の画面に入る。見出しを目印に飛べる |
| 表層 | 一覧と同じ暗い配色と見出しの書体（Big Shoulders Display）、信号色のオレンジ。本文は端末の日本語書体 |

## `meta.json` の `intro`

```json
"intro": {
  "codeUrl": "https://github.com/haranishi/pagecrate",
  "poster": "demo-poster.webp",
  "highlights": ["できること1", "できること2"],
  "notice": "使う前の注意（いまの制約や権利）"
}
```

- `intro` があると、そのDayの紹介ページを作る。`status: external` と `externalUrl`（https）が前提。無ければ、ビルドを止める。止めないと、書いたのにページが出ない、という静かな失敗になる。
- `codeUrl` は任意。https だけ受け付ける。`highlights` と `notice` も任意で、無ければその節を出さない。
- `poster` は任意。そのDayのフォルダの中の画像ファイル名（webp・png・jpg）だけ。動画のポスターに使う。無ければ画面写真を使う。名前を書いてファイルが無ければ、ビルドを止める。
- 題名・説明・タグ・制作メモ・スクリーンショット・動画は、今ある `meta.json` の項目を使う。同じ内容を二重に書かない。

## 実装

- `scripts/lib/external-intro.mjs`：`intro` の検証と、ページのHTMLを返す関数。本体のビルドから分けて、単体で試せるようにする。
- `scripts/site/intro.css`・`scripts/site/intro.js`：一覧の `home.css`・`home.js` と同じ置き方。ビルドが `dist/<フォルダ名>/` に書く。
- `scripts/build.mjs`：`intro` の読み取り、`dist/<フォルダ名>/index.html` の書き出し、`_headers`・`sitemap.xml`・404 の候補への掲載、カードの副リンクを足す。

### 判断の理由

- スクリプトとスタイルを別ファイルにするのは、公開済みのDayと同じ CSP（`script-src 'self'`・インライン禁止）をそのまま使うため。構造化データだけはインラインだが、実行されないデータなので CSP に掛からない。
- 画像・動画・フォントの参照は、文書相対にする。`/100days/` の下でも、元のホストでも、同じHTMLで動く。
- 構造化データは WebPage と BreadcrumbList の2つだけ。外部Dayの本体が何者か（アプリ・拡張・サイト）は一律に言えないので、SoftwareApplication は使わない。
- 計測タグを入れないのは、紹介ページが閲覧者の情報を送らないと言えるようにするため。
- 「アプリを開く」を注意のあとにも置くのは、権利と規約の注意を読んでから開く流れを作るため。外部へ移ることは、↗ の印で示す。
- ポスターを別にできるようにしたのは、画面写真の直後に同じ絵が続くと、同じものを2回見せることになるため（画面の採点で指摘された）。
- 短い箇条書きと補足の文は、`text-wrap: balance` で行の長さをそろえる。2文字の語が行をまたいで割れるのも減る。長い段落は `pretty` のまま。
- カードの主ボタンを紹介ページへ変えないのは、他の外部Dayと同じ動きを保ち、既存の試験（主ボタンとサムネが外部へ飛ぶ）を壊さないため。

## 捨てた案

- 全外部Dayに自動で紹介ページを作る。4件の動きが同時に変わり、本人の指示（Day081）を超えるため、見送った。
- README.md を変換して本文にする。依存なしのビルド規則に反し、リポジトリ内の相対リンクも混じる。
- `publicUrl` を紹介ページにする。Xの返信リンクが、アプリから紹介ページへ変わってしまうため、見送った。
