# Day100 kamoku の要件

kamoku（日本の個人事業主向けのローカル会計ソフト。GitHubで公開中のOSS）を、100日チャレンジの最後のDay100として出す。インストールせずに、一覧からそのまま開いて触れる形にする。

## 決まっていること（2026-11-26・本人）
- kamoku を100日チャレンジの最後の企画（Day100）にする。PRを作成してマージする。足りないところは直す。
- 公開は、ブラウザだけで動くお試し版を作って出す。
- 100本目は kamoku の掲載を中心にする。過去の作品をまとめる画面や、利用数の集計は入れない。共有画像だけ作り直す。

## 要件

### R1 お試し版
1.1 `meta.json` は `status: published`。公開URLは `https://rairakku.com/100days/day-100-kamoku/`。
1.2 開くと、架空の事業の帳簿が入った kamoku が、追加の操作なしで使える。取引の登録、仕訳帳、帳票、書き出しができる。
1.3 データは端末の中だけにあり、再読み込みで最初の帳簿に戻る。配信元以外への通信はしない。
1.4 画面に、お試し版であること（架空のデータ・保存されない・税の計算は参考値・画面の「今日」は帳簿に合わせた日付）と、ソースへのリンクが出る。
1.5 幅390・768・1440で横スクロールが出ない。タッチでも主な操作ができる。
1.6 どのkamokuから組み立てたか（コミット）と、同梱する第三者のライセンスを、配信物に含める。
1.7 CSPは、このDayにだけ `'wasm-unsafe-eval'` を足す。`'unsafe-eval'` は付けない。
1.8 共有欄（X・LINE・リンクのコピー・端末の共有）と、OGP・canonical を持つ（全アプリ共通の検査に通る）。

### R2 説明の正確さ
2.1 `meta.json`・README・Xの投稿文は、コードと作業記録に照合した事実だけを書く。本人しか知らない体験は書かない。
2.2 「会計の相談に答える」「申告できる」「電子帳簿保存法に対応」とは書かない。税理士の確認が済んでいないことと、名前の商標を確認していないなら、その旨を書く。

### R3 一覧ページ
3.1 一覧の件数は100になる。共有画像（`static/assets/og.png`）を作り直す。

### R4 公開面の約束
4.1 このリポジトリ・配信物・投稿に、事業所名、ローカルのパス、実際の帳簿・明細、秘密の値を入れない。
4.2 他社サービスとの比較表現を書かない。

### R5 検査と公開
5.1 `npm run precheck`・`npm run build`・単体試験・`npm run publish:check -- --day 100`・Day100のブラウザ試験を通してからPRを出す。
5.2 PRは公開用の状態で出し、CIが通ったらマージする（本人指示）。本番で、画面の動きと素材を確かめる。
5.3 Xの投稿は本人の操作として残す。
