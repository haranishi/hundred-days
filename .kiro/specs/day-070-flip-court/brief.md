# Brief: フリップコート

## Problem
短時間で遊べる新作として、相手の参加を待たず、スマホまたはPCの1台で始められるゲームを作る。

## Current State
100日アプリにはDay069まである。本人が再提案の①「フリップコート」の作成を選択した。

## Desired Outcome
1人でCPUと60秒対戦し、打球の着地と挟み返しで陣地を争い、結果から再戦できる。

## Approach
既存の静的Webアプリと共有機能に合わせる。新たな外部サービスを使わず、画面内のCPUと対戦する。
球技の返球と陣取りの判断を両立できるか、最初の試遊で確かめる。

## Scope
- In: 小さな盤面、ラケットとボール、着地・列の反転、60秒のCPU戦、結果・再戦・共有。
- Out: オンライン対戦、参加者募集、ログイン、ランキング、必殺技・カード・ステージ追加。

## Boundary Candidates
- Game rules: 盤面、着地、反転、陣地の集計、試合の終了。
- Match and input: 返球、CPU、時間、一時停止、スマホ・キーボード操作。
- Presentation: 導入、盤面と結果、反転の説明、共有、画面幅への対応。
- Repository integration: 新Dayの制作記録、既存のビルド・単体・ブラウザ検査への接続。

## Out of Boundary
既存Dayの遊び、共通共有機能の挙動、iroriの実装と公開状態は変更しない。

## Upstream / Downstream
- Upstream: 既存のDay構成・共有機能・検査手順。
- Downstream: 本人による試遊と、別途指示を受けて行う公開作業。

## Existing Spec Touchpoints
- Extends: なし。独立した新作の仕様を作る。
- Adjacent: Day069の仕様、既存Dayの実装。仕様の承認を新作へ流用しない。

## Constraints
ユーザーが選択した1人CPU戦・60秒・着地による挟み返しを引き継ぐ。
要件案の確認後に設計・タスクを具体化し、承認された範囲で実装する。
新しい依存や素材を増やす前に、既存コードと標準機能で実現できるか確認する。
