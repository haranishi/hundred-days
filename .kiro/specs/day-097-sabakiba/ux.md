# ユーザーストーリーとUX5階層（実装の前に書いた・2026-11-21）

## ユーザーストーリー
| ユーザー | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| **主役**: 一尾の魚を前にした家庭の人（手が止まる） | 次に包丁をどこへ、どの向きで入れるかを、今の手元と同じ向きで見たい。動画では向きが違い、止めて戻すのも濡れた手でつらい | 台所の視点で3Dが開く。次へ／前へが大きく、手順の動きを繰り返し見られる |
| 同上 | 骨が体のどこにあるかを見たい。見えないので包丁が骨に当たらず、身が残る | 透視で、背骨・腹骨・小骨の位置と、刃がその上を滑る線が見える |
| 左利きの人 | 左右が逆だと頭の中で反転する作業が要り、間違える | ボタン1つで、画面も文章も左右が入れ替わる |
| 釣り人 | 釣った魚（アジ・サバ・キス・タイ・カツオ）をその場でさばく。見慣れない魚は似た魚の手順で応用したい | 種ごとに「この手順が使える魚」が書いてあり、さばく前に安全（毒魚・寄生虫）が分かる |
| 料理を始めたばかりの人 | 切る練習を、魚を無駄にせず繰り返したい | 切り線をなぞって採点でき、「小刻みに引かない」などの理由が出る |
| 親子（食育） | 魚の体の中（骨・内臓）を見せながら、危ないことも伝えたい | 部位の名前と、刃物・寄生虫の注意が、画面から離れずに読める |

## UX5階層
- **①戦略**: 目標＝「次にどこへ刃を入れるか分からない不安」と「身が骨に残った後悔」を減らす。差別化＝**台所と同じ向きの3Dで、骨と刃の通り道を透かして見られ、なぞって練習できる**こと
  （動画・写真・図解は強いが、向きの固定・骨の中・手元との見比べが弱い）。成功＝1尾の最後の手順まで進める割合と、練習の再挑戦。魚の図鑑・レシピ集にはしない。
- **②要件**: 8種・5方法・3D視点・刃の通り道・練習・安全・部位と使い道・共有。対象外は brief.md（毒魚・締め方・アカウント）。
- **③構造**: 入口（魚をえらぶ）→ 魚の前置き（道具・安全のひとこと・必要時間）→ ガイド（手順ごと）⇄ なぞって練習 → できた（部位と使い道・共有）。
  別ルート＝「さばく前に」ページ・部位の名前。迷う分岐＝魚を変える（進み具合は魚ごとに残す）。3Dが使えない端末＝文章だけの手順に切り替わる。
- **④骨格**: 一番大きい要素は**3Dの画面**（1つ）。手順の文章は画面の下（スマホ縦）または右（横・PC）に置き、3Dと同時に見える。主操作＝「次へ」（親指の届く下端・大きく）。
  副操作＝再生・透視・視点・左利き・練習は、小さな札にまとめ、押す場所を固定する。3Dの操作（回す）と画面のスクロールがぶつからないよう、3Dの上では縦スクロールを奪わない。
- **⑤表層**: 明るい台所の朝（白木のまな板・ステンレス・淡い背景）。切る線は鮮やかな朱、手の位置は青。切る線・手・刃の向きは、色だけでなく形（矢印・手の印・流れる点線）でも区別する。
  難しい言葉（血合い・腹骨・背わた・ぜいご・柵）は読み仮名を付ける。動きは刃物の速さに近い落ち着いた速度。動きを減らす設定で止める。

## 5階層を通して実装が変わった点（実装前の記録）
1. 視点の既定を「自由に回せる3D」から「台所の視点（まな板の手前・やや上から）」に変えた。手元との見比べが目的なので、回せることより、向きが合っていることが先。
2. 手順のデータに「魚の置き方（頭の向き・腹か背か）」を必須にした。向きの違いが、動画で最もつまずく所（調査 research/landscape.md）。
3. 「手の位置」の印（もう一方の手）を、刃の通り道と同じ重さで扱うことにした。包丁だけ見せると、押さえる手がおろそかになる。
4. 左利きを後付けにせず、最初から文章の左右の言葉を記号（{L}・{R}）で持つ設計にした（後から文を直すと、全種の全手順を探す羽目になる）。
5. 透視を「見た目の演出」でなく、手順の必須の機能にした。骨の位置が見えないことが最大のつまずき。
6. 練習の採点に、一致度のほかに「なめらかさ（一筆で引けたか）」を入れた。小刻みに動かすと断面が荒れる、が実際の最重要の技術のため。
7. 安全は、最初に一度だけ出す全画面の同意でなく、各魚の前置きに「ひとこと」＋詳しいページへのリンクにした。毎回止められると使わなくなるが、見落とされても困る。
8. 画面を消さない・大きなボタンを要件に足した。濡れた・汚れた手で、台所に立てかけたスマホで使う場面が主役だから。
