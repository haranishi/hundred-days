# Day99 meibo の要件

meibo（営業リスト向けのCRM。GitHubで公開中のOSS）を、100日チャレンジのDay99として出す。このDayの成果物は、一覧のカード・宣伝動画・Xの投稿文の3つ。アプリ本体と企業データは、このリポジトリに入れない。

## 決まっていること（2026-11-24・本人）
- Day99はmeibo。名前もmeiboのまま出す（仮称。商標の照合は未了のまま）。
- 出し方は動画とGitHubへの案内。誰でも触れる公開デモは付けない。
- 動画の人物映像は、Flow・Googleの動画生成で作る（実際に使ったのはFlowの Gemini Omni 1.2 Flash）。画面は実際のmeibo。

## 要件

### R1 一覧のカード
1.1 `meta.json` は `status: external`。`externalUrl` と `publicUrl` は、meiboのGitHubリポジトリ（https）。
1.2 カード用に `demo.mp4`（無音・540×960・16秒前後）と `screenshot.webp` を置く。
1.3 説明・制作メモ（AIに任せたこと・本人が決めたこと・失敗と修正）は、コードと作業記録に照合した事実だけを書く。
1.4 「ブラウザですぐ試せる」「登録なし」とは書かない。自分のPCかサーバーで動かすことと、公開デモが無いことを正直に書く。

### R2 宣伝動画
2.1 縦1080×1920・30fps・30秒。BGMなし（silent）・A案・B案の3本と、一覧用の `demo.mp4`。
2.2 画面は、実際に動いているmeiboを撮る。作り物の画面は足さない。AI生成は人物の映像（冒頭と最後）だけ。
2.3 字幕は、その時の画面で起きていることだけ。金額・割合はアプリが出した値を読み取って使う。「速い」「他より優れる」「大手の営業管理ツールの名前」は書かない。
2.4 1コマ目は動いている絵にする。字幕は縦の安全域（CSS y=77〜768）に収める。
2.5 AI生成の映像に、文字・ロゴ・顔のアップを出さない。終わりのカードに「冒頭と最後の人物映像はAI生成・画面のデータは合成」と書く。
2.6 BGMと効果音は、Nodeの計算だけで合成する。数値検査（−16 LUFS ±1・真のピーク −1.5 dBTP 以下・合図のずれ ±5 ms）に通す。
2.7 画像だけの採点を3系統で最大3周。20点中16点以上で合格。耳での試聴は本人が行う。

### R3 Xの投稿文
3.1 本文はXの重み換算で280以内。`Day 99 / 100` から始め、リンクは返信欄に置く。
3.2 返信は2本（できること／正直に書いておくこと）。`meta.json` の `social.x` に入れ、`npm run x:prepare` を通す。
3.3 機能と数字は、実際に動かして確かめた事実だけを書く。

### R4 公開面の約束
4.1 このリポジトリ・動画・投稿に、実在商標との比較表現、事業所名、ローカルのパスを書かない。
4.2 meiboのリポジトリは、このDayでは変更しない（commit・pushしない）。

### R5 納品と記録
5.1 動画と投稿文は、納品用のフォルダ（Drive）へ入れる。Obsidianに、Dayの記録を書く。
5.2 PRは公開用の状態（`status: external`）で出す。マージとX投稿は本人。
