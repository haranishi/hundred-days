# 操作と画面の設計：リンクの毒見

## ユーザーストーリー
| ユーザー | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| 本命：知らない人から届いたリンクを、押す前に確かめたい人（スマホ・非専門家） | 荷物の不在通知やカード会社を名乗るSMSのリンクを、押す前に「やめたほうがいいか」を知りたい。専門用語は分からない。 | 貼って10秒以内に、判定の一文と「いま取る行動」が最上部に出る。専門用語は最上部に出ない。幅360pxで読める。 |
| このアプリが救う相手：家族や同僚に「これ大丈夫？」と聞かれる人 | 理由を添えて短く答えたい。「怪しい」だけでは相手が納得しない。 | 結果の要約（判定・理由3つ以内）を1タップでコピーできる。理由は実際に見えた値つき。 |
| 補助：自分のサイトや店のサイトを運営・制作する人 | 何が弱くて、何を足せば直るかを知りたい。点数が低くても責められている感じは避けたい。 | 守りの点数・A〜F・上位3つの直し方（貼れる設定例つき）が出る。「点数が低い＝危険なサイトではない」と書く。 |
| 補助：キーボードだけ・読み上げを使う人、動きが苦手な人 | 同じ内容を、マウスなし・動きなしで使いたい。 | 全操作がキーボードでできる。進行と結果が読み上げ領域に出る。動きを減らす設定で針の動きが止まる。 |

## UX5階層
| 層 | 判断と画面への反映 |
|---|---|
| 戦略 | 目標は、リンクを踏む前の数秒を「なんとなく不安」から「根拠のある判断」に変えること。既存の診断サービスは、利用者向け（一覧照合）と運営者向け（ヘッダー採点）に分かれ、英語と専門用語が前提。差別化は5つ。①平易な日本語。②利用者向けと運営者向けを2つの軸に分け、混ぜない（守りが弱いだけで「危険」と読まれる誤解と、守りが堅いのに偽サイトという見落としの両方を防ぐ）。③実際に見えた値と転送の経路を見せる。④「安全」と言い切らない。⑤何も保存しない。 |
| 要件 | 載せる：アドレスの目視判定・転送先の確認・ヘッダー/Cookie/HTMLの事実・DNS/登録日/security.txt・2軸の判定・直し方・報告先。載せない：ログイン、履歴、ウイルス検査、既知の詐欺サイト一覧との照合、隠しファイル探しなど侵入に近い確認、診断先の画面の取得・表示、結果の公開ランキング。 |
| 構造 | 入力 → 調べている途中（段階が見える） → 結果。結果は「判定 → 行動 → 経路 → 所見」の順で、所見は軸（訪問者／運営者）で切り替える。迷う分岐は3つ。(1) つながらなかった：理由と次の行動を出し、アドレスの見た目の結果は残す。(2) 判定が分かれた：軸ごとに別の言葉で出す。(3) 見本：本物でないと明記して同じ画面へ。しくみ・限界・運営者向けの案内は同じページ内の見出しへ。 |
| 骨格 | 最大の要素は、入力欄（初期画面）と判定の帯（結果画面）。1画面に最大の要素は1つ。結果は縦に、判定の帯 → 行動3つ → 経路 → 軸の切り替え → 所見 → 見ていないこと → コピー・もう一度。PCは左に判定・行動・経路（固定）、右に所見。主操作ボタン（調べる）は入力欄の直下。 |
| 表層 | 和紙の地色と墨の文字、銀の針をモチーフにする。針は結果に合わせて銀から黒ずみへ変わる（毒に触れると銀が黒ずむという昔の毒見の言い伝え）。4段階は色・記号・言葉の3つで示す（青緑：確認／山吹：気になる／橙：注意／朱：近づかない／鼠：不明）。明朝系は題名だけ、本文はゴシック、URLと値は等幅。動きは針が入る・黒ずむ一回のみで、動きを減らす設定では出さない。 |

**この5階層を通して実装が変わった数：11。**
①診断を「利用者向け」「運営者向け」の2軸に分け、点数と段階を混ぜない構造にした（当初は100点1本の案）。②「安全」の語を一切使わず、見つからなかった場合も「見つかりませんでした」と書く文面規則にした。③アドレスの目視判定を通信の前に先出しし、通信が遅くても最初の結果が出るようにした。④診断を転送の追跡と周辺情報の2回の呼び出しに分け、結果を段階的に足せるようにした。⑤`?`以降を既定で送らない（個人情報や認証用の文字列が入りうるため）設定と、その明示を足した。⑥診断先の画面を取って見せる案（スクリーンショット）をやめた（危険なページを自分の側で描かない・複製しない）。⑦既知の詐欺サイトの一覧との照合をやめ、外部サービスへのリンク（押したときだけ）に回した。⑧点数の付け方を画面から読めるようにした。⑨見本を3つにし、実在しないドメイン（予約済みTLD）で通信なしに同じ画面を出すようにした。⑩`点数が低い＝危険ではない`の注記を運営者の軸の先頭に固定した。⑪家族に送る短い要約のコピーを足した。

## 画面と流れ
`#app[data-phase]` が現在の画面を示す。phase は `idle / checking / result / failed`。

| phase | 内容 | 次へ |
|---|---|---|
| idle | 題名・一文の紹介・入力欄・調べるボタン・くわしい設定（`?`以降も送る）・見本3つ・3段階の説明・やること/やらないこと | 調べる → checking／見本 → result |
| checking | 入力欄は残し、段階（アドレスを読む／つなぐ／ページの中身／守りの設定／まとめる）を一覧表示。アドレスの目視結果は最初に出す | 完了 → result／失敗 → failed |
| result | 判定の帯・行動・経路・軸の切り替えと所見・見ていないこと・コピー・もう一度・外部の診断サービス | もう一度 → idle（入力を残す） |
| failed | つながらなかった理由と次の行動。アドレスの目視結果は残す | もう一度／入力を直す |

## 判定の言葉（段階ごとの定型）
| 水準 | 見出し | 一文 |
|---|---|---|
| ok | なりすましの兆候は見つかりませんでした | 見つからなかったことは、安全の保証ではありません。 |
| note | 少し気になる点があります | 入力を求められたら、公式の窓口から開き直してください。 |
| warn | 注意してください | ID・パスワード・カード番号は入れないでください。 |
| danger | 近づかないでください | なりすましの兆候が複数あります。開かずに、公式の窓口から確かめてください。 |
| unknown | 調べきれませんでした | つながらなかったので、アドレスの見た目だけで判断しました。 |

## 文面規則
- 結論 → 理由 → 次の行動の順。専門用語は、初出で括弧書きの平易な言い換えを付ける（例：HSTS（常にHTTPSで開かせる設定））。
- 所見の根拠は、実際に見えた値を等幅で1行添える。見えない値を推測で書かない。
- 「〜かもしれません」の連発は避け、見えた事実と、そこからの読みを分ける（事実／読み）。
- 軸Aでは「詐欺サイトです」と断定しない。「なりすましの兆候」「公式ドメインではありません」と事実で書く。
- 軸Bでは責めない。「足りません」ではなく「付けると良いもの」と書く。
