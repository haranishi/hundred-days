# 脅威モデル：第三者のURLを取りに行くAPI

このリポジトリは今まで「静的サイトと、入力を受け取らないAPI」だった（`docs/security.md`）。
Day74は初めて、**利用者が決めたURLへサーバーから接続する**。守る対象は次の4つ。
(1) 内部・他人の資源に届かせない。(2) このサイトの無料枠と評判を守る。(3) 診断先に迷惑をかけない。(4) 利用者の入力（URL）を漏らさない。

| 脅威 | 対策 | 確かめ方 |
|---|---|---|
| 内部・予約アドレスへの接続（SSRF） | URLの検査（http/https・80/443・認証情報なし・2048字以内・NFKC・数値ホスト/IPv6/IPv4射影/予約名/末尾ドット/`@`の細工を拒否）→ 名前をDoHで引き、**1つでも**公開でないアドレスがあれば拒否（IPv4は特殊用途の範囲を拒否、**IPv6は`2000::/3`だけを候補にする許可リスト**で、`2001::/23`・`2001:db8::/32`・`2002::/16`・`3fff::/20`などを除く。独立レビューで、旧版が列挙以外のIPv6を公開と扱っていた欠陥を指摘され直した） → 転送先ごとに最初からやり直す。DoHが失敗したら閉じる。**基盤が非公開アドレスへのfetchを拒否する保証は公式文書で確認できていない**ので、基盤には頼らない。残るリスク：DoHで引いた結果と、fetchが実際に使う解決先が一致する保証はない（DNSの切り替え）。Workerには社内ネットワークも秘密もなく、IP直指定のfetchは基盤が断る（既知の制約）ので、影響は小さいと見ている | 攻撃ベクトル表の単体テスト。変異試験（検査を1つ外すと落ちる）。実観測（localhost・メタデータIP・DNSが私設を指す名前） |
| 自分自身を呼ぶ再帰・増幅 | 現在のホストと`*.hundred-days.pages.dev`を拒否 | 単体テスト |
| 他サイトのページから呼ばせる（`<img src=…/api/…>`で標的へ送らせる） | `Sec-Fetch-Site`が`same-origin`/`none`/未送信以外は403。CORSは出さない | 単体テスト（`cross-site`で403） |
| 大量診断・同じ対象への連打 | IPごと1分12回（IPはSHA-256で匿名化したキー）、同じURLは5分キャッシュ、1診断＝対象へ最大6回のGET＋周辺の3〜4回。RDAPはドメインごとに24時間キャッシュ（レジストリの規約が大量の自動照会を制限するため） | 単体テスト（13回目が429・キャッシュ命中で再送なし） |
| 一度しか使えないリンクを、診断のGETで使い切らせる（本人確認・登録・配信停止・ログイン用） | `?`以降を既定で送らない。語やパスの形から一度きりらしいリンクを検出し、調べる前に確認を挟む。画面にも書く | 単体テスト（検出の例）＋E2E（確認が出て、選ばないと通信しない） |
| 資源の枯渇（巨大・遅い・無限転送・圧縮爆弾） | 本文は復号後64KiBで`cancel()`。DoHの応答は64KiB、RDAPは256KiBで打ち切り、配列は64件まで。`<base>`が2048字を超えるときは採用せず、相対URLの解決は1文書1500回まで（長いbase×多数のリンクでCPUが跳ねる、とレビューで指摘された）。RDAPの転送は自分でたどり（最大3回・https・公開名のみ）（無料枠のCPU 10msに収めるため。160KiBの解析は実測4〜6msで、エッジでは超えうる）、HTML以外は読まない、転送5回、全体12秒・1ホップ7秒、応答JSONは64KiB以下 | 単体テスト（無限ストリーム・停止する`fetch`・巨大な属性） |
| 取得文字列を画面に出すときのXSS | サーバーは本文を返さず事実だけ返す。画面は`textContent`のみ。CSP `script-src 'self'`。JSONは`nosniff` | ソース走査の単体テスト＋敵対的な値を流すE2E |
| 診断先の悪用（このAPIを踏み台にした探査） | 受け身の1回だけ。探索・ログイン・入力値の送信・ポート走査・隠しパスの確認はしない。取得するパスは対象のURLと`/.well-known/security.txt`、`http://`の転送確認だけ | 単体テスト（観測が叩いたURLの一覧を固定） |
| 診断先への迷惑 | `LinkDokumi/1.0 (+URL)`と名乗る。URLに運営者向けの説明（取得元の見分け方・断り方）を置く。拒否（403・429・ボット対策）は結果として表示して終わり、再試行しない。robots.txtは取りに行かない（利用者が指定した1回の取得で、リンクのプレビューと同じ扱い。RFC 9309は巡回するクローラー向け）。断りたい運営者は、`LinkDokumi`のUser-Agentを拒否する | 単体テスト（拒否で再送しない・取得するパスの固定） |
| 誤判定・名誉毀損 | 断定語を使わない文面規則。軸ごとに段階を分ける。見ていないことを常に書く。結果の公開共有をしない（共有はアプリ自体）。**「兆候」と書けば免責になるという根拠は確認できていない**ので、観測した事実・条件・日時を示し、評価語は事実から読める範囲に留める | 文面の走査テスト（禁止語）＋人の確認 |
| 利用者のURLの漏えい | `?`以降と`#`以降を既定で送らない。サーバーはURLを記録しない（`console`に出さない）。端末にも保存しない。API応答は`Cache-Control: no-store`（端末や中間に残さない）。サーバー内のキャッシュ鍵はURLのSHA-256で、鍵のホストは`cache.invalid`（外から取り出せない） | 単体テスト（送信URLの検査）＋E2E（送ったURLを捕まえて確認） |
| 停止したい事故 | 環境変数 `LINK_DOKUMI_DISABLED=1` で両APIが503（デプロイ不要） | 単体テスト |

## 運用（`docs/security.md` に写す）
- **気づける状態**：Cloudflare → Workers & Pages → `hundred-days` → Metrics で日次リクエスト数を見る。使用量の通知を作る。
- **叩かれたとき**：まず`LINK_DOKUMI_DISABLED=1`（デプロイ不要で両APIを止める）。WAFのRate limiting rules（無料で1本。条件はパスとIP）は、**ゾーンの機能で、`pages.dev`のようにゾーンが無い入口には効かない可能性が高い**（公式に確認できていない）ので、独自ドメインを当てるまで当てにしない。
- **規約**：Cloudflareの規約に、第三者サイトへの自動リクエストを個別に許可する文言は確認できていない。禁止されているのは過大な負荷・悪用・フィッシングなどで、1診断＝1回のGET中心・レート制限・名乗り・停止スイッチで抑える。
- **キャッシュと上限はデータセンター単位**。分散して叩かれれば、その数だけ増える（`/api/day-009/vehicles` と同じ制約）。

## 取り込まないもの
スクリーンショットの取得（危険なページを自分の側で描かない）、診断先の本文の保存・表示、診断履歴、アカウント、既知の悪意あるURL一覧の取り込み（古くなり、誤判定の責任が生じる）。

## 2回目の独立レビュー（2026-10-22）で足した対策
- **N1 長大な`Location`で計算を使わせる**：`Location`のホストは相手が決める値。検査（`validateTarget`）を通ったものだけ登録ドメインを引き、PSLの引きは「規則の最大ラベル数（7）」で打ち切る。253字を超える名前は境界を引かない（以前は4096ラベルで約176ms）。
- **N2 写し（報告書・要約）に秘密が残る**：URLの「?」「#」以降は、大文字のスキーム・`//host/…`・空白で分断された値でも落とす。認証情報つきURLのパスワードは伏せる。
- **N3 取得した値の行区切り・制御文字**：サーバー（`clip`）でC1制御（U+0085など）とU+2028・U+2029を除き、報告書・要約でも1行へ直す（偽の見出しや判定を挿入させない）。
- **N4 断られたあとの追加アクセス**：403・429・ボット対策のあとは、画面が`around`に`site=0`を付け、診断先への追加のアクセスを省く。説明（「サイト運営者の方へ」）と動きを一致させる。
- **残る**：RDAPの転送（最大3回）は、転送先のホスト文字列の検査まで（DNSの検査はしない）。上流が攻撃者の選ぶ転送を作る経路は見つかっていない。
