# HTML解析のCPU予算・CI失敗への対応

## 背景と要件
PR175のCI（run 40346767405、job 121655650044）で、既存のS2性能試験だけが失敗した。
長いbaseと同じ相対リンク1500個の入力を測る中央値が10.031414msとなり、10msの上限を超えた。
本文64KiB・URL長2048字・文書当たり1500回のURL解決予算は、既存の設計と脅威モデルを維持する。
試験の閾値・skip・並列度を変えず、同じURLの重複解析を減らす。

## 設計
- 直前のsrc・base・URL解析結果だけを、extractHtmlFactsの呼出内で保持する。
- cache hitでも1500回の予算を消費する。上限検査をcache照合より先に行う。
- baseかsrcが変われば再解析する。解析失敗のnullもその組合せだけで再利用する。
- 呼出をまたぐ状態やMapは持たず、メモリ上の保持は1項目に限る。

## タスクと検証
- [x] CIログ、既存設計・脅威モデル、CPU予算の手引きを確認した。
- [x] 変更前の対象30件はローカルで成功し、CIとコード差がないことを確認した。
- [x] 重複解析・予算維持・base変更・無効URL・文書間独立性の回帰試験を通す。
- [x] 変更前後の同じ入力で解析結果と性能を比較する。
- [x] Day74の既存試験を通す。buildと新PRのCI判定は主担当が行う。

## 結果
Node 24.22.1で変更前（HEADのコード）と変更後を同じプロセスに読み、同入力を交互に測定した。
各9回の中央値を5組取り、その中央の値を比較。6入力すべてで抽出結果のdeepEqualが成功した。

| 入力 | 変更前の中央値 | 変更後の中央値 |
|---|---:|---:|
| CIのS2：32k字のbase＋同一リンク1500個 | 1.5555ms | 1.3013ms |
| 同一リンク2000個 | 1.7443ms | 1.5263ms |
| 2種類のリンク交互（memo不一致） | 1.3440ms | 1.3605ms |
| 同じsrcの途中でbase変更 | 0.0082ms | 0.0083ms |
| 無効URLの繰返し後に有効URL | 0.0452ms | 0.0336ms |
| 1500個のリンク直後のscript | 0.8173ms | 0.5644ms |

- 新回帰4件のうち、変更前は重複解析・無効URLの重複・文書間非共有の3件が失敗し、変更後は全成功した。
- 同一相対リンク1500個のURL構築は1500→1回。cache hitでも予算は尽き、その直後のscriptのhostはnull、schemeはrelativeのまま。
- 対象ファイルは34件、Day74全体は1118件が全成功。既存の10ms性能閾値・skip条件・CI並列度は変更していない。
- 変更はparserの直前1項目の再利用と関連4試験、この記録だけ。依存追加・外部通信はない。
- 生の測定値は`/private/tmp/day074-ci-performance-20261027.json`。Mac上の測定はGitHub runnerの速度保証ではなく、新PRのCI結果を別途確認する。

- 主担当による`npm run check`も成功。単体4,922件成功、既存1件skip、構文・漏洩検査・ビルド成功。
