# CPRビートの設計

## ユーザーストーリーとUX5階層
| 階層 | 判断 |
|---|---|
| 戦略 | 救命講習の前後にリズムの感覚を覚える。救命技能を判定しない |
| 要件 | 30秒のタップ、お手本、音なし練習、任意のセンサー・振動、結果と公式資料 |
| 構造 | 最初の説明 → 設定 → 3秒準備 → 30秒練習 → 結果 → 再挑戦 |
| 骨格 | PCは大きなタップ面＋設定、スマホは設定・開始・タップ面が自然に続く |
| 表層 | 生成り・濃紺・青緑。大きい数字、音に同期する穏やかな輪、文字の状態表示 |

## モジュール
- lib/rhythm.js：単調増加時刻、区間集計、動きの高域抽出・ヒステリシス・不応期。
- lib/metronome.js：Web Audioの先行スケジュール、無音時の時計、停止時の予約音破棄。
- app.js：idle/countdown/running/resultの状態、権限、DOM、入力・表示・中断。
- shared/share.*：正本を同期し、一般の紹介だけを共有。成績やセンサー値をURLへ入れない。

## 計測
時刻はperformance.nowで統一し、画面更新はrequestAnimationFrameで行う。
平均は60000×区間数÷最初から最後までの時間。休止区間を外れ値として除外しない。
直近6区間の平均をライブ表示し、結果の割合は全測定区間を分母にする。
開始・終了までの無入力も最長の入力間隔に含め、少数入力の範囲内率を誤解させない。
動きは符号付きの方向で1往復1回を参考検出する。変位や圧迫深さへ変換しない。
重力込みの値は時刻差から時定数600msの低域を除く。逆向き半周期で再武装し、閾値と280msの不応期を使う。
初回のセンサー応答を待ち、拒否・未対応・応答なしはタップへ戻す。

## 音・振動・中断
クリックは短い合成音で、ユーザーの開始・試聴操作後にAudioContextを準備する。
先読みは約100ms。遅延した拍をまとめて再生せず、次の拍へ戻す。
音なし練習では音・お手本の輪・振動を出さず、入力への反応だけを残す。
振動はAPIの有無と戻り値を区別して表示し、対応を保証しない。
画面非表示・離脱・途中停止は練習を中断し、完走の結果を表示しない。

## 検証と公開
状態・純粋関数はnode:test、ブラウザは既存Playwrightを使用する。
本番用ビルドを配信し、CSP、共有、OGP、サイズ、音の停止、失敗からの復帰を確認する。
追加依存・解析・サービスワーカーは入れない。元の作品や他Dayを変更しない。
公開可能なmetaでPRを用意する。マージ・本番公開・SNS投稿は別操作として残す。
