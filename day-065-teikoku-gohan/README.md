# Day65 定刻ごはん

食材を積んだ列車を「出発順」と「分岐の向き」だけで動かし、注文の料理を締切までに届ける1画面のパズル。調理の操作はしない。通った駅の順番がそのままレシピになり、火の駅（焼く・煮る）で仕上がったあとに1分を超えて待たされると焦げる。全6面で、登録はない。進み具合は端末の中（localStorage）だけに残り、プレイ記録はサーバーへ送らない。共有ボタンを押したときだけ、説明・結果・URLを共有先（X・LINE・端末の共有機能）へ渡す。

## ねらい

決めることを2つに絞り、説明を読まずに30秒で遊び方が分かることを優先した。失敗したときは、どこで・誰に待たされたかを必ず結果に出す。原因が分かれば、組み直す手がかりになるからだ。

## 設計で決めたこと

- **列車と注文は1対1。** 同じ食材の列車をどの注文に回すかを自動で決めると、何が起きたのかを30秒で読めない。
- **星は完食時刻で決める（★★★＝最短）。** 「最短ダイヤ」という言い方は鉄道の見立てに合い、共有もしやすい。待ち時間の合計で決める案は、数字の意味が伝わりにくいので捨てた。
- **焦げは駅を出る瞬間に判定する。** 原因（出口の線路がふさがっている）を、列車の記録にある相手（blockedBy）でそのまま示せる。画面に出す「焦げた瞬間」は仕上がり＋猶予＋1分（`lib/explain.js` の burnMinute）。再生の「焦げた！」・音・運行図の✖・文の「N分に焦げた」をこの分にそろえる。駅を出た分（以前の✖の位置）は、3分以上待つと焦げた瞬間より後になる。
- **「ジリジリ」の間だけ、再生を1分＝1.2秒に落とす（`lib/playback.js`）。** 通常の速さでは0.5秒（2倍で0.25秒）しか出ず、気づけなかった。時計は止めずにゆっくり進める。文字だけを1.2秒残す案は捨てた。焦げる場合は「焦げた！」が時計の分とずれるため。
- **全面を最初から開ける。** Xから来た人は途中の面から遊ぶ。
- **地図は面の見出しとヒントのすぐ下に置き、編集中と再生中は帯の下に固定する。** 初めの版では注文票の下にあった。375×667 だと最初の画面に地図がほとんど入らず、発車ボタンに隠れていた。結果シートの間と、画面の高さが450px未満（横向き）では固定しない。
- **面を開いたら、出発順の1番目の列車を選んだ状態にする。** 分岐の切替ボタンがすぐ地図に出るので、最初の一手が画面から分かる。組み直したときも同じ。
- **注文票は横に送らず、折り返して全部見せる（スマホは2列）。** 横スクロールだと見切れた札に気づかない。
- **見本のダイヤは、反映した中身のまま発車してクリアしたときだけ★1。** 少しでも組み替えれば時刻どおりの星になる。見本を見た面は全部★1にする案も考えたが、「反映した状態で発車したら」という決めに合わせた。
- **分岐の切替ボタンは、選んだ列車の進路の上にある分岐にだけ出す。** 通らない分岐を切り替えても進路は変わらず、押しても何も起きないように見えるため。
- **運行図の行は出庫線・駅・配膳の手前だけ。** 行と行のあいだの線路で待った時間は、次の行の帯の下に点線で描く（前の行を出てから次の行に入るまでの待ちを全部）。走っている時間は列車の色の細い線で結ぶ。どの列車も、出発から配膳まで途切れずにたどれる。
- **待った場所は1つの規則で呼ぶ。** 線路は「その列車が次に着く駅の手前」、次に駅が無ければ「配膳の手前」。分岐・合流の名前は使わない（文の「合流の手前」と運行図の「配膳の手前」が同じ所を指していた）。運行図の点線と同じ範囲なので、単体テストが全計画で文と運行図の分数を突き合わせる。
- **同じ種類の駅は、時間がちがえば「3分」、同じなら出庫線からの道のりで「近」「遠」。上下では呼ばない。** 運行図の行の上下や、配膳への入り口の上下と紛らわしかった。面5の焼く駅は着く分が同じなので、配膳までの道のりで比べる。配膳へ入る線路が2本ある面3は、線路の長さ（1分・2分）。
- **遅れの文は、待ちが原因か、道のりと出発順が原因かを分ける。** 「待たされなければ着いた分」（到着−待ちの合計）が締切以内なら待ちだけが原因、過ぎていれば待たなくても間に合わない。同じ料理を作るもっと短い道があれば、その道のりも出す（答えの全体は教えない）。最初の版は待ちしか言わず、面3で本当の原因（遠い焼き場までの道のり）に気づけなかった。
- **2分以上かかる線路には、線路の横に分の札を出す。** 枕木を数えなくても、遠い焼き場が地図から分かる。札は分岐ボタン・建物・ほかの札にかからない位置を、線路の中ほどから外へ探して置く。
- **再生中、締切を過ぎてまだ着いていない列車には、地図の上で赤い輪と「遅れ」を出す。** 固定した地図の下に注文票が隠れていても、遅れに気づける。文字は列車の丸のまわり8か所から、建物の名前・ほかの列車・時計などに重ならない所を毎コマ探す（名前に重なるのを一番重く数える）。
- **編成のカードに、締切と注文の工程を出す。通る駅が注文どおりのときだけ小さな✔（違っても✘は出さない）。** スマホでは固定した地図の下に注文票が隠れ、締切を覚えて並べていた。✘まで出すと、どこが違うかを自分で見つける余地が無くなる。
- **結果の間は、下の帯に「組み直す」と（クリアしたら）「次の面へ」。結果シートの中には置かない。** 長い結果の下までスクロールせずに押せる。同じ名前のボタンを2つ置くと、読み上げで区別できない。
  幅900px以上・高さ700px以上（PC）では、結果のあいだだけ帯を右の列（結果シートの下）に置く。左の下端だと、結果を読んだ直後の視線から遠い。
- **結果の行は、失敗を先に並べる。結果シートの先頭を画面の上に出す。** 原因を最初の画面で読める。固定した地図のための scroll-padding-top が結果でも効くと、上に地図の切れ端が残る（`html[data-phase="result"]` で帯だけにする）。2回失敗したら、見本の入口は一行の結果のすぐ下（末尾だとスマホでは見つからなかった）。最後の面をクリアしたときは「次の面へ」が無いので、「組み直す」を濃い色にする。
- **小さなスマホ（高さ450〜700px・幅639px以下）は、帯を固定せず、編集中は注文票を出さない。** 編成のカードに同じ注文と締切があり、面6では注文票だけで200px近くを取って、カードが1枚しか見えなかった。再生と結果では出す（✔が付いていく）。面チップを押したら、面の名前と指示文が見える一番上へ戻る。
- **一言（通知）は、地図の上ではなく下の帯のすぐ上に出す。** 地図の上だと、分岐ボタンと駅の札を覆った。
- **組み直す・次の面へ・面の切替のスクロールは一瞬で。** なめらかに動かすと、動いている間に押した所が隣のボタンに当たった。
- **運行図の帯（17px以上のもの）と結果の行にも、地図の丸・カードと同じ出発番号を付ける。紺の丸に白い数字。** 運行図の列車が色でしか見分けられなかった。最初は帯の上に白い数字を置いたが、黄の帯（#f2a900）では 2.01:1 しかなかった。色ごとに文字色を変えるより、どの色の上でも同じ見え方（7:1以上）になる丸にそろえた。運行図の文字は11px以上の基準なので、数字も11px。
- **再生中の列車の丸に出発の番号。黄色（5両目）の経路だけ濃い縁取り。** 同じ🥩の列車を色に頼らず見分ける。番号は左の縁に出し、地図の左端や建物の名前にかかるときは右へ。黄色はクリーム色の地で薄かった。
- **見本を反映したら、編成の下の注意書きに「元に戻す」を出す。** 確認なしで自分の組み方を上書きしていた。最初は一言（10秒）にボタンを付けたが、評価者が見逃した（時計を止めて長く進めると消える）。消えない場所へ移した。一言にボタンを付けると、地図の上に居座り、注意書きと重複するので外した。
- **面6の締切を変えた（お刺身11・ひと口ステーキ17・角煮19・ゆで卵20・焼きにんじん23分）。** 締切の早い順に並べるだけで1回目に★3になり、最終面が面5より易しかった。解は4通りで、締切の早い順では解けない。
- **地図の高さは面ごとに、駅・分岐・曲げ点の範囲に上下の余白を足した高さにする（幅360は同じ）。** 面1・2で、地図の下半分が空白にならない。

## ルールと面データの正

- 面データの正は同じフォルダの `levels.json`。`lib/levels-data.js` はその写し。面を直すときは levels.json を直して `verify-levels.mjs` を通し、写し直す（テストが中身の一致と、ソルバーで計算し直した par・解の数を確かめる）。

## 罠

- **基準の sim は、出発前に車庫で待った分を記録しない。** 記録は出庫線に入ってから始まる。遅れの原因を出すときは、出発予定（k×headway 分）との差から求める（`lib/explain.js` の yardWait）。面3・5・6には、車庫でしか待っていないのに遅れる計画がある。
- **指定の色だけでは文字が 4.5:1 に届かない組み合わせがある。** 白文字×焼く駅（#d9481c）は 4.29:1、--ok の文字は 3.84:1、配膳×--ink は 4.33:1。色の値は変えず、駅の文字の下に暗い帯を敷き、成功の文字は --ok-ink、配膳の文字は --serve-ink にした。
- **斜めに駅へ入る線路では、建物の縁から一定の距離だけ戻しても角に列車がかかる。** 列車の円が四角から離れる位置まで戻して止める（`lib/render.js` の edgeGeom）。
- **SVG の要素に CSS で transform や fill を当てると、属性より CSS が勝つ。** 列車の位置は外側の g の属性で、揺れは内側の g の CSS アニメで動かす。運行図の斜線は属性の fill なので、CSS で fill を当てない。
- **localStorage の名前の定数を「〜_KEY」にしない。** gitleaks がAPIキーと誤検知した前例がある。STORAGE_NAME にした。
- **共有欄は、帯の「共有する」（読み上げ名「このアプリを共有する」）から開く窓に置く。** 共通の試験（shared-share）は、このボタンを押してから共有欄を測る。
- **320px幅では、分岐ボタン（44px）が車庫の文字や隣のボタンに重なった。** 辺・長さ・駅・締切は変えず、分岐と駅の座標（pos）だけを動かした（面3・5・6。levels.json と build-levels.mjs も同じ値）。面3の配膳への直通線は、曲げ点（via）が辺の情報なので動かしていない。そのため縦の部分がわずかに斜めになる。
- **地図を固定すると、フォーカスや scrollIntoView で出した要素が地図の下に隠れる。** 帯と地図の高さぶん scroll-padding-top を取ってある。
- **一言（トースト）は2.8秒で自然に消える。** 面の切替や発車で消えることを確かめる試験は、待たずにその場で見る。待つ形だと、消す処理が無くても通ってしまう。
- **Playwright の時計は install しただけでは実時間で進む。** 再生の途中を確かめる試験は pauseAt で止めてから runFor で進める。止めないと、確認を待つ間に列車が着いてしまい、着いたときの処理で試験が通ってしまう。
- **遅れの文の「直せば間に合う」は、1手で済むとは限らない。** 先にいた列車を後ろへ回すと、別の待ちが表に出ることがある（面3）。試験は、文の指示に1手ずつ従って、最後に間に合うまでの流れで確かめている。
- **`.chip` という class は、面チップのボタンと地図の列車の両方にある。** 試験で地図の列車を数えるときは `#map-svg .chip` と絞る（絞らないと面チップを拾う）。
- **試験用のブラウザでは、短い距離のなめらかなスクロールが一瞬で終わる。** 面の切替（80px ほど）がなめらかかどうかを位置では見分けられないので、E2E は scrollIntoView に渡した動かし方も記録して確かめる。
- **Playwright の偽の時計で、時間の長さは MutationObserver と performance.now で測る。** 画面のコマ（rAF）は偽の時計で進むが、CSS の transition は実時間で進む。一言の見た目の濃さは、偽の時計を進めても変わらない。
- **DOM 標準の `append` に null を渡すと、「null」という文字が画面に出る。** 条件つきの部品は `h()`・`fill()`（`lib/dom.js`）に渡す（どちらも null を除く）。E2E の `expectClean` が、画面に null・undefined・NaN が出ていないかを毎回確かめる。5周目に結果画面で実際に起きた。
- **Tab を奪う近道は、「Enter/Space で選んだ直後の1回」に限る（`onCarKey`・`state.kbJump`）。** 選んである列車のカードで常に分岐ボタンへ飛ばすと、カード⇄分岐ボタンの往復になり、発車に届かない（キーボードトラップ）。5周目に実際に起きた。
- **sticky の帯は、入れ物（親）の範囲の外へ出られない。** 横向きのスマホ（高さ450px未満）で、帯を右の列の中に置くと、列の上端に押し込まれて1両目のカードに重なった。`.board__side` を display: contents にして、帯を格子の2列目の全行に渡し、下へ寄せた。
- **日本語の折り返し。** 2段で決める（`lib/phrase.js`）。料理名・駅の名前・数と単位は、`phraseSegments` が折れないかたまりにする。ほかの文字は、`chunkSegments` が文節の切れ目だけで折る：助詞で終わるひらがな→漢字、句読点のあと、別の語に変わるところ。送りがなのところ（「焼き｜場」）では折らず、助詞は直前の名前や数に付ける。`word-break:auto-phrase` は使わない。語の途中で割ることがあり、iPhone の Safari は対応していない。18文字を超えるかたまりは折れない span にしない（狭い幅ではみ出す）。
