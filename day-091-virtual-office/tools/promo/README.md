# Day091「バーチャルオフィス」の宣伝動画

32秒の縦型動画（1080×1920・30fps）と、100日の一覧用の demo.mp4 を作る道具です。画面はすべて本番（https://day91.rairakku.com/ ）を実時間で録ったものです。後から重ねたのは、字幕・押した位置の輪・白い閃光・「あるある」の札・終わりのカードだけです。

流れは機能の一覧ではなく、見た人が使いたくなる順にしました。問いかけ（3人が机に座り、吹き出しが出る）→ あるある（札が画面を埋める。アプリは映さない）→「オフィスを作る」（音のドロップ）→ リンクをコピーすると2人が入ってくる → 歩く・座る・状態・ひとこと → 会議室・休憩室・卓球 → ひとりでもNPCの同僚がいる → 無料・ログイン不要。
絵コンテは `timeline.mjs` の1つの表で、映像（`render-promo.mjs`）とBGM（`promo-audio.mjs`・2案）が同じ表を読みます。

## 作り直し

要るもの: ネット接続（本番につなぐ）、Playwright（リポジトリの `node_modules`。別の場所は `PLAYWRIGHT=`）、ffmpeg / ffprobe、手元の Zen Kaku Gothic New の Bold と Black（既定は `~/Library/Fonts/`、別の場所は `PROMO_FONT`・`PROMO_FONT_BLACK`）。

```sh
node day-091-virtual-office/tools/promo/promo-audio.mjs --variant a --out-dir <書き出し先>
node day-091-virtual-office/tools/promo/promo-audio.mjs --variant b --out-dir <書き出し先>
node day-091-virtual-office/tools/promo/verify-audio.mjs --out-dir <書き出し先>
node day-091-virtual-office/tools/promo/render-promo.mjs --frames-dir <コマの置き場> --out-dir <書き出し先> --mux a,b
```

- 書き出し: `Day091_virtual-office_promo_{silent,a,b}.mp4`・`demo.mp4`（字幕なし・無音・540×960・約16秒）・`first-frame.png`・`contact-sheet.jpg`（1秒ごと）・`cut-check.jpg`（各カットの前後2コマ）・`capture-report.json`・`bgm_{a,b}.{wav,mp3}`・`audio-report.json`・`spectrogram-{a,b}.png`。
- `--only main,alone,overlay` で一部だけ撮り直せます。`--compose-only` は重ねと書き出しだけ、`--no-compose` は撮影だけです。
- 時間の目安（2026-11-13）: 全部で約3分（撮影1.1分、重ね1.1分、合成と書き出し0.7分）。コマはPNGで約0.8GBです。
- 1回の撮影で本番の同期サーバーに6回つなぎます（同じIPから1分に30回まで）。429で入れないと「待っても起きない」で止まるので、1分待ってやり直します。

## 撮り方: 時計は止めず、実時間で録る

- 同期サーバーを通る実時間のアプリなので、Day088の「時計を止めて1コマずつ進める」方法は使えません。3台のスマホ（ブラウザの文脈 A・B・C）を本番の同じオフィスに入れて決めた秒に操作させ、画面に出すスマホを CDP のスクリーンショットで撮り続けます（1080×1920 のPNG、毎秒約36枚、各コマに時刻）。各カットは、基準の出来事（押した時刻など）からの実時間でコマを選びます。30fpsの各コマには時刻がいちばん近い撮影コマを使います。ずれは最大約50msで、オフィスを読み込んだ直後の2コマだけでした（招待の画面が静止している所）。
- 採らなかった方法: Playwright の動画録画は画質が下がります（VP8に圧縮される）。CDP の画面配信（screencast）は、CSSの大きさ（540×960）までしか出ません。
- 画面は 540×1020 のスマホです。この高さで地図がいちばん大きく（420px）なります。窓に入れるのは上の 540×825（見出し・行き先のボタン・地図の全体）で、寄りは実画面を切り出して拡大するだけです。
- 押す操作は本物のタッチです（0.1秒前に指を下ろし、離した時刻を記録）。色の欄だけは `<select>` なので Playwright で選びます。リンクは本物のクリップボードへコピーし、コピーされた住所がそのオフィスと一致することを確かめます。卓球は、台の絵から球の位置を読んでラケットを動かします。
- ページの移動中に頼んだスクリーンショットは返ってきません（最初は4秒止まった）。0.2秒で返らなければ CDP の接続を作り直します。「オフィスを作る」を押して約0.07秒後に画面が暗い読み込み中に替わるので、上端の色が替わる直前のコマでカットします。
- 記録に接続先の `k=` は書きません。オフィスのIDも `/o/<id>` に伏せます。ブラウザの状態（storageState）は保存しません。
- 招待の画面に映るリンクは、`/o/` の後ろのIDだけを重ねの層の白い帯（「••••••••」）で隠します。欄は撮ったコマから毎回探します（白い中身と灰色の枠）。字は等幅（13pxで1字6.5px）なので、IDは29字目から始まります。「コピーしました」が出ると画面が20px上へずれますが、帯も一緒に動きます。名前を入れる画面の欄も同じ見た目なので、探すのは招待が開いている間だけです。demo.mp4 には同じ帯をコマに焼き込みます。招待が映る全コマで帯がIDを覆っていることを `capture-report.json` の `idMask` で確かめます。
- 寄りの枠は、止まっている所やゆっくり寄る所で文字を途中で切らない位置に置きます。目安は、行き先ボタンの文字より下（y 360以上）、地図下端の案内文より下（y 805以上）、招待の画面ではカードと影（x 60〜490）の外側です。招待の画面で1.15倍に寄ると、暗くなった背景の見出しだけは端で切れます。

## 落とし穴

- 「在席」の人と活動中の人の名札が、地図の外へ消える本番のバグがありました（状態アイコンが隠れると、名札を並べる計算がずれ続けた）。2026-11-13に直り、いまは座った人がそのまま「在席」で映ります。再び起きたら、`timeline.mjs` の `SEATED_STATUS` を `'home'` にすると、座る前に「在宅」にして避けられます。
- さくらを先に会議室へ入れておきます。会議室にひとりで入るとNPCが現れ、最後の「ひとりでも」の場面と重なるためです。

## BGM

720/7 BPM（1拍7/12秒）にしたのは、ドロップ（7.0秒）と終わりのカード（28.0秒）を小節の頭に合わせるためです。A「ドットのオフィス」はハ長調のパルス波と三角波のベース、B「あさのカフェ」はヘ長調のエレピ・マリンバ・鐘です。札ごとに小さなポン、画面で押した11か所に小さなチックを入れ、ひとりの場面はパッドだけにしました。seedを固定しているので、同じ入力からは同じバイト列になります。
`verify-audio.mjs` の検査項目: −16 LUFS±1、真のピーク −1.5dBTP以下、クリップ0、0.5秒ごとの音量が −40dBFS以上、ドロップと終止和音で3dB以上上がり、その位置が1コマ以内、ひとりの場面で3dB以上下がる、低域 −9〜−6dB、高域 −43〜−38dBFS、作り直して同じSHA256。2026-11-13は両案とも全項目に合格しました。数値とスペクトログラムで確かめただけで、耳では聴いていません。
