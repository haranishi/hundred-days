# FROSTLINE（コード名 ginrei）

ブラウザで開くだけで、雪山をスノーボードかスキーで滑れる3Dゲーム。舞台は、架空の盆地（一辺 4 km・標高差 1,500 m）。
北の山頂から、谷と森を抜けて、凍った湖のほとりの集落まで滑る。西は岩壁と氷河、東はゲレンデとリフト。朝の光の中を滑る。
ねらいは「切る・削る・飛んで回る」の手ごたえ。エッジを立てれば雪を切って曲がり、板を横へ向ければ雪を削って減速する。その違いが、姿勢・雪煙・音・跡に出る。
空中では、回転・宙返り・板をつかむ技ができる。駅に着くと一本の記録が出て、1 操作で次の一本へ行ける。
山には、ジャンプ台が 3 つ（小 2・中 1）と、自然の雪の段・崖がある。最初の一本は、針葉樹のあいだのゆるい「森の道」。
道具は、最初の画面でスノーボードとスキーから選ぶ。操作は同じで、スキーは、曲がりが大きく・切り替えが軽く・低い姿勢が速い。

既存の雪山ゲームに着想を得たが、再現はしない。名前・地図・画面・人物・音はすべて独自に作る。

公開先は https://rairakku.com/100days/day-089-frostline/（100 日チャレンジの Day89）。コードは MIT License で公開している。

## 動かす

```sh
npm install
npm run worldgen   # 山のデータを作る（1 分ほど）。データは大きいので Git に入れていない
npm run dev        # http://127.0.0.1:5183/
```

操作は、左右キーで曲がる・下で制動・空白キーを押して離すとジャンプ・上で低い姿勢（平らな所では蹴って進む）。
ジャンプ台では、空白キーを押したまま縁を越えても踏み切る。空中で空白キーを押している間は、左右で回転・上下で宙返り（押している間、板をつかむ）。
C キーで視点の切り替え、M キーで山の地図、E キーで直前の地点へ復帰、R キーでやり直し（仕掛けを通った直後は、その手前へ戻る）。
スマホは、画面の舵とボタンで同じ操作ができる。

## 公開のしかた

100 日チャレンジ（`haranishi/hundred-days`）の `day-089-frostline/` に、組み立てた本体を置く。このフォルダは、その `source/` に写してある。

```sh
npm ci && npm run worldgen                  # 山のデータを作る（1 分ほど。Git には入れていない）
node tools/build-day089.mjs ..              # 相対の住所（./）で組み立て、1 つ上の Day のフォルダへ置く
node tools/shots/share-check.mjs --url http://127.0.0.1:5185/   # 共有の窓・題字の収まり・誤り 0（手元の配信で）
```

共有の欄は、100 日チャレンジの共通部品（`shared/share.js`）が入れる。`public/shared/` は、手元で動かすための写し。
単独で配るとき用のセキュリティの設定（`public/_headers`）・404 のページも残してあるが、100 日のサイトでは使わない（サイト全体の設定が受け持つ）。
デモ動画と一覧のカードの画像は `node tools/shots/demo-capture.mjs --out DIR`（1 コマずつ撮るので、毎回同じ動画になる）。

## 決めたことと理由

- **描画は three.js の WebGPU 方式**（WebGL2 へ自動で切り替わる）。影・空・後処理の部品が WebGPU 側にそろうため。両方式とも毎秒 60 コマを確認した。
- **山は1つの純データ**。物理も描画も同じ高さの関数を読むので、見えている雪面と滑っている雪面がずれない。
- **物理の状態と見た目を分ける**。物理は 1/120 秒の固定刻みで、描画はその間を混ぜて描く。同じ操作なら同じ結果になる。
- **素材はすべて自作**。形は手続きで作り、音は雑音と発振器から合成する。素材の権利を持ち込まないため。
- **名前は FROSTLINE**（2026-11-11 本人が決めた）。候補の「シュプール」は、集英社の登録商標（第 5498388 号）の指定に「オンラインゲームの提供」が入っていたので使わない。
  FROSTLINE は、日本の第 9 類・第 41 類に登録が無い（J-PlatPat で確認）。海外の『DayZ』に同名の拡張版があることは、本人に伝えてある。

## 確かめ方

```sh
npm test                                   # 単体試験
node tools/shots/boot-check.mjs            # 起動（--webgl・--webkit も）
node tools/shots/touch-check.mjs           # 指の操作と配置（4 つの画面幅）
node tools/shots/play-probe.mjs --spawn jump-mid --steps "5:;2:;1:"   # 出発地点から滑らせて撮る（この例は、中くらいのジャンプ台）
node tools/shots/refviews.mjs --out DIR    # 参考画像と同じ 9 つの視点で撮って、左右に並べる（参考画像は refs/valley/。Git に入れていない）
node tests/sim/gear-measure.mjs            # スノーボードとスキーの滑りを、同じ斜面・同じ操作で並べて測る
```

どの撮影の道具も、アドレスへ `?gear=ski` を足すと、スキーで撮る（例：`--url "http://127.0.0.1:5183/?gear=ski"`）。

体験と見た目の良し悪しは、作った人と別の担い手が、実際の操作か画像で採点する（決まりは `.agent-harness/contracts/`）。
結果は `.agent-harness/runs/` に残す（`gamefeel2`＝体験、`ui`＝画面、`visual/rider`＝人物、`visual/valley`＝山の見た目、`ski`＝スキー）。

## やらないと決めたこと（いまは）

- スキーの板 2 本を別々に計算すること：物理は、どちらの道具も「1 枚の板」として解く。スキーの違いは、値（回る半径・抵抗・切り替え）と姿勢で出す（理由は `.kiro/specs/ski-gear/design.md`）。
- 実在の山の再現：権利の心配が無く、滑って面白い地形を狙って置けるので、架空の山にした。
- アクセス解析・Cookie・外部への通信：入れない。設定と進み具合は、端末のブラウザにだけ保存する。
