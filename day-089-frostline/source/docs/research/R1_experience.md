# R1：雪山を滑る「手ごたえ」の構成

## 1. 結論

- **解釈：核は、傾斜・板の向き・速度の変化を、操作・姿勢・雪・音が同時に伝えること。**
- 事実：SteepのS字ターン、速度管理、自由なライン取りは評価される一方、技入力と着地の分かりにくさには不満がある。[S02][S04]
- 事実：開発者は地質を参考にしつつ遊びのため地形を変え、選手の助言で回転速度も調整した。[S01]
- 解釈：「リアル」は厳密な現実再現だけでなく、予測できる運動と納得できる結果から生まれる。
- 提案：まず旋回・横滑り・減速・接地・着地を短い斜面で成立させ、技の種類を増やす。
- 提案：前方が見えるカメラ、状態連動の音、即再試行を、精密な雪変形より先に整える。
- 提案：PCとスマートフォンは共通の滑走状態を操作し、入力方法は各端末に合わせる。
- 未確認：SteepのFOV・追従式・雪質別の物理定数。以下の実現案は独自作品への提案である。

### 操作・カメラの読み取りで注意する点

事実：PCレビューでは滑走中の右スティックが技入力になり、キーボードもJ/L等を使う両手操作になる。マウス主体の設計としては不自然と評された。[S15]
事実：トリック入力が狭い時間窓に集中するという批評がある。[S04] 一方、ゲームディレクターは選手の助言で回転速度を調整したと説明する。[S01]
未確認：踏切前のスピン仕込みの厳密な受付時間、スティック量／保持時間と回転速度の関数。ジャンプの構えと回転の仕込みを同一視しない。
事実：着地の攻略回答にはグラブを接地直前まで持つ助言と、入力を離す助言がある。[S08] 解釈：助言を一つの確定操作にまとめるには条件が不足する。
提案：PCは旋回キー＋制動＋ジャンプ保持／解除、スマートフォンは操舵領域＋制動＋ジャンプを基本候補にする。技の多指入力は通常滑走を確かめてから増やす。

## 3. 優先順位トップ10

以下は資料を踏まえた**提案順位**。効果量を実験で比較した結果ではない。

1. **旋回と横滑りの区別**：板を横へ向けたときの減速と移動方向の遅れを、姿勢・跡・音で一致させる。[S02][S03]
2. **傾斜に沿う加減速と接地**：直滑降・横断・制動を使い分け、起伏を滑った感覚を作る。[S02]
3. **前が見える追従カメラ**：高速時にも次の凹凸・木・着地先を読めるようにする。[S04]
4. **安定した応答**：端末負荷で踏切タイミングが変わらないようにし、描画品質を調整できるようにする。[S05]
5. **予測できるジャンプと着地**：構え→踏切→回転→姿勢を整える流れを見せ、補助の強さを選べるようにする。[S07][S16]
6. **状態に合う滑走音と風音**：無音でも映像、画面を見なくても音から状態差が分かることを目指す。[S10]
7. **即再試行と失敗理由**：短い試行を繰り返して、自分で改善できるようにする。[S04][S11]
8. **雪煙と残るシュプール**：接地の結果と、選んだラインを目に残す。[S05][S21]
9. **自由な出発点と地形の選択肢**：緩斜面、林間、起伏、急斜面をつなぎ、自分で難度を選べるようにする。[S01][S07]
10. **雪質差と滑走の振り返り**：まず少数の雪質を一貫して表現し、リプレイで良い滑りを残す。[S06][S13]

## 4. 避けるべき不満点

褒められた点は、S字ターンと速度管理、広い山でのライン選び、雪・風の音、待たずに繰り返せること。[S02][S04][S10]
技の評価は割れており、「自然で応答がよい」[S02]と「速度や回転が予想できない」[S04]を両方残す。以下は支持率ではなく、各筆者・投稿者の報告である。

| 不評だった点（事実） | 回避策（提案） |
|---|---|
| 技の入力窓が狭く、回転量が読めない。[S04] | 踏切と回転の入力受付を見える化し、一定条件で同じ結果になるか確認する |
| 自動回転・着地への介入を減らしたいという声。同スレッドには慣性を好む声もある。[S09] | 慣性と補助を分け、補助量の選択と短い練習課題を用意する |
| Gの説明不足で転倒が不規則に感じる。[S10] | 衝撃の予告と回復を明示。着地角度・障害物接触など原因を具体的に返す |
| 身体が前方の障害物を隠す。[S04] | 高さ・左右の位置・注視点を調整し、平坦面と急斜面で見通しを確認する |
| 雪に隠れた岩で急減速。負荷時の反応低下。[S05] | 障害物を雪面の陰影等で読めるようにし、描画負荷を優先的に下げる |
| イベントが定型的で、解放のため好みでない課題も求められる。[S14] | 自由滑走を独立して楽しめるようにする。地形と進路選択で課題の性質を変える |
| 地図上で課題を探す時間が増え、表示が景色を邪魔する。[S02] | 競技・難度・完了状態で絞り込み、滑走中の情報を最小限にする |
| 再試行で曲が変わる、掛け声が多い点が修正対象になった。[S11] | リトライしても曲を継続し、声・音楽・滑走音を別々に調整可能にする |
| 類似作Infinite Airでは起き上がった場所から動けない場合がある。[S19] | 復帰地点の斜度と空間を確保し、出発点へ戻る操作を常に用意する |

## 6. 真似してはいけないもの／使ってよいもの

一般的な制作上の整理であり、個別の法的判断ではない。米国著作権局はゲームの発想・遊び方と、文章や図柄等の表現を区別している。[S28]
以下の「使ってよい」は**ジャンルの発想として独自に制作する対象**という意味で、他作品のデータ利用の許諾を意味しない。

| そのまま真似・流用しないもの（提案） | 共通の発想として独自制作に使うもの（提案） |
|---|---|
| Steep等の作品名、ロゴ、GoPro等のブランド表示、公式との関係を思わせる宣伝 | 雪山フリーライドというジャンル、自作名称・ロゴ・ブランドなしのアクションカメラ視点 |
| 他作品固有の山・コース・ランドマークの配置、地図・高さデータの抽出物 | 稜線・谷・林間・圧雪・深雪など自然の一般的特徴。自作の山と進路 |
| UIの画面構成、アイコン、配色・書体・装飾の具体的な組合せの引写し | 俯瞰地図、マーカー、速度表示、危険表示、課題一覧という機能 |
| 固有キャラクター、衣装・板の絵柄、アニメーションデータ、台詞、技の演出の引写し | スキー／スノーボード、S字旋回、ジャンプ、スピン、グラブ、自然な身体動作を自作する |
| 楽曲・録音音声・雪面音・画像・3Dモデル・シェーダーコードの抽出や無断転載 | 風音、エッジ音、着地音、雪煙、シュプールを自作・適切なライセンス素材で表す |
| 固有のイベント名・文章・数値・配置をまとめて再現すること | タイム競争、スラローム、技採点、自由滑走、即リトライ、リプレイという考え方 |

名称は著作権とは別に商標等の論点があり、この出典だけで利用可能と判断しない。実在地形も自然の事実と、他社が制作した地図・地形データ・ゲーム用配置を分ける。

## 7. 未確認・限界

- 方法：Web検索語30件。本文を開いて読めた公式・開発者インタビュー・レビュー・攻略・投稿だけを採用。動画・実機は未視聴／未操作。関連Obsidianには本件の根拠になる既存メモがなかった。
- 事実確認の粒度：公式は機能・意図、レビューは筆者の体感、投稿は個人の報告。選定は体系的な全件調査ではなく、不満の頻度・多数派は判定していない。
- 版の差：発売期、1.04、五輪DLC、後年の投稿を混在させている。初期レビューの不評が現行版にも残るとは断定しない。Riders Republicのプリセットと着地モードも区別した。
- 未確認：SteepのFOV値と速度連動、カメラ距離・ばね・揺れ・転倒時の制御、衝撃の閾値・回復時間・現実のGとの対応。ゲームのG表示を実加速度計算の証拠にしない。
- 未確認：雪質別の摩擦・深雪の沈下と抵抗、跡の寿命・保存範囲、音楽が切り替わる内部条件。レビューの見た目の説明と内部物理は区別した。
- 未確認：Steepの回転仕込みの厳密な時刻・キー全対応。取得できないWiki・本文が空のページの検索抜粋は根拠にしない。SNOWの比較は省略。他作の「未確認」を「機能なし」と読まない。
- 技術の限界：ブラウザの実現案と難度は設計仮説。three.js 0.187.0は依頼の前提として扱い、最新版確認やAPI調査、コード作成、性能実測はしていない。
- 提案：次段階では短い斜面で「ターンを予測できるか」「着地失敗の理由が分かるか」「同じラインを再挑戦したいか」をPCとスマートフォンで確かめる。
