# Implementation Plan

- [x] 1. 土台：描画の入口と、Node で確かめられる計算
- [x] 1.1 (P) 区画の選び方を作る
  - カメラの位置と視錐台から、描く区画の一覧（原点・一辺・段・中央の高さ）を返す。高さの最小と最大を段ごとに持つ
  - 全域を過不足なく覆う、隣どうしの段の差が1以内、モーフ後の共有辺の頂点が一致、視錐台の外を選ばないことが試験で通る
  - _Boundary: src/render/terrain の cdlod_
  - _Requirements: 1.1, 1.2, 1.3, 1.4_
- [x] 1.2 (P) 傾きと細かな法線の配列、画質の段の値を作る
  - 山の配列から傾きの配列（大きな形・タイル）を作り、細かな法線のタイルを手続きで作る。段ごとの値を1か所に集める
  - 傾きがBスプラインの解析微分と一致し、段の値が設計の表どおりであることが試験で通る
  - _Boundary: src/render/terrain の texture-data、src/render の tiers_
  - _Requirements: 5.3, 7.1_
- [x] 1.3 描画の作成と方式の判定・誤りの捕捉・器への差し込みの形を作る
  - WebGPU で始め、使えなければ WebGL2 へ切り替える。どちらも無理なら理由つきで止める。大きさと画素比を段の上限で決める
  - 空の場面が、WebGPU・WebGL2・WebKit で誤りと警告なしに描ける（起動の検査）
  - _Requirements: 7.4, 7.5, 8.1, 10.1_

- [x] 2. 地形
- [x] 2.1 山の配列を GPU のテクスチャにし、高さを読む TSL 関数を作る
  - 高さ・タイル・雪質の地図・傾き・日当たりを、形式とフィルタを決めて転送する。高さは16点のBスプラインで読む
  - GPU で読んだ高さと山の問い合わせの差が、無作為の1000点で 2 cm 以内（実ブラウザの検査）
  - _Requirements: 2.1, 2.2_
- [x] 2.2 区画をインスタンスで描き、境目をモーフでつなぐ
  - 選んだ区画を1種類の格子で描き、距離に応じて頂点を親の格子へ寄せる。法線は画素ごとに傾きから作る
  - 山頂・雪原・沢・ふもとの固定の場面で、すき間と段差が無く、カメラを動かしても形が飛ばない
  - _Requirements: 1.1, 1.2, 1.3, 1.4_
- [x] 2.3 雪と岩の材質の土台を作る
  - 岩の露出で岩を出し、境目を不規則にする。新雪・圧雪・氷を明るさと光沢で分ける。細かな法線を近くだけ足す
  - 固定の場面で、岩の帯と雪質の違いが見分けられ、遠景がちらつかない
  - _Requirements: 5.1, 5.2, 5.3_

- [x] 3. 空・光・影・霞
- [x] 3.1 空と太陽、空から作る環境光を作る
  - 山のデータの夕方の向きで空と太陽を置き、同じ空から環境光を作る
  - 日陰の雪が空の色で照らされ、黒くつぶれない
  - _Requirements: 3.1, 3.5, 4.1_
- [x] 3.2 霞を作る
  - 高さとともに薄くなる霧を距離で積分し、色を空の地平線から取る
  - 遠い山が段階的に霞み、地図の端と空のあいだに線が出ない
  - _Requirements: 4.2, 4.3_
- [x] 3.3 カスケード影と、焼いた日当たりの地図を合わせる
  - 近くはカスケード影、遠くは山のデータの日当たりで暗くする。段ごとに影の段数と解像度を変える
  - 山の大きな影が遠くまで見え、カメラを動かしても影の縁がちらつかない
  - _Requirements: 3.2, 3.3, 3.4_
- [x] 3.4 後処理を組み立てる
  - 高は時間方向のアンチエイリアスと弱いブルーム、中と低は軽いアンチエイリアス。色の変換は最後に1回
  - 3つの段で誤りなく描け、白飛びと黒つぶれが目立たない
  - _Requirements: 7.1, 7.2_

- [x] 4. 木・樹氷・岩
- [x] 4.1 木・樹氷・岩の形を手続きで作る
  - 樹氷・雪をのせた木・岩を、近く用と遠く用の2段で作る
  - 近くで見て雪をかぶって見え、同じ形の繰り返しに見えない（向きと大きさの個体差）
  - _Requirements: 6.1, 6.3_
- [x] 4.2 移動に合わせた出し入れを作る
  - カメラの周りの升を対象に、近い升から時間の上限つきで並べ、遠い木は簡単な形へ切り替える
  - 山の問い合わせと同じ位置に立ち、CPU を6倍遅くして走り続けても、近く 200 m で木が消えず、1コマが 33 ms を超えない
  - _Requirements: 6.1, 6.2, 6.4, 9.2_

- [x] 5. まとめと検証
- [x] 5.1 系の登録・カメラの差し替え・確認用のカメラ・段の切り替えを仕上げる
  - ほかの系が場面への追加と毎コマの更新を登録でき、カメラを差し替えられる。段を再読み込みなしで切り替える
  - 確認用のカメラで山を見回せ、試験用の窓口から段を切り替えても誤りが出ない
  - _Requirements: 7.2, 8.1, 8.2, 8.3_
- [x] 5.2 起動前の準備と、速さ・再現性の検査を通す
  - 使う描画の準備を起動時に済ませ、滑走中に初めて映るもので固まらないようにする
  - 高の段・1440×900 で 95% のコマが 16.7 ms 以内。同じ場面を2回撮って見分けがつかない。3方式の起動の検査が通る
  - 検証（2026-11-10）：5 地点とも 95% のコマが 16.7 ms（`tools/shots/perf-check.mjs`）。同じ場面の2回の撮影は、中の段で画素単位に一致、高の段で差の出る画素が 0.5% 未満（残りは残像処理の位相）。WebGPU・WebGL2・WebKit の起動の検査が通る
  - _Requirements: 2.2, 7.3, 9.1, 10.1, 10.2_
