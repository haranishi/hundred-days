# Brief: game-shell

## Problem
物理と描画ができても、時間の進め方・入力・画面の部品が無ければ遊べない。試験と撮影を再現できる仕組みも要る。

## Current State
下調べの試作ページだけがある。題字・HUD・入力・一時停止・試験の道具は無い。

## Desired Outcome
開いて1操作で滑走が始まる。キーボード・ゲームパッド・指のどれでも同じ操作ができる。
時間は固定刻みで進み、試験と撮影では手動で送れる。実ブラウザの検査と固定撮影が1つの命令で回る。

## Approach
時間・入力・画面の部品を、物理と描画から切り離した部品として作る。物理・世界・描画は外から差し込む。
3D の描画が無くても動かせるよう、上から見た確認用の表示と、仮の滑走を同梱する。

## Scope
- **In**: 固定刻みの時間、手動送り、入力の統合、題字・HUD・一時停止・設定・転倒の案内、タッチの操作部品、設定の保存、試験用の窓口、実ブラウザの検査と撮影の道具。
- **Out**: 物理、山のデータ、3D の描画、音、山の地図、最終の配線（`src/main.js` は統合の作業で書く）。

## Boundary Candidates
- 時間（固定刻み・手動送り・一時停止）
- 入力（キーボード・ゲームパッド・タッチ → 同じ操作の値）
- 画面の部品（題字・HUD・一時停止・設定・案内）
- 試験用の窓口と、検査・撮影の道具

## Out of Boundary
- 滑走の規則（転倒の理由の文言は出すが、判定は ride-sim）
- 画質の段階の中身（段の名前と選び方だけ持つ。影や解像度は mountain-render）

## Upstream / Downstream
- **Upstream**: なし（物理と世界は形だけに依存）
- **Downstream**: mountain-render・ride-feedback（時間と画質の段階、試験用の窓口、撮影の道具を使う）、mountain-play

## Existing Spec Touchpoints
- **Extends**: なし
- **Adjacent**: ride-sim と操作の値の形を共有する

## Constraints
DOM と CSS だけで作る。ポインターロックを使わない。指だけで全操作ができる。幅 390・768・1440 で崩れない。`steering/tech.md` の試験の決まりに従う。
