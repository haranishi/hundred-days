# 設計：谷と湖のマップ（valley-map）

## 何を決めたか

| 決めたこと | 理由 |
|---|---|
| いまの山（火口のある独立峰）は捨て、参考画像の盆地 1 つに作り替える | 本人が配置を指定した。2 つの山を持つと、移動の仕組みと確かめる量が倍になる |
| 配置は「目印の点と高さの表」から作る（絵をなぞらない） | 参考画像は 9 枚で細部が食い違う。本人の指示も「固定配置と全体画像を優先」。数値にすれば、試験で守れる |
| 進める順は、①大まかな地形・湖・集落と 9 つの視点 → ②森・岩・氷河・リフト・建物の細部 → ③滑る仕掛け | 本人の指示の手順。配置が合う前に細部を作ると、作り直しになる |
| 光を「夕方」から「南東の朝の光」へ変える | 参考画像は、青空で、影が北西へ落ちる。夕方の低い光のままでは、どの視点も参考と合わない |
| 湖は高さの格子に平らな面として入れ、氷と水の区別は別の小さな絵で持つ | 物理・描画・跡が同じ高さを読む作りを保つ。水の所は、描画（水の色）と物理（落ちる）が同じ絵を読む |
| 橋の床は、高さの問い合わせに「重ねる面」として足す（地形の格子には入れない） | 橋の下に流れの溝を見せたい。格子に盛ると、アーチの下が雪の土手で埋まる |
| 建物・橋・リフトの形は、別の道具で作って配る（人物と同じやり方） | 形を手続きで作り、Node だけで絵にして確かめられる。配置は山のデータが持つ |
| 山の一辺は 4,096 m・格子 2 m（最初の 6,144 m・3 m から縮めた） | 参考画像は、建物の大きさから見て一辺 1 km ほどを詰めて描いた絵。同じ縮尺にすると 40 秒で滑り終わる。滑る長さを残せる範囲で、建物と木が小さく見えすぎない大きさにした |
| 山の形は「設計の面を、流れの浸食で刻む」（`tools/worldgen/lib/alpine.js`） | 下の「山の形の作り方」。式だけで描く方法と、浸食だけで育てる方法は、どちらも採点で落ちた |

## 山の形の作り方（2026-11-11 に作り直した）

1. **配置は 2 種類の折れ線で決める**：谷の底の線（`VALLEY`・`GLACIER`）と、尾根の線（`RIDGES`）。あいだを、なめらかな面でつなぐ（設計の面）。
   線どうしは、距離の逆数で混ぜる（いちばん近い線だけを使うと、入れ替わる所で面が折れた）。
2. **尾根型の起伏を 3 つの大きさで重ねる**（500 m・200 m・80 m）。支尾根と岩の出っぱりが、全体に散る。東のゲレンデでは弱める。
3. **流れの浸食で刻む**（8 m 格子で 150 回 → 4 m 格子で 40 回）。尾根は設計の高さへ引き戻し、谷の底の線は固定する。掘る深さに、場所ごとの上限を置く。
4. 硬い岩の斜面（西と北の上部）は、地層に沿った**崖の帯と雪の棚**にする。
5. **雪を積む**：ならした傾きで、付く・付かないを決める。岩は「雪の厚みが薄い所」から決まる（斜度のしきい値で塗らない）。氷河は、雪の面を氷の段で置き換える。

主な尾根は、大きく曲げてある。地図の縁に平行でまっすぐな尾根は、上空から、箱の縁に見えた。

## データの受け渡し（`world.json` に足すもの）

```
"layout": "valley-1",
"sun": { x, y, z },                       // 太陽の向き（南東・高さ 28° 前後）
"lake": { "level": 1180, "x0": .., "z0": .., "size": .., "grid": 1024 },  // 絵は lake.u8：0＝陸、1〜199＝氷、200〜255＝水（橋の下の流れも水）
"structures": {
  "lodge":   { x, y, z, yaw, length: 46, width: 19 },
  "chalets": [ { x, y, z, yaw, variant: 0〜2 } ],                          // 8 棟
  "bridge":  { x, y, z, yaw, length: 22, width: 4, rise: 2.2 },
  "lift":    { "base": { x, y, z }, "top": { x, y, z }, "towers": [ { x, y, z, height } ] },
  "roads":   [ [ [x, z], ... ] ]
},
"views": [ { "id": "aerial", "name": "全体", "ref": "01-aerial.png", "pos": [x,y,z], "target": [x,y,z], "fov": 40 }, ... ]   // 9 つ
```

- 建物・リフトの柱・橋の欄干は、障害物の問い合わせ（`obstaclesNear`）にも出す（円をいくつか並べて形に近づける。種類は `building`・`tower`）。
- 山のデータの問い合わせに `waterAt(x, z)`（水が見えている所か）を足す。物理は、接地中にここへ入ったら転倒（理由 `water`）にする。

## 見た目で合わせるもの（描画の作業。参考画像ごと）

雪面に点々と出る岩・岩壁の縦の層・氷河の青と段・湖の青緑と氷の割れ目・雪をかぶった針葉樹・木と石の山荘・地平線の遠い山並み。
合わせ方は「固定の視点で撮って、参考画像と並べ、別の担い手が採点する」（`ginrei-visual` の契約）。

## 検討して捨てた案

- **参考画像から高さを読み取って地形にする**（画像から深度を推定）：絵ごとに食い違い、滑れる斜度にならない。配置だけを数値で写す。
- **湖の上を全部氷にして、どこでも滑れるようにする**：安全だが、参考の「一部が凍った湖」と違う。水は中ほどに置き、岸沿いは氷で通れるようにする。
- **リフトに乗って上がる時間を作る**：雰囲気は出るが、待ち時間になる。駅で一本を区切って、1 操作で上へ移る（続けて遊べる仕組みのまま）。
- **いまの山を残して、盆地を 2 つめのマップにする**：上の表のとおり。
- **山の形を、式だけで描く**（I15・I15b）：指数関数の谷・sin の縞の岩ひだ・平面を重ねた山頂は、櫛の歯・板の岩壁・円錐になった。
- **平らな面から、隆起と浸食だけで育てる**（I15c）：配置を合わせる補正が形を壊し、ぼやけた塊になった。数値の決まりのために足した壁（45 m で 91 m 上がる）も残った。

## 落とし穴（先に分かっていること）

- 前の山づくり（I11）で、ジャンプ台と崖は「設計した軌道」と「実際の飛び」がずれ、検査を通らなかった。仕掛けは、地形ができてから、実際の物理で飛ばした軌道から着地の面を逆算して作る。
- 浸食の計算は、盆地の出口（湖）を水の行き先にしないと、谷が湖の手前で埋まる。湖を「水の出口」として扱う。
- 光の向きを変えると、焼いた日なたのデータ・空・影の届く向きが全部変わる。描画の側は、太陽の向きを山のデータから読む。
- 木を並べて描く部品（`scatter.js`）は、知らない種類の障害物を「木」として描いていた。建物の当たりの点（2 m おき）が、山荘や小屋の上の木のかたまりになった。種類は、木・樹氷・岩だけを描く。
- 地形の区画の大きさ（葉の一辺）は、山の大きさから決める。決め打ちだと、山を縮めたとき、近くの地面が描かれなかった。
- 空の式（SkyMesh）は、太陽が高いと、見上げた空が濃い紺になる。日中は、色を決めた式で空を描く。
- 氷の板と水のまだらは、湖の絵そのものへ焼く。描画の側で境目を崩すと、見た目は氷なのに水に落ちる所ができる。
- ジャンプ台は、1 台ずつ別の帯にならして置く。型の着地は深く掘るので、着地の後は時速 85 km を超える。次の台まで 250 m 以上要る。
  「620 m の 1 枚の平面に 3 台」は、置ける帯が無かった（ならす量が 29 m）。依頼の数値は、型を通った後の速さまで概算してから出す。
- 岩壁の溝の雪の筋は、雪質の地図だけを変えて入れる（高さは変えない）。描画だけで岩に雪を乗せると、雪に見える岩で転ぶ。
- 後から足す道と並木は、先に開けてある所（谷の広い帯・駅・集落）を上書きしない。森の道の並木が、合流する帯の真ん中に立って、道をふさいだ。
- 最初の一本（出発地点の並びの先頭）は、でたらめな舵で 60 回滑らせて、転倒の少なさで選ぶ。無操作の検査だけで選ぶと、帯の外のこぶや、木のそばを選ぶ。
- 上空と真上の視点は、地図の中だけを写す。引くと、地図の四角い縁が写る（地図の外の山並みは、縁の近くが無地の雪）。
