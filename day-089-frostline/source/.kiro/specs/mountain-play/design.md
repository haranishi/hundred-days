# 設計：続けて遊べる仕組み（mountain-play）

## UX の5階層

| 階層 | 決めたこと |
|---|---|
| 戦略 | 続ける理由は 3 つ用意する：すぐ次を滑れる（輪）・まだ行っていない地点がある（探検）・前より上を狙える（課題と記録）。他人との競争は入れない |
| 要件 | 入れる：一本の記録、技の名前と点、地点ごとの課題 3 つ、累計で開く 3 地点、隠れた 4 地点、地図からの移動、仕掛けの手前へのやり直し。入れない：順位表、時間制限つきの催し、通貨、装備の強化 |
| 構造 | 滑走 → 駅で自動に区切る → 記録（決定で次の一本）→ 滑走。横道は地図だけ。どの画面からも 1 操作で滑走へ戻れる |
| 骨格 | 記録の画面は、数字 5 つ・課題 3 つ・ボタン 3 つを 1 枚に収める（スクロールなし）。地図は、絵と詳細を横に並べ、狭い画面では縦に積む |
| 表層 | いまの題字・一時停止と同じ板（半透明の濃い板・白い字・橙の強調 1 色）。★は形で示し、取れたものを橙にする。動きは不透明度と移動だけ |

5階層を通して、実装が変わった点は次の 6 つ。
1. 一本の終わりを「どこかで止まったら自動で記録の画面」にしない。景色を見るために止まった人の邪魔になるので、駅の外では案内の行のボタンにした。
2. 地点に鍵をかけるのを、難しさ 4 の 3 か所だけにした。課題の達成で開く作りは、好みでない課題を強いる（調査 R1 の不満）。滑った量で開く。
3. やり直しの戻り先に「仕掛けの手前」を足した。ジャンプ台を飛び直すたびに出発地点から滑り直すのでは、続かない。
4. 記録の画面の最初の選択を「次の一本」にした。「もう一度」を最初にすると、同じ地点に留まりやすい。
5. 地図の印とは別に、名前のボタンの列を置いた。6 km の山を 390px に縮めると、印どうしが 44px より近くなる。
6. 技の点の合計は、0 点の間は出さない。技を使わない人の画面を、数字で塞がない。

## 部品の分け方

| 場所 | 責任 |
|---|---|
| `src/play/tricks.js` | 着地の出来事 → 技の名前と点（純粋な関数） |
| `src/play/run.js` | 一本の記録（積み上げ・終わりの判定・まとめ） |
| `src/play/goals.js` | 地点の種類 → 課題 3 つ、一本のまとめ → 達成 |
| `src/play/progress.js` | 保存と読み込み・検証・累計・開く条件・見つけた地点 |
| `src/play/index.js` | 上をまとめる窓口（`createPlay`）。画面と器はここだけを呼ぶ |
| `src/ui/summary.js`・`src/ui/map.js` | 記録の画面と地図。表示の中身を作る関数と、DOM へ映す部分を分ける |

`src/play` は DOM も three.js も読まない。依存の向きは `core ← world ← sim ← play ← ui`（play は sim の状態と出来事を読むだけ）。

## 課題の表（地点の種類ごと）

| 種類 | 2 つめ | 3 つめ |
|---|---|---|
| practice（練習） | 360 を決める | 技の点 1,000 以上 |
| park（ジャンプ台の列） | 技の点 2,000 以上 | 宙返りを決める |
| bigair（大ジャンプ台） | 滞空 2.5 秒以上の飛びを決める | 1 回の飛びで 2,000 点以上 |
| open・plateau（雪原） | 最高速度 90 km/h 以上 | 転ばずに駅まで |
| forest（森） | 転ばずに駅まで | 技の点 1,500 以上 |
| ridge（尾根） | 滞空 0.6 秒以上の飛びを 2 回 | 技の点 1,500 以上 |
| gully（沢） | 滞空の合計 4 秒以上 | 転ばずに駅まで |
| steep・chute・spine（急な面） | 転ばずに駅まで | 落差 5 m 以上の飛びを決める |

「決める」は、着地がきれいか重い（乱れ・転倒は数えない）。値は `src/play/rules.js` に集め、山ができてから滑って合わせる。

## 器とのつなぎ（`src/game.js`）

- 段階に `map` と `summary` を足す（どちらも時間を止める）。`play.update` は、物理の 1 刻みごとに状態と出来事を受ける。
- 「出発地点へ戻る」は、`play.retryPoint()` が返す地点へ戻す（無ければ出発地点）。
- 試験用の窓口に `play()`（状態・まとめ・地図の中身）を足す。採点役と検査の道具は、画面のボタン（`data-action`）を押して操作する。

## 検討して捨てた案

- **ふもとから上へ乗り物で戻る演出**：雰囲気は出るが、待つ時間が増える。次の一本までを 1 操作にするほうを取った。
- **終わりの無い自動生成の斜面**：ずっと滑れるが、地形を覚えて線を選ぶ遊びが無くなる。山は 1 つのまま、地点と課題で続ける理由を作る。
- **課題の達成で地点を開く**：上の 2 のとおり。
- **地図を 3D の俯瞰にする**：見栄えはするが、描画の負荷と操作の難しさが増える。生成した絵 1 枚と DOM のボタンで足りる。

## 保存の形

鍵は `ginrei.progress.v1`。読み込みは必ず検証し、型の合わない項目は初期値に戻す（設定の保存と同じやり方）。保存に失敗しても滑走は続ける。
