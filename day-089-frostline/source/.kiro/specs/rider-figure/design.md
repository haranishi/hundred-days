# 設計：滑走者の作り直し（rider-figure）

## 何を決めたか

| 決めたこと | 理由 |
|---|---|
| 服は「距離の関数」で形を作り、面に起こす | 丸い立体をなめらかにつなぐと、肩や腰の継ぎ目が自然に消える。筒と球を並べる今の作りでは、継ぎ目が必ず見える |
| 面に起こす処理は、ブラウザでなく Node の道具で先にやる | 起動のたびに計算すると、スマホで 1 秒近く待たせる。できたデータは 600 kB 以下で、Git に入れる |
| 動かし方は、骨と重み（スキニング） | ひと続きの面を関節で曲げる、いちばん普通のやり方。three.js が GPU で計算する |
| 骨の向きは、姿勢の計算が出す関節の位置から毎コマ作る | 姿勢の計算（I4・I14）は関節の位置を出す作りで、試験もある。これを作り直さない |
| 硬い道具（ヘルメット・ゴーグル・靴・ビンディング・板）は別の面にして、骨へ固定する | 曲がらない物まで重みで曲げると、形が歪む |

## データの流れ

1. `tools/ridergen/`（Node）：立った姿勢（腕を少し開く）で、服の形を距離の関数で組む → 面に起こす → 法線・重み・部位の番号・しわの強さを頂点に付ける → `public/models/rider-v1.bin` と `rider-v1.json` を書く。
2. `src/render/ride/skeleton-math.js`：姿勢の計算の出力 → 骨ごとの位置と向き（純粋な計算。試験できる）。
3. `src/render/ride/figure.js`：データを読み、骨つきの面を作り、毎コマ 2 の結果を骨へ入れる。材質（布・色分け・縫い目）もここ。

骨は親子にしない。全部を体の根もとの直下に並べる。
姿勢の計算は世界の座標で関節を出すので、親子の計算を挟んでも、誤差と手間が増えるだけだからだ。骨の長さが姿勢で少し変わるとき（脚の伸び）は、骨の軸方向の拡大で合わせる。

## 骨の一覧（19 本）

腰・腹・胸・首・頭、左右の上腕・前腕・手、左右のもも・すね・足。上着のすそとフードは、胸と腰の重みで動かし、揺れは頂点の計算で足す。
ひじ・ひざのねじれは、曲げる面の向き（関節 3 点が作る面）から決める。前腕のねじれは、手の向きとの中間を取る。

## 落とし穴（先に分かっていること）

- 地形と同じく、頂点を計算で動かす材質は「前のコマの位置」を自分で書かないと、動きの速度の絵が壊れる（`tech.md` の落とし穴）。
  骨つきの面は three.js が前のコマの骨を持つが、すその揺れを頂点の計算で足すぶんは、同じ揺れを前のコマの位置にも足す。
- 速度の絵へ書く材質の指定は、残像を消す処理のある段だけにする（無い段で指定すると、シェーダーの組み立てで落ちる）。
- 骨の向きを作るとき、曲げがほぼ 0 だと曲げる面が決まらない。前のコマの面を持ち越す。

## 検討して捨てた案

- **いまの筒と球を磨く**：色と法線を足しても、継ぎ目は残る。
- **AI の有料生成（Meshy）で人物を作る**：見栄えは最短で上がるが、有料で、本人の確認が要る。まず自作で作り、足りなければ本人に提案する。
- **CC0 の人体モデルに服を着せる**：顔も肌も見えない人物なので、人体の作り込みが無駄になる。服と道具の形を直接作るほうが早い。
- **Blender で手作業**：設計役は絵を見ながら手で彫れない。式で作れば、直しが試験と差分で追える。

## 合否の見方

- 道具が書き出す 4 枚の絵で、要件 1 の部位が見分けられること（Codex が自分で見て直す）。
- 実ブラウザで、8 つの姿勢を 3 方向から撮り、作者と別の担い手が見た目を採点する（めり込み・裏返り・継ぎ目・部位の見分け）。
