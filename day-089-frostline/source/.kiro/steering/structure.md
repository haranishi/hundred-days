# 構成の方針

## フォルダと責任

| 場所 | 責任 | 依存してよい先 |
|---|---|---|
| `src/core/` | 時間の進め方（固定刻み・手動送り）、種つき乱数、小さな数学、画質の段階、試験用の窓口 | なし |
| `src/world/` | 山の純データの読み込みと問い合わせ（高さ・法線・雪質・木と岩） | core |
| `src/sim/` | 滑走の物理と規則（接地・切る/削る・ジャンプ・着地・転倒）。DOM も three.js も読まない | core・world の問い合わせの形だけ |
| `src/input/` | キーボード・ゲームパッド・タッチを、同じ操作の値へまとめる | core |
| `src/render/` | three.js の描画。地形・空と光・影・滑走者・カメラ・雪煙・跡・後処理 | core・world・sim の状態（読むだけ） |
| `src/audio/` | 滑走の状態から作る合成音 | core・sim の状態（読むだけ） |
| `src/ui/` | 題字・HUD・一時停止・設定・地図・タッチの操作部品 | core・sim の状態（読むだけ） |
| `src/main.js` | 部品をつなぐ場所。ここだけが全部を知る | すべて |
| `tools/worldgen/` | 山を作る生成スクリプト（Node） | src/world の式を共有する |
| `tools/shots/` | 実ブラウザでの起動検査・固定撮影・性能測定・指の操作の試験 | なし |
| `tools/agents/` | Codex を走らせる補助 | なし |
| `tests/` | 単体試験（Vitest）。物理・世界・時間の決定的な検算 | src |
| `public/world/` | 生成した山のデータ（git に入れない） | — |
| `spikes/` | 下調べの試作。本体から読まない | — |
| `docs/research/` | 調査の報告（R1〜R4）と途中メモ | — |

依存の向きは core ← world ← sim ← （render・audio・ui）の一方通行。逆向きに読まない。
sim が描画や音へ知らせたいことは、状態の構造体と、その刻みの出来事の一覧（離雪・着地・転倒など）に書く。

## 名前と書き方

- ファイル名は小文字とハイフン。1ファイル1責任で、500行を超えたら分ける。
- 単位は SI（m・s・kg・rad）。角度を度で持つのは表示だけ。変数名に単位を書かない代わりに、JSDoc に書く。
- 座標は Y が上、X が東、Z が南（北は −Z）。原点は地図の中心。
- 物理の係数は `src/sim/params.js` に集め、出どころ（調査 R2 の表・提案値・調整値）を横に書く。
- 見た目の調整値は、直した周回と理由を横に残す（例：`// R2: 評価者「雪煙が画面を覆う」0.9→0.55`）。
- コメントは「なぜ」を書く。処理を日本語に直しただけのコメントは書かない。
- 本人向けの文言（画面の文字・報告）は平易な日本語。コードの識別子は英語。

## 試験の置き方

- 物理・世界・時間は Vitest。調査 R2 の数値目標（終端速度・制動距離・離雪の境界など）を回帰試験にする。
- 描画は Node で確かめられない。実ブラウザで「コンソールに誤り・警告が無い」「固定撮影が撮れる」を検査にする。
- 画面の操作は、指の操作（1本指のドラッグ・2本指の同時押し）を CDP で再現する。幅 390・768・1440 で確かめる。
- 試験が無い・落ちる状態では、体験や見た目の採点へ進まない。

## 仕様と記録の置き場所

- 仕様は `.kiro/specs/<名前>/`（要件・設計・タスク）。全体の順番は `.kiro/steering/roadmap.md`。
- 工程の契約は `.agent-harness/contracts/`、周回ごとの記録は `.agent-harness/runs/`。
- Codex への依頼書は `.agent-harness/briefs/` に残し、同じ依頼を別の担い手へ渡せるようにする。
- 再開の入口は Obsidian の `02_notes/40_プロダクト企画/銀嶺GINREI_企画/` に置く。
