# Roadmap

## Overview

ブラウザで動くオリジナルの雪山フリーライド（スノーボード）を、体験を先に、見た目を後に磨く順で作る。
M1（滑りの核）は 2026-11-10 に本人が遊んだ。出た要望は5つ。もっと険しい山、ジャンプ台、ずっと続けられる仕組み、丁寧な人物、回転や宙返りの技。
これを M2「遊びの幅」として先に作る。画を写真に寄せる作業は M3 へ送る。遊びが固まる前に画を磨くと、作り直しで無駄になるからだ。

## Approach Decision

- **Chosen**: 世界の純データ・物理・画面の土台・描画・演出・遊びの決まりを別の仕様として並行に作り、`src/main.js` でつなぐ。
- **Why**: 物理・山・遊びの決まりは Node だけで検算できるので、Codex に任せて並行に進められる。描画と画面は実ブラウザで目で確かめる。
- **Rejected alternatives**: ALPINE FLOW の改修（物理と描画を作り直すことになる）。1つの大きな仕様（並行に進められない）。実在の山の標高データ（本人が架空の山を選んだ）。

## Scope

- **In**: 架空の山1つ、スノーボードの自由滑走、三人称と一人称、切るターンと横滑り、ジャンプと着地、転倒と即再開、雪質の違い、木と岩、雪煙と跡、合成音、
  PC（キーボード・ゲームパッド）とスマホ（タッチ）。M2 で足すもの：空中の技（スピン・宙返り・つかみ）と点、ジャンプ台・崖・ルンゼなどの地形の仕掛け、
  山の地図と駅、一本ごとの記録、地点ごとの課題、手元に残る進み具合、作り込んだ滑走者。
- **Out**: 対戦・共有・順位表、リプレイの書き出し、実在の山、会員登録、課金。公開と SNS 共有は M4 まで扱わない。

## Constraints

- three.js 0.187.0・JavaScript・Vite。物理は固定刻み 120Hz で決定的。
- 素材は自作と CC0。既存作品の山・画面・名称・音を再現しない。考え方（地図から出発地点を選ぶ・技に点が付く）だけを学ぶ。
- commit は手元の git だけ。push・公開はしない（本人の選択）。
- 体験の採点は実装者と別の担い手が行い、1つの契約につき上限は3周。最後は本人のプレイで決める。

## Boundary Strategy

- **Why this split**: 山のデータ・物理・遊びの決まりは画面なしで試験できる。描画は世界のデータだけ、演出は物理の状態だけ、画面は遊びの決まりの結果だけを読む。
- **Shared seams to watch**: ①世界の問い合わせと `world.json`（出発地点・駅・仕掛け）②滑走の状態と出来事（`src/sim` が書き、描画・音・画面・遊びの決まりが読む）
  ③時間の進め方と試験用の窓口（`src/core`）④遊びの決まりの公開関数（`src/play`）。変えるときは読む側の仕様も見直す。

## Specs (dependency order)

### M1：滑りの核（本人の確認まで済み。採点は 10 → 11 → 14 点で、合格点 16 には未達のまま M2 へ引き継ぐ）

- [x] mountain-world -- 山を作る生成スクリプトと、高さ・雪質・木と岩の問い合わせ
- [x] ride-sim -- スノーボードの物理と規則（切る・削る・飛ぶ・着地・転倒）
- [x] game-shell -- 時間の進め方・入力・題字と HUD と一時停止・試験用の窓口・撮影の道具
- [x] mountain-render -- 地形・空と光・影・木と岩の描画と、画質の段階
- [x] ride-feedback -- 滑走者の姿勢・カメラ・雪煙・跡・音

### M2：遊びの幅（2026-11-10 の本人の要望）

状態（2026-11-11）：実装は一通り入った。採点は、どれも合格点に届いていない（体験 13 → 15 → 15／20。山の見た目 5 → 4 → 6／20。
人物 10／16 と画面 14／20。どれも 3 周で打ち切り）。残った差は本人へ伝え、本人のプレイで次を決める。

- [ ] ride-tricks -- 空中のスピン・宙返り・つかみと着地の判定。M1 の採点で残った制動と横滑りの直しも含む。Dependencies: ride-sim
- [ ] mountain-features -- 険しい上部、ジャンプ台の列、崖の帯、ルンゼ、駅、出発地点の追加、地図の絵。Dependencies: mountain-world
  （山の形は valley-map へ置き換えた。仕掛けの焼き込み・物理での検査・駅・地図の絵の仕組みは、そのまま使う）
- [ ] valley-map -- 本人の参考画像の配置（北に山頂・中央に谷・西に岩壁と氷河・東にゲレンデとリフト・南に凍った湖と集落）へ、山を作り替える。
  進める順は、①大まかな地形と 9 つの視点 → ②森・岩・氷河・リフト・建物の細部 → ③滑る仕掛け。Dependencies: mountain-features の仕組み
- [ ] mountain-play -- 一本の記録、技の名前と点、課題、進み具合の保存、山の地図と区切りの画面。Dependencies: ride-tricks と mountain-features の受け渡しの形
- [ ] rider-figure -- 継ぎ目のない体と服、道具の作り込み、技の姿勢。Dependencies: ride-feedback
- [ ] ski-gear -- スキーを足す（2026-11-11 の本人の依頼）。道具の選択・スキーの滑りの値・スキーの人（板 2 本・ストック・前向きの姿勢）・2 本の跡。Dependencies: ride-sim・rider-figure
  作り終えて、採点も上限まで回した（滑り 11 → 14／16 点で合格。見た目 6 → 10 → 9／16 点で不合格のまま停止）。残りは、作者が滑って決める。

### M3：画を写真に寄せる

- [ ] snow-look -- 雪の質感・大気・遠景・跡の変形を、参照写真との固定撮影で詰める。Dependencies: M2

### M4：公開（本人が決めてから）

- [ ] publish-gate -- 配信の容量、SNS 共有4点セットと OGP、名称の商標確認、公開の検査。Dependencies: M3

工程の分担と周回の決まりは `.agent-harness/contracts/` に置く。M2 の体験の採点は `ginrei-gamefeel-v2.yaml` で行う（技・仕掛け・続ける流れを採点項目に足したため、周回を数え直す）。
