# 技術の方針

## 採用した構成と理由

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語 | JavaScript（ES Modules・型は JSDoc） | 本人の指定。ビルド無しでも読める |
| 描画 | three.js 0.187.0 の WebGPURenderer と TSL。WebGL2 へ自動で切り替わる | 影（CSMShadowNode）・時間方向のAA（TRAA）・AO・空（SkyMesh）が WebGPU 側に揃う。2026-11-10 の試作で両方式が同じ絵・毎秒60コマだった |
| 物理 | 自作。固定刻み 120Hz・決定的 | 板の向きと進む向きを分けた雪上の力学は、汎用の物理エンジンに無い（調査 R2） |
| 画面の部品 | DOM と CSS | HUD は数個の表示だけ。枠組みを入れる理由が無い |
| 音 | WebAudio の合成音 | 滑走の状態（横滑り・荷重・速度）へ連続に追従させたい。素材の権利確認も要らない |
| 道具 | Vite 8・Vitest 5・Playwright 1.64 | 手元の実績。依存は公開から1週間以上たった版だけを `npm install --before` で入れる |

捨てた案は3つ。WebGLRenderer 固定は、新しい影・後処理が WebGPU 側にしか増えないため見送った。
TypeScript は本人指定に合わないため使わない。Rapier 等の物理エンジンは、雪面のエッジの力を表せないため使わない。

## 世界の骨格は1つの純データ

山の形・雪質・木の位置は `tools/worldgen` が種から作り、`public/world/` へ書き出す。
描画・物理・音・地図は、同じ問い合わせ（`src/world`）だけを読む。別々に地形を計算しない。

- 高さ ＝ 大きな形（3m 格子・2048²・3次Bスプライン補間）＋ 中くらいの凹凸（96m で繰り返すタイル × 場所ごとの強さ）。
- CPU と GPU は同じ配列を同じ式で読む。GPU 側だけの雑音関数で高さを作らない（接地がずれる）。
- 生成物は git に入れない。`npm run worldgen` で作り直せることを正とし、生成物には種と版を書く。
- 乱数は機能ごとに別の系列にする（木の配置を変えても、山の形が変わらない）。

## 状態と見た目を分ける

物理（`src/sim`）は毎刻み、滑走の状態を1つの構造体へ書く。描画・音・HUD はそれを読むだけで、書き換えない。
見た目の値（カメラ・姿勢・音量）は、ばねか平滑化を通して連続に保つ。状態が跳んでも画が跳ばないようにする。
時間は「実時間」と「手動送り」を切り替えられる。試験と撮影は手動送りで行い、同じ入力から同じ結果を得る。

## 試作で確かめたこと（2026-11-10・M4 Pro）

- Playwright 同梱の Chromium は、`--enable-unsafe-webgpu --enable-features=WebGPU --use-angle=metal --enable-gpu --ignore-gpu-blocklist` を付けると画面なしでも WebGPU（Metal）で動く。付けないとソフトウェア描画になり、1コマ 78ms かかる。
- Playwright の WebKit も WebGPU で動いた。Safari 系の確認に使う。
- 本物の Chrome（`channel:'chrome'`）は使わない。画面なしで起動すると、Dock から普段の Chrome を開けなくなる。
- R32F の高さテクスチャを頂点シェーダーで `textureLoad` し、自前で補間する方式は、WebGPU・WebGL2 の両方で動いた。
- 524,000 三角形の地形＋影4段＋TRAA＋ブルームが、1280×720 で毎秒60コマ出た。
- 記録は `.agent-harness/runs/spike-renderer/`、試作コードは `spikes/renderer/`。

## 落とし穴

- `CSMShadowNode` の `camera` を自分で代入しない。初期化が飛び、組み立て時に `AssignNode` の誤りで落ちる（試作で踏んだ）。
- 後処理の入口は `RenderPipeline`。`PostProcessing` は r183 から非推奨の別名。
- three.js は版ごとに API が変わる。記憶で書かず、`node_modules/three` の実物と r187 の公式例で名前を確かめる。
- シェーダーの誤りは Node の試験で見つからない。描画を触ったら、実ブラウザのコンソール（警告も）を必ず見る。
- 変数名に `patch`・`sample`・`input`・`output`・`common`・`filter`・`active` を使わない（GLSL の予約語）。
- 単体試験は `NODE_OPTIONS=--max-old-space-size=1536` を付ける。循環した物体を `deepEqual` へ渡さない。
- ブラウザを使う試験は、この Mac 全体で同時に2本まで。終わったら試験用ブラウザを閉じる。
- ポインターロックは使わない。視点はドラッグで動かす（自動試験が本物のカーソルを動かす事故を避け、スマホと操作をそろえる）。
- 描画の事前準備は、後処理の描画先に合わせる（`renderer.js` の `precompile()`）。`renderer.compileAsync(scene, camera)` を直接呼ぶと、画面へ直接描く場合の準備になり、速度の絵つきの本番とは別物になる。
- 半透明の物（雪煙・跡・雪の粒）は、残像を消す処理が使う「速度の絵」を書き換えない。そのための `material.mrtNode` は、速度の絵を持つ段（TRAA）でだけ付ける。持たない段で付けると、出力が空になって組み立てで落ちる。
- 頂点の位置を計算で決める材質（`positionNode`）は、速度の絵のために「前のコマの位置」を自分で教える（`positionPrevious.assign(...)`）。three.js は、教えないと動かす前の元の形の位置を使う。地形でこれを忘れていて、カメラが止まっていても速度が巨大な値になり、残像を消す処理が地形の上で正しく働いていなかった（動きのぼかしを足して、分身だらけの絵になって気づいた）。同じ形を並べて描く物（`InstancedMesh`：木・樹氷・岩）は three.js が自分で処理する。同じ代入を足しても、まっすぐ滑る連続 12 コマでは差が出なかった（足す根拠が無いので、標準のままにしている）。
- 白い雪の上の白い粒は見えない。陰を暗くすると黒い煙に見える。明るさを保ったまま青くする（`spray.js`）。
- 手動送りの直後に撮ると、1コマ前の絵が写ることがある。描いてから2コマ待って撮る（`play-probe.mjs`・`play-session.mjs`）。
- 採点役には、固めた版（`vite build` → `vite preview` を別のポート）を見せる。開発サーバーだと、こちらの編集のたびにページが読み直されて、採点の途中の状態が消える。
- 採点役（別の会話）はファイルを書けないことがある。報告は本文で返させ、設計役が `runs/` へ保存する。
- `tests/world/production.test.js` は 14 秒かかる。ブラウザの検査や採点と同時に流すと時間切れで落ちるので、退行と見誤らない（単独で流し直す）。

## 画質の段階

高（PC）・中（新しめのスマホ）・低（古いスマホと WebGL2）の3段。影の段数、内部解像度、TRAA と AO の有無、
木と雪煙の数をまとめて切り替える。1項目だけ切ると画の釣り合いが崩れるので、段ごとに決める。
URL の `?q=low` などで固定でき、原因の切り分けに使う。

## 権利

素材は自作と CC0 を基本にする（調査 R4）。Mixamo・Fab・Sonniss・Pixabay の素材は、公開リポジトリへ入れられないので使わない。
使った素材は `docs/assets-ledger.md` に、作者・URL・取得日・ライセンスを残す。装備に実在ブランドの意匠を付けない。
