# 解説の書き方と、権利・規約の線引き

`data/commentary.json` に解説を足す人（毎日の更新を含む）が守ること。法律の専門家には確認していない。下の線引きは、2026-10-07に全文を読んだ規約に基づく。

## 根拠にした規約
- [API利用条件](https://www.nobelprize.org/about/terms-of-use-for-api-nobelprize-org-and-data-nobelprize-org/)：データはCC0。「データを変えたり検閲したりしない」「利用者を誤解させない」「人をおとしめない」「題名やロゴに提供元の名前・商標を使わない（出典としての表記は歓迎）」
- [サイトの利用条件](https://www.nobelprize.org/about/terms-of-use/)：サイトの文章・写真・データは提供元のもの。**許可なしの複製・翻案（翻訳・言い換えの写しを含む）は禁止**。リンクは「HTMLページ全体」だけ可。画像・動画への直リンク、公式の要素の埋め込み、公式のロゴは不可。例外で使うときは、改変せず©表記と出典の明記が要る

## 守ること（検査できるものは `tools/check-commentary.mjs` が見る）
1. **公式サイトの文章は、写さない・訳さない・言い換えない。** 読むのは事実を確かめるためだけ。書くときは論文などの一次資料の事実から、自分の言葉で、文の構造も順序も写さずに書く。短い引用もしない（条件が付くため）
2. **APIのデータ（CC0）だけは原文のまま出す**：賞の名前・受賞者名・年・分野・発表日・受賞理由。受賞理由は訳さず、変えない
3. **すべての文に出典を付ける。** 出典は、読んで本当に支える箇所を確かめたhttpsのURLだけ。論文は `https://doi.org/…`。公式サイトへのリンクはHTMLのページ（`/prizes/…`・`/laureate/…`）だけ。PDF・画像・動画・`/uploads/` は載せない
4. **事実と期待を混ぜない。** `changed` は、すでに起きて記録がある事柄だけ（「かもしれない」「期待される」「可能性」「予定」を使わない）。まだのことは `expected`
5. **評価しない・おとしめない。** 賞賛・順位・誇張の言葉（天才・偉大・革命的・画期的・奇跡…）を使わない。論争や優先権の争いは書かない。**文学賞・平和賞は `mode: "facts"`**（受賞理由と活動の事実だけ。変化・期待・年数は書かない）
6. **「ノーベル」「Nobel」を、題名・見出し・ひとこと・共有の文・画面の最初の1画面・OG画像に入れない。** 使ってよいのは、出典欄・断り書き・説明の本文。「公式」「公認」「提携」と書かない。メダル・ロゴ・公式風の飾りを使わない
7. **個人の情報を書かない。** 生年月日・没年月日・生まれ・死去・住所・家族・健康（匿名の1例の臨床報告は、論文に載る範囲で、特定できない形で最小限に書いてよい）。写真・肖像は使わない。**受賞者の年齢は、解説のカードには出さない。** 年齢検索の欄だけが、公式データ（CC0）から数えた発表日の満年齢を出す（初版の10/6の確認で了承。厳密な読みでは個人情報にあたる余地があるため、公開の判断はあなたに仰ぐ）
8. **日本語の名前は Wikidata の日本語ラベル（CC0）だけ。** URLを `jaSrc` に書く。無ければ英語のまま。漢字を推測しない
9. 解説は「作者が出典をもとに書いたもの」と全カードに出す。確認日（`verifiedAt`）は、出典を開いて確かめた日
10. **企業の発表（`company`）は、原則載せない。** 宣伝に見える恐れと、承認などの状態がすぐ古くなる点があるため（医学賞の開発会社の承認申請の発表は、2026-10-07の本人の判断で外した）。載せるときは「会社の発表」と明記し、規制当局の情報は確認していないと書き、日付を付ける

## データの形（`data/commentary.json`）
```json
{ "schema": 1, "year": 2026, "entries": { "<cat>": {
  "verifiedAt": "2026-10-07", "mode": "science",
  "headline": "1文・60字以内",
  "what": [{ "text": "…", "src": ["s1"] }],
  "changed": [{ "text": "…", "src": ["s2"] }],
  "expected": [{ "text": "…", "src": ["s3"] }],
  "gap": [{ "label": "（2人の発見を分けるときだけ）", "startYear": 2002, "endYear": 2026, "years": 24, "what": "起点の出来事を一文で", "src": ["s1"] }],
  "people": [{ "id": "1061", "ja": "…", "jaSrc": "https://www.wikidata.org/wiki/Q…" }],
  "sources": { "s1": { "title": "…", "publisher": "発行元（2002年）", "kind": "paper", "lang": "en", "url": "https://doi.org/…" } }
} } }
```
- `<cat>` は `med`・`phy`・`che`・`lit`・`pea`・`eco`。`kind` は `paper`・`official`・`institution`・`registry`・`media`・`data`・`reference`（事典・用語集。定義の出典に使う）・`company`（企業の発表）。`lang` は任意で `en`／`ja`（`en` の資料には画面で「英語」の印が付く）。ウェブページの題は引き写さず自分の日本語で書く（論文の題だけは原題のまま）。論文の発行元には出版年を添える
- `what` は2〜4、`changed` は0〜5、`expected` は0〜3。`mode: "facts"` は `headline`・`what`・`people`・`sources`・`verifiedAt` だけ
- 年数は「論文の出版年と2026年の差」。カードの注記にも共有文にもそう断る。`gap` は1〜2件の配列（`label` は2件のときだけ必須）。`years` は `endYear - startYear` と一致し、`endYear` は `year`。起点は「その賞が評価した発見」を最もよく表す論文や出来事。「最初の」と書かない（確かめられない）。選んだ理由は作業記録に残す
- 文字は平文（HTMLやタグを入れない）。使っていない出典を残さない

## 更新の手順（発表のたび。目安は1賞30分）
1. APIで発表を確かめる：`https://api.nobelprize.org/2.1/nobelPrizes?nobelPrizeYear=2026&nobelPrizeCategory=<phy|che|med|lit|pea|eco>`（受賞者が入るまで、発表から数分〜10分かかる）
2. 事実の資料を作る：一次資料（論文のDOIは Crossref で発行日を確かめる）から、事実を短く、出典つきで。公式サイトの文章は写さない
3. `commentary.json` に足す。`node day-060-prize-explained/tools/check-commentary.mjs` を通す
4. **別の担当が、出典を1つずつ開いて、文ごとに照合する。** 公式の文章との近さ（訳や言い換えの写しが無いか）も見る
5. 画面を実際に開いて確かめる（解説の欄・出典番号・準備中の状態）。`npm run build`・`npm run precheck`・E2E
6. 公開後、本番で確かめる
