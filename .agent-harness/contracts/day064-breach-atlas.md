# Day64 漏洩の地図 — 工程契約

開始: 2026-10-11。依頼: 日本企業が公表した情報漏洩を、Obsidianのグラフビューに近い3Dマップで探索する。

## 目的と範囲

- 公開一次資料から選んだ事例を、原因のハブと企業ノードでつなぐ。規模の大きい事例を大きく表示する。
- 企業を探す → ノードまたは一覧から選ぶ → 公表規模・確認状況・情報項目・出典を確かめる、を中心の操作にする。
- 企業間の取引関係・攻撃経路・企業の安全性は推定しない。漏洩原データ・個人情報・認証・課金・自動収集・日次更新・地理的な座標は対象外。
- 書き込みは Day64本体、専用設計/調査/検証資料、Day64テスト、Day索引、Day64に必要な配信除外、第三者表記に限定する。
- 既存リポジトリの作業コピーで実施し、元の作業場所の変更はしない。
- commit、push、PR、デプロイ、公開、外部送信は今回の依頼に含まれない。ユーザーの明示指示があるときだけ行う。

## 受け入れ条件

1. 企業・規模・単位・確認状況・公表日・一次資料URLを持つ事例を15件以上収録。各数値を公式発表と照合する。
2. 件・人・アカウントを混ぜて順位を付けない。未公表を0として扱わない。確認と可能性を明記し、上限・概数・推計・重複・海外範囲を保持する。
3. 同一企業の別事例を足し合わせない。初報を続報が訂正している場合は訂正を反映する。
4. 3Dの回転・ズーム・ノード選択、検索、原因/年/確認状況の絞り込み、単位切替、全体表示への復帰が動く。
5. 390/768/1440pxで主要操作・出典確認ができる。WebGLが使えない場合も一覧から同じ情報を読める。キーボード操作と動きを減らす設定に対応する。
6. 出典リンク・確認日・収録範囲・大きさの読み方が画面から分かる。X/LINE/共有シート/リンクコピーとcanonical/OGPを用意する。
7. 単体、データ検査、Day64ビルド、関連ブラウザテストが通り、スクリーンショットを実際に確認する。

## 検証と改善

- ロジック: 数値/単位/日付/一次資料、検索、絞り込み、同単位での並び替え、未公表、決定的な配置、正の大きさ、選択URL。
- 実操作: 3D選択、一覧選択、検索ゼロ件→復帰、単位切替、絞り込み、出典、共有、キーボード、WebGL不可。
- 体験評価 → UI評価。実操作と画像で採点し、独立レビューと自己点検は区別する。
- 最大3周。同一の失敗が2周続いたら原因と残件を報告する。未確認を合格にしない。

## 初期判断

- 生データをアプリから検索する構成ではなく、検索で得た公式資料を検証して静的な事例集を同梱する。閲覧者の検索は同梱事例が対象。
- ノードの大きさは同じ単位内の公表規模を対数尺度で表す。視認性のための最小径を持ち、件数比そのものではないことを明示する。
- マップの線は共通原因の分類だけを示す。大きさは現在の企業の危険度を示さない。
