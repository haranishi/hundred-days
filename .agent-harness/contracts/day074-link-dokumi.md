# リンクの毒見：開発契約

## 目的
URLを貼ると、そのリンクの「なりすましの兆候」と、サイトの「守りの弱点」を、受け身の確認1回で調べて平易な日本語で返す無料のWebアプリを、新しいDay74として作る。

## 承認状態
本人が「サイトの脆弱性がわかる、リンクを送ると安全かどうか分かるウェブサイトを、cc-sddとハーネスで作り、100日チャレンジへ今日分としてマージ」と依頼した（2026-10-22・音声入力）。同日の自律進行の指示に基づき、要件・設計・タスクは承認済みとして進める。要件の個別レビューは未実施で、`spec.json` に残す。

## 変更範囲
- 新Day `day-074-link-dokumi/`、専用仕様 `.kiro/specs/day-074-link-dokumi/`、この契約と検証記録。
- 新しいサーバー側の入口 `functions/api/day-074/`（第三者のURLへ接続する。脅威モデルは仕様の `threat-model.md`）。
- 新作の単体・ブラウザテスト（`tests/e2e/day-074.spec.mjs`）。
- 統合に要る最小限の変更：`functions/README.md`・`docs/security.md`・READMEのDay一覧・`THIRD_PARTY_NOTICES.md`（必要なら）。
- 既存Dayの機能は変えない。Day73（offbeat.）には触れない。

## 対象外
ログイン・履歴・アカウント・診断先の画面の取得/表示・ウイルス検査・既知の悪意あるURL一覧との照合・隠しファイル探しなど侵入に近い確認・X投稿・プロモ動画・第三者へのメッセージ送信。
他の作業場所にある未コミット変更の移動・削除・取り消し。

## 受け入れ
- 貼ったURLに対し、アドレスの見た目の結果が通信なしで先に出て、続いて転送の経路・守りの設定・周辺情報が足される。どの段が失敗しても残りで結果を出す。
- 結果は2つの軸（なりすましの兆候／サイトの守り）に分かれ、混ざらない。「安全です」と言い切る文がない。
- 公開でない宛先（ループバック・私設・リンクローカル・メタデータ・内部名・DNSが私設を指す名前・転送の途中で向かう先）へ、関数は接続しない。
- 診断したURLを、サーバーにも端末にも残さない。`?`以降は既定で送らない。
- 取得先の文字列は、画面でHTMLとして解釈されない。
- 幅320px〜で崩れず、キーボードだけで使える。共有・OGP・canonical・CSPの契約を満たす。
- 既存の検査と、新作の単体・E2E・実観測・体験評価・画面評価・独立レビューに証拠がある。人の実機（iPhone Safari等）は未確認なら未確認と書く。

## 検証方法
`node --test day-074-link-dokumi/tests/`、構文・ビルド・`npm run check`、公開ゲート（`npm run publish:check -- --day 74`）、Chromium/WebKitの重要フロー（`tests/e2e/day-074.spec.mjs`）。
ローカルのworkerd（wrangler pages dev）で関数を動かした実観測。
実操作の体験評価（10項目×0〜2点・16点以上かつ0点なし）、続けて画像による画面評価（同じ基準）を、実装者とは別の評価者が行う。順番は体験 → 見た目。
別担当による読み取り専用のセキュリティ・コードレビュー。実装者の「全テスト合格」は、メインが再実行して確かめる。
