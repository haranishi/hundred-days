# Day77 実3Dへの刷新：開発契約

## 目的と判断根拠
ユーザーの「2Dではなく3Dで荷物を仕分けたい」「既存の3D作品を参考に品質を上げたい」
という2026-10-26の再依頼を実装する。セキュリティ警告への追加依頼も対象とする。
既存の要件・判定データを引き継ぎ、[3D設計](../../.kiro/specs/day-077-hoan-swiper/3d-design.md) を現行仕様とする。

## 変更範囲と担当境界
- 主担当：UX・仕様更新、Day77のHTML/CSS/入力・状態と描画の統合、E2E、最終判断。
- 描画担当：独自の手続き3Dモデル、材質・照明・影・搬送・X線、ローカルThree.js同梱。
- Security担当：実在するDependabot警告の特定、最小依存更新と既存Dayの検証。
- 独立評価：描画・UI実装とは別担当がコードレビューとブラウザで画面/体験を確認する。

## 完了条件と検証
- 検査場と全36品目を実3Dで描画し、仕分けとX線・視点切替が動く。
- 研修/60秒/練習/図鑑/結果/保存/共有を維持する。
- タッチ、マウス、キー入力が同じ判定へ進み、キャンセルで回答しない。
- 3D故障時のテキスト進行と再読み込みを確認する。
- 390/768/1440pxの実画像と実操作に基づく独立評価で、各16/20以上・0点なし。
- 単体テスト、全体check、Day77 E2E、公開ゲートを通過する。
- 依存更新後の既存テスト・ビルドを通し、警告対象の解消を照合する。
- 記録は仕様のv3-validation.mdとruns/day077-hoan-swiper/v3-independent-review.mdに残す。

## 制約と停止条件
- コード・素材・数値をspiderbenchから転用しない。外部CDNや外部モデルを利用しない。
- 無関係なDayの機能、航空ルール自体、SNS投稿は今回変更しない。
- 改善は最大3周。同一失敗2周の場合は原因と残件を報告する。
- 通常の仕様更新・実装・検証・作業ブランチのcommit/push/PRまで進める。
- 本番マージはリポジトリのAGENTSに従って本人の操作とする。
