# フリップコート：開発契約

## 目的
1人でCPUと60秒対戦する球打ち・陣取りゲームを、新しいDayとして作る。

## 承認状態
本人が要件案と、設計・タスク作成・実装・検証の一括進行を承認した。
各仕様は生成とレビューの完了を確認して承認済みに更新する。企画選択だけを承認根拠にはしない。

## 変更範囲
- 新Day、専用仕様、この契約と検証記録。
- 新作の単体・ブラウザテストと、必要な既存検査への登録。
- 新Dayの共有コピー・制作記録・一覧の同期。
- ビルドへの接続に必要な最小限の変更。既存Dayのゲーム内容は変えない。

## 対象外
オンライン対戦、会員機能、外部サービス、ランキング、既存作品の改修。
他の作業場所にある未コミット変更の移動・削除・取り消し。

## 受け入れ
- 初回の説明から開始・着地・反転・60秒の終了・再戦まで1人で完結する。
- 反転の境界、CPUとの同じ判定、得点と同点、一時停止と再戦を検証する。
- スマホとPCで操作でき、色以外でも陣地と結果が分かる。
- 既存の検査と、新作の実ブラウザ操作・UI評価に証拠がある。
- 未検証の機器や、人間の面白さを合格扱いしない。

## 検証方法
判定の単体試験、構文・ビルド検査、Chromium/WebKitの重要フローを使う。
入力と画面を実操作で確認し、5〜10分の体験評価と画面評価を行う。
別担当が使える工程では読み取り専用の独立レビューを行う。

## 工程
調査 → 要件の確認 → 設計 → タスク → 実装 → 機械検証 → 体験・UI評価。
各仕様の承認範囲を守る。改善は最大3周、同一失敗が2周続けば原因と残件を返す。

## 外部への反映
この新作のcommit・push・PR・マージ・デプロイ・SNS投稿は、本人から指示を受けた範囲で行う。
2026-10-19、本人の100daysへのマージ依頼を受け、commit・push・PR作成・マージを進める。公開設定はdraftを維持する。
