# Day64 社会的意義とUI整理

依頼: 公表記録アプリの社会的な役割を考え、見にくいUIを整理する。主担当が調査・設計・実装・検証を行う。

- 目的: 個人が公表内容を確かめ、小規模な組織や授業が過去の記録から備えを考えられる入口にする。
- 範囲: Day64の情報構成、読みやすさ、検索・地図・学びの導線、公的な学習資料へのリンク、関連する説明・検査・ローカル配信物。
- 設計: `docs/day064/purpose-ui-design.md` のユーザーストーリー・UX5階層を実装前に適用。
- 成功条件: 初期画面で目的と検索が分かる。地球儀を残しつつ読む部分を明るくする。詳細条件は全幅で開閉・取消ができる。記録から該当する学習テーマへ進み、テーマから日本の記録と公的資料へ戻れる。
- データ: 15,871公表記録、日本2,522、確認状況・原資料・数値の定義を維持。公表件数を危険度や独立した事故数に読み替えない。学習テーマは一般的な備えで、個別事故の原因や予防効果の認定をしない。
- 根拠: IPAの中小企業向けガイドライン、内部不正防止ガイドライン、個人情報保護委員会の対応資料を確認し、資料リンクと確認日を残す。
- 検証: 既存の重要ブラウザフロー、新しい学習・条件パネル・検索後の地図移動、390/768/1440pxの実画像、キーボードと失敗からの復帰、ビルドとローカル配信物照合。変更した操作を実体験で自己点検する。
- 社会的効果の評価: 目的に沿う導線の実装と、利用者の理解・行動改善の実証を区別する。今後は原資料到達と備えの説明ができるかを本人同意の利用者テストで確かめる。
- 改善最大3周。同じ製品不具合2周で残件を報告。commit・push・公開・外部送信の指示は今回ない。
