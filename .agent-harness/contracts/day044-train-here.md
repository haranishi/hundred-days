# 旧契約：Day 044 — 乗る電車、いまここ

2026-09-20に3Dビューへ変更。現行の要件は [day044-3d-scene.md](day044-3d-scene.md)。
以下は最初の2D案の履歴です。

## 目的・範囲

山手線で乗る駅・降りる駅を選び、近づく列車の位置と進行方向を確認する。
初版は山手線のみ。地図は駅の位置を結ぶ概略図。正確な軌道・GPS・到着予測は扱わない。
変更範囲は day-044-train-here、対応するAPI・テスト、および一覧・出典・開発用配信への必要な統合。
公開、commit、push、PR、外部への登録・送信は今回の実装工程に含めない。

## ユーザーストーリー・受け入れ条件

- 初めて東京の電車に乗る人が、乗車・降車駅から内回り／外回りを選べる。
- 近づく列車を一覧または地図で選び、走行区間・方向・提供された遅延を読める。
- データの最終更新を確認でき、欠測・期限切れを現在の運行と誤認しない。
- 未接続でも、明示的に選んだ架空デモで駅の選択と追跡を試せる。
- 390／768／1440px、キーボード、動きを減らす設定で操作できる。

## UX5階層

1. 戦略：地理と進行方向がわかり、待つ列車を見つけられる。
2. 要件：30駅、両方向、候補選択、位置確認、鮮度、再試行、明示的な架空デモ、共有。
3. 構造：駅選択→方面選択→候補一覧→選択列車の詳細と地図。1画面を基本とする。
4. 骨格：PCは左に乗車操作、右に地図。スマホは駅選択と地図、候補を縦に配置。
5. 表層：淡い地図、山手線の緑、方向を文字・矢印で併記。デモは常時ラベル表示。

## 設計への反映

- 混雑した全東京ではなく、山手線に絞り路線と選択列車の読み取りを優先。
- 時刻表の確認前に発車時刻・到着時刻を生成しない。駅数と走行区間で案内する。
- 実データ未設定では電車を出さない。架空デモへの切替は利用者の操作に限る。
- ライブの描画は最後に確認された駅／区間。更新間の演出は位置推定と明示する。

## 検証・制約

単体：環状線の方向、終着駅、候補抽出、不正入力、古いデータ、API応答とキー非露出。
ブラウザ：初回、駅変更、列車選択、追跡、デモ退出、失敗から再試行、3画面幅。
必要なビルド・機械チェックと実操作。改善最大3周、同一失敗2周で残件を報告。
Claude Opusへ設計・実装レビューを依頼する。認証できるまで未実施と記録する。
実APIは利用登録と許諾済みトークンが必要。実応答の未検証を完了扱いしない。
