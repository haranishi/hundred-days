# Day別コードの整理

## 目的と範囲

GitHubでアプリ名から該当するコードを見つけられるよう、Day別フォルダーをリポジトリ直下に配置し、READMEにDay・アプリ名・コード・公開ページの対応を示す。
既存の全43フォルダーと、ビルド・テスト・補助スクリプト・説明文のパスを更新する。

## 対象外

アプリの機能変更、デザイン変更、依存更新、公開URL変更。外部公開のDay 019・020は制作記録として明記する。

## 受け入れ条件

- Day 001〜043のファイルを欠落なく移動する。
- READMEから各Dayのフォルダーへ移動でき、共通コードとAPIの所在がわかる。
- ビルドと単体テストが成功し、ブラウザテストが全件検出される。
- 各アプリの配信ファイルが移動前と同一であることをハッシュで確認する（文書・制作メタデータ・補助ツールを除く）。
- 共通部品・外部公開Day・APIを利用する代表Dayのブラウザ検証を実施する。

## 公開と検証

ローカルで実装・検証を完了してから差分を報告する。GitHubへの反映は本人の明示指示の範囲で行う。
公開前チェックを実行し、最大3周まで修正する。
