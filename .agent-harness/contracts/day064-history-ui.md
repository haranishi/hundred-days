# Day64 過去資料の収録と見て理解できるUI

依頼: 2026-10-11。「もっと見てわかるUI」「過去のデータを全部」、追加依頼「5,000〜1万件」「Rustで軽くする」へ拡充する。

## 目的・変更範囲

- 政府の公開年度資料に掲載された過去の事案表を年度ごとに全行確認し、企業の公式発表で確認した近年の事例と統合する。取得した資料内の対象事例を恣意的に数件だけ選ばない。
- 全国の全事件を保証できる公開台帳と、主要事案だけの資料を区別する。収録済みの資料・期間・件数、資料自体の選定条件、未収録の範囲をアプリから確認できるようにする。
- 事例単位の年代表示、原因の分布、同じ単位での規模比較、全履歴の探索を用意する。既存の3D・SVGマップ、企業ノート、出典、共有も使えるようにする。
- Day64の本体・データ生成・調査・専用テスト・検証記録・第三者表記を変更する。無関係なDayには触れない。
- 公表されている事例の要約と数値を扱う。漏洩した個人情報の原データは収集しない。commit・push・公開・外部送信は本人の別途明示指示の範囲に従う。
- 公的な公開台帳の実在する掲載記録を5,000件以上、可能なら1万件以上取り込む。海外の通知台帳は国内の個別事例と地域・資料を切り替えて探索する。複数当局への届出を独立した事故件数と断定しない。「公表記録」として掲載行と除外・重複を検査する。
- RustをWebAssemblyへコンパイルし、Workerで検索・フィルタ・集計・ソートを実行する。HTML/CSSとDOM操作はブラウザ側で行う。依存を増やさず、詳細データと3Dは必要時に読み込み、カードはページごとに表示する。

## 受け入れ条件

1. 資料一覧と資料ごとの取込件数・重複・除外理由を保存し、既存19事例から過去資料へ大幅に拡充する。全件性は資料内の掲載事例について検査する。
2. 年・原因・単位・確認状況・情報項目・数値の留保・出典を各事例に保持する。紛失・誤廃棄や流出未確認を流出確認済みと断定しない。同一事故の続報は重複事例にしない。
3. 全履歴を事例単位で探索でき、別単位を合計・順位付けしない。年代の空欄を事件ゼロと断定しない。
4. 年代グラフ・原因の内訳・事例カードまたは規模比較の表示が、検索・絞り込み・ノートと連動する。多数の事例でも3Dのラベルと主要操作が使える。
5. 390/768/1440px、キーボード、動きを減らす設定、WebGL不可・操作中の喪失で探索と出典確認ができる。
6. データ検査・主要ロジック・関連ブラウザ検査・Day64とサイト全体のビルドを通す。実操作と3幅の画面を確認し、変更点と未収録の範囲を記録する。
7. Rustのネイティブ検査、実Wasmと代替処理の結果照合、実データ全件での検索・集計時間を記録する。Wasm/Workerが使えない場合も閲覧でき、初期表示では3Dを読み込まない。

## 検証と改善

新しいユーザーストーリーとUX5階層を設計資料へ追記してから実装する。体験評価とUI評価を行い、実操作・画像・検査結果を証拠にする。改善は最大3周、同じ失敗が2周続けば原因と残件を返す。必要な独立レビューは共通ハーネスの利用条件に従う。
