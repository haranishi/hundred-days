# Day087 実装と検証（2026-11-06）

折り紙の折り方を、紙が折れる動きとして3Dで見るアプリ。作品は紙飛行機・白鳥・立方体の箱（ふた無し）。
仕様は `.kiro/specs/day-087-oricube/`。追加ランタイム依存はthree.js（Day044の同梱版を未改変で複製）のみ。外部通信・保存なし。

## 作り方
折りエンジン（純粋なJS）と作品データ・単体試験をCodex、画面と3D表示をOpusが並行して作り、親が実ブラウザで統合・検証した。
紙は共有頂点の三角形メッシュで、折り線で切って動く側を軸のまわりに回す。層の順序・ヒンジ（引きちぎり）・折り目の貫通は構築時に検査する。
箱は、壁の立ち上がりに角が連動する機構で、角の位置を三辺測量で求める（`drive`）。

## 機械検証
- Day087単体: 93件成功（辺の長さ・面積・向きを全手順の5点で／層の順序と貫通／変異試験／箱の壁角度と解析解／折り目が紙の外へ出ない／縁の線と層の濃淡／レビュー指摘の回帰／タイムライン）。
- Day087 E2E: 25件成功（ビルド後のdistに対して実行）。作品切替・最後までの再生と完成・コマ送り・つまみ・手順の一覧・手順ごとに止める・視点と重なりの広げ方・完成の1周回転・キーボード・動きの軽減・WebGLなし・スマホの指（1本指で回す／2本指で寄る／2本目の指でボタン）・縦横と360〜844pxの44px/はみ出し・紙の寄せ。
- `npm run check`: 構文1,709ファイル・エラー0。単体5,200件中5,199成功・失敗0・既存の1件スキップ。依存監査・ビルド成功。
- 公開ゲート: 静的な契約・ビルド・ブラウザ合格。横断338件中337成功・既存の1件スキップ（Day087の共有・OGP・ヘッダーを含む）。トップページ・404の試験も合格。
- 変異の確認: 折り目の交差判定を直す前の実装で新しい試験が落ちること、2本目の指の処理を外すとE2Eが落ちることを確かめた。

## 実画面で見つけて直したこと
- 折り目の線が紙の外へとげのように飛び出した（三角形と線分の交差で、ほぼ0を負として扱い境界を飛ばしていた）。単体試験は幾何の保存だけを見ていて通っていた。画面で見て気づき、全手順で線が三角形の中に収まる試験を足した。
- 紙の上にまだらな影の縞が出た。影の板が紙の最下層の0.0025下にあり、紙のpolygonOffset（斜めからだと数mm相当）が板との隙間を超えていた。机と影を下げて解消。
- 翼の折り線を、試験の基準に合わせて実物と違う角度にしていた。実物の11.25°へ戻し、基準の側を直した。
- 作品が3つになりスマホ幅でロゴとタブが重なった。縦並びに直した。

## 独立レビューと評価
- Codex読み取り専用のコードレビュー: 再現できた7件。構築時に拒否できる4件（駆動角が非対称で追従頂点が跳ぶ／回転のNaN／0°のhingeの矢印／エラーの操作番号）を直し、3件（層の貫通検査が、貫通する面を折れた辺と同じ直線で分割すると見逃す／fold後に一部だけ開くとrankの段差が残る／同じ壁に複数のひれを `outside` で重ねると間隔が取れない）は既知の限界として `engine-notes.md` に記録した。出荷中の3作品は踏まない。
- 体験評価（Opus・実操作）: 17/20 合格。減点は中割り折りの用語説明と案内線の種類、まだら模様（上記で修正）。
- 画面評価（Opus・画像のみ）: 第1回14/20、第2回16/20 合格（0点なし）。指摘のうち、完成時の導線の一本化・完成の回転を1周で始めの向きへ・紙の寄せ・文字の折り返し・副題・凡例を手順に合わせる・手順の一覧・共有ボタンの揃え・縁の線と層の濃淡・白鳥の表裏の色を直した。
- 偽陽性として直さなかったもの: スマホのキーボード説明（模擬環境が hover を真にするため。実機では出ない）、共有URLの試験用引数（本番は canonical を使う）。

## 制約・未確認

# 第2弾：作品を10個に（2026-11-07）

作品は紙飛行機・ハート・ポチ袋・ヨット・もみの木・ネクタイ・着物・白鳥・立方体の箱・鶴の10個。仕様は同じ `.kiro/specs/day-087-oricube/`（要件5章・設計・models-more.md・タスク9〜15）。
追加した仕組みは、作品を選ぶ一覧、複数の折り目が同時に動く「連動折り」（鶴の正方基本形のつぶしと花弁折り）、作品を使うときに組み立てる遅延ビルド（鶴は「準備しています…」を出す）、手順ごとのおすすめ視点への自動追従。

## 作り方
連動折りの試作と実装・作品データ・性能の改善・独立レビューをCodex、作品選択UIと評価後の画面の修正をOpus、統合と実画面の検証を親が担当した。評価役のOpus（画像だけ／実操作）は別セッションで2周回した。

## 機械検証
- Day087単体: 294件成功（第1弾93件）。連動折りの解く部品、回転しても閉じ方が変わらないこと、作品ごとの完成の基準、組み立て時間（CPU時間で測る）、作品の絵の鮮度、試験の登録漏れ防止、推奨視点が真横にならないこと、案内線が紙の外へ出ないことを含む。
- Day087 E2E: 56件成功（第1弾25件）。作品選択（スマホの指・キーボード）、全作品が最後まで再生できる、準備中の表示、手順ごとの視点追従、完成札の位置、独立レビューの4件の回帰（案内線の描画資源・つまみの値・手順一覧のSpace・動きの軽減）など。
- `npm run check`: 成功。構文1,751ファイル・エラー0、単体5,401件中5,400件成功・失敗0・既存の1件スキップ、依存監査・ビルド成功。
- 公開ゲート（`npm run publish:check -- --day 87`）: 静的な契約に違反なし、横断338件中337件成功・既存の1件スキップ。
- 変異の確認: 独立レビューの4件の修正を部分的に壊した版でビルドし、足したブラウザ試験が4件とも落ちることを確かめた（描画資源の解放を外す／`app.js` を修正前へ戻す）。

## 評価
- 1周目：画面（画像のみ）13/20で不合格（3D表現が0点）、体験15/20で不合格。視点の手順ごとの宣言と自動追従、キー操作とフォーカス、鶴の用語の説明、手順の長さなどを直した。
- 2周目：画面17/20、体験17/20でどちらも合格（0点なし）。
- 2周目のあとに直した点は、独立した再採点はしていない。単体・ブラウザ試験と、実画面の目視で確かめた。
- 独立コードレビュー（Codex読み取り専用）は2回。エンジン側は試験の登録漏れなどを直した。画面まわりは4件（案内線の描画資源が作品切替で増え続ける／つまみの値のずれ／手順一覧でSpaceが開閉でなく再生になる／完成の回転中に動きの軽減をONにしても止まらない）を直した。

## 実画面で見つけて直したこと
- かぶとは数値の検査を全部通ったが、開いた形が十字で実物と違った（口の検査が凸包だけだった）。目で見て気づき、かぶと・舟・紙コップは見送った。
- 鶴の組み立てが7.3秒かかった（点の位置検索が線形）。索引にして0.5秒にし、起動時に全作品を組み立てる方式をやめて、使うときに組み立てるようにした。
- 鶴・ヨット・もみの木の専用試験が `tests/index.mjs` に未登録で、一度も走っていなかった（独立レビューで発覚）。登録し、登録漏れを見張る試験を足した。
- 白鳥の完成が縦の1本線に見えた（推奨視点が紙の縁の向き）。立つ作品用の視点 `profile`・`quarter` を足し、どの手順でも最良の向きの4割以上の面積で見えることを試験にした。
- 折りの途中で紙が床より下へ振れると、完成した姿が影から浮いた。机と影をいまの姿勢の最下点に合わせた。
- 裏返す・谷折りの案内線が、紙の外へ大きくはみ出した（紙飛行機の手順6で0.25、鶴の手順6で0.79）。紙を包む球の半径で線を伸ばしていたため。紙の三角形との交差で切り詰め、全作品・全手順の案内線の両端が紙の上にあることを試験にした（直す前の実装で落ちることを確認）。
- ポチ袋の裏がからし色で表の山吹色と見分けにくかった。江戸紫にした（表裏の明暗比 約2.3→約3.6）。凡例が「中割り折り」と出ていたのは、谷折りの線で描くようにした。
