# Day 045 体験評価2周目とUI採点の反映

入力は2つ。体験評価2周目（18/20・合格）の残指摘4件と、UI採点（17/20・合格、3幅×4状態の実測つき）の改善指示。
どちらも合格しているので、ここで直すのは「安く効くもの」だけに絞った。

## ゲームの手触り

**ウェーブ通過の文字が重ならないようにした。** 全滅の瞬間に浮き文字を全部消してから
「ウェーブn クリア +報酬」を1件だけ y=250 に置く。「WAVE n」は y=330 のまま。
通過中は「読まれた → 艦隊が回避」も描かない。単体テストで「通過時の浮き文字は1件」を固定した。

**波ごとの圧を体感できる量にした。** 射撃間隔 `max(0.45, 1.7×0.85^(wave−1))`、
歩みの速さ `1 + 0.18×(wave−1)`、敵弾 `170 + 18×wave`。
開始行は `72 + 24×min(wave−1, 4)` で頭打ちにする。青天井にすると、
5波を過ぎたあたりで最下行が防衛線のすぐ上から始まり、腕ではなく初期配置で決着してしまう。

**▽の意味を初回だけ言葉にした。** 遊び始めて4秒以降、▽と自機が12px以内に重なった最初の一度だけ、
▽の上に「▽ ここを狙われている」を1.5秒出す。1ゲームに1回まで。
記号の説明は、記号が意味を持った瞬間に出さないと読まれない。

**読まれ度メーターを危険域で色分けした。** `.reading[data-level]` が
calm(<40)／warm(40–69)／hot(70–89)／critical(≥90) を持ち、メーターの色が変わる。
criticalでは数値も同じ赤にして1秒周期で点滅させる。`prefers-reduced-motion: reduce` では点滅しない。

## UI採点の指摘

**熱の帯（配色の減点原因）。** 実測で heat=1.0 のセルが背景比3.09:1、実戦域の0.4〜0.6では1.52〜1.96:1だった。
原因は、暗い背景の上で半透明の赤を濃くしても輝度がほとんど動かないこと。
不透明度ではなく**輝度**の階調に変えた（`lib/heat-color.js`）。
heat 0 は薄い枠だけで塗らず、0.3で rgb(190,90,70)＝4.4:1、1.0で rgb(255,140,90)＝8.5:1。
帯は y=8〜52 の44pxに厚くし、いちばん熱いセルの上辺に白1pxを引いて色以外でも分かるようにした。
ラベル「撃ち癖の熱」は帯の下（y=72）へ。単体テストで熱0.3の背景比3.0以上を固定している。

**キャンバスの高さ上限（モバイルの減点原因）。** iPhone実機の表示高664pxで、開始後にツールバー下端が3px切れていた。
幅の上限を `(100dvh − 150px)×0.75` から `(100svh − 220px)×0.75` に変更（`svh` 非対応は `vh`）。
実測で 390×664 のとき一時停止ボタンの下端が636px、表示高664pxに収まる。E2Eに1件足した。

**結果画面からの共有（CTAの穴）。** 「もう一度」の下に結果専用の共有行を足した。
Xの投稿画面（点数・ウェーブ・講評とアプリ名を含む本文）と、公開URLのコピー。
共通の共有欄（`#share`・`.share`）は横断E2Eが「1つだけ表示」を見ているので触らず、
結果側は `result-share` という別のクラス名にした。E2Eでhrefの中身を1件固定した。

**44px未満のリンク2件。** ヘッダーの戻りリンク（154×23px）とフッターの「プライバシー」（83×17px）に、
行の見た目を変えずに44pxの当たり判定を付けた（実測 154×44・83×44）。

**オーバーレイ越しの透け。** 開始前・一時停止・結果の表示中は、キャンバス内の帯とラベルを描かない。
390pxでラベルがアイブローと5pxまで近づく問題も、これで消えた。

**付随で直したところ。** 共有行を足すと結果パネルが390×664で106px溢れたので、
段落の余白と得点の文字を詰め、統計2行を1行にまとめた（1px以内に収まる）。
`#result` に `justify-content: safe center` と縦スクロールを入れ、溢れても上端が切れないようにした。

## 直さなかった指摘

- **デスクトップの空白を2カラムで埋める。** 指示どおり見送り。1日アプリの枠を超える改修で、
  HUD・キャンバス・操作説明の縦積みという骨格から作り直しになる。**次回改修の候補として残す。**

## プロモ動画の音量

下見版は統合ラウドネス −24.7 LUFS・ピーク −6.0 dBFS で、他のDayの −16.6〜−17.1 LUFS より明らかに小さい。
合成段の ffmpeg に `-af loudnorm=I=-17:TP=-1.5:LRA=7` を通した。定数は `LOUDNESS_FILTER` として書き出し、単体テストで固定。
実際の書き出しと聴取はこの回では行っていない。
