## モデル側で変わったこと（実装済み・単体試験135件が通る。変えない）
- **夜1のガイドは、何度出し入れしても星を減らさない**（練習用）。`toggleGuide` は夜1で `usedGuide` を立てない。夜2以降は付けた時点で立てる。従来の画面の文言は、夜1「ガイドを重ねる」（★なし）／夜2以降「ガイドを重ねる（★−1）」のままで合う。
- **ヒント**：`useHint(session)` は `{ index, kind, text }` を返す。`kind` は `'diagnosis'`（いまいちばんずれているものの名指し）、`'principle'`（その夜の考え方）、`'end'`（出し尽くした。`text` は「ヒントはここまで。灯りと道具を、1cmずつ動かして確かめよう。」）。**同じ文を二度出さない**。配置が変わって名指しの文が替わったときは、また名指しを先に出す。`session.hintIndex` は無くなり、`session.shownHints`（出した文）が増えた。
- **近さの文**：`describeAssessment(session)` の `detail` に、「近い」「あと少し」のとき、`'関係ない道具の影が残っている'`／`'灯りの高さがずれている'`／`'道具の横位置がずれている'`／`'ずれている道具がある'` のどれかが入る（夜1・夜2の「近い」では空）。
- **ずれの言葉**：「だいぶ」は10cm以上、「少し」は3〜10cm、「ほんの少し」は3cm未満。
- **しきい値**：夜3・夜4・夜5の合格の下限を下げた（全部が±3cm以内なら大半が合格）。夜1の開始は灯り135cm、夜2は道具ごとの被覆を78%に。
- **推理**：夜4の「踏み台」の手がかりは「犯人は、20cmの踏み台の上に立って灯りを提げた。」だけ（式を書かない）。夜5の容疑者は 日向（178cm）・柊（180cm）・蓮見（188cm。アリバイで外れる）で、日向と柊を、灯りの高さ108cmの正確な読み（106.8cmとの差）で分ける。誤答の理由は、非整数を小数1桁で出す（「106.8cm」「112.8cm」）。

## 依頼内容

### A. モデルの変更に、画面と試験を合わせる（必須）
1. **E2E と画面の文言を、上の変更に合わせて直す。** 期待を消して通さず、新しい仕様の期待に書き換える。直す所の例：ヒントの順序（診断→考え方→考え方→「ここまで」。3回目以降に診断が出る前提の試験）、夜1のガイドの星（出し入れしても星3つ）、夜4の踏み台の手がかりの文、夜5の容疑者とアリバイ（以前の「同じ身長の2人」の試験は夜3だけに）、誤答の理由の小数、夜1の開始の灯り。
2. **遊び方のダイアログ（index.html）**：ガイドの文を「ガイド・ヒント・誤った推理を使うと、星が減ります。夜1のガイドは練習用なので、何度出し入れしても減りません。」に。「灯りは上下、道具は左右」の説明に、「灯りを上げると影は下がり、下げると影は上がります。」を足す。
3. **ヒントの出し方**：`kind: 'end'` のときは、注記に「ヒントN：」を付けず、文だけを出す（番号を振らない）。`kind` が `diagnosis`・`principle` のときは、従来どおり「ヒントN：…」（N は `index + 1`）。
4. **夜1のガイド**：画面の文言は変えずに、夜1で「ガイドを消す→重ねる」を何度繰り返しても、判決が「星3つ（ガイド・ヒント・誤答なし）」になる試験を足す。
5. **近さの文**：`detail` の新しい文が、幅360で `band-text` の1行に収まる（既存の「いちばん長い近さの文が1行に収まる」試験を、新しい最長の文で通す）。

### B. 画面だけで直せる小さな指摘（体験評価 第2周のバグ表より）
6. **B4**：推理画面で「考え方を見る（★−1）」を押したら、出た答え（`#deduction-hint-text`）が画面に入るようにスクロールする（`scrollIntoView({ block: 'nearest' })`。reduced-motion のときは瞬時）。幅390×844の夜1の推理画面で、答えが表示領域に入る試験を足す。
7. **B6**：結末の「星Nつ（ガイドを使った・ヒントを使った・誤った推理があった）」が、語の途中（「誤った推理があ／った」）で割れない。理由ごとを折り返さない範囲（`.nb`）で包み、理由のあいだの「・」で折り返せるようにする。幅360・390で、どの組み合わせでも語の途中で割れないことを試験にする。
8. **B9**：灯りを選んだまま←→を押したとき（道具を選んでいるのに↑↓を押したときも）、何も起きないままにしない。注記の欄に、4秒間だけ「灯りは上下だけ動きます。道具は、上の選ぶ札（←→キー）から選べます。」（道具を選んでいて↑↓のときは「道具は左右だけ動きます。灯りは、上の選ぶ札から選べます。」）を出し、そのあとはコーチ文かヒントに戻す。`#feedback` にも同じ文を出す。キーの試験を足す。ヒントが出ているときは、ヒントの文を消さずに、注記に重ねない（その場合は `#feedback` だけ）。
9. **B5**：夜2以降の「ガイドを重ねる（★−1）」を「ガイド（★−1）」に短くし、幅390×844の夜5でも「ヒント／ガイド／はじめから」が1行に収まるようにする（押したあとの「ガイドを消す」はそのまま。夜1は従来どおり「ガイドを重ねる」）。収まらなければ、収まる文言を選んでよい。
10. **推理画面で外した人の「この人だ」**：判定には使わないままで、見た目を少しだけ控えめにする（外した人のカードの「この人だ」を、枠だけのボタン風に。文字のコントラストは4.5:1以上を保つ）。

### B-2. 星の判定を、入り直しても一貫させる（体験評価 第2周 B2）
11. 夜のガイド・ヒント・誤答・「考え方を見る」の使用を、**解決するまで（ページを開いている間）保つ**。夜を出て（事件簿へ戻る）から同じ夜に入り直しても、使った分は消えない。使った分は、その夜を解決した時点（判決で星を決めたあと）で消す。「進行をリセット」でも消す。保存先は、app.js の中のメモリー（`Map` など）でよい（`localStorage` には書かない。ページを再読み込みすれば消える）。
   - 入り直したとき、画面は初期状態（灯り・道具の位置、ガイドの表示、注記はコーチ文）に戻してよい。ただし、星の計算には、保っている使用歴を使う（`session.usedGuide`・`session.hintsUsed`・`session.shownHints`、`wrongAnswers`、`deductionHintUsed` へ戻す）。ヒントの「次のヒント」の表示や、出したヒントの文のくり返し防止（`shownHints`）も引き継ぐ。
   - 試験：夜4でガイドを使う→事件簿へ→夜4に入り直して補助なしで解く→判決が「星2つ（ガイドを使った）」になる。夜1は、ガイドを出し入れしても使用にならない（A-4）。解決したあと、同じ夜を遊び直すと使用歴が空で始まる。

### D. 画面評価 第2周（15/20・不合格）の指摘（評価書 `visual-r2.md`。必読）
画像の寸法は CSS px。**合格の条件は、すべて自分で測って最終報告に書く。**

12. **幅360×高さ640で、主要操作を最初の画面に収める**（TOP1）。夜1〜4は、「下げる/上げる」が下端から8px以上離れて全部見え、「ヒント／ガイド／はじめから」の行も入ること。夜5も、「下げる/上げる」が全部見えること（「ヒント／ガイド」の行は、入ればよい）。方法は任せる。使ってよい手：①高さ700px以下の画面で、証言ストリップを小さく（スケッチ72×54px程度・引用は隠して「全文を読む」だけ）、②「下げる/上げる」を高さ44pxに、③道具のチップを**1段の横スクロール**にする（段が増えない。右端が切れて続きがあると分かる見た目にし、選んだチップが見えるようにスクロールする。`role=radiogroup`・矢印キーでの移動・`data-item` は保つ）、④それでも足りなければ、壁を高さ約210pxに抑える。**操作列が動かない保証（改修1の合格条件）は保つ**：注記欄の高さは2行分のまま固定（幅360で2行）。
13. **手がかりカードの間隔と本文の幅**（TOP2）。再現室の「現場メモと手がかり」（`#stage-clues`）の手がかりカードを、推理画面の `#deduction-clues` と同じ間隔（8px）にし、枠線が重ならないようにする。幅480px未満では、種類の札（証言・足跡・決まり…）を本文の上に置き、本文をカード幅いっぱいに使う（再現室でも推理画面でも）。幅360で「証言」「足跡」「踏み台」がそれぞれ3行以内に収まること。
14. **外した人のカード**（TOP3）。外した人のカードでは、「この人だ」を枠だけのボタン（`.button-ghost` 相当。文字は4.5:1以上）にし、琥珀の塗りを残さない。「✕ 外した（戻す）」の枠は、他の「外す ✕」と同じ色にする。判定には使わないのは変えない。
15. **壁の目盛り数字**（TOP4）。`lib/view.js` の目盛り数字（150・100・50）を、紙の壁に対して4.5:1以上の濃い色（`--ruler` トークンを `#6B4F2A` 程度に。目盛りの線も同じ）にし、字を12px以上・太さ600にする。縁取りは残す。数字が影・道具・灯りの玉・選択の札と重なって読めなくならない（`placeTag` の避ける対象は、数字の大きさに合わせて広げる）。
16. **画面どうしの左端と、部品の様式**（TOP5）。
    - 幅720px以上で、導入・推理・現場図（幅900px未満）の読む列を、中央寄せをやめ、**ヘッダの左端にそろえて左寄せ**にする（`max-width` は残し、右側だけを絞る）。結末・エピローグは、中央揃えの構図のまま（判子・見出し・星・ボタンを中央に）。幅768で、事件簿・導入・再現室・現場図・推理の最初の要素の左端が同じ x（±1px）、幅1440でも同様。
    - 共有ダイアログ（`shared/share.css` は触らない）：共有ボタン（X・LINE・リンクをコピー・共有…）の枠色・太さを、他の副ボタンと同じ様式に `app.css` から上書きする（`#share .share__button` など）。Instagram・YouTube についての注記の色は、説明文と同じ補助の灰にする。
    - 事件簿の「はじめる →」のピルを、高さ36px以上・文字14pxに（主ボタンより弱く見えないように）。
17. **細部（画面評価）**：
    - 推理の見出し「灯りを提げていたのは、誰か。」を「灯りを提げたのは、誰か。」に変える（2行目が3字だけにならない）。E2E の期待も直す。
    - 補助ボタンとカードの枠色：押せる部品（`.button-secondary`・`.button-ghost`・`.chip`・`.nudge`・`.icon-button`）の枠を `--line-strong`（地に対して3:1以上）にし、輪郭が見えにくい問題を直す（カードの枠は今のままでよい）。
    - 「ガイドを消す」（`aria-pressed="true"` の副ボタン）の朱の枠と暗い赤の塗りをやめ、琥珀の枠・薄い琥珀の塗りに（朱は、取り消せない「リセットする」だけに使う）。壁のガイドの朱とは、色でなく「ガイドを消す」の文字と `aria-pressed` で対応づける。
    - 見た目が小さい押す場所：「全文を読む」は、枠付きの小さなピル（高さ36px以上）に。「はじめから」「進行をリセット」は、枠付きの補助ボタン（高さ44px）に（`#reset-stage`・`#reset-progress` の ID は保つ）。
    - 注記欄は、高さが固定のまま、文を**縦の中央**に置く（1行のとき、下に空きができて見えないように）。
    - 結末とエピローグの判子（`.stamp-holder`）の上下に、ヘッダと小見出しから12px以上離れる余白を足す。
    - 導入のスケッチ（`.witness-card`）：幅560px未満で、スケッチを中央に置く（左に寄って右が空かないように）。
    - 描画できない環境の案内（`#unsupported`）に、「再読み込み」ボタン（`location.reload()`）を足す。E2E の描画不可の試験で、ボタンがあることを確かめる。
    - 遊び方ダイアログ：幅360×高さ640で、最後の段落まで1画面に入るよう、余白と行間を詰める（入らなければ、下端に「↓ 続きがあります」のように、スクロールできると分かる印を出す）。
    - 事件簿の鍵の文言：幅720px以上では、「前の夜を解決すると開く」を1行に（`.case-state` の `max-width` を広げる）。
    - 共有ダイアログのURL欄：幅360でも末尾が見えるよう、URL欄の文字を小さく（11px程度）するか、折り返せる表示にする（入力欄の値は変えない。`#share-url` の ID と `readonly` は保つ）。
    - 「ヒント（★−1）」を押したあとの「次のヒント」：星の払いを書き直さない代わりに、`title`・`aria-label` に「ヒントは最初の1回で星が1つ減ります。2回目以降は追加で減りません」と持たせる（見た目は「次のヒント」のまま）。
