- **Git は一切変えない**（add・commit・push・branch・stash・reset・checkout など）。設計側が行う。`git status`・`git diff` の閲覧だけはよい。
- `rm -rf` は環境が拒否する。ファイルを消すときは `rm -f`、またはそのファイルを空にしない。
- 一時ファイル・画像・ログは、スクラッチパッド配下の**自分専用の固有名のディレクトリ**（例：`<スクラッチパッド>/ui-fix-1/`）へ置く。リポジトリに残さない。リポジトリのファイルへ、ホームディレクトリを含む絶対パスを書かない。
- 依存を足さない。外部フォント・画像・通信なし。CSP は `script-src 'self'; style-src 'self'`：`style="…"` 属性と `<style>` は使えない（CSSOM の `el.style.setProperty()` は使える）。`innerHTML` を使わない。文は `textContent` か DOM API で作る。
- 配信サーバーは Bash の `&` で起こさない（止まる）。`run_in_background: true` で起動するか、スクリプトの中で spawn して終わったら kill する。E2E は自分でサーバーを spawn する作りなので、そのまま動く。
- 画面ロック中は Chromium が落ちることがある。落ちたら WebKit（後述の設定）で回す。

## モデルの最新API（実装済み・単体試験 122 件が通っている。変えない）
- `describeAssessment(session)` → `{ step, label, detail, fills }`。`fills` は4つの目盛りの満ち具合（0〜1の配列、長さ4）。IoU が各段の範囲のどこにあるかで連続して伸びる。成功のときだけ `[1,1,1,1]`。
- `useHint(session)` → `{ index, kind, text }`。押すたびに交互：1回目・3回目…は `kind: 'diagnosis'`（いま、いちばんずれているものの名指し。例「灯りが、だいぶ高い。下げてみよう。」）、2回目・4回目…は `kind: 'principle'`（その夜の考え方）。`index` は何回目か（0から）。画面には「ヒント{index+1}：{text}」と出す。
- `confirmSolve(session)`：灯りと必要な道具を正解へそろえるが、**邪魔な道具（夜5の山高帽・地球儀）は置いた位置のまま残す**（左右が入れ替わらない）。
- 事件簿のデータ：`caseDef.coach`（最初の一言）、`caseDef.coachNoGuide`（夜1だけ。ガイドを消しているときの一言）、`caseDef.showsHeight`（夜1だけ true）。`readingOf(caseDef)` は、夜1だけ「灯り99cm。6割で割ると、身長は165cm。」、夜2以降は「灯りの高さは96cm。これを提げた人の身長は？」（身長は書かない。計算は自分でする）。夜3と夜5は、灯りの高さに合う身長の人が2人いて、アリバイを読まないと決まらない（容疑者カードに同じ身長が2つ並ぶ）。
- `session` の他の項目（`guideOn`・`usedGuide`・`hintsUsed`・`hintIndex`・`selected` など）は従来どおり。`reset` はガイドの表示を変えない（消したままなら消えたまま）。

### A. 再現室の状態欄・注記欄・ヒントの出し方（体験評価 TOP4、画面評価 TOP1）
いまは、最初の操作で指示文（2行）が近さの文（1行）に置き換わり、操作列が約25px動く。ヒントの文は操作列の下に出て、スマホでは画面の外。
- **DOM を次の形にする**（`.stage-main` の中）。
  1. 1行目：`#lamp-readout`（灯りの高さ）と `#item-readout`（選んだ道具の横位置）。幅360でも1行に収まり、`#item-readout` が出入りしても行の高さが変わらない。
  2. 2行目：`#band-text`（近さの文。いつも出す。指示文に置き換えない。左）と `#meter`（右）。
  3. 3行目：新しい **`#note-text`**（`<p>`）。いつも出す。最初は事件のコーチ文、ヒントを押したらそのヒントの文。
- `#hint-text` は廃止（DOM と app.js の参照を消す）。ヒントの文は `#note-text` に、`ヒント{index+1}：{text}` で出す。ヒントを押したあとは、操作・道具の選び替え・ガイドの付け外しをしても消さない。次のヒントを押すか、「はじめから」、夜を出る／入るまで残す。「はじめから」では、ヒントの文を消して、コーチ文へ戻す（`hintsUsed` は戻さない）。
- コーチ文は、`caseDef.guide === 'on' && !session.guideOn && caseDef.coachNoGuide` のとき `coachNoGuide`、それ以外は `caseDef.coach`。ガイドの付け外しで、すぐ切り替わる。`coachVisible` フラグは廃止。
- `#note-text` に `data-kind="coach"` / `"hint"` を付ける。hint は琥珀の左線と面（`.hint-text` の見た目を移す）、coach は同じ余白・同じ枠の大きさで、線と面だけ目立たなくする（種類が変わっても高さが変わらない）。
- 高さの予約：`#band-text` は1行分、`#note-text` は幅720px未満で2行分の `min-height`（コーチ文は幅360で最大2行）。ヒントが3行になる分は伸びてよい。**ヒントの文は、2行に収まる文なら、操作列を動かさない**。
- ≥900px の2列配置と、高さの低い横向き配置にも、`#note-text` の置き場所を作る（状態の下、操作の上）。
- `#meter`：4つの目盛りを、`describeAssessment` の `fills` で**部分的に**満たす。各 `<i>` に CSSOM で `--fill`（0〜1）を入れ、CSS は `transform: scaleX(var(--fill))` の擬似要素で伸ばす（`transition` は短く。reduced-motion は既存の全体規則で止まる）。`data-band`（`far|warm|near|match`）と `aria-label` は従来どおり残す。`match` は4つ満ちて光る（従来の見た目）。`data-band` だけで点灯させる既存の規則は、`fills` ベースに置き換える。
- **合格の条件**：幅 360・390・768・1440 で、`#nudge-minus`・`#nudge-plus`・`#hint`・`#item-select` の上端の位置が、(a)最初のドラッグ／ボタンの前後、(b)チップで別の道具を選んだとき、(c)2行以内のヒントを押したとき、のどれでも 1px 以内で動かない。夜5で `#hint` を押すと、幅390×844で `#note-text` の全文が**スクロールなしで**表示領域に入る。

### H. 数字・単語の途中で行が割れない（画面評価 TOP2）
- 「身長175cm」「身長は165cm。」「壁から260cm」「20cmの踏み台」「廊下の奥の壁」などで、数字や単語の途中で行が割れる。**日本語の語＋数字＋単位を割らない**仕組みを作る。方法は選んでよい：(a) 純関数 `lib/text.js` の `protect(text)`（数字の直前の日本語1文字との間に U+2060 WORD JOINER を入れる等。句読点の直後には入れない＝「。」の後の自然な改行は残す）、(b) 数字と前後1〜2文字を `white-space: nowrap` の `<span>` で包む（DOM API で作る。textContent が変わらないので、E2E の文の一致が崩れない）。(a) を選ぶと E2E の `toHaveText` が壊れるので、テスト側で見えない文字を外す補助を作る。
- 事件簿の文・容疑者カードの肩書（`家政婦・150cm`）・手がかり・現場図の文・結末など、数字を含む動的な文すべてに適用する。`lib/text.js` を作るなら、`tests/text.test.mjs` に例を入れて `tests/index.js` へ足す。
- **合格の条件**（自動で確かめる）：幅 360・390・768・1440 で、全画面（home・briefing・stage・solved・deduction・verdict・epilogue、夜1〜5）の表示文について、「行頭が数字か `cm` か `＝` か `−` の行が無い」「日本語の文字と直後の数字の間で折り返さない」ことを、Range の `getClientRects` などで測る小さなスクリプトで確かめる（結果を最終報告に書く。E2E に入れられるなら入れる）。
