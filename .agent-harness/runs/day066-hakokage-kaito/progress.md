## 決めたこと（理由と捨てた案は 01_rules.md・02_ui*.md）

- ルール：判定は「動いた直後」と「警備員の後」の2回、次の1歩の予告を常に出す。巡回は一直線の道で、端と箱の前で1歩使って向きを変える。出口は宝まで閉じた扉。レーザーは点滅しない。盤は最大8×8。星は par 以内★3・par×1.5以内★2。
- 面：手で骨組みを作り、ソルバーで箱の置き場所と巡回の出だしを総当たりして選んだ（build-levels.mjs --place）。乱数の面は読みにくく使わなかった。
- 検証の基準：依頼の V4「par が変わる」を「解なしか par が増える（箱が助けになる）」に厳しくした。V7 の「出口」は「押し間違うと出られなくなる箱（罠で確認）」の広い意味。通路を文字どおりふさぐ罠は面5・6・8。
- 詰みの検出は押した直後だけ。上限1万状態（全面の詰み状態の最大9164より多い＝取りこぼさない）。Node で最悪44ms（面8）。
- 変異テスト：最初は「巡回の向き＝最後に動いた向き」が生き残った。一直線の道では区別できないと分かり、道を一直線に限って、変異を「予告が箱を見ない」に替えた。
- 画面：型5つと盤のマスを reference/layout.mjs の純粋関数に置いた。`node reference/layout-table.mjs` で、全8面×7つの画面幅で盤（36px以上）と操作が最初の画面に収まり、8px以上余る。色の比は相対輝度（指数2.4）で計算。
- 公開前チェック：`npm run precheck` が exit 0（今回のファイルで漏洩パターンなし）。絶対パス・実名・実在の作品名・絵文字なし（★☆は文字）。
