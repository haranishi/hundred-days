## 対象
スマホ向けの、1手ずつ進む忍び込みパズル。押せる箱で、見張りと警備員の光やレーザーをさえぎり、影を通って宝を取り、出口へ逃げる。全8面。X・LINEから来た人が、主にスマホで遊ぶ前提。
URL: `<BASE>`（依頼文で指定。例 `http://127.0.0.1:4570/day-066-hakokage-kaito/`）。`?level=N`（1〜8）でその面へ直行できる。

## あなたの立場
**忍び込みにも箱を押すパズルにも詳しくない、パズルが好きな普通のスマホユーザー**として遊ぶ。判断の根拠は画面に出ている文字・見た目・ヒントだけ。「これは探索の問題だ」のような専門知識で先回りしない（初見の分かりやすさが測れなくなる）。

## 前提として受け入れる設計判断（覆す提案は不要）
1. 1手ずつ進む。乱数なし。光は直線だけで、画面に見えている光がそのまま判定。次の1歩で光るマスは点線の枠（予告）。
2. 警備員は一直線の道を往復し、道の端と箱の前では1手使って向きを変える。見張りはその場で向きを変える（面4・8は4方向に回る）。
3. 箱は押すだけ（引けない・2つ並びは押せない）。出口は宝を取るまで閉じた扉。「最初へ」は確認なしで、「ひとつ戻す」で取り消せる。
4. 操作は十字ボタンとキーだけ。盤のタップ・スワイプは無い。結果の欄は十字ボタンの場所に出る（窓ではない）。
5. 星は最少手数（目安の手数）が基準。同じ面で2回失敗すると「お手本」（最短の手順の自動再生）が出る。見ても星は減らない。
6. 暗い配色だけ。絵文字なし。全8面を最初から選べる。
7. 予告は、箱を動かさずに待った場合の次の光。その手で箱を押したときだけ、遮光・巡回が変わるため、予告と結果が違うことがある（仕様）。
上記以外（説明の量、文言、ヒント、演出、結果の見せ方、操作の手数、面の並びなど）は**評価・提案の対象**。減点対象は「原因が分からない失敗」「操作不能・詰み」「表示と判定の矛盾」「単調・情報過多・理不尽」。

## 操作ツール（時計を止められるプレイテスト用サーバー）
LLMの操作は1手ごとに数秒かかるので、**ゲーム内の時計を止めておき、「人間がその操作に要したはずの秒数」だけ進める**道具を用意した。クリックは座標で本物のヒットテストを通す（重なり・押しにくさ・誤タップはそのまま再現される）。

起動（Bashを `run_in_background: true` で）:
```
cd <REPO>/.agent-harness/runs/day066-hakokage-kaito && node tools/playtest-server.mjs --out=<R>/experience-shots --port=<PORT> --base=<BASE>
```
`<REPO>`・`<R>`・`<PORT>`・`<BASE>` は依頼文で指定する。起動後 `curl -s localhost:<PORT>/state` が返れば準備完了。

| 操作 | コマンド |
|---|---|
| 今の画面の見えている文字と、押せる部品の一覧（中心座標・大きさ付き） | `curl -s localhost:PORT/state` |
| スクショを撮る（`full=1`で縦に全部） | `curl -s "localhost:PORT/shot?name=s1-start"` → 返ってきた `path` を Read で見る |
| タップ/クリック（座標かテキスト） | `curl -s -X POST localhost:PORT/click -d '{"x":195,"y":588}'` または `-d '{"text":"待つ"}'` |
| キー操作 | `curl -s -X POST localhost:PORT/press -d '{"key":"ArrowRight"}'` |
| **手の列をまとめて押す** | `curl -s -X POST localhost:PORT/moves -d '{"seq":"LLDRR","gapMs":300}'`（U上 D下 L左 R右 `.`待つ z戻す r最初へ。見つかる・詰む・成功したら、そこで止まって知らせる） |
| マウスを載せる | `curl -s -X POST localhost:PORT/hover -d '{"x":300,"y":400}'` |
| スクロール | `curl -s -X POST localhost:PORT/scroll -d '{"dy":300}'` |
| **ゲーム内時間を進める（ミリ秒）** | `curl -s -X POST localhost:PORT/advance -d '{"ms":400}'` |
| 最初からやり直す（幅・面・動きの設定を変えられる） | `curl -s -X POST localhost:PORT/restart -d '{"width":1440,"height":900,"level":8,"keep":true,"reduced":false}'` |
| 起きたエラー・警告・ブラウザの警告ダイアログの記録 | `curl -s localhost:PORT/events` |

- 起動直後は時計が止まっている。**タップした後は `/advance`（300〜400ms）を呼んで、動きを終わらせてから**スクショを撮る。`/moves` は1手ごとに自分で時計を進める。
- `/restart` の `keep: true` は、星や音の設定を引き継ぐ（保存の確認用）。付けなければ初回の状態になる。`level` で面に直行する。`reduced: true` で「動きを減らす」設定。
- **`/moves` は人が数手先まで考えて続けて押すのと同じ使い方**に限る。最初の2面は十字ボタンのタップ（`/click`）で遊び、押しやすさを測ること。`/moves` は盤のタップではなくキー入力なので、十字ボタンの評価には使えない。
- 考える時間は実時間の制限ではない（このゲームに制限時間はない）。ただし**1つの判断に要した体感の秒数**を、毎回見積もって記録する。
- 音は聞こえない。音の評価は「未確認」と書き、減点も加点もしない。
- 起動に失敗する・応答しないときは、ツールの不具合として報告し、`mcp__chrome-devtools__*` か `mcp__claude-in-chrome__*` で代替してよい（その旨を評価書に書く）。

## 遊び方（必須のパス）
各パスで**毎回、スクショを撮り、画面を見てから次の操作を決める**（スクリプトで一気に流さない）。

1. **P1 初見（390×844）**: 説明を読まずに面1から始める。面1→面2→…と、解けるところまで進める。面ごとに「画面を見て何が分かったか／何を操作したか／何が起きたか／試行回数／かかった体感秒数」を記録する。解けない面は「解けなかった」と正直に書く。面1と面2は十字ボタンのタップで。
2. **P2 わざと見つかる**: 面1で光の中へ歩いて入る／光を止めている箱を押してどかす、面4・面5で警備員や見張りの動きに合わせて見つかる。**原因の文と二重の枠だけで次の手が分かるか**を判定。同じ面で2回見つかって「お手本」を出し、反映→最後まで見る。タップ数と体感時間を測る。
3. **P3 詰み**: 面3で箱をレーザーの真下へ落とし（右へ4回・下へ2回）「もう出られない」が出るか。面6で箱を出口に近い穴へまっすぐ押し上げた場合も。詰みの欄の文で、何を直せばいいか分かるか。
4. **P4 企画の反証を確かめる**（下の表）。
5. **P5 終盤**: 面7・面8を解く。何回で解けたか、どこで詰まったか、お手本に頼ったか、星を取れたか。面6と比べた難しさも書く。
6. **P6 PC幅（1440×900）と横向き（844×390）**: `/restart` で幅を変え、面1と面8。レイアウト、押しやすさ、盤と操作の並び。
7. **P7 キーボード**: 面1を矢印・Space・Z・Rだけでクリアする。Tab の順とフォーカスの見え方。あそびかたの「文字のキー」の切替を外すと、W・Z・Rが効かず、矢印は効くこと。
8. **P8 動きを減らす**: `/restart` に `"reduced":true`。面1で、動き・点滅・揺れが止まるか。情報は欠けないか。
9. **P9 保存**: 面1〜2をクリア→`/restart` に `"keep":true`→面の一覧に星と記録が付いているか。音を切って、再読み込み後も切れたままか。

実プレイしていない項目は「未確認」と書き、勝手に満点・減点しない。

### 企画の反証を実プレイで確かめる（P4）
| 反証 | 確かめ方 | 合格の目安 |
|---|---|---|
| ① 箱を押さずに抜けられる | 面1・面3で、箱に触らずに宝へ行こうとする | 光が切れ目なく塞いでいて、押さずには宝へ行けない |
| ② 警備員の視野が予測できず失敗が理不尽 | 見つかるたびに「点線の予告を見ていれば避けられたか」を記録する | 避けられた回数／見つかった回数を数字で書く。理不尽と感じた場面があれば、その画面と理由 |
| ③ 箱が三つの役割を持てない | 面2で交わるマスに箱を置き、2本とも止まるか／面5で道の端に箱を落とし、警備員が手前で引き返すか／面3で箱を真下のレーザーへ落とすと「もう出られない」が出るか／面7で1つの箱がレーザーと警備員の両方を止めたと感じたか | 3つの役割を、自分の手で確かめられた |
| 「片方を外しても同じ面白さ」ではないか | 箱を押す楽しさと、光を避ける楽しさの、どちらか一方だけで遊べてしまう面がないか | 一方だけでは解けない面を挙げる |

## 評価者の掟
