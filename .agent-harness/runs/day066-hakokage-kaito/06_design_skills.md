# デザイン系スキルの使いどころ

本人が最近入れたデザイン系スキル（`design:` の7本）を、下の表の場所で使う。
使ったら「使った／手で再現した」「出した表」「直した数」を記録する。使ったふりは書かない。
Skill ツールで呼べないときは、そのスキルの枠組み（見出しの順・表の列）を自分で再現し、「手で再現した」と書く。

| 工程 | 担当 | スキル | やること | 残す証拠 |
|---|---|---|---|---|
| 設計・文言 | 設計Opus | `design:ux-copy` | 02_ui_text.md の全文言を点検する。ボタンは結果が分かる言い方／失敗や詰みは「何が起きた＋なぜ＋次にどうする」／同じものは同じ言葉／日本語は短く | 直した文言の数と前後 |
| 設計・仕様 | 設計Opus | `design:design-handoff` | 02_ui*.md を引き渡し仕様の型で見直す。状態の表（通常・押している・無効・フォーカス・失敗中）、動きの表（長さ・イージング・動きを減らす設定のときの代わり）、端の場合（長い文・小さい画面・横向き）、フォーカス順・ARIA・キーボード | 足した項目の数 |
| 設計・部品 | 設計Opus | `design:design-system`（document / extend） | 色・間隔・文字・影・動きをトークンの表にし、部品（十字ボタン・帯・窓・カード）ごとに状態を書く。02_ui_style.md に足りない所だけ足す | トークン表 |
| 設計・点検 | 設計Opus | `design:accessibility-review` | 仕様の段階で点検する。コントラスト表、タッチの大きさ、キーボード操作、フォーカス表示、画面読み上げ、動きを減らす設定、拡大200% | 点検表と直した数 |
| 実装の最後 | 実装Sonnet | `design:accessibility-review` | できあがったページに同じ点検を当てる。実測で示す（getComputedStyle、getBoundingClientRect、キーボードだけで1面クリア、拡大200%のスクショ） | 点検表（Critical 0 件） |
| 実装の最後 | 実装Sonnet | `design:design-system`（audit） | CSS の直書きの値（:root の外の色、決めた段階にない px）を数え、トークンを使うよう直す | 数と直した数 |
| 見た目評価 | 評価Opus | `design:design-critique` | 各画面（タイトル・遊ぶ・クリア・失敗・窓）を 390×844 と 1440×900 で講評する。第一印象・使いやすさ・視線の順・一貫性・アクセシビリティ。10項目の採点に足す（置き換えない） | 講評の表と優先3つ |
| 見た目評価 | 評価Opus | `design:accessibility-review` | 実ページで点検する。Critical が残るなら合格にしない | 点検表 |
| 体験評価 | 評価Opus | `design:user-research`（型だけ） | 遊んだ記録を使いやすさテストの形で出す。課題ごとの成功・つまずき・時間・声 | 表 |
| 周回の整理 | 発注側 | `design:research-synthesis` | 複数周の指摘を「繰り返し・新しい・直った」に分け、本人に返す要点だけにまとめる | 要点 |

## 守ること
- 文言は 02_ui_text.md が正。スキルが提案しても、02_ui_text.md に反映してから実装する。実装者が文言を作らない。
- 英語のスキルが出す提案は、日本語の画面で成り立つ形（長さ・敬体・用語）に直す。実在商標・他作品名を出さない。
- スキルの出力は参考。合否は 03_gates.md の試験と、評価の点数で決める。
- このファイルや記録に、スキルの置き場所（ローカルの絶対パス）を書かない。
