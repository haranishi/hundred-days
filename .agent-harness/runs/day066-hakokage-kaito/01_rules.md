# ルール（正は reference/sim.mjs。これは読みやすい要約と、決めた理由）

## 盤

- 横8×縦8マスまで。盤の外は壁。面データの文字：`#` 壁／`.` 床／`P` 怪盗の出発点／`B` 箱／`T` 宝／`E` 出口。
- 出口は盤の外周に置く扉。宝を取るまでは閉じていて、壁と同じ（入れない・箱も入らない）。宝を取ると開き、入ると成功。光は出口で止まる。
- 宝の上は光が通る。宝を取るまで、箱は宝のマスに入れない。取った後は普通の床。
- 座標は [x, y]（左上が [0, 0]）。向きは U 上／R 右／D 下／L 左。待つは `.`。手順は文字列（例 `RRU.L`）。

## 1手の順序（act）

1. 怪盗が上下左右に1マス動くか、その場で待つ。
2. 進む先に箱があれば押す。押せるのは、その先が床（壁・出口・未取得の宝・箱・警備員のどれでもない）のときだけ。引けない。2つ並びは押せない。
3. 動けない手（盤の端・壁・閉じた出口・警備員・押せない箱）は無効。手数も時間も進まない。画面では「ぶつかる」動きだけ出す。
4. 宝のマスに入ったら宝を取る。宝を持って出口に入ったら、その時点で成功（警備員は動かない）。
5. 判定A：その時点の光が怪盗のマスに当たっていたら見つかる。
6. 警備員が全員同時に1歩（下の「警備員」）。
7. 判定B：その時点の光が怪盗のマスに当たっていたら見つかる。
8. 待つ手では判定Aを飛ばす（何も動いていないので、前の手の判定Bと同じ）。

## 光と影

- 光は光源の隣のマスから、向いている方へまっすぐ進む。止めるのは壁・出口・箱だけ。警備員・宝・怪盗では止まらない。
- 光源は2種類。警備員（向いている方へ）と、レーザー（壁のマスから決まった向きへ。いつも点いている）。
- 影＝箱に止められた光の、箱の向こう側（壁・出口・盤の端まで）。ほかの光が当たるマスは影にしない。影は描画のためのもので、判定は光だけで行う。

## 警備員

- 巡回（patrol）：横か縦の一直線の道を往復する。いつも進む向きを向く。道の端では、来た向きのまま前を見る。
  - 次のマスが道の外なら、その場で向きを変える（1歩使う）。
  - 次のマスに箱があれば、その場で引き返す（1歩使う）。箱が巡回を変える仕組みはこれだけ。
- 見張り（watch）：その場で `looks` の向きを順に向く（1歩に1つ）。`looks` が1つなら動かない。
- 警備員のマスには、怪盗も箱も入れない。警備員どうしの道は重ならない（面データの検査で止める）。
- 画面の呼び名は種類で分ける：見張り（watch）は「見張り」、巡回（patrol）は「警備員」（02_ui_text.md）。この文書の「警備員」は両方をまとめた呼び名。

## 次の1歩の予告（preview）

- 怪盗が「待つ」としたら、警備員がどう動き、どこが光るか。画面の点線はこれを描く。
- 予告と結果が食い違うのは、怪盗がその手で箱を押したときだけ：箱の位置が変わるので、遮光・巡回が予告と変わる（箱をどかすと光が戻る。箱を警備員の次のマスへ押すと、警備員はその箱の前で引き返す）。

## 勝敗・星・詰み

- 成功：宝を持って出口に入る。失敗：見つかる。失敗の後は「ひとつ戻す」か「最初へ」（画面の言葉は 02_ui_text.md）。
- 手数＝成功までに進めた手の数（無効な手は数えない。戻した手は消える）。
- 星：手数が par 以内で★3、par×1.5（切り上げ）以内で★2、それ以外の成功は★1。見つかった回数・ヒント・お手本を見たかは数えない。
- 詰み：箱を押した直後に `canWin(level, state)`（上限 `DEAD_CHECK_LIMIT`＝1万状態）を調べ、`'dead'` なら「この箱の位置では、もう出られない」を出す。`'unknown'` は何も出さない。詰んだ状態から行ける先は詰んだ状態だけなので、上限が面の詰み状態の総数（最大は面8の9164）を超えていれば、詰みは必ず見つかる（verify が確かめる）。

## 見つかった理由（caught.reason）

| reason | いつ | 判定 |
|---|---|---|
| walked-in | 光っているマスへ自分から入った | A |
| uncovered | 光を止めていた箱を押してどかし、元の箱のマスに入った自分に光が届いた | A |
| guard-move | 警備員が1歩進み、光が自分に届いた（一直線の道では起きない。前へ進むと光は短くなるだけ。念のため残す） | B |
| guard-turn | 巡回が道の端で向きを変え、光が自分に届いた | B |
| guard-turn-box | 巡回が箱の前で引き返し、光が自分に届いた | B |
| guard-rotate | 見張りが向きを変え、光が自分に届いた | B |

同じ瞬間に複数の光が当たるときは、警備員（番号順）→レーザー（番号順）の最初の1つを原因にする。

## 細部の例

| 場面 | 結果 |
|---|---|
| 箱を光の中へ押す。押した後の自分のマスは箱の影 | 見つからない |
| 光の向き（光源の方）へ箱を押していく | 自分はずっと箱の影にいる（光源へ近づくほど影は長くなる） |
| 光を止めていた箱を、光の線の外へ押す | 自分が元の箱のマスに入り、見つかる（uncovered） |
| 巡回の次のマスへ箱を押す | その手で警備員は引き返す（予告では進むはずだった） |
| 巡回が道の端に着いた次の手 | その場で向きを変える。端の1マス先は、着いた手と次の手の2回照らされる |
| 4方向の見張り | 同じ線のマスは4歩に1回照らされる。入って出るには2回続けて暗い必要がある |
| 宝のマスが光っている | 入ると、宝は取れるがその手で見つかる |
| 閉じた出口へ動く | 無効（手数も時間も進まない） |
| 宝を持って出口に入る | 成功。その手で警備員は動かない |

## 決めたことと捨てた案

- ターン制・乱数なし・光は直線だけ：反証②「視野が予測できない」を潰すため。捨てた案：扇形の視野（端のマスで判定が揺れる）。
- 判定を2回（動いた直後と警備員の後）：見えている光＝判定。捨てた案：警備員の後だけ（光の中を素通りできてしまう）。
- 巡回の道は一直線、向きは進む向き：予告の光と、実際に来る警備員が一致し、すれ違いも起きない。捨てた案：L字の道（角でどちらを向くかが読めない。変異テストでも、一直線なら「最後に動いた向き」と区別できないと分かった）。
- 向きを変えるのに1歩使う：箱の前で止まって引き返す瞬間が目に見える。捨てた案：同じ手で反転して進む（変化が一瞬で読めない）。
- 出口は宝まで閉じる扉：宝なしで出口に乗る迷いをなくす。捨てた案：いつも開いた床。
- レーザーは点滅しない：時間で変わる光は警備員だけにして、予告の描き方を1種類にする。
- 警備員は光を止めない：「光を止めるのは壁と扉と箱だけ」と一言で言える。
- 盤は最大8×8：スマホ縦で1マス36px以上と十字ボタンを両立させるため（依頼の縦10マスから縮めた）。
- 検証の世界（sim.mjs の world）：V4 の「箱が巡回に効かない」は「警備員が箱をすり抜ける」で作る。配信では NORMAL だけを使う。
