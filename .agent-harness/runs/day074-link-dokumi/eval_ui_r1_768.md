# 画面評価 r1・幅768px（画像のみで採点）

- 評価の対象：指示書に挙がった14枚（idle 3・checking 1・result-danger 3・result-ok 2・owner 2・failed-429 1・how 2）。各1回だけ開き、コードは見ていない。
- 採点の範囲：この幅（768px）での見え方だけ。px の値はすべて画像からの目測。

## 結論

合計 **17/20点、0点の項目なし**。合格の線（16点以上かつ0点なし）は越えている。
1点にとどまったのは「タイポグラフィ」「幅への適応」「CTA・導線」の3項目。いちばん効く直しは、全画面に出ている不自然な折り返しと、見本カードでURLが語の途中で割れる点（H1・H2）。

## 撮影の疑い・画像の範囲外（実装の不具合とは断定しない）

1. 背景のむら：idle-768-2 の下部と idle-768-3 の中ほどに白っぽい斑がある。和紙の地紋か描画のむらか、画像では区別できない。
2. 見出し下の区切り線（idle-768-1、checking-768-1）が右へ薄れ、カードの右端より手前で消えて見える。意図したぼかしなら問題ない。
3. checking-768-1 の題名が初期画面より小さい（約56px→約38px）。調べている間だけ見出しを縮める設計なら問題ない。回転記号が途中の形なのは、動きを止めて撮った都合（前提どおり）。
4. 結果の画像（result-danger・result-ok・failed-429）は結果の欄から撮られている。ヘッダーや入力欄との位置関係、結果より上にある操作は範囲外。
5. 相談先と外部の診断サービスの欄が、どの結果画像にも写っていない（result-danger-768-3 は「見ていないこと」の途中で終わる）。「相談先を外部サービスより上に置く」前提は、この幅では確かめられなかった。
6. how-768-1 は見出しから始まり、3つの札の選択中表示は写っていない。owner-768-1 も切り替え部品から始まるため、判定の帯との位置関係は範囲外。

## 改善指示（全部・優先度つき）

### 高

- **H1 不自然な折り返しをなくす（全画面の本文と見出し）**：本文と見出しに `word-break: auto-phrase`（文節で改行する指定。`<html lang="ja">` が前提で、効くのは Chrome 系だけ）を付ける。Safari 向けには BudouX などで文節の境目に改行候補を入れる。最終行が1〜2字になる箇所は `text-wrap: pretty` で抑える。直す例：idle-768-1「サイ／ト」、idle-768-2 右カード「示しま／す。」「意／味」「なりすま／し」と左側「送／り先」、idle-768-3 と how-768-1「短／縮URL」「先／頭」「開い／た」、result-danger-768-2「読めま／す。」、result-ok-768-1「付け／られます」、result-ok-768-2「読め／ます。」「し／ません。」「していま／す。」、owner-768-1「評価で／す。」「止ま／って」、how-768-1・2「しませ／ん。」、how-768-2「時間切／れ」「段階／にはしない」「と／は限りません」、failed-429-768-1「こ／のまま」。
- **H2 見本カードのURLを1行で見せる（idle-768-2）**：3列で1枚約238pxのため、「https://www.amazon.co.jp.a／ccount-／check.example/signin」「https://www.well-／kept.example/」と語の途中やハイフンで割れる。ハイフンが改行の印に見え、持ち主の名前（登録ドメイン）の位置も読めない。このアプリが教えたい読み方を、見本が邪魔している。900px未満では見本カードを1列（横長）にしてURLを1行に収める。折り返すなら「.」「/」の直後だけに改行候補（`<wbr>`）を入れ、語の途中では切らない。結果画面と同じく、登録ドメインの部分を太字＋下線にする。
- **H3 回数上限の画面に再試行ボタン（failed-429-768-1）**：お知らせ枠の直下に「もう一度調べる」を置く。待つ間は「あと45秒」のように残りを出して押せない状態にし、時間が来たら押せるようにする。
- **H4 行動3から相談先へ直接行けるようにする（result-danger-768-1）**：「入力済みなら公式の相談先へ連絡してください」のカードを、相談先の欄へのページ内リンクにする（「相談先を見る ↓」）。または、相談先の欄にある主な窓口を1〜2件、このカードの中に電話番号つきで出す。

### 中

- **M1 「点」の意味をそろえる**：訪問者向けの「+9点」（result-danger-768-2・3）は疑わしさの加点で、運営者向けの100点満点（高いほど良い）と向きが逆。訪問者向けは「疑わしさ +9」のように別の言葉にする。運営者向けは、上の一覧「先に付けると点が戻るもの」の「+40点」と詳細の「−40点」（owner-768-1）を、どちらも「直すと +40点」にそろえる。
- **M2 点線は見本だけに使う（failed-429-768-1）**：回数上限のお知らせ枠を、実線か、左に太線を引く型（owner-768-1 の注意書きと同じ型）に変える。
- **M3 「段階」は訪問者向けだけの言葉にする**：運営者向けの「段階 F（15点）」（result-danger-768-2 の切り替え部品）、点数カードの「段階 F」（owner-768-1）、「段階の目安」を、「評価 F」「評価の目安」に言い換える。
- **M4 下の3つの札に選択中の表示（idle-768-3「しくみと限界／サイト運営者の方へ／プライバシー」）**：下に「しくみと限界」の中身が出ているのに、3つとも同じ見た目。タブなら、選ばれた札を墨の塗り＋白文字にし、読み上げにも選択中と伝える。ページ内の目次なら、札の下の区切り線をやめ、タブに見えない形にする。
- **M5 見本カードに押せる印（idle-768-2）**：点線の箱に文字があるだけで、ボタンに見えない。各カードの下に「この見本で試す ›」を置き、カード全体を押せる範囲にして、押したときの見た目の変化も付ける。
- **M6 誰の回数上限かを先に書く（failed-429-768-1）**：「つながらなかったので」「つながりませんでした（回数の上限）」は、相手のサイトにつながらなかったように読める。「このツールの回数の上限（1分あたり12回）に達したため、相手のサイトには問い合わせていません」のように書き直す。
- **M7 証拠の値にラベルを付ける（owner-768-1・2「見えたこと」）**：「http://old-shop.example/」「connect_failed」の灰色の枠の前に「最後に応答したアドレス」「HTTPSを試した結果」などの小見出しを付ける。本文の「HTTPSの接続もできませんでした。つながりませんでした。」は「HTTPSで接続を試しましたが、つながりませんでした。」の1文にまとめる。
- **M8 長文の1行を短くする（idle-768-1 の説明文、idle-768-3 と how-768-1・2 の「しくみと限界」）**：1行約43〜45字。文章のかたまりだけに最大幅（約38〜40字。例 `max-width: 40em`）を付け、カード類は今の幅のままにする。
- **M9 小さな灰色文字を大きく・濃く**：「重大度 高」（result-danger-768-2・3）、「訪問者向けの判定」（各結果の1枚目）、段階の物差しの文字、「（見本・実在しないサイトです）」（idle-768-2）は12〜13px。意味を持つラベルは14px以上にし、地とのコントラスト比4.5:1以上を実測で確かめる。
- **M10 2列カードの折り返し（idle-768-2「訪問者向け／運営者向け」）**：1枚約360pxで、右カードの改行3か所がすべて語の途中。H1 を当てても不自然なら、900px未満は1列にする。

### 低

- **L1 節見出しのジャンプ率**：「いま取る行動」「たどった経路」「見つかった兆候」（result-danger-768-1・2）を約17px→20px前後に上げるか、見出しの上の余白を広げて節の切れ目をはっきりさせる。
- **L2 左右の余白**：600px以上では左右16px→24〜32pxに広げる（全画面）。
- **L3 番号の丸の型**：idle-768-2「調べる3つのこと」は線の丸＋明朝の数字、結果の「いま取る行動」は墨で塗った丸＋ゴシックの数字。役割で分けるなら、その使い分けを他の番号付きの並びでも守る。
- **L4 行動が1件なら番号を付けない**（result-ok-768-1「いま取る行動」）。
- **L5 「4つの段階で示します」の横に記号が5つ（idle-768-2 左カード）**：「4つの段階で示します（調べきれなかったときは「不明」）」とし、不明の行の前に細い区切りを入れる。
- **L6 「安全の保証ではありません」の置き場所をそろえる**：result-danger-768-1 と failed-429-768-1 は帯の最下段（時刻の行）、result-ok-768-1 は見出しの直下。どちらかに統一する。result-ok では同じ文が帯の中、切り替えの下、「見ていないこと」の中と3回出る（result-ok-768-1・2）。帯の中の1回は前提どおり残し、切り替えの下の1回は削る。
- **L7 優先度と減点の筋（owner-768-2）**：「既知の弱点があるバージョン」が優先度 中・−12点、「開発元の保守が終わったバージョン」が優先度 高・−10点で、中のほうが減点が大きい。対応を見直すか、並び順の決まりを一覧の上に一言書く。また、最優先と高が同じ黄土色で、黄土は訪問者向けの「気になる」の色でもある。運営者向けの優先度は墨の濃淡で分ける。
- **L8 運営者向け一覧の濃い枠（owner-768-1「先に付けると点が戻るもの」の3件）**：押せるボタンに見えるのに印がない。押すと詳細へ移るなら「›」を付け、押せないなら枠を他のカードと同じ薄い色にする。
- **L9 専門語の前に言葉を置く**：「200 応答あり」（result-danger-768-2、result-ok-768-1・2）→「ページが表示されました（応答200）」。「64KiB」「公開DNS」「応答ヘッダー」（idle-768-3、how-768-1）にも平易な言い換えを先に置く。訪問者向けの「見ていないこと」に出る CSP・script-src・default-src の項目（result-ok-768-2）は、運営者向けの側だけに出す。
- **L10 「見本」札の位置**（result-danger-768-2、result-ok-768-1 の「たどった経路」）：見出しの下に札だけの行ができる。見出しと同じ行の右に置く。
- **L11 調べている途中の画面（checking-768-1）**：「・「?」から後ろは送っていません」の先頭の「・」を外す。手順リストの記号の列を上のカードの線にそろえるか、手順リストもカードに入れる。止める手段が1画面目に見えないので、「やめる」を「調べています」カードの中に置く（下にあるなら上へ移す）。
- **L12 入力欄の下の三角記号（idle-768-1「一度しか使えないリンク」）**：段階「注意」と同じ形なので、別の形の記号にする。
- **L13 お椀の黒（checking-768-1、各結果の1枚目）**：画面で唯一の真っ黒なかたまりで、目が引っぱられる。文字と同じ紺寄りの墨色に寄せ、光沢を弱める。好みの範囲。
- **L14 Enter の案内（idle-768-1「Enterで調べる・Shift＋Enterで改行」）**：768px は指で操作するタブレットが多い。`@media (hover: none)` では隠すか、小さくする。
- **L15 「良かった点」カードの「良い点」ラベル（result-ok-768-2）**：見出しと重なる。省くか、根拠の値（例：登録日）に替える。
- **L16 括弧の幅（各結果の1枚目の時刻の行）**：「22日(木) 19:38（日本時間）」で半角と全角が混ざって見える。曜日の括弧も全角にそろえる。

## 採点外の気づき（本人の確認を勧める）

- 見本1のURLに実在企業の名前（amazon）が入っている（idle-768-2、result-danger-768-1・2）。末尾が予約済みの .example なので実在のサイトではないが、「公式そっくり」の偽物の例に実在のブランドを使う形になる。過去のDayで「公開面に実在の商標を出さない」とした前例があるので、架空のブランド名に替える案を出しておく。法的な判断ではない。
- checking-768-1 と failed-429-768-1 の「parcel-notice.jp」は .example ではなく .jp。実在する名前なら、撮影画像やプロモで偽の宅配通知の例として出したとき、その持ち主を怪しく見せるおそれがある。撮影用には .example や .test の名前を使う案。
