## 撮影の疑い（実装の不具合とは断定しない）

1. **画像どうしの重なり。** 2枚目以降の上端に、前の画像の下端と同じ内容が約135px写っている（idle-768-2 の上端「設定では送りません。」、result-danger-768-2 の上端の行動1・2、owner-768-2 の上端「優先度 最優先 減点 40」）。スクロール量が画像の高さより小さかったためと見られ、ページの不具合ではない。
2. **checking-768-1 の回る印が円弧の途中で止まっている**（「つなぐ・転送先をたどる」の行）。動きを止めて撮るという前提どおり。
3. **背景の淡いむら。** 地の暖かい白に淡い濃淡が見える。和紙の質感として意図したものか、固定の背景が各画像に焼き込まれたものかは画像から決められない。文字の読みやすさへの影響はない。
4. **フォーカスの枠はどの画像にも写っていない。** フォーカスを当てて撮っていないためで、有無は判断できない。

## 改善指示（優先度つき・全部）

### 優先度 高（見た目の不具合と、誤解を招く文言）

1. **owner-768-2「残り11件を表示」の上に余白を足す。** すぐ上のカード「開発元の保守が終わったバージョンの表示があります」の下の線とほぼ接している。上の余白を16px前後（カード同士の約8pxより広く）にして、カードの続きではなく一覧の操作だと分かるようにする。
2. **failed-429-768-1「たどった経路」の右上「つながりませんでした」を、起きたことに合わせる。** 帯の中では「相手のサイトには問い合わせていません」と言っている。ここも「問い合わせていません（回数の上限）」のように同じ事実を書く。今のままだと、相手のサイトが落ちているように読める。
3. **idle-768-2「調べる3つのこと」1の説明で「短縮URL」を切らない。** 「短縮URL」を改行しないまとまりにする。how-768-1 の同じ内容は「短縮URL」が切れずに出ているので、そちらと同じ扱いにする。
4. **result-danger-768-3 の兆候の札「兆候 +9」の数字の意味をはっきりさせる。** すぐ上の「見つかった兆候 9件」やタブの「兆候 9件」と同じ形で数字が並び、「この項目に兆候が9つある」とも読める。単位を付ける（例：「強さ +9点」）か、運営者側の「減点 40」と同じ形の言い方にそろえる。

### 優先度 中

5. idle-768-2「この見本で試す ›」の高さを約33pxから44px以上にする（上下の内側の余白を増やす）。768pxは指で押す端末が多い幅なので、見本カード全体を押せる範囲にしてもよい。
6. idle-768-3「このページの説明」の3つの文字リンク（しくみと限界 ↓／サイト運営者の方へ ↓／プライバシー ↓）に上下の余白を足し、押せる高さを44px近くにする。result-danger-768-2「相談先を見る ↓」、owner-768-1「点数と評価の付け方を見る ↓」も同じ。
7. 句の途中の折返しを直す：idle-768-1「「?」 / から後ろ」、how-768-1「送り先・ / 読み込むファイル」（行末が「・」）、how-768-2「その / 場合は」、owner-768-1 と owner-768-2「（http:// / では応答がありました）」。切れているまとまりを、改行しない単位にする。
8. result-danger-768-1・result-ok-768-1「調べた相手」の説明「色の付いた部分が、このアドレスの持ち主の名前です」を「太字で色を付けた部分が…」に替える。見た目はすでに太字なので、言葉を直すだけで色の見分けに頼らなくなる。
9. idle-768-3 の凡例（見つからない・気になる・注意・近づかない）を、カードの幅いっぱいに4等分して並べる。今は左3/4に寄り、右側が空いている。
10. result-danger-768-1 で「いま取る行動」を、コピーの3ボタンより上（帯のすぐ下）へ移すことを考える。近づかない判定のとき最初にすべきことは「リンクを開かず公式の窓口から確かめる」で、コピーはその後になる。「家族に送る要約をコピー」を塗りで強調するのは残してよい。設計上の意図があるなら今のままでもよい。
11. failed-429-768-1 の帯は「アドレスの見た目だけで判断しています」と書いているのに、見た目で何が分かったかが1画面目にない。checking-768-1 の「見た目で目立つ点はありません」のような一言を帯の中に添える。

### 優先度 低（磨き）

12. 番号の丸を1種類にそろえる。idle-768-2 は明朝の数字に線の丸、result-danger-768-1・2 はゴシックの数字に墨塗りの丸。説明の番号と行動の番号を分けるつもりなら、その区別をほかの画面でも守る。
13. ボタンの型を整理する。今は、墨塗り（調べる）、白地に線（結果をコピー・やめる・残り11件を表示）、生成り地に線（公式のページを開く・電話する）、丸い札形（この見本で試す ›）、灰青塗り（もう一度調べる）の5種類。白地と生成り地の差は小さく、規則が読み取りにくい。外へ出るボタンには外部を示す印（↗）を付けて、地色の差に頼らないようにする。
14. idle-768-2 の見本カードのURL行と、result-danger-768-3・result-ok-768-2 の「最後のページ」の完全なURL行（どちらも約12pxの等幅）を、13〜14pxに上げる。
15. owner-768-1 の注意書き（墨の太い左線の囲み）は、太字の1文「点数が低くても、危険なサイトという意味ではありません。」の後で改行し、残りを次の段落にする。今は1行目が「設定の」で早く折れ、2行目が長く、右端の凸凹が目立つ。
16. idle-768-1 の注記の先頭の印「①」は、手順の番号に見える。「一度しか使えないリンク」を表したいなら、注意の印にするか、「1回」と文字で示す。
17. failed-429-768-1「もう一度調べる（あと40秒）」は灰青の塗りで、押せるボタンに見える。待っている間は線だけの見た目にするか時計の印を付けて、まだ押せないことを形でも示す。
18. result-danger-768-3・result-ok-768-2 の札「見本」は実線で囲まれている。見本は点線という約束に合わせて点線にすると、規則が一目で通る。
19. how-768-2 の「見ていないこと」と「診断が確実でない理由」で、「JavaScriptで後から作られる部分」と「ログイン後の画面」が重なっている。片方にまとめて短くする。また「見ていないこと」の中の「見つからなかったことは安全の保証ではありません。」は見出しと意味がずれるので、ここからは外す（結果の帯にはすでに出ている）。
20. idle-768-1 の「Enterで調べる・Shift＋Enterで改行」は、768pxのタブレットでは物理キーボードが無いことが多い。この幅では文字を小さくするか、入力欄の下へ回してもよい（任意）。
21. 768pxでは、文章の最大幅（約600px）とカードの幅（約718px）の差で、文章の右に約140pxの空きが出る（idle-768-1 の説明3行、how-768-1）。読みやすさは保たれているので任意。気になるなら、この幅だけ文章の最大幅を少し広げる。

- 「調べた相手」で持ち主の部分だけを太字と地色で示し、「手前の部分は、持ち主が自由に付けられます」と添える説明（result-danger-768-1）。

- failed-429-768-1 の「このアプリの回数の上限に達しました。相手のサイトの問題ではありません。」と、残り秒数つきの再試行ボタン。
