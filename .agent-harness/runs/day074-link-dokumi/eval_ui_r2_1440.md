## 撮影の疑い（実装の不具合とは断定しない）

1. result-danger-1／result-ok-1／failed-429-1 は、題と説明より下から始まる（y≈7 に区切り線）。結果が出たあと自動で結果の位置へ送る作りなのか、撮影した位置の都合なのかは、画像からは分からない。
2. owner-1 は帯の上端（y≈10）から始まり、点線の「見本の結果です」が写っていない。タブを切り替えたときに画面がこの位置へ送られる作りなら、運営者タブの1画面目から見本の印が消えることになる（要確認）。
3. result-danger-2/3 と result-ok-2 では、スクロールしても右列が同じ位置に留まる。固定要素が焼き込まれたのではなく、右列を上端に留める作り（sticky）だと判断した。owner では右列が普通に流れる。「残り5件を表示」で右列を伸ばした直後にどう動くかは、画像からは確認できない。
4. checking-1 の回転表示は、動きを止めて撮ったもの（前提のとおり）。
5. idle-1 の注意書きの先頭の記号が「①」（丸に1）に見える。小さく描いた「丸に!」が潰れて見えている可能性もある。
6. 地の和紙の濃淡（右上がわずかに暗いなど）は、質感の表現だと判断した。

## 改善指示（全件・優先度つき）

### 高
1. **待機画面の左列の空白（idle-2）**：左列は入力カードで終わり、右列の「訪問者向け『なりすましの兆候』」「運営者向け『サイトの守り』」の横に約490pxの空白ができる。→ 1440ではこの2枚を左列の入力カードの下へ移し、右列は「見本で試す」と「調べる3つのこと」にする。目安は、左右の列の下端の差を120px以内に収めること。
2. **丸にiの二重の意味（checking-1 右カード、owner-2「参考」）**：段階「気になる」と同じ丸にiが、灰色で中立の情報にも使われている。→ 中立の情報には、段階の5つの記号（丸にチェック・丸にi・三角に!・八角形に×・丸に?）と重ならない記号を使う。たとえば四角にメモ線の記号、または記号を置かず細い左線だけにする。丸にiは「気になる」専用にする。
3. **不自然な折返し2か所**
   - idle-3／how-1「やること」の4つ目：「（/.well-known/security.txt）」の後で行が折れ、「を調べます。」が行頭に孤立する。→ 等幅の語と直後の「を調べます。」をまとめて折返さない指定にする。または、パスを文末から外して「連絡先の公開（security.txt）」と短く書く。
   - owner-1 の評価の目安：「A 90〜100点 B 75〜89点 C 60〜74点 D 40〜59点」で1行使い、「F 0〜39点」だけが2行目に落ちる。→ A〜Fの5つを同じ幅のマスで1行に並べるか、区分ごとに折返し禁止にして3＋2の2行に分ける。

### 中
