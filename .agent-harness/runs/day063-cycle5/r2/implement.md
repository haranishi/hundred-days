## 5. 懸念と、評価者に見てほしい点

- **iPhone の実機では確かめていない**：代わりに WebKit 26.5 でレイアウト検査を流し、全件合格しました。実機の Safari とはフォントの描画や画面の高さ（アドレスバー）が少し違う可能性があります。
- **文節の区切りは規則による近似**：`Intl.Segmenter` の辞書はブラウザやそのバージョンで少し違います。文言を変えたら、レイアウト検査（4幅）を流して確かめてください。
- **段落の右側の空き**：文節の途中で折らないため、次の文節が長い行は右に空きが残ります（1440の解説の公的見解など）。語を守ることを優先しました。
- **flex の中の短い文言は文節化しない**：ボタンや札（「Xで投稿」「被弾 +¥19,800」）の文字は、flex の入れ物の直下にあります。ここに `<wbr>` を入れると別々の項目に分かれ、読み上げ名が「Xで 投稿」のように空白入りになるので、何も入れません（どれも1行の短い文言）。
- **nowrap の中にも `<wbr>` を入れない**：Chrome は `white-space: nowrap` の中の `<wbr>` でも折り返すためです（「Dark Commercial／Patterns」の折れで気づいた）。
- **カットインの1秒は、押しても何も起きない**：X1 のとおり、R2で受け入れてもらった設計判断3（カットイン中も操作できる）を覆しています。素早い人には1秒の待ちになります。
- **確保した場所の空白**：×の一言と未回答の警告の場所を最初から取っているので、出る前はポップアップの下（約56px）と質問の箱の下（約40px）が空いています。出入りで画面を動かさないための引き換えです。
- **音は聞いて確かめていない**（コメントの修正だけ）。
- **E2Eの所要時間**：実時間の待ち（20秒の時間切れなど）があり、1回4.3分、`--repeat-each=3` で12.9分かかります。

## 6. 要件書と食い違ったところ

1. **W1の作りを参考実装から広げた**：`<wbr>`＋keep-all だけでは、Chrome も WebKit も句読点・括弧・記号の前後で自分で折りました（Chrome「「罠UI」｜を」、WebKit「（｜契約」「¥12,｜800」）。そこで次を足しました。文節の内側の記号のまわり2〜3文字を nowrap の span で糊付けする。`<strong>` などをまたいで1つの文として区切る。行頭のひらがなは句点のあとだけにする（参考実装は読点のあとも許していたが、要件(b)に合わせた）。「お金」の接頭辞・複合動詞・長い複合語・短い括弧書き・1文字の文節・空白の規則。
2. **解説のボタンの下端固定は、高さ700px以下に限らず常に効かせた**：390×720 や 360×740 でも、いちばん長い解説で「この現場をやり直す」が画面の外に出たためです。本文が収まるときは位置が変わらず、ぼかしは続きがあるときだけ出します。
3. **375×667 に収めるため、文言を少し短くした**：第3〜第5現場のミッション（2行に収まる長さ）、第3現場の赤帯（「現在◯人が検討中です！」）と通知（「あと1分で部屋が解放されます」）。解説の引用も同じ文言に合わせました。第3現場は要件の第4現場と同じく、短い画面で余白を詰めています。
4. **第3現場の通知の1.5秒は、現場の表示（カットインの開始）から数える**：操作できるようになってから0.5秒後に入れ替わります。お知らせ帯の静かな文言（「会員限定セール開催中！ 対象プランはポイント5倍」）は新しく書きました。
5. **X3の合図は「はい」を選ぶたびに出る**（いいえ→はいと選び直したときも）。
6. **X9の「ノーミス」は、やり直しなし・被害0円・時間切れなしの周だけ**：被弾したまま進んだ周は「やり直し 0回」と出します。
7. **共有ダイアログの並び替えはCSSだけ**：`shared/share.js` は触らず、`order` でコピーの結果を注記の下へ移しました。結果画面の共有欄は、`share.js` と同じく「共有…」を先頭に置きました。
