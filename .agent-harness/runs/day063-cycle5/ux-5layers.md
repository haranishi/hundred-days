# Day63「解約ボタンは、どれ？」ユーザーストーリーとUX5階層

実装前に通すべき工程を、今回は評価のあと・修正に入る前に実施した。既存アプリの手直しであり、独立評価（体験14点、視覚9点、各20点満点）で見つかった問題を、戦略層から見直す目的で書いている。

## ユーザーストーリー

| ユーザー | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| 本命：XやLINEのリンクからスマホで開く20代 | 数分で終わる軽い勝負がしたい。「やられた」悔しさを、友達に話せるネタにしたい | 開いて10秒以内に最初の操作へ入れる。1周は3〜5分。結果をXとLINEで送れる。もう1周したくなる目標が見える |
| 本命：ダークパターンという言葉を知らない人 | 説教されずに、手口の名前と見抜き方を知りたい | 失敗した理由が、押した直後の1画面で分かる。画面外や警告ダイアログで流れが止まらない |
| 救う相手：解約できない・勝手に定期購入になる被害に遭いやすい人 | 同じ手口を現実のサイトで見たとき、足を止めたい | 本物に近い見た目で罠を再現する。罠は読める範囲で意地悪にし、理不尽にはしない |
| 作者（100日チャレンジの一作として公開する） | 共有されても、壊れて見えない状態で出したい | テスト全パス。390px幅で崩れない。OGPとシェアの導線がある |

## UX5階層

| 階層 | 決めたこと |
|---|---|
| ①戦略 | 差別化の源泉は「罠UIを、時間に追われながら実際に操作して、先に『やられた』を感じ、その直後に仕組みを言葉で知る」体験。クイズや解説記事では代替できない。そのため「理不尽さ」は敵になる（原因が分からない失敗、画面外のボタン）。繰り返し遊ぶ理由は、答えの暗記で終わらないことと、次に狙う目標が見えること |
| ②要件 | 載せる：5現場の罠体験、失敗理由の明細、制限時間、ランク、Sランクの条件、端末内の自己ベスト、シェア（X・LINE・共有シート・リンクのコピー）。載せない：アカウント、ランキングサーバー、外部への送信・計測、課金、実在企業の名称やロゴ、解説の増量 |
| ③構造 | 開始→現場1〜5（各現場：カットイン→操作→結果モーダル）→結果→再挑戦かシェア。迷う分岐は、失敗後の「やり直す／次へ」と時間切れ。復帰路は、結果から1タップの再挑戦。ゲーム中は共有を出さない（共有ダイアログを開いている間もタイマーが進む不公平を避ける） |
| ④骨格 | いちばん大きい要素は偽サイト（罠）。HUDとミッションは圧縮して上に置き、スマホでも次に押すものが画面内に入る。最終確認のようにあとから現れる部品は、自動で画面内へ運ぶ。解説モーダルは現行の型（判定→明細→手口→心理→公的見解）を維持 |
| ⑤表層 | 暗いHUDと明るい偽サイトの対比は維持。赤と緑だけに意味を持たせない（被害額には色に加えて文字の合図を付ける）。ゲーム側の文字は4.5:1以上。主要ボタンのグラデーションは文字が読める濃さまで落とす。動きは `prefers-reduced-motion` で止められる |

## 通したことで変わった実装

評価の指摘をそのまま直す項目と、5階層を通して初めて決めた項目を分けて数える。

- 5階層を通して初めて決めた項目：2個。①ゲーム中は共有ボタンを隠す（③構造）。②被害額を色だけで示さず、文字の合図を併記する（⑤表層）
- 5階層を通して「載せない」と決めた項目：3個。ランキングサーバー、外部計測、解説の増量。自己ベストは端末内の保存だけにとどめる
- 評価の指摘をそのまま直す項目は、要件書（`r1/requirements.md`）に番号つきで列挙した

## 実装後の照合（3周を終えて）

- 初めて決めた2個は、どちらも実装され、E2Eで固定した。共有ボタンは開始画面と結果画面だけに出る。被害額は赤と「⚠」と読み上げ用の文を併記する
- 「載せない」と決めた3個は守った。ランキングサーバーも外部計測も入れていない。解説に足した文は、評価の指摘による2行だけ（第3現場の「同じ料金でも…」と、第4現場の引き止めの1行）。このほか、解説の引用を画面に出た文言に合わせて書き換えた
- 5階層を通す前に決めていたことを、**遊んでみて覆した**ものが1つある。R1の設計は「カットイン中も偽サイトを操作できる」だった。体験評価とコードレビューが別々に、二度押しが次の現場の罠ボタンに貫通する不具合を見つけたため、R3で「カットイン中は操作できず、時計も進まない」に改めた（③構造と④骨格の修正）。戦略層の「理不尽な失敗を作らない」から見れば、この変更が正しい
- 評価で見つかり、5階層には無かった項目は、要件書（`r1/requirements.md`、`r2/requirements.md`）に番号つきで列挙した

形式を埋めただけで終わっていないかを、この照合で確かめた。5階層から直接生まれた実装は2個、不要と判断して見送ったものは3個。
