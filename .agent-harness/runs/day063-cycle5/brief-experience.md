## 対象
スマホ向けの欺瞞UI（ダークパターン）脱出ゲーム。全5現場。偽の通販・予約・退会画面で、罠を避けて「被害額0円」で目標を達成する。各現場に制限時間がある。シェアされて遊ばれる前提（X・LINE経由、主にスマホ）。
URL（配信済み）: `http://127.0.0.1:4180/day-063-dark-patterns/`

## あなたの立場
**ダークパターンという言葉を知らない、普通のスマホユーザー**として遊ぶ。判断の根拠は画面に出ている文字・見た目・ミッション文だけ。「これは典型的な○○パターンだ」という専門知識で先回りしない（それで正解してしまうと、初見の分かりやすさを測れなくなる）。

## 前提として受け入れる設計判断（覆す提案は不要）
1. 本作は欺瞞UIの**疑似体験教材**。偽サイト側が意地悪であること（目立たない拒否リンク、危険な選択肢の事前選択、逃げる×ボタン、二重否定、配色逆転ボタン等）は**意図した罠**。罠の存在自体は減点しない。**減点対象は**「原因が分からない失敗」「操作不能・詰み」「表示と判定の矛盾」「ゲームとして単調／情報過多／理不尽」。
2. 時間切れは、被害額が0円でも**ミッション未達**として扱う。最終一覧に「未達 (時間切れ)」と出し、ランクは最高でもB。Sランクは「被害0円・時間切れなし・総操作時間が短い」場合のみ。
3. 計時は実時間の累積（解説モーダルを読む時間は含めない）。
4. 第3現場（ホテル）はプラン順が入れ替わっても、危険な「返金不可プラン」が初期選択になる。
5. 第4現場（定期便）の確定ボタンの文言は「選択中の契約・オプションで注文を確定」。
上記以外（制限秒数、Sランクの閾値、説明量、演出、ステージの並び、文言など）は**評価・提案の対象**。

## 操作ツール（時計を止められるプレイテスト用サーバー）
LLMの操作は1手ごとに数秒〜十数秒かかり、実時間のままだと制限時間（20〜30秒）が必ず切れてしまう。そこで、**ゲーム内の時計を止めておき、「人間がその操作に要したはずの秒数」だけ進める**道具を用意した。
クリックは座標で本物のヒットテストを通る（重なり・押しにくさ・誤タップはそのまま再現される）。

起動（Bashを `run_in_background: true` で。出力先は後述の `<R>`）:
```
cd <REPO>/.agent-harness/runs/day063-cycle5 && node tools/playtest-server.mjs --out=<R>/experience-shots --port=<PORT>
```
`<PORT>` と `<R>` は依頼文で指定する。起動後 `curl -s localhost:<PORT>/state` が返れば準備完了。

| 操作 | コマンド |
|---|---|
| 今の画面の見えている文字と、押せる部品の一覧（中心座標・大きさ付き） | `curl -s localhost:PORT/state` |
| スクショを撮る（`name`は自由。`full=1`で縦に全部） | `curl -s "localhost:PORT/shot?name=s1-start"` → 返ってきた `path` を Read で見る |
| タップ/クリック（座標かテキスト） | `curl -s -X POST localhost:PORT/click -d '{"x":195,"y":588}'` または `-d '{"text":"捜査を開始"}'` |
| マウスを載せる（PC幅の確認用） | `curl -s -X POST localhost:PORT/hover -d '{"x":300,"y":400}'` |
| キー操作 | `curl -s -X POST localhost:PORT/press -d '{"key":"Tab"}'` |
| スクロール | `curl -s -X POST localhost:PORT/scroll -d '{"dy":300}'` |
| **ゲーム内時間を進める（ミリ秒）** | `curl -s -X POST localhost:PORT/advance -d '{"ms":8000}'` |
| 最初からやり直す（幅も変えられる） | `curl -s -X POST localhost:PORT/restart -d '{"width":1440,"height":900}'`（省略で今の幅のまま新規セッション） |
| 起きたエラー・警告・**ブラウザの警告ダイアログ(alert)**の記録 | `curl -s localhost:PORT/events` |

- 起動直後は時計が止まっている。**`/advance` しない限りタイマーは進まない**。
- **時間の使い方が評価の核心**。1つの判断の前に「普通の人が画面を読んで、どこを押すか決めて、指を動かすまで」の秒数を `/advance` で進める。目安: 日本語は丁寧に読んで毎秒8〜10字、斜め読みで毎秒15字前後。ミッション文＋画面を一通り把握するのに初見は**1画面あたり5〜12秒**、部品を開く等の手間があれば+3〜8秒。**あなたが人間ならどれだけかかるかを毎回見積もって記録する**（甘くも辛くもせず）。慣れた2周目は3〜6秒でよい。
- 撮影前にゲーム内演出（現場のカットイン等）を見るなら、`/advance` で1〜2秒進めてから撮る。
- ツール上の制約: **音は聞こえない**。音の良し悪しは判定できないので、項目4の音の部分は「未確認」と書き、減点も加点もしない。CSSアニメーションは実時間で動く（撮影は自動で0.7秒待つ）。
- 起動に失敗する・応答しない場合は、ツールの不具合として報告し、`mcp__chrome-devtools__*` か `mcp__claude-in-chrome__*`（ToolSearchで取得）で代替してよい。その場合は時計を止められないので、その旨を評価書に書く。

## 遊び方（必須のパス）
各パスで**毎回、スクショを撮り、画面を実際に見てから次の操作を決める**（スクリプトで一気に流さない）。

1. **P1 初見・標準ペース（390×844）**: 最初から最後まで1周。各現場で「画面を見て何が分かったか／何を押したか／何が起きたか／使った秒数」を記録。
2. **P2 わざと失敗する**: 新規セッションで、どれかの現場で罠側を押して被害を出す→解説モーダル→「やり直す」で同じ現場に戻る。**タップ数と体感時間**を測る。別の現場では**何もせず**制限時間を超過させ（`/advance`）、その後の表示・最終結果との整合を確認する。
3. **P3 慣れた2周目以降（390×844）**: `/restart` して最低**2周**、速いペースで遊ぶ。1周目と比べて**判断が変わったか**（金額・並びが変わるだけで同じ操作列で解けるか）、飽きるか、を見る。累計で「3分遊んで単調か」を判断できる量を遊ぶ。
4. **P4 PC幅（1440×900）**: `/restart {"width":1440,"height":900}` で1周。レイアウト・押しやすさ・hoverの挙動。
5. **P5 キーボード**: 1現場だけ Tab/Enter/Space で操作してみて、フォーカスの見え方・詰まり・モーダル後の復帰を確認。

最低でも合計**6周分（P1・P3の2周・P2・P4・P5）**を実際に遊ぶこと。実プレイしていない項目は「未確認」と書き、勝手に満点・減点しない。

## 評価者の掟
- 「重大な問題のみ報告」にしない。**気づいたことは全部書く**。絞るのは依頼側。甘く採点しない。点数の調整（10〜12点に寄せる／満点にする）をしない。
- 改善指示は「どこを・どうする・どうなっていれば合格か」まで具体化する（例:「第1現場のミッション文が3行で読むのに9秒かかる→1行20字以内に」）。
- **実プレイで測れたこと**と**推測**を分ける。推測は推測と書く。
- 「AIの面白い」は人間の面白さの代理指標にすぎない。最終判定は本人プレイ。その限界を最後に1行書く。
- 撮影・ツール側の不具合（時計を止めた影響、アニメ途中の撮影など）をアプリの欠陥として報告しない。疑わしければ「撮影の疑い」として別枠に書く。
