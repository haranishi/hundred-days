## 1. やること（この順・すべて小さく）

**F1【必須・中1】出したばかりの部品にも、二度押しの入力ガードを掛ける**
- 事実: R3のX1は、現場の読み込み直後（カットイン中の `#stage-viewport`）と結果画面（`#screen-result`）にだけ約0.4秒の入力ガードを掛けた。**現場の中で新しく出る部品**には掛かっていない。375×667では、第3現場の「この条件で予約を確定する」（実測589〜636）の真下に、解説モーダルの「この現場をやり直す」（約590〜634）が来る。2回押すと、突破の記録が取り消され、解説も読めずに現場が始まり直す（「やり直し1回」になり「ノーミス」も消える）。第4現場の赤い大ボタン（560〜607）の上半分は「次の現場へ進む」に重なる。第5現場の「退会手続きへ進む」を素早く2回押すと、スクロール中の最終確認のボタンに2回目が当たりうる。第4現場の「割引を捨てて解除する」を2回押すと、閉じた直後の2回目が下の選択肢の行に当たり、外した定期便が付き直る可能性がある。
- 体験評価の再現（5通り）: ①390×844タッチ：第3現場で罠のまま確定（195,660）を2回 → 被害¥28,000のまま解説もやり直しもなく第4現場へ。安全プランの確定や、第4現場の灰色ボタン（195,683）の2回押しでも、成功の解説を飛ばして次へ。②375×667タッチ：第2現場の「無料トライアルを開始する」（188,631）を2回 → 2回目がモーダルの「この現場をやり直す」（188,614）に当たり、成功が取り消される（やり直し回数も増える）。③375×667：第3現場の罠の確定（188,612）を2回 → 失敗が見えないまま再開。④1440×900キーボード：第3現場の確定にフォーカスしてEnterを2回 → モーダルが開くとフォーカスが「次の現場へ進む」に移るので、2回目のEnterで次の現場へ進む。
- やること: 出した直後の約450ms（定数 `INPUT_GUARD_MS`。0.4〜0.5秒）だけ、その部品を `inert` にする関数を1つ作り（例: `guardInput(el, then)`。タイマーを要素ごとに持ち、同じ要素に掛け直すときは前のタイマーを止める。明けたら `inert` を外して `then` を呼ぶ）、次の3か所に使う。
  1. **解説モーダル**（`#modal-cleared`）: `showClearedModal` で掛ける。`btnNextStage.focus()` は**ガードが明けてから**（inertの中にはフォーカスできない）。`closeModal` ではタイマーを止めて `inert` を外す。
  2. **第5現場の最終確認**（`final-confirm-area` の箱）: 表示した直後に掛ける（`bringIntoView` のスクロールが終わるまでの間）。
  3. **第4現場の引き留めダイアログを閉じた直後**: `close()` のあと、偽サイト本体（`content`）に掛ける。`chkSub.focus()` はガードが明けてから。
- 合格（E2E・**375×667**、第3〜第5現場）: (a) 第3現場でキャンセル無料プランを選び `#btn-hotel-submit` を `dblclick` → `#modal-cleared` が開いたまま・`#hud-stage-text` が「3 / 5」のまま・やり直しの回数が増えない。ガードが明けたら `#btn-next-stage` にフォーカスが移る。(b) 第4現場で赤い `#btn-stage1-loud` を `dblclick`（チェックは外した状態）→ モーダルが開いたまま・「4 / 5」のまま。(c) 第5現場で「はい」を選び `#btn-real-cancel` を `dblclick` → 最終確認は出ているが、その現場は確定されない（モーダルは出ない）。(d) 第4現場で定期便を外そうとして引き留めダイアログの `#btn-remove-sub` を `dblclick` → 定期便のチェックは外れたまま。(e) **キーボード（1440×900）**: 第3現場の `#btn-hotel-submit` にフォーカスして Enter を2回（`keyboard.press('Enter')` を続けて）→ モーダルが開いたまま・「3 / 5」のまま（停止中は主ボタンへフォーカスを移さないので、2回目のEnterが次の現場へ進まない）。(f) 390×844タッチで、上の①②③と同じ操作（第3現場の確定を2回、第2現場の開始を2回）も。いずれも**ガード明け（400ms以上後）は通常どおり押せる**ことも確かめる。時計を止める道具（`page.clock`）か `clickAt`（既存の補助）を使って決定的にする。既存の「二度押し」のE2E（モーダル→次の画面、結果画面）は壊さない。
- README の「前の画面のボタンを2回押しても、2回目が次の画面に届きません」は、**直した後の実態に合わせて**正確に書き直す（「画面が切り替わった直後の約0.4秒、解説・最終確認・確認ダイアログも押せない」）。

**F2【必須・低1】期限を過ぎた確定の前に、「罠解除」の合図を出さない**
- 事実: 裏に回ったタブを戻した直後など、表示更新（最長100ms）より先に正しい選択肢を押すと、「✓ 罠解除」の帯と解除音のあとに、被弾音と「TIME UP!」が続く。
- やること: 成功の合図（帯・音）を出す前に `isOverdue()` を見て、期限切れなら合図を出さずに時間切れとして確定する（例: 合図と確定を1つの関数にまとめる）。既存の `recordStageResult` の期限判定は残す。E2E: 時計を進めて期限を過ぎてから拒否リンクを押す → 「罠解除」の帯が出ない・解説は「TIME UP」。

**F3【必須・低2】入力が止まっていないのに確定しない**
- 事実: 入力を止める手段が `inert` だけ。`inert` に未対応の環境（Safari 15.5未満など）では、カットイン中に押せて、積算0msの確定になる。
- やること: `recordStageResult` の冒頭で、`!isTimeout && state.stageStartedAt === null`（計時がまだ始まっていない＝カットイン中）なら何もせずに返る。E2E: `dispatchEvent('click')`（inertを素通りする）でカットイン中に確定しようとしても確定されない。

**F4【任意・低3】文節化の後片付けが、飛ばす要素の中にも及ぶ**
- `lib/phrase.js` の `phrasifyNode` の先頭で `<wbr>` と糊付けの span を外すとき、`[data-no-phrase]` と `white-space: nowrap` の中は除く（`closest(SKIP_SELECTOR)` などで判定）。`tests/e2e/day-063-layout.spec.mjs` の「文節の区切り（phrasifyNode）」で `#t-skip` に `<wbr>` を1つ入れて固定する。小さく安全にできるときだけ。

**F5【必須・低4・低6】文書とコメント**
- README の「作りの特徴」に1行: 「flexの直下と `white-space: nowrap` の中の文字は文節化しない。そこには短い文言だけを置く」。
- `app.css` の古いコメント（「下の操作は妨げない」。カットイン中の偽サイトは今は操作できない）を直す。
- `CLOSE_NAG_TEXT`・`SURVEY_WARNING_TEXT`・第2現場の `noteText` を `innerHTML` に入れる箇所は、ほかと同じく `escapeHtml` を通す。

**F6【任意・体験TOP5】第4現場の解説に、確認ダイアログの手口を1文**: `explanationFor`（第4現場）の文末に、引き留めの手口を1文足す（例:「さらに、チェックを外そうとすると『本当に解除しますか？』と引き留めるダイアログが出る手口も使われます。」）。成功（BUSTED）でも被弾（TRAPPED）でも出る。単体テストで「引き留め」を含むことを確かめる。F1〜F5が通ってから。

**F7【任意・体験B2】時間切れモーダルの「この現場の被害：未達」**: 時間切れのときだけ、見出しを「この現場の結果：」、値を「時間切れ（未達）」にする（被害ありのときは「この現場の被害：」のまま）。ラベルの要素にIDを付けて切り替える。既存のE2Eが「未達」を見ているなら壊さない。F1〜F5が通ってから。
