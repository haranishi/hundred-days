## 6. 要件書と食い違ったところ・自分で判断したところ

1. **READMEの秒数**：要件の例文は「約0.4秒」です。結果画面の停止（`RESULT_GUARD_MS` = 400）は変えず、新しい停止は450msなので、「結果画面は約0.4秒、解説と最終確認は約0.5秒」と分けて書きました。
2. **F2を、選んだ瞬間の合図にも広げた**：確定の合図（第1現場の拒否リンク、第5現場の「退会する」）に加え、第2現場のチェック、第3現場のプラン、第4現場の配送補償と「解除する」、第5現場の「はい」も `disarm()` を通します。期限のあとに正しい選択肢を選ぶと、合図を出さずにその場で時間切れになります。これまでは帯と音が出て、次の表示更新（最長0.1秒後）で時間切れになっていました。
3. **第5現場の掛け直し**：最終確認が出たあとに「退会手続きへ進む」をもう一度押すと、最終確認をもう一度指の下へスクロールします。このときも停止を掛け直します。
4. **(c)の確かめ方**：§3のとおり、`dblclick` に加えて停止中の `clickAt` で確かめました。滑らかなスクロールの途中の位置は速さしだいで、決定的には作れないためです。
5. **F4の作り**：要件は「`closest` で判定」です。飛ばす要素は `closest` で、nowrap は親の computed `white-space` で判定しました。加えて、`phrasifyNode` が入れる `<wbr>` すべてに印 `data-phrase-break` を付けています。印がないと、nowrap の中に自分で入れた `<wbr>`（文字ノードの先頭の切れ目）と書き手の `<wbr>` を見分けられず、「何度呼んでも同じ結果」の約束を守れません。見た目と改行の位置は変わりません（4幅のレイアウト検査で確認）。
6. **F6の見出しを定数にした**：確認ダイアログの見出し「本当に定期便を解除しますか？」を `stages.js` の `retentionQuestion` に移し、ダイアログと解説の両方がそこから文言を取ります。解説は画面の文言をそのまま引く、というほかの現場と同じ約束を保つためです。
7. **防御を1行足した**：確認ダイアログを開くとき、前に閉じたときの停止のタイマーが残っていたら止めます。残っていると、そのタイマーが開いているダイアログの背後を押せる状態に戻してしまうためです。通常の操作では起きません（停止中は定期便のチェックを押せない）。合成のクリックと、`inert` のない古いブラウザへの備えです。
8. **既存のテストを合わせた**：時計を止めたテストは、解説・最終確認・確認ダイアログのあとで停止が明けるまで時計を進めます（`passInputGuard`・`retryFromModal`、レイアウト検査の `toModal`）。Escで閉じたあとのフォーカスは `toBeFocused()` で待ちます。合計時間の期待値には§5の 2×450ms を足しました。検査の中身は弱めていません。
9. **押しっぱなしの Enter を無視する処理を足した**：合格条件(e)は「Enter を続けて2回」です。停止を入れたあとで確かめると、確定ボタンで Enter を押し続けた場合は、停止が明けて主ボタンにフォーカスが移ったあとの自動リピートで、解説を飛ばして次の現場へ進みました（Chromium と WebKit で再現）。B1(e)と同じ結果になる経路で、評価書のTOP5の1も「自動リピートを無視する」を挙げています。そこで、解説モーダルで `e.repeat` の Enter・Space を無視する処理（4行）を足し、E2Eで固定しました。指を離して押し直した Enter は普通に効きます。
