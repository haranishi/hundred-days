## 1. 結論

**合計12/20点で不合格**（合格条件は16点以上かつ0点なし）。0点の項目は無い。

主戦場の390×844と375×667は出来がよい。最初の画面に地図・列車カード・発車が収まる。選んだ列車の色が地図の分岐と経路にもそろうので、遊び方は画面から読み取れる。減点の大半は、狭い幅・横向き・細部の不揃いから来ている。

いちばん大きい問題は次の3つ。
1. **横向き（844×390）では地図が固定されない。** 下の列車を選べる位置までスクロールすると地図が画面の外に出て、分岐を見ながら操作できない。初期表示では、発車ボタンが注文票に重なる。
2. **320×568と横向きの右列では、編成カードが崩れる。** 「注文」「通る駅」のラベルが値とずれ、ラベルの無い行ができる。
3. **文字が小さい。** カード・地図の注記・運行図の文字は11px前後。390幅の6面の運行図は、5色の線が交差して読みにくい。

## 4. 改善TOP5

### 1. 横向きでは地図を固定し、発車を内容に重ねない
- **どこを**：844×390の左列の地図（`12b-l6-selected`で画面の外に出る）。右列の下端の発車と組み直す（`00-start`では注文票に、`10-l4-burnt-result`では結果の行に重なる）。
- **どうする**：2列表示のときは、左列の地図と注記を画面の上端に固定（sticky）し、右列だけを流す。右列の最後には「固定ボタンの高さ＋16px」の余白を入れ、ボタンの後ろに縦画面と同じクリーム色の帯を敷く。高さ450px未満では一行説明を隠し、題名とタブを1行にまとめる。
- **合格の条件**：844×390で6面の列車5を選んだ状態でも、地図全体と選んだカードが同じ画面に見える。固定ボタンがどのカードや行にも重ならない。

### 2. 狭い幅でも編成カードの行を崩さない
- **どこを**：320×568の`08-l3-selected`・`12b-l6-selected`と、844×390の右列の編成カード。
- **どうする**：「注文」「通る駅」を、ラベルの列と値の列からなる2列のグリッドにし、ラベルを値の1行目に上揃えする。幅が足りないときは「道のり◯分」を通る駅の行から外し、題名の右に置く。カード幅が360px未満なら▲▼を縦に積む。
- **合格の条件**：ラベルと値が同じ行に並び、ラベルの無い値の行ができない。5両のカードの高さがそろう。

### 3. 12px未満の文字をなくし、運行図を読める大きさにする
- **どこを**：編成カードの「注文」「通る駅」「道のり」、地図の下の注記、運行図の行名・目盛り・凡例、320幅の地図の駅名と分の札。
- **どうする**：文字の最小を12pxにする。運行図は行名を短くして描く幅を広げる。番号札はバーの外に出す。凡例は、その結果に出てきた記号だけを出す。PCでは、カードと運行図の文字を13〜14pxに上げる。
- **合格の条件**：390×844のどの画面にも12px未満の文字が無い。6面の運行図で、番号札が隣のバーに重ならず、5両それぞれの線を目で追える。1面の凡例が2行以内。

### 4. 列車の色を駅の色から離す
- **どこを**：列車1（橙赤）と焼く駅、列車4（紫）と煮る駅。`02-l1-switched`の経路の強調、`03-l1-running`と`09-l4-run-a`の駅の上の列車の丸、黄の列車5の経路。
- **どうする**：経路の強調に白い縁取りを付け、駅の箱に入る手前で止める。走行中の列車の丸には白い縁と影を付ける。色相を変えるなら、駅の4色・成功の緑・失敗の赤のどれとも近くない色にする。
- **合格の条件**：列車1が焼く駅に、列車4が煮る駅に止まっている画面で、列車の丸の輪郭が途切れずに見える。

### 5. 地図と結果で呼び名と絵文字をそろえる
- **どこを**：3・5・6面の地図にある2つの「焼く 3分」と、運行図の「焼く（近）」「焼く（遠）」。運行図の「出庫線」「配膳の手前」。同じ🥩を使う5・6面の料理。
- **どうする**：地図の焼く駅の箱に「近」「遠」の小さな札を付ける。車庫から最初の分岐までの線の横に「出庫線」と書く。同じ面で絵文字が重なる料理は、別の絵文字に替えるか、小さな札を付ける。
- **合格の条件**：運行図の行名が、すべて地図上の文字で見つかる。同じ面の料理を、絵文字と札だけで見分けられる。

### TOP5以外の改善候補（優先度の高い順）
1. 結果へ自動スクロールしたときの止まり位置：結果シートの上端を「ヘッダーの直下」にそろえ、注文票の行が半分だけ写らないようにする。
2. 共有窓（`14-share`）：ボタンをアプリ共通の白地・紺の太い枠にする。注意書きは文節で折る（全Day共通の部品）。
3. 結果の「結果を送る」：LINEを足す。
4. PC・横向きの結果画面：運行図を地図の下の空いた左列へ移す。
5. 390×844の3面以降の最初の画面：注文票を「絵文字＋締切」のチップの1列に縮め、編成の1枚目を入れる。
6. 注文票と編成カードの見分け：注文票には選択の枠を付けない。
7. 走行中のずれ：結果の行の高さを最初から確保する。
8. 最終面のクリア後：「全6面クリア」の一言と次の案内を出す。
9. あそびかたの窓：右上に×を置く。
10. 768×1024：題名ブロックと地図ブロックの左端をそろえる。
11. 発車前の列車を、車庫の前に番号付きの丸で描く。
12. 道のりが締切を超えたら赤字にする（パズルの難しさに関わるので任意）。
13. 時計の札を全面で同じ角に置く。
14. トーストの色を紺にそろえる。
15. 5面の長方形の迂回線を、飾り枠に見えないようにする。
16. 音ボタンの状態を文字で示す。
17. 成功行の本文で料理名を繰り返さない。
18. 「結果とリンクをコピー」を1行に収まる語にする。
19. 走行中の編成カードの選択の枠を外す。
20. 6面の注文票の5枚目を半幅にする。

## 5. 残すべき良い点
- **選択中の列車の色が4か所でそろう**（編成カードの枠・注文票の枠・分岐ボタンの輪・経路の強調）。このゲームのいちばんの発明なので、そのまま残す。
- **失敗の理由文が具体的**：誰に何分待たされたか、待たされなければ何分だったか、出口を誰がふさいだかまで書いてある。
- **結果シートの順番と、固定帯のボタンの主従**。
- **救済の流れ**：2回失敗すると見本を提案し、見本のままなら★1だと先に告げ、「元に戻す」で戻れる。
- **画面の高さを稼ぐ判断**：縦画面で地図を固定し、カードだけを流す。375×667では注文票を省いて、編成を最初の画面に入れている。
- **色以外の手がかり**：✔/✖のアイコンと文字、列車の番号札、運行図の斜線と点線、「運行図を文で読む」。
- **焦げの知らせ方**：焦げる前に「ジリジリ」、焦げた列車は✖に変わる。
- **達成が3か所に残る**：タブの★、面の見出しの「自己ベスト」、注文票の「✔ ◯分」。
- **押しやすさ**：押す要素は44px前後。走行中はタブを薄くして、面を変えられないことを示している。
- **PCの表示**：地図が大きく、凡例は2列で読みやすい。

## 6. 撮影の疑い（要点）
- `-full`の合成画像と`07b`では、ヘッダーと固定帯が途中に焼き込まれている。アプリの欠陥ではない。
- 結果画面の上端に注文票の行が半分写る件は、全サイズで同じ形で出ている。アプリのスクロール位置の問題の可能性が高い。ただし撮影スクリプトがスクロール位置を指定しているなら、その影響もありうる。実機で確かめてほしい。
- 結果時の地図で線路の一部が薄い金・灰青・桃に塗られる件は、各列車の経路の表示とみられる。仕様か描画の残りかは画像からは判別できない。
- 共有窓に端末の共有ボタンが無いのは、撮影に使ったブラウザが対応していないためかもしれない。
- あそびかたの窓（320・844）は、窓の中を下までスクロールした状態で撮られている。
- フォーカスの状態と「2倍」を押した後の見た目は、どの画像にも写っていない（未確認）。
- 844×390の最初の画面で発車が注文票に重なるのは、撮影の影響ではなく、アプリの挙動と判断した。
