# Day065「定刻ごはん」実装依頼（実装担当向け・自己完結）

## 作るもの

食材を積んだ列車を、切る駅・焼く駅・煮る駅を通して配膳駅へ走らせ、注文をさばく1画面のパズル。
プレイヤーが決めるのは「出発順」と「分岐の向き（進路）」だけ。調理の操作はしない。
6面（levels.json）。登録なし・外部通信なし・依存ライブラリなし（素のJS・CSS・SVG）。
一周：進路と出発順を組む → 発車 → 動きを見る → 結果と原因 → 組み直す／次の面。

## 守ること

1. ルールは reference/sim.mjs が正。lib/sim.js は同じ結果を返す（1分も違えない）。違いや矛盾を見つけたら、直さずに報告する。
2. 面データ（盤・締切・par・見本）を勝手に変えない。変えたくなったら止めて報告する。面を足さない。
3. 配信するコードは day-065-teikoku-gohan/ の中で完結させる（このフォルダの reference/ を import しない）。lib/sim.js と lib/levels-data.js は写して置く。
4. インラインのscript・on*=属性・外部フォント・外部画像・外部通信は禁止。scripts/ と他のDayは変更しない。
5. コミット・push・PR・マージ・公開をしない。meta.json の status は "draft"。git add もしない。
6. 宣伝動画・デモ動画・X投稿文は作らない（あとで別に頼む）。screenshot は後でよい。
7. 完了報告に「全テスト合格」と書くなら、実行したコマンド・件数・実際の出力を貼る。発注側が再実行して照合する。
8. 読み手に伝わる文章：画面の文言は平易な日本語（専門語・英語を出さない）。READMEは100行以内で、コードを消したら失われる情報（目的・設計判断・捨てた案・罠）だけを書く。

## 設計判断（理由つき。READMEにも要点を書く）

- 列車と注文を1対1にした：同じ食材の列車の割り当てが曖昧だと、30秒で理解できない。
- 星は完食時刻で決める：「最短ダイヤ」という言い方が鉄道の見立てと合い、共有しやすい。待ち時間の合計案は捨てた。
- 焦げは「出る瞬間」に判定：出口の線路がふさがっているという原因を、列車の記録（blockedBy）で示せる。
- 全面を最初から開ける：Xから来た人は途中の面から遊ぶ。

変更・追加したファイルの一覧／実行したコマンドと結果（件数）／reference との差異／未解決の点と、判断が要る点／自分で確かめたこと（画面幅ごとのスクショを見た結果）と、確かめていないこと。
