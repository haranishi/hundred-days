# Day065 権利・規約・法律の確認（独立した読み取り専用レビュー）依頼書

あなたは**独立した確認者**。実装者ではない。**ファイルを変更しない**（書いてよいのは、依頼文で指定された出力先の1ファイルだけ）。Web検索・Web取得は使ってよい。
目的：このアプリを公開（PR→公開）する前に、**著作権・規約（ライセンス含む）・法律**に問題がないかを、しっかり調べる。「調べていない」を「問題なし」と書かない。

## 対象
- アプリ本体：`<APP>/`（index.html, app.css, app.js, lib/, meta.json, README.md, favicon.svg, screenshot.webp）。共有部品 `<APP>/shared/` は全Day共通の自作部品。
- 周辺：ルートの README.md（Day一覧の1行）、LICENSE・THIRD_PARTY_NOTICES.md（あれば）、`<RUN>/05_rights.md`（これまでの確認の記録）。
- 内容：食材を積んだ列車の「出発順」と「分岐」だけで料理をさばく、登録なし・外部通信なしの1画面パズル。全6面。無料の個人制作。「100日チャレンジ」の65日目として公開予定。
- 公開名と、実在の事業との重なりは `05_rights.md` に記録済み（J-PlatPatまで確認済み）。重複して調べなくてよいが、**抜け**があれば指摘する。

## 調べること（すべて、根拠のURLか該当ファイル・行つきで）
1. **著作権**：コード・文章（ヒント・説明・料理名）・音（Web Audio合成のみのはず）・書体・画像・データの出どころ。他人のものを含んでいないか。コード内に、他人のコードの断片・コメント・名前が混じっていないか（`git`の履歴ではなく、ファイルの中身で）。絵文字は端末の書体で出る。**スクショ（screenshot.webp）や動画に写る絵文字**の扱い（Apple Color Emoji ほか、各社の書体の規約）を調べる。
2. **規約・ライセンス**：同梱物（ライブラリ・データ・書体）の有無とライセンス。外部サービスの規約：Xの共有（intent）、LINEの共有、Cloudflare Pages。リポジトリの LICENSE・THIRD_PARTY_NOTICES.md との整合（足し忘れ・矛盾）。
3. **法律**（日本）：商標法・不正競争防止法（名前・見た目・ゲーム性が他作品の模倣にならないか。既存作品との類似を検索で確かめる）／個人情報保護法・電気通信事業法の外部送信規律（端末の外へ何も送っていないことをコードで確かめる。localStorage の扱い）／景品表示法・特定商取引法（販売や広告に当たる表現がないか）／賭博・景品（金銭・景品・ガチャ要素がないか）／食品・医療の表示（料理名や説明が、効能や安全を示していないか）／障害者差別解消法の趣旨（アクセシビリティで明らかな欠落がないか）／他、気づいたもの。
4. **公開文との整合**：README・meta.json・画面の文言が、コードの実態と合っているか（「外部への通信なし」「登録なし」「端末の中だけに保存」など）。数字・日付・URL。本人しか知らない体験を推測で書いていないか。

## 守ること
- 実装者のコメントや説明を信じない。ファイルと、実際の通信（grep で URL・fetch・XMLHttpRequest・import・src・href）で確かめる。
- 「問題なし」と書くときは、**何を、どう調べたか**を書く。調べられなかったことは「未確認」。
- 重さを付ける：重大（公開を止める）／要対応（直してから公開）／注意（残してよいが記録）／参考。直し方（どこを・どうする）まで書く。
- 法律の専門家ではないので、断定を避け、「確認した範囲では」と書く。

## 出力（`<R>`に1ファイル）
1. 結論（公開してよいか。止める問題の有無。2〜3行）
2. 項目ごとの結果表（上の1〜4。結果・根拠・重さ）
3. 見つかった問題と直し方（重い順）
4. 確認したが問題なかったもの（調べ方つき）
5. 未確認のこと
最後に、依頼元へ返す要約（30行以内）を最終メッセージで返す。
