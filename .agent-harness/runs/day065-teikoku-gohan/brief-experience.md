## 前提として受け入れる設計判断（覆す提案は不要）
1. 列車と注文は1対1。どの列車がどの料理になるかは最初から画面に出る。
2. 通る駅の順番がレシピになる（切ってから焼く／焼いてから切るは別の料理）。
3. 火の駅（焼く・煮る）は、仕上がってから1分を超えて出られないと焦げる。切る駅は待っても焦げない。
4. 星は完食時刻で決まる（最短なら★3、最短+1分なら★2、それ以外のクリアは★1）。面1・2は、クリアすれば必ず★3。
5. 見本のダイヤは、同じ面で2回失敗すると出せる。使ってクリアすると星は1つまで。
6. 全面を最初から選べる。盤・締切・列車の数は固定（ランダムではない）。
7. 再生は1分＝0.5秒。2倍とスキップがある。
8. 面を開くと、1番目の列車が選ばれた状態になっている。スマホでは、編集中と再生中だけ、地図が画面の上に固定される（結果シートの間は固定されない）。
9. 編成の各カードに、「注文」（工程と締切）と「通る駅」が並ぶ。通る駅が注文の工程と同じときだけ、✔が付く（違うときは何も付かない）。
10. 結果の間は、画面下の固定帯に「組み直す」と（クリア時は）「次の面へ」が出る。見本のダイヤを出した直後の一言に「元に戻す」が付く。
11. 火の駅で、仕上がったあとに待つ「ジリジリ」の間は、再生がゆっくりになる（1分＝1.2秒）。
12. 最終面（面6）は、締切の早い順に並べても通らないように作ってある（解は4通り）。難しさの評価（何回で解けたか、詰まった理由、見本に頼ったか、星を取れたか）を、面5と比べて必ず書く。
上記以外（説明の量、文言、ヒント、演出、結果の見せ方、操作の手数、面の並びなど）は**評価・提案の対象**。減点対象は「原因が分からない失敗」「操作不能・詰み」「表示と判定の矛盾」「単調・情報過多・理不尽」。

## 操作ツール（時計を止められるプレイテスト用サーバー）
LLMの操作は1手ごとに数秒かかるので、**ゲーム内の時計を止めておき、「人間がその操作に要したはずの秒数」だけ進める**道具を用意した。クリックは座標で本物のヒットテストを通る（重なり・押しにくさ・誤タップはそのまま再現される）。

起動（Bashを `run_in_background: true` で）:
```
cd <REPO>/.agent-harness/runs/day065-teikoku-gohan && node tools/playtest-server.mjs --out=<R>/experience-shots --port=<PORT> --base=<BASE>
```
`<REPO>`・`<R>`・`<PORT>`・`<BASE>` は依頼文で指定する。起動後 `curl -s localhost:<PORT>/state` が返れば準備完了。

| 操作 | コマンド |
|---|---|
| 今の画面の見えている文字と、押せる部品の一覧（中心座標・大きさ付き） | `curl -s localhost:PORT/state` |
| スクショを撮る（`full=1`で縦に全部） | `curl -s "localhost:PORT/shot?name=s1-start"` → 返ってきた `path` を Read で見る |
| タップ/クリック（座標かテキスト） | `curl -s -X POST localhost:PORT/click -d '{"x":195,"y":588}'` または `-d '{"text":"発車"}'` |
| マウスを載せる | `curl -s -X POST localhost:PORT/hover -d '{"x":300,"y":400}'` |
| キー操作 | `curl -s -X POST localhost:PORT/press -d '{"key":"Tab"}'` |
| スクロール | `curl -s -X POST localhost:PORT/scroll -d '{"dy":300}'` |
| **ゲーム内時間を進める（ミリ秒）** | `curl -s -X POST localhost:PORT/advance -d '{"ms":8000}'` |
| 最初からやり直す（幅も変えられる） | `curl -s -X POST localhost:PORT/restart -d '{"width":1440,"height":900}'` |
| 起きたエラー・警告・ブラウザの警告ダイアログの記録 | `curl -s localhost:PORT/events` |

- 起動直後は時計が止まっている。**`/advance` しない限り、再生は進まない**。発車したら、再生を見るために `/advance`（1分＝500ms。20分の面なら10000ms前後）で進めるか、画面の「スキップ」を押す。**どちらを使ったかを記録する**（再生を見ないと原因の理解度が測れない）。
- 考える時間は実時間の制限ではない（このゲームに制限時間はない）。ただし**1つの判断に要した体感の秒数**を、毎回見積もって記録する。
- 音は聞こえない。音の評価は「未確認」と書き、減点も加点もしない。
- 起動に失敗する・応答しないときは、ツールの不具合として報告し、`mcp__chrome-devtools__*` か `mcp__claude-in-chrome__*` で代替してよい（その旨を評価書に書く）。

## 遊び方（必須のパス）
各パスで**毎回、スクショを撮り、画面を見てから次の操作を決める**（スクリプトで一気に流さない）。

1. **P1 初見（390×844）**: 説明を読まずに面1から始める。面1→面2→…と、解けるところまで進める。面ごとに「画面を見て何が分かったか／何を操作したか／何が起きたか／試行回数／かかった体感秒数」を記録する。解けない面は「解けなかった」と正直に書く。
2. **P2 わざと失敗する**: 面2で締切の遅い料理から出して失敗→結果の原因の文を読む。**原因の文だけで次の手が分かるか**を判定。さらにもう一度失敗して「見本のダイヤを見る」を出し、反映→発車→クリアまで。タップ数と体感時間を測る。
3. **P3 星を取りに行く**: 面3と面5で、★3（最短ダイヤ）を目指して何度か組み直す。何回目で★3に届いたか、届かなかったら諦めた理由。「もっと速くしたい」と思えたか。
4. **P4 焦げ**: 面4で、わざと焦げる組み方を作る。焦げる前の合図（ジリジリ）に気づけたか、焦げた理由が分かったか。
5. **P5 最終面**: 面6（5両）を解く。何回で解けたか。情報が多すぎないか。
6. **P6 PC幅（1440×900）**: `/restart {"width":1440,"height":900}` で面1〜2。レイアウト、押しやすさ。
7. **P7 キーボード**: 面1をTab/Enter/Spaceだけでクリアする。フォーカスの見え方、詰まり。

実プレイしていない項目は「未確認」と書き、勝手に満点・減点しない。
