# Day 027「スクショに額縁を」要件定義

スクショを貼る（⌘V / Ctrl+V）か、落とすか、選ぶと、**余白・角丸・影・背景を付けた1枚**がその場でできる。背景と比率を選び、PNGで保存するか、そのままクリップボードへコピーする。画像はブラウザの中だけで処理し、どこにも送らない。ページを閉じれば画像は消え、スタイルの設定だけ端末に残る。

## 背景と狙い

- SNSや資料にスクショをそのまま貼ると、端が切れて見え、地味で、画面の余白と同化する。余白と影と背景を付けるだけで「見せるための1枚」になる。
- 同じことをするWebサービスはあるが、多くは画像をサーバーへ送るか、登録や課金が要る。**このアプリは通信ゼロで、開いて3秒、貼って1秒で終わる**。仕事の画面や個人情報を含むスクショでも、外へ出ないことを画面に書いて約束する。
- 難易度設計（Day21〜30）: **localStorage**（背景・比率・余白・角丸・影・枠の設定を保存。画像は保存しない）＋**演出のこだわり**（画像が置かれた瞬間に、額縁がふわりと着地する）。外部依存は0。
- 企画当初のバックログ（2026-08-08）にあった「スクリーンショットをSNS用に整えるアプリ」を、そのまま1日アプリの枠で作る。

## ユーザーストーリー

| ユーザー | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| 作ったものをXに載せる私（本命） | スクショを撮ってから投稿まで、10秒で「見せる1枚」にしたい。アプリを開いて、別のアプリで加工するのは面倒 | ⌘V / Ctrl+V で貼るだけで結果が出て、「PNGで保存」か「画像をコピー」の1回で持ち出せる |
| 資料にスクショを貼る私 | 背景色を資料の地色と合わせたい。白背景や透明も欲しい | 背景に単色（紙・墨）と透明があり、透明はPNGの透過として保存される |
| Instagramにも出す私 | 正方形や4:5にしたいが、スクショは横長 | 比率を選ぶと、画像はそのままの縮尺で中央に置かれ、背景が足される |
| 業務画面を扱う私（このアプリが救う相手） | 画面に顧客名が映っているので、加工サービスにアップロードしたくない | 通信が一切発生せず、その旨が画面に書いてあり、ページを閉じると画像が消える |
| スマホでスクショを撮った私 | パソコンが無くても同じことをしたい | 「クリップボードから貼る」ボタンか「画像を選ぶ」で読み込め、保存とコピーがスマホでも動く |
| 毎日使う私 | 毎回同じ設定に直したくない | 背景・比率・余白・角丸・影・枠の設定が次に開いたときも残っている |

## UX5階層

- **戦略**: 「画像編集ツール」ではなく、**「貼る→整う→持ち出す」を10秒で終わらせる道具**。成功＝⌘Vの1秒後に結果が見え、保存かコピーの1回で投稿画面に貼れる。差別化の源泉は、通信ゼロ（業務画面でも安心）と、貼ってすぐ結果が出る速さ。編集の自由度では勝負しない。
- **要件**: 載せるもの＝貼る・落とす・選ぶ・クリップボードから読むの4入口／背景10種（グラデーション7・単色2・透明）／比率6種／余白・角丸・影のスライダー／ウィンドウ風の枠／PNG保存／画像コピー／設定の保存。対象外＝トリミング、文字入れ、複数画像の合成、端末のモックアップ（特定メーカーの意匠は使わない）、JPEG書き出し、履歴。
- **構造**: 単一画面。上から「ステージ（結果のプレビュー。空のときは置き場）」→「持ち出す操作（保存・コピー・別の画像）」→「見た目の設定（背景・比率・余白・角丸・影・枠）」→「使い方とプライバシー」→シェア。900px以上はステージを左、設定を右の2列。迷う分岐は「画像でないものを置いたとき」「クリップボードに画像が無いとき」で、どちらも状態を変えずに一言返す。
- **骨格**: いちばん大きい要素は**ステージ**1つ。設定はステージの下（狭い幅）か右（広い幅）。主要ボタンは「PNGで保存」1つを塗りにし、「画像をコピー」「別の画像」は枠だけ。スライダーは3本だけで、値は現在の画像に対するピクセル数で見せる。
- **表層**: 地は生成り色、文字は墨色、主要ボタンと選択中の印はひとつの青緑。背景の見本は丸い色見本そのもので示す（名前はaria-labelとツールチップに）。数字は等幅。演出は1つだけ、**画像が置かれた瞬間に額縁が0.96倍から等倍へふわりと着地し、影がにじむ**（0.6秒）。`prefers-reduced-motion`では止める。透明背景のときだけ、プレビューの下に市松模様を敷いて「透明」を伝える。

### UX5階層を通したことで決まった実装（11件）

1. 入口を**ページ全体の貼り付け**にする。入力欄にフォーカスしていなくても⌘Vで読み込む（戦略層：10秒で終わらせる）
2. 「クリップボードから貼る」ボタンを置く。スマホには⌘Vが無い（要件層）
3. 結果は**出力解像度そのままのCanvas**を1枚だけ持ち、プレビューはそれをCSSで縮めて見せる。プレビューと保存物のずれを構造的に無くす（構造層）
4. 出力は元画像の実寸を保ち、余白・角丸・影は**元画像の幅に対する比率**で決める。小さな画像でも大きな画像でも同じ見え方になり、設定を保存しても意味が変わらない（要件層）
5. 長辺4096pxで頭打ちにし、超えるときは縮めて注記する。ブラウザのCanvas上限とメモリで落ちるのを防ぐ（要件層）
6. 画像は**保存しない**。保存するのはスタイルだけ。業務画面のスクショが端末に残らないことを約束できる（戦略層）
7. 比率を固定しても画像は縦横比を変えず、背景を足して中央に置く。トリミングは作らない（要件層）
8. 端末のモックアップ枠は作らない。特定メーカーの意匠を避け、「ウィンドウ風の枠」は無彩色の帯と3つの灰色の丸だけにする（表層）
9. 透明背景でも影は描く。透過PNGとして資料に置いたときに浮いて見える（表層）
10. 色見本は色そのものを見せ、名前はaria-labelにする。選択中は太い枠＋チェック印で示し、色だけに意味を持たせない（表層）
11. 4状態：空（置き場と「サンプルで試す」）／読込中（大きな画像のデコード中）／エラー（画像でない・読めない・40MB超）／不正入力（スライダーは範囲内に固定、保存データの型違いは既定値に戻す）（要件層）

## 機能要件

**状態**
- `<main id="app" data-state="empty|loading|ready|error">` の1か所で切り替える
- 空: `#dropzone`（見出し「スクショをここに置いてください」、説明「⌘V / Ctrl+V で貼る・ドロップ・画像を選ぶ」、ボタン `#pick`「画像を選ぶ」・`#paste-button`「クリップボードから貼る」・`#sample`「サンプルで試す」）
- 読込中: `#loading`「読み込み中…」（`aria-live="polite"`）
- 準備完了: `#preview`（Canvas）と操作ボタン、`#output-size`・`#source-info`
- エラー: `#error-body` に理由。「別の画像」で空へ戻る
- 状態が切り替わったら次の操作へフォーカスを移す: `ready` → `#preview`（`tabindex="-1"`）、空 → `#pick`、エラー → `#error-again`。「PNGで保存」には当てない（Enterの押し込みで誤保存になる）

**入口（4つ。どれも同じ `loadFile(file)` に入る）**
- `<input type="file" id="file" accept="image/*" class="sr-only">` と `#pick`
- `document` の `paste` イベント。`clipboardData.files` か `items` から最初の画像を取る。画像が無ければ `#message`「クリップボードに画像がありません」。テキスト入力欄（`range`・`checkbox`・`file` 以外の `input`、`textarea`、`contenteditable`）にフォーカスがあるときは何もしない。スライダーにフォーカスが残っていても画像は受け取る
- `document` の `dragover`/`drop`。ドラッグ中は `#stage` に `data-over="true"`。複数ファイルは最初の1枚だけ使い、`#message`「1枚だけ使います」
- `#paste-button`：`navigator.clipboard.read()` で画像の項目を探す。非対応・拒否・画像なしは `#message`「この環境ではボタンから貼れません。⌘V / Ctrl+V で貼ってください」（画像なしは「クリップボードに画像がありません」）
- `#sample`：`./sample/sample.webp`（自作。Day 026 のスクリーンショット 1200×750）を `fetch` して同じ経路で読み込む。`#source-info` の名前は「サンプル」

**読み込みの判定**
- `file.type` が `image/` で始まらず、かつデコードもできない → エラー「画像ファイルを選んでください（PNG・JPEG・WebP・GIF・BMP）」
- 40MB（40 × 1024 × 1024 バイト）超 → エラー「40MBまでの画像に対応しています」
- デコード失敗（SVGなど寸法の無いもの、壊れたファイル）→ エラー「この画像は読み込めませんでした」
- デコードは `createImageBitmap(file)`、無ければ `Image` と `URL.createObjectURL` で。デコード中は `loading`
- 描画で例外が出たとき（Canvas非対応など）→ エラー「この環境では画像を加工できません」
- 読み込めたら `ready`。`#source-info` は「元画像 1200 × 750 · サンプル」の形（ファイル名は `textContent` で入れ、80文字で切る）

**レイアウト計算（`lib/layout.js`・純関数・DOMに触れない）**

```
computeLayout({ imgW, imgH, padding, radius, shadow, aspect, frame, maxSide = 4096 })
→ { width, height, scale, pad, radius, shadow: { blur, offsetY, alpha }, bar, card: { x, y, w, h }, image: { x, y, w, h } }
```

- `padding`・`radius`・`shadow` は 0〜100 の整数。範囲外は 0〜100 に丸める
- `pad = round(imgW × 0.25 × padding / 100)`（既定40 → 幅の10%）
- `bar = frame ? round(max(18, imgW × 0.036)) : 0`（ウィンドウ風の帯の高さ）
- カード = 帯＋画像。`cardW = imgW`、`cardH = imgH + bar`
- 自動比率: `width = cardW + 2pad`、`height = cardH + 2pad`
- 固定比率 `r = 横/縦`（`1:1`=1、`4:5`=0.8、`16:9`、`9:16`、`1.91:1`）: `width = max(cardW + 2pad, (cardH + 2pad) × r)`、`height = width / r`。カードは中央
- 長辺が `maxSide` を超えるときは `scale = maxSide / 長辺` で全体を縮める（それ以外 `scale = 1`）。最終の `width`・`height`・座標・寸法は `Math.round`。最小1px
- `radius = imgW × 0.06 × radius / 100 × scale`（既定35 → 幅の2.1%）。角丸はカード全体に掛ける（帯があるときは帯の上角が丸くなり、画像の上角は直角）
- `shadow.blur = imgW × 0.08 × shadow / 100 × scale`、`offsetY = blur × 0.45`、`alpha = shadow === 0 ? 0 : 0.18 + 0.27 × shadow / 100`
- 検算（800×500・既定値・枠なし・自動）: `pad 80`、`width 960`、`height 660`。1:1 → `960 × 960`。枠あり → `bar 29`、`960 × 689`。6000×3000・既定値 → `scale = 4096 / 7200`、`width 4096`、`height 2389`

**描画（`lib/draw.js`・`(ctx, layout, image, background, frame)`）**
- 背景: グラデーションは左上→右下（135度相当）。単色は塗り。透明は `clearRect` のみ
- 影: `shadowColor = rgba(0,0,0,alpha)`、`shadowBlur`、`shadowOffsetY` を付けてカードの角丸矩形を白で塗る
- 角丸矩形は `roundRect`。無いブラウザ（Safari 16.4未満など）では `arcTo` で同じ形をなぞる
- カードの角丸で `clip` し、帯（`#e9e9ee` の帯と `#c9c9d1` の丸3つ。丸の半径 `imgW × 0.0075 × scale`、中心は左から `imgW × (0.022, 0.044, 0.066) × scale`、高さは帯の中央）と画像を描く
- `devicePixelRatio` は使わない（Canvasは出力解像度そのもの。プレビューはCSSで縮める）

**設定（`<section id="controls">`。常に表示・常に操作できる。画像が無いときは値だけ保存する）**
- 背景: `#backgrounds` に `<button class="swatch" data-bg="<id>" aria-pressed aria-label="<名前>" title="<名前>">`。44px 以上の丸。選択中は太い枠とチェック印
- 比率: `#aspects` に `<button class="chip" data-aspect="auto|1:1|4:5|16:9|9:16|1.91:1" aria-pressed>`。表示は「自動」「1:1」「4:5」「16:9」「9:16」「1.91:1」
- 余白 `#padding`、角丸 `#radius`、影 `#shadow`：`<input type="range" min="0" max="100" step="1">`。既定 40 / 35 / 50。隣の `#padding-value` / `#radius-value` / `#shadow-value` に現在の画像幅で計算したピクセル値（「80px」）。長辺を4096pxに縮めるときは縮めた後の値。画像が無いときは幅1200pxとして計算した値
- 枠 `#frame`：`<input type="checkbox">`「ウィンドウ風の枠を付ける」。既定オフ
- どれを変えても、画像があれば即再描画（`requestAnimationFrame` で1フレームにまとめる）

**持ち出す**
- `#download`「PNGで保存」（主要ボタン）：`canvas.toBlob(…, 'image/png')` → `URL.createObjectURL` → `<a download>`。ファイル名 `framed-YYYYMMDD-HHMM.png`（端末の現地時刻）。`#message`「保存しました」。`toBlob` が `null` を返したとき（iOS SafariのCanvas面積上限など）は「この画像は書き出せませんでした。比率や余白を小さくしてください」
- `#copy`「画像をコピー」：`navigator.clipboard.write([new ClipboardItem({ 'image/png': blob })])`。成功で `#message`「コピーしました。そのまま貼り付けられます」、非対応・失敗で「この環境ではコピーできません。PNGで保存してください」、`toBlob` が `null` のときは保存と同じ文言
- `#again`「別の画像」：Canvasを破棄して空へ。`URL.createObjectURL` したものは `revokeObjectURL`
- `#output-size`：「出力 960 × 660 px」。`#size-note`：長辺を縮めたときだけ「元画像が大きいので、長辺を4096pxに縮めて書き出します」

**保存（`lib/store.js`）**
- キー `day027.frame.v1`：`{ v: 1, bg: 'grape', aspect: 'auto', padding: 40, radius: 35, shadow: 50, frame: false, updatedAt }`
- 読むときに検証：`bg` は背景一覧のid、`aspect` は6種のどれか、3つの数値は 0〜100 の整数、`frame` は真偽値。1つでも違えばその項目だけ既定値。JSONが壊れている・`v` が違うときは全部既定値
- **画像は絶対に保存しない**
- localStorage が使えないときは `#storage-error`「この環境では設定を保存できません。加工と保存はそのまま使えます」を出し、機能はすべて動く

**演出**
- 画像が `ready` になった瞬間、`#preview` に `.is-landing` を付け、600ms 後に外す（CSSで `transform: scale(0.96)`→1、`opacity` 0→1、影のにじみ）
- `prefers-reduced-motion: reduce` では `.is-landing` を付けない

**プレビュー**
- `#preview` は `<canvas role="img" aria-label="額縁を付けた画像 960 × 660 ピクセル">`。CSSで `max-width: 100%`、高さは画面の 70vh まで。背景が `transparent` のときだけ `data-transparent="true"` を付け、CSSの市松模様を敷く

**シェア・OGP**
- `index.html` の `</head>` 前に `./shared/share.css` と `./shared/share.js`（defer）。`<meta name="share:text">` は「スクショに額縁を — 貼るだけで、SNSに出せる1枚に。画像は端末の外に出ません」（アプリ名を含める）。`<main>` の末尾（`#app` の中の最後）に `<div id="share"></div>`。OGP・canonical はビルドが入れるのでアプリ側に書かない

## 非機能・技術

- 依存ゼロ・ビルドなしの vanilla JS（ES modules）。`index.html`＋`app.css`＋`app.js`＋`lib/`（`layout.js` 計算／`draw.js` 描画／`backgrounds.js` 背景一覧／`store.js` 保存／`filename.js` ファイル名）
- **外部通信ゼロ**（サンプルの `fetch` は同一フォルダ内。外部フォント・外部画像無し）。CSP はリポジトリ既定（`img-src 'self' data: blob:`）のまま
- 描画は1回の操作につき 50ms 以内を目安（4096px級は例外。`requestAnimationFrame` でまとめる）
- アクセシビリティ：すべてのボタン・色見本・チェックボックスの操作領域は 44px 以上。スライダーはキーボードで動く。コントラスト 4.5:1 以上。フォーカスリング可視。`#message` は `role="status"`
- レスポンシブ：320 / 390 / 1280px で横スクロール無し。1200×750 でステージ・「PNGで保存」・背景の見本が同じ画面に入る
- `alert/confirm/prompt` を使わない。ファイル名などユーザー由来の文字列は `textContent` で入れる。`innerHTML` にユーザー入力を入れない
- 定数名を「KEY」で終わらせない（シークレット検査が誤検知する）。ソースにローカルの絶対パスを書かない

## やらないこと
