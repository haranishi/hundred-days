# Day 048 紹介動画

34秒・1080×1920・30fps の縦型動画を作るツール。本物のアプリを iframe で動かして1コマずつ撮り、1020枚の連番PNGと BGM（`promo-audio.mjs` のA案）を ffmpeg でまとめる。依存パッケージは足さない。

## 使い方：試し描きで確かめてから本番を描く

リポジトリのルートで実行する。ffmpeg・ffprobe と Playwright の Chromium が要る。アプリのフォルダはツール自身が空きポートで配信するので、`npm run build` も `dist/` も使わない。

```sh
export PLAYWRIGHT='<playwright の index.js>'
node day-048-dish-oracle/tools/promo/render-promo.mjs --preview    # 540×960で撮って拡大する
node day-048-dish-oracle/tools/promo/render-promo.mjs              # 1080×1920で撮る
node day-048-dish-oracle/tools/promo/render-promo.mjs --out <mp4>  # 出力先を変える
```

作成環境では試し描きが約1分、本番が約3分半かかった。書き出すのはこのフォルダの `promo.mp4`・`promo-first-frame.png`・`preview-contact.jpg`（2秒おきの17コマ）で、どれも gitignore 済み。連番PNGとWAVは OS の一時フォルダに置き（本番で約0.7GB）、終われば消す。BGMだけを聴くなら `node day-048-dish-oracle/tools/promo/promo-audio.mjs` を使う。

## 絵コンテ：秒は timeline.mjs が正本

| 秒 | 絵と操作 | 字幕 |
| --- | --- | --- |
| 0–4 | 2問答えた状態から撮る。3問目の質問画面で霧が回り、読みの輪は4%。2秒に答える | 心にある一皿、当てます |
| 4–10 | 4・6・8秒に答える（小節の頭＝BGMの拍）。答えるたびに「↑ +◯%」の札 | 質問に答えるだけ |
| 10–16 | 10・12・14秒に答え、16.0秒に10問目を答えて推測へ | 答えるほど、見えてくる |
| 16–20 | 鐘と同時に輪が100%に満ちて光り、全景へ引く。たこ焼きの絵が玉から浮かび上がる | 10問で、見抜く |
| 20–26 | 20秒に「当たり！」。21〜22秒で決め手3つが見えるまで iframe 内を送る | 決め手まで、見せます |
| 26–30 | 2回目の占いを撮影の外で「参りました」まで進め、26.2〜27.8秒に「ばあちゃんの煮しめ」を1文字ずつ打つ。28.4秒に教える | 外れたら教えて。覚えます |
| 30–34 | アプリ名・DAY 048 / 100・URL のエンド画面（promo.html 側で描く） | なし |

字幕の「10問」は数字を書き込まず、画面から取る。記憶の空な別のブラウザ文脈で同じ占いを当たりまで進め（下見）、won の画面の問数を読む。本番の won の画面ともう一度突き合わせ、違えば止まる。

## 動きは3種類とも動画の秒で動かす

このアプリには Day 045 のような手動の時計が無い。動きの出どころは次の3つで、どれも実時間に任せると機械の混み具合でコマごとの進みが揺れる。

- JS のタイマーと時刻（考える顔・押した答えの光・霧の知らせ・差の札・受け流し）。`page.clock` を止めた状態でページを読み込ませ、1コマごとに `runFor` で進める。iframe の中の `setTimeout`・`Date`・`performance.now` も同じ時計で動く
- CSS のアニメーションとトランジション（霧の回転・読みの輪・浮かび上がる絵など）。これは `page.clock` では止まらない。毎コマ iframe の `document.getAnimations()` を全部止め、その動きが初めて現れた動画の秒からの経過を `currentTime` に入れる。無限に回る霧もこれで動画の秒どおりに回り、有限のものは終わりで止まる
- クリックと入力。時刻表の絶対時刻に行い、「動きが終わったら次へ」とは組まない。Day 042 は終わりの返事を待って字幕を進めていて、機械が混んだときに字幕だけが3秒遅れた

アプリは新しい質問が出てから350ms（開始直後は400ms）の答えを受け流す。時計を止めたまま2問続けて押すと2問目が捨てられるので、撮影の外では受付が始まるまで時計を進めてから押し、押すたびに問数が増えたかを確かめる。まぼろしと浮かび上がる絵は画像なので、毎コマ読み込みと展開を待ってから撮る。

撮影の外で進める準備（最初の2問と2回目の占い）の後は、有限の動きを終わりまで進めてから撮影を再開する。準備の途中の絵は1コマも写らない。スクリーンショットの `animations: 'disabled'` は使えない。Playwright の仕様で無限の動きが初期状態に戻され、霧が止まる。

## 料理と種：たこ焼き・20260996 に固定した

条件は「2問答えた状態から残り8問を2秒おきに答え、16.0秒の10問目で最初の推測が当たる」こと。水晶玉に映るのは読みの輪の料理なので、2問答えた時点からそれがたこ焼きで、読みが一度も下がらない種を総当たりで探した。20260996 では読みが 4→6→11→16→43→59→87→94% と上がり、10問目で100%になる。

推理のエンジンは制作中に2度直り、そのたびに選び直した（20260923→20260946→20260996）。料理データやエンジンを直すと、同じ種でも流れが変わる。条件から外れれば下見か1コマ目の検査が止めるので、そのときは料理と種を選び直す。

## 撮影用の見た目：iframe に CSS を差し込み、アプリのソースは変えない

隠したのは、見出し・足もと（共通の共有欄）・キーボードの手引きと、筋に関わらない操作（ひとつ戻る・最初から・もう一度占う・結果の共有・教えずに終える）。後者は、ぼかした iframe の下端から半分だけ覗き、画面を散らかしていた。教える欄の候補も隠している。1文字目の「ば」でだけ8品が並び、2文字目で消えるので、0.2秒だけ札が跳ねて見えたためだ。

大きさは2段に分けた。質問中は窓（`--ask`）を広げて水晶玉を寄りで大きく見せ、推測からの全景（`--big`）は札と「当たり！」が iframe に収まる大きさにした。「読み ◯%」・差の札・読みの軌跡はスマホで読める大きさまで上げた。

ほかに次の4点を変えた。

- iframe の背景を透明にし、夜空は promo.html が画面全体に描く。仕様上、ページと iframe の `color-scheme` が食い違うと iframe に不透明な下地が入るので、両方を dark にそろえてある
- 教えた後の札は字を少し小さくして、「覚えました。」と「次は…読めます。」の2行に収めた
- `main` の下に余白を足した。文書が短いと `scrollTo` は黙って手前で止まり、札が縁のぼかしに沈む。ツールは毎コマ、狙った位置まで送れたかを確かめる
- 教えた瞬間、アプリは先頭へ一気にスクロールを戻す。舞台が1コマで跳ねるので、0.5秒かけて戻すよう上書きした

## 検査：落ちたら動画を見て直し、検査は外さない

- 書き出した動画から字幕の札だけを切り出し、コマ差分で切り替わりを測る。4・10・16・20・26・30秒の6回と照合し、回数違いか0.4秒超のずれで失敗にする。測るのは元の30fpsのまま。20fpsに間引くと、ffmpeg の変換で全部が一律0.1秒遅れて測れた
- 1コマ目は、状態が質問中・2問回答済みで、水晶玉に映す料理がたこ焼き、まぼろしの層に `assets/dishes/takoyaki.webp` が読み込まれて濃さ0.2以上で出ていること
- 毎コマ、画面の状態を時刻表と照合する。16.0秒はたこ焼きの推測で読み100%、22秒は決め手の欄が iframe に収まっていること、28.4秒は教えた名前が札に出ていること。答えを押すたびに、受け流されていないことも確かめる
- 寸法1080×1920、音声あり、尺34秒±0.15秒。配信元以外への通信0件、ページのエラー0件（コンソールのエラーも数える）
- BGM は合成の段階で −17 LUFS・真のピーク −2.4 dBTP に合わせてあるので、ラウドネスを掛け直さない。AAC にした後を測り、−17±0.5 LUFS かつ真のピーク −1.5 dBTP 以下でなければ失敗にする。作成時の実測は −17.0 LUFS・−2.5 dBTP

## 既知の限界

- 0〜4秒のまぼろしは、ほぼ見えない。2問答えた時点の読みは4%で、アプリはこれを濃さ3割弱・強いぼかしで霧の奥に描く。茶色の影になるのは9秒ごろ、たこ焼きと分かるのは13秒ごろ。アプリの実際の見え方なので、動画側で濃くしていない
- 答えた瞬間（2・4…14秒）のコマでは、次の質問が0.3秒の溶け込みの始まりで透明になっている。2秒おきの一覧では質問欄が空に見えるので、文言は奇数秒のコマで確かめる
- 2回目の占いは、煮しめに近い肉じゃがのつもりで答えている。いまのエンジンは推測できる料理が残らないと途中で降参するので、肉じゃが・角煮を外したあと22問目で「参りました」になる。答えも推測も画面には写らない
- フォントと絵文字は OS に依存する（作成環境は macOS のヒラギノと Apple Color Emoji）
- 人の耳での聴取と、X・Instagram に上げた後の再圧縮の見え方は、このツールでは確かめていない
