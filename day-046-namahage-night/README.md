# Day 046 — 泣ぐ子は、いねがぁ

大晦日の夜、なまはげが山を下りて里の家々を回る横スクロールアクション。4ワールド20面。

## 何をするか

左右移動とジャンプだけで、面の右端にある**家の戸口**へたどり着く。着くと「泣ぐ子はいねがぁ」と吠える。
餅を食べると **ちび → なまはげ → 荒鬼** と大きくなり、荒鬼は二段跳びができる。被弾すると一段階もどる。
カラス・野犬・雪うさぎ・雪かきイノシシは上から踏める。着地せずに続けて踏むと点が倍（×2・×3）になる。
米俵20個で残機がひとつ増える。ミスは0.8秒で自動的にやり直しになる。

**面ごとの目標は3つのお札**。早駆け（目標時間内）・福集め（米俵6個と隠し餅1個）・無傷（被弾もミスもなし）。
戸口に触れればお札の数に関係なくクリアで、お札は別々の挑戦で取ったぶんも積み上がる。全20面で60枚。
米俵6個のうち3個は地上の主路に、3個は上段の棚に置いてある。隠し餅も上段にある。

## なぜこの題材か

なまはげは怖がらせる妖怪ではなく、**大晦日に山から里へ下りて家々を訪ね、怠けを戒めて祝福を置いていく来訪神**だ。
遊びの筋を行事の筋に重ねたかったので、ゴールを旗ではなく家の戸口にして、20面を通すと山から里へ下り切る形にした。
自作のマリオ風は世の中に山ほどあるので、操作の新しさでは勝たない。題材で勝ちにいく賭けをしている。

**なまはげを敵役にしない**と決めた。だから攻撃ボタンを作らず、**出刃包丁は絵の中にも持たせていない**（行事の道具を武器として扱わないため）。
戒める相手である子どもも敵に出さない。障害は雪・氷・風・鳥・獣だけにしている。

## 設計上の判断

- **操作は移動とジャンプだけ**。ボタンが増えるほど初見が落ちるので、20面ぶんの変化は仕掛けの側で作った。
  能力（風呂敷＝滑空／駆け鈴＝速く走る）も入力を増やさず、**持てるのはひとつだけ**にして拾い替えで性格が変わるようにした。
- **能力は近道と報酬の手段で、通せんぼには使わない**。各面の主路はちび・能力なし・二段跳びなしで通れる。
  能力が要る道には必ず受け床を置き、失敗しても下段の主路に戻るだけにしている。
- **上段へ入る手段は面ごとに1つだけ**にした。雪台・崩れる枝・風呂敷の滑空・駆け鈴の助走・踏んだ反動のどれかで、
  その面の頭に出る1行説明にどれを使うかを書いてある。棚の下は必ず雪床にして、**落ちても主路に戻るだけ**にした。
- **新しく覚えることは1面に1つ**。雪台は1-2、風呂敷は1-3、二マスの穴は1-4、崩れる枝は2-1、駆け鈴は3-2、
  雪かきイノシシは3-3、氷は3-4、というふうに初登場を1面1つに割り振っている（穴を1-4に寄せたため、
  荒鬼の二段跳びはどの面でも必須にしていない）。
- **早駆けの目標時間は自動操作の実測から決める**。`safe` の自動操作が戸口へ着いた tick を1.25倍し、
  120の倍数（＝1秒刻み）へ切り上げた値を `parTicks` にした。`lib/level-data.js` に面ごとの旧値・新値・根拠を書いてある。
- **面は手で置いた**（自動生成ではない）。最初に自動生成（平らな床＋穴と小物）で20面を作ったが、
  テストは通るのに遊びにならなかったので捨てた。置いたあとは毎回、実物の物理で走らせて到達と回収を確かめている。
- **跳べる距離が面の設計を決める**。滞空0.667秒×110px/s＝73px。3マスの穴（48px）は体の幅を足すと60px要るので、これが上限。
  当初の88px/s・-270では52.8pxしか出ず3マスを跳べなかったため、速度とジャンプを上げた。
- **高い足場の右端から落ちた先に穴を置かない**。足場の端では自動操作も人も一度跳んでしまうので、着地点は最大6マス先になる。
  ここを踏み外すと理不尽になるため、面データを作るたびに「足場の右端＋6マス」に穴が無いかを機械で調べている。
- **戸口の当たり判定は縦いっぱいの柱**にした。1マスぶんだけだと、跳んだまま通り過ぎて先で詰む（実際に自動操作が詰まった）。絵は1マスぶんだけ描く。
- **乱数を使わない**。敵も動く床も位置と時間の関数なので、同じ入力からは必ず同じ結果になる。到達性のテストとデモ撮影がこれに依存している。
- 更新は**1/120秒の固定刻み**。描画は320×192を整数倍で拡大する（`imageSmoothingEnabled = false`）。
- `lib/physics.js` はDOMにも時計にも触れない。状態を受け取って次の状態を返すだけ。
- **予告は絵を足さずに座標のずらしで作る**。雪うさぎは耳を2px下げ、イノシシは前脚の下に雪煙を3つ置き、崩れる枝は左右に1px揺れる。
  **色だけに頼らない**ために「!」も重ねている。倒した敵は24tickかけて16px上へ抜けて消える。
- **自動操作（`lib/autopilot.js`）はテストと紹介動画で共用**する。人の上手さを真似るものではなく、地形が通れるかを機械で確かめるためのもの。

## 絵

主人公の原画（`assets/hero-art.webp`）はAIの画像生成で作った3段階の並びで、タイトル画面にそのまま出している。
**ゲーム内のドット絵は、生成画像を自動縮小せず、16×16（主人公は10×14〜12×24）のマスに1マスずつ置いて作った**
（`lib/sprites/hero.js`・`lib/sprites/props.js`）。自動で縮小した版も試したが、10×14では顔がつぶれて読めず、
歩き・跳び・被弾のコマごとに顔が変わってしまったため使っていない。
パレットは全体で16色。背景は世界ごとに、山・杉林・吹雪・家並みを1画素ずつ塗り分けている。

## 操作

← → / A D：移動　Space / ↑ / W / Z：ジャンプ（短く押すと低く、長く押すと高い）
R：やり直し　Esc：面えらび　スマホは画面下端の3ボタン

## 保存

`localStorage` の `namahage.v1` 1件だけ。解放したワールド・音設定と、面ごとの
`{ bestTicks, bestScore, seals }`（`recordsV2`）を持つ。`seals` は 早駆け1・福集め2・無傷4 のビット和。
プレイ中の状態は保存しない。読めない・壊れている場合は初期値で動く。**外部通信はゼロ**。

## 検証

```sh
node --test day-046-namahage-night/tests/     # 単体
npx playwright test tests/e2e/day-046.spec.mjs # E2E（リポジトリ直下）
```

20面すべてについて、**敵・つらら・崩れる枝を全部有効にしたまま**自動操作で走らせ、ミスなく戸口へ届くことを確かめている。
報酬を狙う自動操作では、20面すべてで**米俵6個と隠し餅1個が取れる**ことも確かめている。
あわせて、新しい記号（`R B F S J %`）を消した地形でも届くことを確かめ、**主路が既存の記号だけで通れる**ことを保証している。
1-1 は「右だけを押し続ける走り」で最初の雪うさぎを踏めることを単体テストで固定している。
敵込みの難易度は機械では判定せず、実際に遊んで決める。
