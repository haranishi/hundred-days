# Day82「影討ち」の紹介動画

36秒・縦1080×1920・30fps・H.264（yuv420p・bt709）・AAC 192k。本物の遊びの画面だけで作り、闇と灯り、小石で釣る、背後の当て身、信長の討ち取りと燃え上がる本能寺を見せる。
本編は Day 直下の `demo.mp4`（BGM は B 案。2026-11-02 に本人が選んだ。`PROMO_MAIN_BGM=a` で A 案を本編にできる）。BGM 違いの A 案などの出力は、git の追跡外の `output/` に置く。

## 縦の作り方：縦長の窓でそのまま描く（a）を選んだ
- 試したもの：(a) 縦長の窓（720×1280 の CSS ピクセル・倍率1.5 → 1080×1920）でそのまま描く、(b) 横長（1920×1080）で描いて縦枠の中段に置き、上下をぼかした背景で埋める。(c) 中央の切り抜きは、縦の画角が同じなら (a) と同じ絵になる（違うのは HUD の並びだけ）ので (a) にまとめた。
- (a) を選んだ理由：(b) は遊びの絵が幅1080×高さ608に縮み、暗い夜の画面ではぼかした背景が黒い泥になって人物も扇も読めなかった。(a) は肩越しの追従カメラが縦長でも人物を中心に大きく映し、HUD（目的・攻略段階・レーダー・明るさの目盛り・構え・小石）も読める大きさになった。
- 撮影のときだけ CSS で隠した HUD：操作キーの一覧（縦の窓では折り返して下中央の案内と重なった）、視点をつかむ案内、目的の細かい説明、経過時間、共有欄。討ち取り演出の題字「本能寺の変」も、終わりの画面の題名と重ならないよう隠した。目的・攻略段階・レーダー・明るさ・構え・小石・その場でできること（E など）はそのまま映している。
- 色の調整：ゲームの夜はとても暗く、スマホの画面では人物と扇が沈むので、全編に同じ曲線（暗部だけを持ち上げ、黒と白は動かさない）をかけた（`render.mjs` の `GRADE`）。

## 録画は自動操作で作った
- 3つの撮影（`scenes.mjs`）はどれも配信物（`index.html` と `assets/`）を自前の静的サーバー（ポート4880〜4899）で開いた `?autostart=1&seed=1` の本物の遊びの画面で、操作は道順の台本（`window.__autopilot`）と自動操作の口（`window.__input`。Q で狙う・離して投げる）だけで行った。数値・結果・状態は書き換えていない。捕まらない設定（`god=1`）も使っていない。
  - `gate`：通りから表門の灯りへ出て「？」を溜め、闇へ戻る。小石を塀越しに投げる。発見 0・小石 1。
  - `atemi`：台本 `ura` の始めを使い、裏門の提灯持ちが門の前を南へ過ぎたら後をしゃがんで追って当て身。発見 0・当て身 1。
  - `ura`：ゲームに入っている台本 `source/tools/routes/ura.json` をそのまま流した。結末は討ち取り（win）・発見 0・当て身 0。
- カメラだけを固定の構図にした場面が2つある（11.3–14秒の境内、20–24秒の信長）。ゲームの調べ用の口 `window.__game.look` で、カメラ以外は何も変えない。20–24秒は台本が「しゃがんで待つ」手順の間だけ固定し、動き出す前に追従へ戻した。
- 時間は「仮の時計」で進めた：ページの `requestAnimationFrame` と `performance.now` を差し替え、1/60 秒を2回まわすごとに1コマ（1/30 秒）撮る。撮影に時間がかかってもゲームの中の時間と録画の 30fps がずれない。ゲームのソースは変えていない（`lib/harness.mjs`）。
- 描画は GPU（Chromium・ANGLE の Metal・Apple M4 Pro）。ソフトウェア描画なら `assertGpu` で止まる。

## 曲（BGM）
コードで作ったオリジナル曲（`audio.mjs`。サンプルや外の音源は使わない）。D の陰旋法（都節：D・E♭・G・A・B♭）、90 BPM（1拍＝2/3秒）。映像の切り替え（10.0・11.33・14.0・18.0・20.0・24.0秒＝15・17・21・27・30・36拍目）、当て身の E（16.0秒＝24拍目）、討ち取りの E（26.0秒＝39拍目）、終わりの画面（31.33秒＝47拍目）はすべて拍の上にあり、そこに太鼓を置いた。
- 構成：導入（0–10秒。低いドローンと撥弦の動機、遠い太鼓）→高まり（10–18秒。1拍ごとの撥弦、切り替えに太鼓と拍子木）→張りつめ（18–24秒。A と B♭ の刻み、太鼓の連打）→息をのむ（24–26秒。ドローンと高い一音）→討ち取りの一打と山（26–31.3秒）→余韻（31.3–36秒。最後の1.2秒でフェードアウト）。1コマ目から鳴っている。
- A 案＝静かな緊張：低いドローン＋撥弦（Karplus–Strong）＋遠い太鼓。B 案（本編）＝脈打つ太鼓が中心：半拍ごとの太鼓と締め太鼓、撥弦は合いの手だけ。
- 音量は ffmpeg の `ebur128` で測って −17 LUFS・真のピーク −2 dBTP 以下に合わせる（先読みのリミッターで、切り詰めはしない）。直流は 25Hz の高域通過で除く。

## 作り直す手順
リポのルートの `node_modules`（Playwright）と ffmpeg を使う。このフォルダに package.json は無い。
```
node capture.mjs gate          # 撮影（1場面ずつ。--every N で N コマに1枚の下見、--port で 4880〜4899 のポート）
node capture.mjs atemi
node capture.mjs ura           # output/takes/<場面>/ に JPEG の連番・states.jsonl・take.json
node audio.mjs                 # output/bgm-a.wav・bgm-b.wav・audio.json
node subtitles.mjs             # output/subs/*.png・layout.json
node render.mjs                # ../../demo.mp4（B案）・output/promo.mp4・promo-a.mp4・promo-b.mp4・promo-clean.mp4・first-frame.png・timeline.json
node audit.mjs                 # 関門（不合格なら終了コード 1）。output/contact-sheet.jpg・audit-demo.json
node audit.mjs output/promo-a.mp4
node render.mjs --break sub-shift && node audit.mjs output/broken-sub-shift.mp4   # 落ちることの確認
node render.mjs --break loud && node audit.mjs output/broken-loud.mp4
```
編集の正本は `edit.mjs`（どの撮影の印から何コマ使うか・字幕の秒・テンポ）。撮り直してコマ番号が1つずれても、印からの相対なので同じ場面になる。`render.mjs` は、古い撮影の残りのコマを使わないよう、今の撮影の「録る区間」かを確かめる。

## 関門（`audit.mjs`）
長さ 36.0±0.05秒／1080×1920／30fps／H.264 yuv420p（bt709）／音声あり（AAC）／積分ラウドネス −17±1 LUFS／真のピーク −1 dBTP 以下／20MB 以下／1コマ目と5・15コマ後の絵の差／黒・真っ白のコマが無い（コマと各秒の平均輝度）／字幕が10%の内側（`layout.json` の配置と、字幕なしの基準 `promo-clean.mp4` との差で明るくなった画素の範囲）／字幕の入れ替わり時刻を動画から測って絵コンテと0.1秒以内／1コマ目から音／直流なし／切り替えと打音の拍（±50ms。AAC の前エコーで数十 ms 早く測れることがある）。
