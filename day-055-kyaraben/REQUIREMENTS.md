# キャラ弁設計図（仮称）の要件

絵を1枚えらぶと、そのキャラ弁を実際に作るための材料と量、前の晩と当日の朝の手順、食材ごとの実寸の型紙、完成イメージを出すWebアプリ。2026-09-30に本人が依頼した試作で、企画と調査の記録は Obsidian の `02_notes/40_プロダクト企画/キャラ弁アプリ_企画/` にある。名前は仮。

## 決めたことと理由

| 決めたこと | 理由 |
|---|---|
| AIのAPIを使わず、画像は端末の中だけで処理する | 無料でAPIキーが要らない。子どもの絵を外へ送らずに済む。サービス側で既存キャラの画像を生成・提供しない形にできる（startup-design の調査で、サーバー側の生成は著作権の高リスク領域と分かった）。型紙は色の領域から実寸で出せる |
| 画像を読むAIと画像生成AIを組み合わせる案は捨てた | 1回ごとに料金がかかり、APIキーを隠すサーバーも要る。有名キャラでは生成を断られたり通ったりと安定しない。Gemini API は18歳未満が使うサービスを認めていない。部品の名前（目・耳など）をAIに当てさせる機能は、v2で任意にするか検討する |
| 主役は型紙の印刷 | 汎用AIは絵を出して終わる。実際に切れる型紙が差になる。完成イメージは見当をつけるためのもので、写真風にはしない（出来上がりとの落差を生まないため） |
| 子どもの絵とオリジナルキャラを前面に出す | 既存キャラは、家庭で作って楽しむ範囲（私的使用）で使うよう画面に書く |
| 食材は定番の一覧から選ぶ | 自由に選ばせると、手に入らない食材や切れない細さの案が出る |

## 使う人と場面

3〜5歳の子の親。遠足や運動会の前の晩に「この絵のお弁当にして」と頼まれた。キャラ弁には慣れていない。台所でスマホを見ながら作る。

## ユーザーストーリー

1. 絵を撮るか選ぶだけで、買う物と量が分かる（買い物の前に）
2. 食材ごとの実寸の型紙を印刷して、そのとおりに切れる
3. 前の晩にやることと、朝にやることが分かれている
4. 家に無い食材を、別の食材に置き換えられる
5. 難しそうなら、細かいパーツを減らして簡単にできる
6. アレルギー（特定原材料）と衛生の注意が分かる
7. 作る前に、出来上がりの見当がつく
8. 手元に絵が無くても、サンプルで試せる

## UX 5階層

| 階層 | 決めたこと |
|---|---|
| 戦略 | 成功は「型紙の印刷（PDF保存を含む）か買い物メモのコピーまで進むこと」。差は実寸の型紙、前の晩と朝の段取り、アレルゲンの目印 |
| 要件 | 下の「v1で作るもの」 |
| 構造 | 1ページ3段階（①絵をえらぶ ②食材と大きさを整える ③作る）。印刷は専用のレイアウト |
| 骨格 | スマホは縦1列（完成イメージ→調整→材料→手順→型紙→注意→共有）。960px以上は左に完成イメージと調整、右に材料・手順・型紙 |
| 表層 | ご飯の白、のりの黒、卵の黄、トマトの赤。弁当箱らしい角丸。本文16px以上、文字のコントラスト4.5:1以上、押せる所は44px以上 |

## v1で作るもの

- 入力：ファイル選択（スマホではカメラも）、ドラッグ&ドロップ、貼り付け、サンプル2枚（こどもの絵風とオリジナルキャラ）。PNG・JPEG・WebP・GIF、20MBまで
- 読み取り：背景の自動除去（透過PNG、縁の色、白い紙と影）。消し残しは「読み取った絵」をタップして消し、元に戻せる
- 食材：色ごとに自動で割り当てる。選び直しと「使わない」ができる
- 調整：弁当箱（幼児用13×9cm、小学生16×11cm、大人18×12cm）と難易度（かんたん、ふつう、こだわり）
- 結果：完成イメージ、材料と量の目安（アレルゲンの目印つき）、道具、手順（前の晩と当日の朝・寸法つき）、食材ごとの実寸の型紙（1cmの確認枠つき）、衛生とアレルギーの注意、私的利用の注意、買い物メモのコピー
- 共有：共有の4点セット（`shared/share.js`）、OGP と canonical（仮に `https://kyaraben.pages.dev/`）

やらないこと：AIによる部品名の推定、写真風の画像生成、アカウント、保存、ギャラリー、課金。

## 受け入れ条件

- 画像をどこにも送らない（外部への通信0件を E2E で実測する）
- サンプルを押してから3秒以内に結果が出る（手元のMac）
- 型紙の SVG は mm 指定の実寸で、1cmの確認枠が10mmになっている
- 幅390pxで横スクロールが出ない。キーボードだけで全操作できる
- 単体テストと E2E が全件通る
