# キャラ弁設計図

絵を1枚えらぶと、キャラ弁の材料と量・前の晩と当日の朝の段取り・食材ごとの実寸の型紙・完成イメージを出す静的サイト。依存は無い。ES modules をそのまま配るので、ビルドもいらない。目的と決めたことの正本は `REQUIREMENTS.md` にある。

## 動かし方

| コマンド | すること |
|---|---|
| `npm run serve` | http://127.0.0.1:4417/ で配る（ポートは `PORT` で変えられる） |
| `npm run test:unit` | `lib/` の単体テスト（`node --test`） |
| `npm run test:e2e` | 画面の E2E。Playwright は `~/Projects/hundred-days` のものを借りる |
| `npm run fixtures` | `tests/fixtures/` のテスト用 PNG を作り直す（node:zlib だけ） |
| `npm run samples` | `assets/samples/` の2枚を SVG から作り直す |
| `npm run og` | `og.png`（1200×630）を撮り直す。撮ったら目で確かめる |
| `npm run build` | `dist/` に公開する物だけを写す（公開は本人が行う） |

画面ロック中は Playwright の Chromium が起動しない（SEGV か起動の時間切れ）。そのときは `KYARABEN_BROWSER=webkit npm run test:e2e` で WebKit を使う。`samples` と `og` は Chromium が起動しなければ自動で WebKit に切り替える。

## しくみで迷いやすいところ

- 画像は端末の中だけで処理する。外への通信は無く、E2E で0件を確かめている。画像も設定も保存しない。
- 読み取りに AI は使わない。縁の色から背景を塗りつぶし、k-means で減色し、色を食材の系統に割り当て、小さすぎる島を隣の層へ移す。乱数を使わないので、同じ絵と設定なら同じ型紙になる。
- `lib/` の直下は DOM に触れない純粋な関数だけにしてある（Node で単体テストするため）。canvas を使う描画は `lib/draw/`。
- 選び直した食材は、層の番号ではなく色の系統ごとに覚える。設定を変えて計算し直すと、層の番号が入れ替わることがあるため。
- 弁当箱や難易度を変えると、読み取りからやり直す。小さすぎるパーツの線引き（mm²）が、実寸の大きさで決まるため。

## 落とし穴

- 型紙の SVG は mm 指定で、1単位が1mm。印刷の設定が「ページに合わせる」だと大きさが変わる。画面の案内と型紙の1cmの枠で確かめてもらう。
- 型紙の `widthMm`・`heightMm` はキャラの実寸。SVG の枠は、名前と1cmの枠を置く余白のぶん、それより大きい。
- 白い紙の決まり（L\*>70 かつ C\*<12 なら背景）は、縁からの塗りつぶしではいつも使う。タップで消すときは、タップした点が白っぽいときだけ使う。ほっぺを消したのに、つながった白い顔まで消えるのを防ぐため。
- 「かんたん」では、黒い層を先に0.8mm太らせてから多数決で掃除する。先に多数決をかけると、細い線が消えてしまう。
- 円形度0.7以上・12mm以下は「丸」になるので、小さな四角も「ストローで抜く」になる。
- Safari の select は高さが31px前後で固定される。`appearance: none` で見た目を作り、44px以上を保っている。
- `shared/share.js`・`share.css` は `~/Projects/hundred-days/shared/` の正本の写し。ここでは書き換えない。幅の調整は `app.css` の `#share .share` で行う。
- 撮影やテストでサーバーを Bash の `&` で起こさない（シェルが返らず止まる）。E2E は Playwright の webServer、撮影はスクリプトの中で spawn して最後に kill する。
- 量はすべて目安。のり・チーズなどは、切りくずのぶん面積に1.3〜1.5倍のゆとりを掛けてから数える。
