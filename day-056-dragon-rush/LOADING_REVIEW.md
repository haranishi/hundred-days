# 起動・怪獣切り替えの読み込み画面

## 設計と完了条件

ユーザーストーリー：街や怪獣の準備が長いとき、待つ理由と進み具合を知り、準備完了後に遊びたい。

- 戦略：読み込み中か、操作できる状態かを区別できるようにする。
- 要件：初回起動と怪獣切り替えを覆い、完了時に閉じる。失敗時には再読み込みを案内する。
- 構造：入口→読み込み→選択／遊び。怪獣を替えると読み込み→新しい怪獣の遊びへ戻る。
- 骨格：画面中央に状況、完了した段階数、経過時間。待機中は背後の操作を防ぐ。
- 表層：既存の濃紺・夕暮れ色を継承。スマホ横向きとPCに対応し、動きを減らす設定に従う。

進捗は通信量の推測ではなく、実処理の段階を表示する。残り秒数を作らない。
初回はゲーム・街・怪獣・描画・操作、切り替えはモデル・描画・街と操作の順。
タイマーだけで完了にせず、最初の描画と操作準備の後に閉じる。
長い待機には通信・端末の説明と再読み込みの操作を出す。

今回は公開Web版の変更。nativeの同期・署名・App Store準備、ゲームの強さや素材の変更は対象外。

## 検証方法

通信を遅らせた初回起動と別の怪獣の選択で、準備中に画面が出て完了後に閉じることを確認する。
通信失敗、押し直し、キーボード、PC・スマホ、動きを減らす設定も確認する。
段階の逆戻り・古い処理からの完了通知・失敗後の遅い完了通知は単体で検証する。
既存のタッチ操作・PC操作・共有・3体の描画を回帰確認し、画像と結果を記録する。

## 読み込み画面の自己点検

独立評価や実機の評価ではない。390・768・1440幅と667・844横向きの画像を目視確認した。
ゲーム全体の面白さ・長期利用は採点対象外。

| UI項目 | 点 | 確認した証拠 |
|---|---|---|
| 3秒理解 | 2 | 起動・切り替えに状況と待つ案内 |
| 視覚階層 | 2 | 状況→説明→段階→経過時間の配置 |
| 配色 | 2 | 現在段階は色・番号・文字で区別 |
| 余白・整列 | 2 | 5サイズの通常待機で重なりなし |
| 文字 | 2 | 小さい横向きでも見出し・段階を読める |
| モバイル | 2 | 横はみ出しなし・再試行44px以上 |
| 導線 | 2 | 自動終了と実際の再読み込みを確認 |
| 一貫性 | 2 | 起動・切り替え・失敗で同じ色と部品 |
| アクセシビリティ | 1 | inert・Tab・減速設定を確認、実読み上げは未確認 |
| 体感速度 | 1 | 準備中と完了の一致を確認、実時間の短縮は未実施 |

自己点検18/20。未確認の実読み上げ・実機の評価を合格したとは扱わない。
体験は「開始→待機→操作」「別の怪獣→待機→再挑戦」「失敗→再読み込み」を実操作で確認した。
今後の優先事項は、実機での待機時間測定、モデル転送量の削減、読み上げ確認、実機の低速回線確認、ページを開き直さない再試行。
今回の残件は実機・読み上げの確認であり、読み込み時間そのものを短くしたとは主張しない。
