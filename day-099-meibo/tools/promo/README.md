# Day099「meibo」の宣伝動画

縦 1080×1920・30fps・30.000秒（120 BPM・15小節・900コマ）。営業リスト向け CRM「meibo」の実画面と、AI 生成の人物映像 2 本（冒頭 4 秒・末尾 7 秒）で構成する。絵コンテの正本は `timeline.mjs` で、映像と音の両方が同じ表を読む。

## 再生成（4 工程）

出力先 `$OUT` はリポジトリの外に置く（mp4・wav・png・jpg はコミットしない）。実行ファイルとデモ DB は引数か環境変数 `MEIBO_BIN`・`MEIBO_DEMO_DB` で渡す。

```sh
promo=day-099-meibo/tools/promo
# 1. 撮影（--ai-a / --ai-b 省略時は仮絵で動作確認できる）
node "$promo/render-promo.mjs" --out-dir "$OUT" \
  --meibo-bin "$MEIBO_BIN" --db "$MEIBO_DEMO_DB" \
  --ai-a "$AI_A" --ai-b "$AI_B" --no-encode
# 2. BGM・効果音の合成（撮影した実時刻 cues.json で同期）
node "$promo/promo-audio.mjs" --variant a --out-dir "$OUT/audio" --cues "$OUT/cues.json"
node "$promo/promo-audio.mjs" --variant b --out-dir "$OUT/audio" --cues "$OUT/cues.json"
# 3. 音の数値検査（22 項目＋スペクトログラム）
node "$promo/verify-audio.mjs" --out-dir "$OUT/audio" --cues "$OUT/cues.json"
# 4. 書き出し（silent / a / b / demo の mp4・first-frame.png・contact-sheet.jpg）
node "$promo/render-promo.mjs" --out-dir "$OUT" --encode-only --audio-dir "$OUT/audio" --mux a,b
```

- `--selftest` はブラウザ・サーバーなしで絵コンテ 900 コマと安全域・合図を検査する。
- `--frames 120-240` は先頭から操作を再現し、指定範囲だけを `preview-120-240/` へ保存する。
- `--ai-a-in`（既定 0 秒） / `--ai-b-in`（既定 0.5 秒、0.5〜7.5 秒を使用）で AI 映像の切り出し開始秒を調整できる（音声は捨てる）。
- `demo.mp4`（540×960・無音・15.6 秒）は `DEMO_RANGES` の UI 場面だけをつなぎ、AI 映像を含めない。

## なぜこの作りか

- **2 ページ撮影（iframe を使わない）**：meibo は埋め込みを拒むヘッダーと Host/Origin/CSRF 検査を持つ。`127.0.0.1` の空きポートへ複製 DB で子プロセスを起動し、アプリ側（DPR 3）を `clip` 付きで撮ってステージ（CSS 540×960・DPR 2）へ貼る。
- **幅の場面切り替えとカメラ寄り**：架電モードと取引先一覧は幅 1280、商談・月次集計は 2×2 で読める幅 960 を使う。カメラ幅を 540px 以下に抑え、アプリ本文（13px）がステージ上で 12px 以上になるよう要素の座標から寄りを計算する。
- **時計とアニメーションの制御**：`page.clock` で 1/30 秒ずつ進め、撮影用 CSS で遷移・アニメーション・smooth スクロールを止める。商談ボードの横送りはコンテナの `scrollLeft` を毎コマ計算して置く。
- **AI 映像は JPEG 連番へ展開**：Playwright の Chromium は H.264 を再生できないため、ffmpeg で 1080×1920（cover）・30fps の JPEG 連番にしてステージへ貼る。
- **金額・社名・日付は実画面から読む**：取引先名の変化・次回対応日時・着地予測の金額は固定書きせず DOM から読み取り、`capture-report.json` に残す。読み取れなければ札を出さずに続ける。

## 踏んだ罠と対策

- **アプリのCSPが撮影用CSSを止める**：meiboは `style-src 'self'` で配信するため、遷移停止のスタイルの差し込み（`addStyleTag`）が拒否された。撮影用のコンテキストだけ `bypassCSP: true` にした（アプリ本体のヘッダーは変えない）。
- **縦長のスマホでは、9:16 の動画の左右が約9%切れる**：全画面に敷き詰められる（cover）ため。字幕と注記の端が欠けるので、文字・札は左右 x=49..491 に収める（`STAGE.safeX`）。撮影中に実測して警告し、`capture-report.json` の `textExtents` に最大の広がりを残す。窓の中身（画像）は端が切れてよい作り。断り書きは16px以上（13〜14px だとスマホ幅で約9px）。
- **CI は依存を入れる前に単体試験を走らせる**：`render-promo.mjs` の先頭で `@playwright/test` を読んでいたため、試験がこの道具を読み込むだけで CI が「パッケージが無い」と落ちた（手元には入っていたので気づかなかった）。Playwright は撮影を始める関数の中で `await import()` する。道具の先頭で第三者パッケージを読まないことは、`tests/promo/cli.test.mjs` が見張る。
- **`hidden` 属性が効かず、AIの仮絵が実クリップを覆った**：`#ai-placeholder` に `display` を指定していたため、`hidden` が無視された。`[hidden]{display:none!important}` を足した。
- **活動メモは必須（`required`）**：架電フォームの `#activity-note` が空だと「保存して次へ」がバリデーションで止まる。撮影前の準備で短い合成メモを入れておく。
- **商談ボード再描画時の `scrollLeft` 戻り**：段階 `<select>` を「受注」へ変えると盤の DOM が作り直され横スクロールが 0 に戻る。変更前の `scrollLeft` を保持して直後に戻してから受注列へパンする。
- **`.crm-board` の `offsetLeft` 基準**：`position: static` のため `offsetLeft` がボード基準にならない。`getBoundingClientRect()` 差分＋`scrollLeft` で列位置を求める。
- **時計停止中の待機**：`page.clock.pauseAt` 中は `requestAnimationFrame` 依存の待機が止まることがある。要素・状態待ちは Node 側ポーリングで行い、3 秒で見つからなければ場面名・手順名・探した文言を出して止める。
- **字幕と色域**：切り替え時に透明度を 0 から上げると薄い途中コマが出るため、下から 14px 上がるだけにする。JPEG 連番は全範囲（pc）のため `scale=in_range=pc:out_range=tv` で書き出す。
- **子プロセスの後始末**：`pkill` は使わず、自分が `spawn` した PID だけを終了時・シグナル時に止める。

## BGM・効果音と権利

- 120 BPM・15 小節・30.000 秒。0–4 秒は呼出音（400Hz×15Hz 揺らぎ×2 回）と夜の室内アンビエンスのみ、4.0 秒に BGM が入る。A 案「朝のリスト」（ト長調・マリンバ分散和音とクラップ）、B 案「机の灯り」（ヘ長調・エレピとブラシ・丸いベース）。
- 音はすべて Node の計算だけで合成（サンプル・既存曲の旋律・外部 API 不使用）。検査は −16 LUFS ±1・真のピーク −1.5 dBTP 以下・クリップ 0・合図ずれ ±5ms・主要合図の前後 100ms 音量差 3dB 以上・無音の穴なし・末尾 0。耳での試聴は本人が行う。
- 画面は meibo 実画面の合成データ。人物映像 2 本は AI 生成（カードに明記）。字幕書体は OS の Zen Kaku Gothic New（SIL OFL 1.1、リポジトリ非同梱）。
