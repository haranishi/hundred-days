# 漏洩の地図 — 記録から備えへ

## 社会的な役割

公開された漏えい資料は、ニュースを読んで終わると経験が共有されにくい。このプロダクトは、原資料を確かめる手間を減らし、教育や小規模組織の備えの見直しに使える入口を目指す。記録数を増やすことだけを成果にしない。

主な利用者は小規模組織の担当者・教育者。個人が利用するサービスの公表内容を確認する用途も支える。地図は探索の入口、詳細は根拠の確認、学習画面は次に考えることを示す役割とする。

## ユーザーストーリーと受け入れ条件

| 利用者 | したいこと・理由 | 受け入れ条件 |
|---|---|---|
| 初めての利用者 | 目的と最初の操作を知りたい | 冒頭に目的・検索、主な表示を3つに整理 |
| サービスの利用者 | 何が確認されたかを根拠から知りたい | 検索→公表内容・確認状況→原資料が連続する |
| 小規模組織の担当者 | 類似する記録から備えを見直したい | 原因別の確認の問い、公的資料、日本の関連記録に到達 |
| 教育者 | 不明・可能性・確認済みを区別して説明したい | 元の確認状況・数値の注記を保持し、一般的対策と個別事故を区別 |
| スマホ・キーボード利用者 | 詳しい条件で絞り込み、戻りたい | 全画面幅で条件パネルを開閉、フォーカスを戻す。390pxで横はみ出しなし |

## UX5階層（実装前の判断）

1. **戦略**: 公表された出来事を、確かな理解と次の備えにつなぐ。成果はデータ数や地図の演出ではなく、原資料の確認と備えの理解。
2. **要件**: 検索・地域・原資料・一般的な備えの入口を優先。詳しい条件、比較、原因グラフは必要なときに開く。新たな監視・履歴保存・ランキングは追加しない。
3. **構造**: 主な入口は「地図で見る」「一覧で読む」「備えを学ぶ」。学習テーマ→日本の原因別記録→公表内容→同じ学習テーマという往復を作る。条件パネルは独立して開閉できる。
4. **骨格**: 上部は短い目的・検索。中央は地図または読みやすい一覧、右は公表内容と出典。左の常設条件を外して中央を広げる。詳細の補足は開閉し、最初に要旨と原資料を見せる。
5. **表層**: 明るい背景・濃い本文・緑の主操作を統一。暗い表現は地球儀の中に限定。日本語の操作名、44pxの主操作、読みやすい行間、動きを減らす設定を保つ。

## 社会的効果を確かめる次の段階

少人数の利用者に、(1)指定の記録と原資料へ到達、(2)確認済みと未確認を説明、(3)自分の組織で見直す項目を一つ挙げる、を試してもらう。到達時間と誤読、理解できた内容を同意の上で聞く。閲覧数や記録数だけでは効果を判断しない。今回のブラウザ検証はこの利用者テストの代替ではない。
