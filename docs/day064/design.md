# 漏洩の地図 — ユーザーストーリーとUX5階層

## ユーザーストーリー

| 誰が | 何をしたいか | なぜか | 受け入れ条件 |
|---|---|---|---|
| 情報漏洩のニュースを見た人 | 日本企業の公表事例を一望する | 単発ニュースから規模と傾向をつかみたい | 開いて30秒以内に大きさ・原因・確認状況の読み方が分かる |
| 利用中のサービスが気になる人 | 企業/サービス名で探し詳細を開く | どの情報が対象だったのか原文で確認したい | 日本語/英語/別名で検索し、日付・対象・一次資料まで到達する |
| 学生やセキュリティの学習者 | 同じ原因・期間の事例を比較する | 外部侵入だけでなく内部持ち出しや設定不備も理解したい | 原因別ハブ、単位別の規模順、年/確認状況の絞り込みが連動する |
| スマホ/キーボード/3D不可環境の人 | 企業の詳細と根拠を読む | 3D操作に習熟していなくても情報を得たい | 一覧と詳細が独立して使え、一覧を選ぶ操作で3Dも反応する |

中心の操作: 規模を眺める → 気になる企業を選ぶ → 公表内容と出典を確認する → 原因/時期を変えて次の企業へ進む。

## UX5階層

### 戦略

情報漏洩の公表事例を理解するための探索ツール。目的は企業を断罪するランキングではなく、公表された情報の規模と原因を比較し、一次資料へつなぐこと。収録した事例の集合であり、日本全体の統計・網羅的な事故一覧ではない。

### 要件

- 暗いグラフ画面、原因ハブ、規模に応じた企業ノード。ドラッグ回転、ズーム、全体表示、2D切替。
- 企業/サービス検索、件/人/ID/未公表の単位切替、原因・公表年・確認状況の絞り込み。条件に合う企業数を表示。
- 詳細: 公表規模と留保、企業/サービス、発表日、要約、対象の情報項目、比較上の注意、公式資料、確認日。
- 原因は根拠のある分類だけにする。大きさは対数尺度、未公表は固定径で中抜き、可能性は中抜きの見た目と文字で区別。
- 同一企業に複数事例がある場合は表示条件内の最大事例を代表として表示し、別事例は詳細から選べる。累計にしない。
- 共有は公開済み事例の選択状態だけ。ユーザーの検索語や行動履歴を送らない。
- 外部フォント・写真・ロゴ・解析・広告は使わない。図形とアイコンは独自のコード。依存のOSSライセンスを同梱する。

### 構造

一画面。左の探索欄と規模順の一覧、中央の3Dマップ、右の企業ノート。マップと一覧は同じ絞り込みデータと選択IDを使用。単位が変わったら対応する事例だけで順位と大きさを再計算する。

フィルタ後に選択が消えたときは、現在の条件の案内に戻す。ゼロ件は検索語と条件を残してリセット導線を示す。URLの事例IDは存在を検証し、事例の単位に合わせて初期表示する。

### 骨格

- 上部: Day64 / タイトル / 収録数 / データ確認日 / 読み方。
- 左: 検索 → 単位 → 原因/年/確認状況 → 規模順の企業一覧。数値と未確定表記を常に並べる。
- 中央: マップを主役にする。左上に表示単位と企業数、下に原因の凡例。右上に2D/3Dと全体表示。操作の説明は一行。
- 右: 選択企業名と規模を最優先、その下に確認状況・公表日・内容・公式資料。出典を折り畳まない。
- 768px以下: 探索欄は開閉パネル、詳細は下部ノート。スマホでもマップと選択ノートの切替を最小限にする。

### 表層

Obsidianの知識グラフに近い落ち着いたダークUI。青黒の背景、細い仕切り、読みやすい白文字、原因別の淡い青/紫/珊瑚/琥珀。警報風の点滅や装飾的グリッチを避け、静かな探索体験にする。日本語はシステムフォント、数値は等幅。基本文字14〜16px、タップ44px以上、通常本文コントラスト4.5:1以上。

## 設計が実装に与える判断

- 規模だけで断定しないため、単位と確認状況の切替をマップの近くに置く。
- 原文へ到達するストーリーを満たすため、ノート内の公式資料を常時表示する。
- 初回の入力負担を減らすため、確認済みの実例を初期表示し、最初からマップとノートを見せる。
- 一覧を同じデータの別表示として実装し、3Dが使えない環境でも中心のタスクを完遂できるようにする。

## 過去資料の拡充とUI改訂（2026-10-11）

ユーザーストーリー: 初めて見る人が「いつの事例が、どの原因で、どれくらいの公表規模か」を図と短いカードでつかみ、企業を選んで原文を確かめる。過去を調べたい人は全事例を年代順に読み、同じ企業の別年の事案へ移動する。

- 戦略: 最新ニュースだけに寄らず、過去資料を含む公表事例のアーカイブにする。取得資料の掲載行を全件点検し、年度資料の選定条件と収録の空白も明らかにする。
- 要件: 全履歴、単位別の規模比較、年代の棒グラフ、原因の件数、年を指定した絞り込み、企業の複数事例の移動、資料ごとの収録状況。紛失・廃棄・誤表示・原因未公表を扱う分類を追加する。
- 構造: 上部で収録数・企業数・期間を把握 → 中央の年代・原因から絞る → 全履歴カードまたは同単位の比較を選ぶ → 右のノートで根拠を確認。3D/SVGは表示切り替えから探索する。全履歴の異なる単位を同じ棒の長さで順位付けしない。
- 骨格: 全履歴を最初に表示する。検索とフィルタは左、年代と原因・表示切り替えは中央、企業ノートは右。カードは企業名・公表年・規模・原因・確認状況の順に読む。同一企業も事例ごとに表示し、情報を省略しない。スマホは図とカードが先に見え、検索パネルとノートへ移れる。
- 表層: Obsidian風の暗色と原因色を保ちつつ、本文14px以上、余白・罫線・数値の大きさに段階を付ける。重要な説明を日本語にする。棒グラフには件数・単位・年代のラベルを付け、色だけで区別しない。

多数ノードのマップでは、すべての事例を描画し、企業名は選択中・指しているものと主要なノードを優先する。選択したノートと検索結果はどの表示でも共通。未公表や複数区分の数字を勝手に合算しない。政府の年度表と企業が直接公表した資料をノート内で見分けられるようにする。

### 5,000〜1万件への拡充とRust（2026-10-11）

- 企業別の公表事例と、政府台帳の届出記録を区別する。地域・台帳フィルタ、届出日と発生日、未公表の規模、通知元と事故主体の違いをノートで説明する。海外の追加についてユーザーへ任意の確認を提示した。
- 全件の軽い索引を一度読み、詳細は分割ファイルから必要時に取得する。検索・集計・並べ替えはRust/WasmのWorkerで実行する。故障時は同じ条件のJavaScript処理で閲覧を継続する。
- 初期表示は年代とカード。1ページ24件、全件数と現在の範囲を表示する。3Dはタブを開いてから読み込み、最新の最大120記録を描画する旨を画面に明示する。全記録は検索とページ送りでたどれる。
- 比較は同じ単位を選択したときのみ可能。規模不明の通知台帳から被害人数を推測しない。台帳を横断して重複事故・人数を合算しない。

## ObsidianのUIメモを参照した可読性の改訂（2026-10-11）

ユーザーストーリー: 初めて使う人が、企業名で検索し、一つの記録を選び、何が起きたか・規模の定義・原資料を読む。分布に関心がある人は年代・原因を開いて全期間を絞る。スマホでは長い説明の前に検索と結果へ到達する。

事前にObsidianの「UI_コンポーネントとパターン」「レイアウト・視覚的階層」「データ可視化の基礎」「アクセシビリティとUXライティング」とデザイントークン集を読みました。採用する原則は、1画面の主役を決める・最低3段の優先順位・内側より外側を広くする余白・比較には棒の長さ・直接ラベル・補足の段階開示・操作が分かる文言。ノート内のCV改善率や時点依存のトレンド数値はアプリへ持ち込みません。

- 戦略: 13,550という収録規模だけでなく、調べたい一件へたどり着けることを優先する。
- 要件: 目立つ企業検索、解除できる条件チップ、現在の結果数、選択状態、原資料の入口、スマホで開閉できる分布、全件をたどれるページ送り。
- 構造: 短い説明・収録数→企業検索と地域→現在の結果の一覧/比較/マップ→選んだ記録の詳細。左の記録一覧はマップ時の補助にし、時系列カードとの重複を減らす。
- 骨格: 8/16/24/32pxの余白。収録数を一つの大きな数字にし、組織数・期間・資料数は補助情報へ。検索はスマホでも折りたたまない。細かい条件と長い根拠は必要時に読む。
- 表層: 初期案は明るい背景、濃紺の本文、青を操作と選択へ。本文16px、補助ラベル12px以上、フォーカスと44pxの主要タップ領域。原因の色は文字と併用し、色だけの判断を求めない。

公開参考は [Datawrapperのグラフ例](https://www.datawrapper.de/charts) と [Linearの機能・画面構成](https://linear.app/features)。グラフと一覧/詳細の整理を参考にし、コード・画面素材・ブランド表現を複製しません。ユーザーには明るい背景/現在のダーク背景の任意の選好を提示しています。

## 国内の侵入関連記録の拡充（2026-10-11）

ユーザーストーリー: 日本の企業・団体の不正アクセスを過去から調べたい人が、一操作で国内の外部侵入へ絞り、組織名や年代で記録を選んで、公表文と調査結果を確認する。

- 国内201記録に公表アーカイブ・国内事例索引から2,321記録を追加。合計2,522、外部侵入1,622・ランサムウェア280とする。「日本の外部侵入を見る」から国内・外部侵入の条件へ移り、検索語や以前の条件を解除する。
- 一括取得した資料を流出の確認済み事故として扱わない。追加記録は基本「公表・報道記録」、出所は「公表アーカイブ」「報道一覧」を表示する。原発表を確認した結果は別の更新ファイルに保持し、「流出なし」「未確認」「流出確認」を詳細に反映する。
- 報道索引の日付は公表・発生・報道が混在するため、一覧とグラフは「記録の日付・年」を使用し、詳細で日付の定義を説明する。人数・件数が未照合なら合計不明にし、複数区分を合算しない。
- 既存事例、同一発表URL、組織内の明示された続報等を整理し、全3,122入力行の取込・重複・既存への統合・除外を台帳に保持する。異なる団体・日付の同一事故は残り得るため、公表記録数を独立した事故数と呼ばない。
- 全15,871記録の索引と159個の分割詳細を使用。24件表示・最大120ノード・Rust/Wasmの検索と代替処理を維持する。大きい本文JSONや全行の取込台帳は通常の初期表示では取得しない。

取込根拠、原資料の照合、実ブラウザと配信物の確認は [国内拡充の検証報告](verification/JAPAN_EXPANSION_REPORT.md) に記録する。今回の目的はデータの拡充と出所の明確化で、前段の長時間探索やUI自己採点を繰り返していない。
