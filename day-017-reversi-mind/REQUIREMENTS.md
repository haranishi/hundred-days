# Day 017 — AIの読みが見えるリバーシ

## 一言で

リバーシで対局しながら、**AIが今どのマスを何点と見ているか**が盤面に重なって見える。しかも**深さ1手から4手へ読みを深めるたびに数字が書き換わり、最善手が入れ替わる過程が見える**。

## なぜ「オセロ」ではなく「リバーシ」なのか

「オセロ」はメガハウスの**登録商標**。ルール自体は19世紀末にイギリスで考案された**リバーシ**で、特許も実用新案もない。8×8の緑盤・白黒石の**意匠権も1993年に失効**している。名称を「リバーシ」にすれば商標の問題は生じない。あわせて**緑の盤・本家に寄せた配色は採らない**（意匠権は失効しているが、寄せない方が説明コストが低い）。

---

## ユーザーストーリー

> **リバーシで負けたとき、自分の何が悪かったのか分からない人**として、
> **AIがどのマスをどう評価しているかを盤面の上で見たい**。
> なぜなら**「そこは角を取られるから悪い」と言われて初めて、次から避けられる**から。

補助ストーリー：

> **AIが何を考えているのか興味がある人**として、
> **読みが深まるにつれてAIの意見が変わる様子を見たい**。
> なぜなら**「AIが考える」がブラックボックスではなく手続きだと分かる**から。

## UX 5階層

### ① 戦略層（なぜ作るか）

| | 内容 |
|---|---|
| 提供側の目的 | 100日チャレンジDay017。企画の軸である「AI駆動開発」を、**アプリの中身そのもの**で見せる |
| ユーザーの目的 | **リバーシを遊びたい、ではない。「AIは何を考えているのか」を覗きたい** |
| 差別化 | 強いAIではなく**思考が見えるAI**。既存のリバーシ実装は無数にあるが、評価値と読みの深化を見せるものは少ない |

> 🔴 **ここで「遊びたい」ではなく「覗きたい」と定めたことが、以降の判断を全部決めている。**

### ② 要件層（何が要るか）

必須：

1. 人 vs AI で対局が成立する（合法手・返し・パス・終局）
2. **候補手に評価値が重なって見える**
3. **なぜその手が良い／悪いのかが日本語で読める**
4. **読みの深さが上がるたびに数字が更新される**
5. 4状態対応（フェーズ Day11-20 の解禁軸）

やらないこと：

- 強さの追求（世界最強を目指さない）
- 対局の保存（localStorage解禁は Day21-30。フェーズ違反になる）
- 人 vs 人、オンライン対戦

### ③ 構造層（情報の並び）

**盤面が主役。評価は別パネルに出さず、盤面のマスに重ねる。**

> 🔴 **却下した案：評価値を右側のリストに出す。** 盤面とリストで視線が往復し、「見えている」感覚が消える。**重ねることが要件そのもの**なので、ここは譲れない。

情報の優先順位：
1. 盤面と石（常時）
2. 候補手の評価値（思考表示ON時）
3. AIの説明（1行・手番のあと）
4. 石数・手番（補助）

### ④ 骨格層（画面配置）

```
┌──────────────────────────┐
│ AIの読みが見えるリバーシ          │
│ ● 12 - 2 ○     あなたの番です    │
├──────────────────────────┤
│      a  b  c  d  e  f  g  h     │
│   1  ・ ・ ・ ・ ・ ・ ・ ・      │
│   2  ・ ・ ・ 12 ・ ・ ・ ・      │  ← 数字＝評価値
│   3  ・ ・ 31 ○  8 ・ ・ ・      │     色＝良い(赤)〜悪い(青)
│   4  ・ ・ ●  ○ ○ [45] ・ ・     │  ← 枠＝いまの最善手
│   ...                           │
├──────────────────────────┤
│ 読みの深さ： ■■■□  3手目を読み中  │  ← 進むたび上の数字が動く
├──────────────────────────┤
│ 💬 f4が最善。角(h1)へ繋がる筋を作り  │
│    ながら、相手の打てる場所を5→2に  │
│    減らせる。                      │
├──────────────────────────┤
│ [ AIの読みを見る ✓ ] [ 最初から ]  │
└──────────────────────────┘
```

> 🔴 **「読みの深さ」バーを骨格層で入れた。** ②の要件4を満たすには、数字が動く**理由**が画面上に無いと「バグで数字がチラついている」に見える。

### ⑤ 表層（見た目）

- 盤：**緑ではなく藍色系**（本家に寄せない・上記の理由）
- 石：黒／白のまま（これは記号であって意匠ではない）
- 評価値：**青（悪い）→ 灰 → 赤（良い）** のヒートマップ。数値も併記（色だけに頼らない＝色覚多様性への配慮）
- 最善手：太い枠で囲む（色に加えて形でも示す）

## UX5階層を通した結果、変わったこと（4件）

| # | 通す前 | 通した後 | どの層で変わったか |
|---|---|---|---|
| 1 | 評価値をヒートマップで重ねるだけ | **日本語の説明を必須要件に格上げ** | ①で目的を「覗きたい」と定めたため。数字だけでは「覗けた」ことにならない |
| 2 | 評価値は右側のパネルに一覧表示 | **盤面のマスに重ねる。パネル案は却下** | ③。視線の往復が体験を壊すため |
| 3 | AIは即座に着手する | **反復深化（深さ1→4）で読みを進め、その過程を見せる** | ②の要件4。かつ①の「ブラックボックスではなく手続き」に直結 |
| 4 | 「読みの深さ」表示は無し | **進捗バーを追加** | ④。数字が動く理由が無いとバグに見える |

> 3番目が最大の変更。**当初は「AIに演出用の待ち時間を入れて思考中に見せる」つもりだったが、それは嘘の演出**になる。反復深化なら**本当に読みが深まって意見が変わる**ので、演出ではなく実装で見せられる。

## 4状態（フェーズ Day11-20 の要件）

| 状態 | このアプリでの現れ方 |
|---|---|
| **空** | 対局前。「対局を始める」ボタンと遊び方 |
| **読込中** | AI思考中。読みの深さバーが進み、評価値が更新される |
| **不正入力** | 打てないマスをクリック。**理由つきで返す**（「そこは石を挟めません」） |
| **エラー** | ⚠️ **該当なし。** ブラウザ内で完結し外部通信が無いため、通信エラー・取得失敗が構造的に起きない。無理に作らず「起きない」と明記する |

終局は独立した状態として扱う（勝敗表示＋もう一度）。

## 技術構成

- 依存ゼロ。バニラJS（ES Modules）
- `lib/board.js` — ルール（合法手・返し・パス・終局判定）
- `lib/ai.js` — 評価関数と反復深化αβ探索
- `lib/explain.js` — 評価の内訳から日本語の説明を組み立てる
- 外部通信なし・保存なし
