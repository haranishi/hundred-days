# Day 017「AIの読みが見えるリバーシ」

リバーシで対局しながら、**AIが今どのマスを何点と見ているか**が盤に重なって見える。さらに**1手先→4手先と読みを深めるたびに数字が書き換わり、最善手が入れ替わる過程**がそのまま見える。

## なぜ「オセロ」ではないのか

作る前に権利関係を確認した。結論は「**ルールではなく、名前と見た目が問題になる**」。

- **ゲームのルールは著作権で保護されない。** 釣りゲータウン2事件（知財高裁 平成24年8月8日）で、一審が認めた著作権侵害を高裁が逆転し、「魚を具体的な魚の絵ではなく、魚影をもって表現すること自体は、**アイデアの領域**」と判断している
- **「オセロ」は株式会社メガハウスの登録商標**（1973年〜）。ここだけが本当に踏んではいけない線
- ルール自体は19世紀末のイギリスで考案された**リバーシ**で、特許も実用新案もない
- 8×8の緑盤・白黒石の**意匠権は1993年に失効**している

つまり名称を「リバーシ」にすれば商標の問題は生じない。**盤の配色も緑にしていない。** 意匠権は既に切れているが、寄せなければ説明する必要すら無くなる。

## 何が新しいのか

リバーシの実装は無数にある。差別化を「AIの強さ」に置くと勝ち目が無いので、**「AIの思考の可視化」**に置いた。

**1. 評価値を盤に重ねる**

候補手のマスに、AIがその手を何点と見ているかを数字で出す。青（悪い）→ 赤（良い）のヒートマップで、**数値も必ず併記する**（色だけに意味を持たせない）。

**2. 読みが深まる過程を見せる**

AIの手番では**反復深化**で深さ1→4と読み直し、そのつど盤の数字を更新する。深さが上がると評価が変わり、最善手が入れ替わることもある。

> 🔴 **これは演出ではない。** 当初は「待ち時間を入れて考えているように見せる」つもりだったが、それは嘘になる。反復深化なら実際に探索し直しているので、数字が動くことに根拠がある。

**3. なぜその手なのかを日本語で言う**

「角(h1)を取れる。角は絶対に裏返らない」「相手の打てる場所を5→2に減らせる」「角の斜め隣（X打）。角を相手に渡す筋を作りやすい」のように、評価の内訳を言葉にする。

## 設計上の判断

**評価関数の要素を3つだけに絞った。** 位置の価値・相手の打てる場所の数・石数（終盤のみ重視）。要素を増やせば強くなるが、**盤に出る数字の理由を日本語で説明できなくなる**。強さより説明可能性を取った。`explain.js` はこの3要素の外側を語らない。

**根の各手だけαβの窓を開き直している。** 通常のαβ探索は「最善手より悪い」と分かった時点で打ち切るため、2番手以降のスコアは正確な値ではなく上界・下界にしかならない。このアプリは**全候補手の点数を画面に出す**ので、そこが丸められると表示が嘘になる。速度より表示の正確さを優先した（深さ4で1.2ms なので実用上の問題はない）。

**同点の最善手は同点のまま出す。** 初手は盤が左右対称なので4手とも同じ48点になる。ここを1つに絞れば見た目は綺麗だが、「同点なのに1つだけ最善に見せる」嘘になる。枠は4つとも付ける。

**エラー状態は作らなかった。** このフェーズ（Day11-20）の解禁軸は4状態対応だが、外部通信も保存も無いアプリでは通信エラー・取得失敗が構造的に起きない。空・読込中・不正入力の3つを実装し、**エラーは「起きない」と REQUIREMENTS.md に明記した**。無理に作ると嘘の状態が増える。

## 実装した4状態

| 状態 | 現れ方 |
|---|---|
| 空 | 対局前。遊び方と「対局を始める」 |
| 読込中 | AIが読んでいる最中。深さバーが進み、盤の数字が更新される |
| 不正入力 | 打てないマスを押したとき。**理由つきで断る**（「自分の石で相手の石を挟める場所だけに打てます」） |
| エラー | 該当なし（上記の理由） |

## 構成

```
lib/board.js    ルール（合法手・裏返し・パス・終局）
lib/ai.js       評価関数と反復深化αβ探索
lib/explain.js  評価の内訳 → 日本語の説明
app.js          画面と状態遷移
```

依存ゼロ・外部通信なし・保存なし。すべてブラウザ内で完結する。
