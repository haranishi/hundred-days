# Day74: リンクの毒見

届いたリンクを開く前に、「なりすましの兆候」と「サイトの守りの弱点」を調べて、ふだんの言葉で返すWebアプリ。
[アプリを開く](https://hundred-days.pages.dev/day-074-link-dokumi/)

## 使い方
1. 届いたリンクを貼って「調べる」を押す。メッセージを丸ごと貼っても、最初のリンクだけを調べる。
2. いちばん上の帯で、判定の一文と「いま取る行動」を見る。
3. 「なりすましの兆候（訪問者向け）」と「サイトの守り（運営者向け）」を切り替えて、所見を開く。所見には、実際に見えた値と、運営者向けの直し方が付く。

試すだけなら、見本3つ（実在しない `.example` のサイト）を押す。見本は通信しない。

## 結果を2つの軸に分けた理由
守りが弱いだけのサイトを「危険」と読ませないため、また、守りが堅い偽サイトを見逃さないために、点数と段階を混ぜない。
運営者向けの点数の先頭には「点数が低くても、危険なサイトという意味ではない」と必ず書く。
訪問者向けの判定は「見当たらない／気になる／注意／近づかない」と、つながらなかったときの「不明」。どれも色・記号・言葉の3つで示す。

## 言わないこと・やらないこと
- 「安全です」「詐欺サイトです」と言い切らない。見えた事実と、そこからの読みを分けて書き、「見ていないこと」を結果に必ず並べる。
- 診断先の画面は撮らない・描かない。危険なページを、こちら側で見せないため。読み取った題名や文章の先頭（最大400字）は、「取得した値」の欄に文字としてだけ並べる。
- ログイン・入力欄への送信・ファイルの実行・繰り返しのアクセス・既知の詐欺サイト一覧との照合はしない。一覧との照合は、押したときだけ開く外部サービスに任せる。

## 利用者の情報の扱い
- 「?」から後ろは既定で送らない（個人の情報やログイン用の文字列が入りやすいため）。「#」から後ろは送らない。
- 本人確認・登録・配信停止のような一度きりらしいリンクは、調べる前に確認を出す。開いただけで使えなくなることがあるため。ただし手がかりが「?」の中の語だけで、「?」から後ろを送らない既定のときは出さない（送らない部分は使い切らない）。
- 端末には何も残さない。サーバーは診断の履歴を残さず、同じ相手への連続アクセスを避けるために結果を最大5分だけ一時的に置く。
- ブラウザの「戻る」で入力の画面に戻れるよう、結果を出すときに履歴を1つだけ積む。URLは変えず、やり直しでは積み増さない。戻ったときは前のURLを全部選んだ状態にする（貼り付けで置き換わる）。「別のリンクを調べる」は欄を空にする。前のURLが残ったまま貼ると、前のリンクのほうを調べてしまうため。
- 診断先に断られたとき（403・429・ボット対策）は、周りの情報を名前と登録日だけに絞り（`around` に `site=0`）、相手のサイトへ追加のアクセスをしない。
- 外部の診断サービスへ渡すURLからも「?」と「#」を落とし、何が渡るかをボタンの上に書く。

## 落とし穴
- 取得した文字列（題名・ヘッダー・フォームの送り先）は、相手のサイトが自由に決める。画面は文字としてだけ表示し、文字の向きを変える制御文字は `⟦U+202E⟧` の形で見せる。
- 編集の道具が、正規表現に書いた `\u2028` などの書き方を生の制御文字に展開して、構文が壊れたことがある。見えない文字の範囲はコードポイントの数で持っている。
- 一部のサイトは、ブラウザ以外からのアクセスを遅くしたり断ったりする。ブラウザになりすますことはせず、「時間切れ」「断られた」と表示する。待ちが長いときは、画面が止まっていないことと、結果は最後に出ることを知らせる。
- 画面の文字は端末のフォント（ヒラギノ・游・Noto など）で表示し、フォントのファイルは同梱しない。`og.png` は、macOS のヒラギノで描いた文字を画像にしたもので、`og.svg` を `.agent-harness/runs/day074-link-dokumi/render-og.mjs` で書き出した（画像生成AIは使っていない）。
- 登録ドメインの境界（どこまでが1つの登録か）は、手書きの表でなく Public Suffix List（MPL 2.0）の本物で引く（`lib/psl-data.js`。`tools/gen-psl.mjs` で生成。出典は `THIRD_PARTY_NOTICES.md`）。手書きの表では `sakura.ne.jp` や `s3.amazonaws.com` のような「利用者ごとのサブドメイン」を表せず、S3上の偽の確認画面を公式扱いにしてしまった。
- 画面に書く数字（転送の回数・読む量・回数の上限・一時的に置く時間）は `lib/contract.js` の `LIMITS` から作る。手で書くと、判定側やサーバーと食い違う。
- 日本語は文節で折り返す。Chromium系は CSS の `word-break: auto-phrase`、対応しないブラウザ（iPhoneのSafariなど）は `Intl.Segmenter` で文節らしいかたまりを作って `<wbr>` を差す。文字そのもの（textContent）は変えない。「script-src」「1分あたり約12回」のような語は、折らないかたまりで包む。
- 横並び（flex）のボタンやリンクの中で文字を分けると、分けた所に隙間が出る。折らないかたまりで包むのは、ボタン・リンク以外の文だけにしている。
- こちら側（回数の上限・サーバー・通信）の都合で調べられなかったときは、相手のサイトの問題に見える言い方をしない。判定側の `evaluate` に `failure`（rate_limited・server_error・network）を渡すと、行動は「待ってから、もう一度」の1件に、一文と所見もこちら側の言い方になる。コピーは出さない。
- 段階の名前は「見当たらない／気になる／注意／近づかない」。接続失敗の「名前が見つからない」と同じ語を避け、「なし」とも言い切らない。

## 開発と検証
リポジトリ直下で `npm run build` のあと、`node scripts/serve-dist.mjs` を実行する。確認先は `http://127.0.0.1:4173/day-074-link-dokumi/`。
観測API（`/api/day-074/trace`・`around`）は静的サーバーには無いので、画面の試験は通信を差し替えて行う。

- 判定・観測: `node --test day-074-link-dokumi/tests/`
- 画面: `npx playwright test tests/e2e/day-074.spec.mjs`
- 公開ゲート: `npm run publish:check -- --day 74`
- 仕様: `.kiro/specs/day-074-link-dokumi/`
