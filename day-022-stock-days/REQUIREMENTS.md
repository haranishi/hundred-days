# Day 022「その備蓄、何日もつ？」要件定義

いま家にある水・食料・簡易トイレの量と人数を入れると、**この家が何日もつか**を1つの数字で出し、**いちばん先に尽きるもの**と、**目標（3日／7日）まで足りない量**を買い物の単位で示す。入力は端末内（localStorage）にだけ保存する。

## 背景と狙い

- 9/1 は防災の日。備蓄を「している」人は多いが、量と期限を把握している人は少ない（防災食の備蓄率59%・「まだ不十分」と感じる人が約半数＝需要ベース100案 #077）。
- 既にあるものとの違い。東京備蓄ナビは世帯構成から「必要量のリスト」を出す。備蓄管理アプリ（クロスゼロ等）は品目を1つずつ登録して期限を追う。保険会社の簡易計算ツールは食料だけを日数にする。**このアプリは「いま家にある分で何日もつか」を水・食料・トイレの3本で一度に出し、先に尽きるものを名指しして、足りない分を「2Lペットボトルあと◯本」の形にする**ところまでを1画面でやる。登録も通信も無い。
- 難易度設計（Day21–30）: **localStorage の初めての本格利用**（入力を覚える）＋**演出を1つ**（タンクが満たされるバー）。

## 数字の出典（画面にも出す）

| 項目 | 1人1日の量 | 出典 |
|---|---|---|
| 飲料水 | **3L**（調理用を含む） | 首相官邸「災害が起きる前にできること」：飲料水3日分（1人1日3リットルが目安）／大規模災害では1週間分の備蓄が望ましい |
| 食料 | **3食**（1日3食として計算する前提） | 農林水産省「災害時に備えた食品ストックガイド」：最低3日分〜1週間分×人数分。大人1人1週間の例＝水21L・カセットボンベ6本程度 |
| 簡易トイレ | **5回** | 内閣府「避難所におけるトイレの確保・管理ガイドライン」（平成28年4月）：「1日当たり必要な便袋の枚数＝最大想定避難者数×5回」「排泄の回数は5回が平均的であると言われています」 |

- 目標日数は **3日（最低）／7日（望ましい）** の2択。既定は7日。
- **年齢による差は付けない**（公式の目安が人数ベースのため）。乳幼児・高齢者・ペット・持病の分は「自由行」で本人が1日の量を決める。
- 生活用水（トイレを流す水・洗面）は含まない。含まないことを画面に書く。

## ユーザーストーリー

1. 備蓄を買ったつもりの私は、いま家にある水・食料・トイレの数を入れるだけで、「うちは何日もつのか」を1つの数字で知りたい。
2. 数字を見た私は、「何が先に尽きるのか」と「7日にするにはあと何を何個買えばいいか」を、そのまま買い物メモにできる形で知りたい。
3. 赤ちゃんやペットがいる私は、公式の目安に無いもの（ミルク・おむつ・ペットフード・薬）も同じ画面で日数にしたい。1日の量は自分で決めたい。
4. 一度入れた私は、次に開いたとき入力が残っていて、期限が切れたものを教えてほしい。ただし名前や住所は入れたくないし、どこにも送ってほしくない。
5. 入力の途中でも、いまの日数がどう変わるかを見ながら数を直したい。

## UX5階層

- **戦略**: 「備蓄リストを出す」でも「在庫台帳をつける」でもなく、**いま家にある分を日数に換算して、次に買う物を1つ決めさせる**道具。成功＝開いて1分で「うちはトイレが先に尽きる。7日にするなら簡易トイレをあと50回分」まで分かる。不安を煽らない。
- **要件**: 人数・目標日数・必須3行（水/食料/トイレ）・自由行（最大4）→ 行ごとの日数、全体の日数（＝最小）、ボトルネック、目標までの不足量、行ごとの期限（いちばん早い期限1つ）。保存は端末内。出典と前提を画面に出す。
- **構造**: 単一画面。上から「世帯と目標」→「在庫の入力（3行＋自由行）」→「結果（日数・先に尽きるもの・不足量）」→「期限」→「出典・前提・限界」→シェア。入力中も結果が見えるよう、**要約1行を画面に固定**する。
- **骨格**: ヘッダー／固定サマリー（あと N.N 日・先に尽きる◯◯・7日まであと◯◯）／世帯（人数ステッパー＋乳幼児・ペットのトグル）／目標（3日｜7日）／行カード（手持ちの量・1人1日の量と出典・日数バー・期限）／自由行の追加チップ／不足量リスト／保存の表記と消去／出典・前提／シェア。
- **表層**: 落ち着いた紙色の明るい画面に、**タンクが満たされるバー**（0〜7日の目盛、3日・7日に印）。先に尽きる行は琥珀で目立たせ、7日そろった行は青緑。赤は期限切れにだけ使う。大きな数字は等幅。

### UX5階層を通したことで決まった実装（10件）

1. 全体の日数は **各行の最小値**とし、その行を「先に尽きる」と名指しする（戦略層：数字は1つ、次の行動は1つ）
2. 不足量を目標日数に対して **買い物の単位**で出す。水は L に加えて「2Lペットボトル◯本」を併記（戦略層）
3. 必須3行の1人1日量は公式の目安に固定し、**それ以外は「1日に使う量」を本人が入れる自由行**にした。出典の無い数字をアプリが作らない（要件層）
4. 人数は合計1つ＋「乳幼児がいる」「ペットがいる」のトグル。ONにすると自由行の候補チップ（ミルク・おむつ／ペットフード・ペットの水）を出すだけで、年齢別の係数は持たない（要件層：公式根拠に合わせる・個人情報を持たない）
5. 目標は3日／7日の2択で既定7日（要件層：官邸「1週間分が望ましい」）
6. 入力のたびに localStorage へ自動保存し、「この端末に保存されています。サーバーには送りません」を常時表示。消去は同じボタン2回押し（ダイアログ禁止）。**localStorage が使えない環境でも入力と計算は動き、保存できない旨だけ出す**（要件層：4状態のエラー）
7. 期限は行ごとに「いちばん早い期限」1つだけ。品目ごとの台帳にはしない（構造層：在庫管理アプリにしない・1日で作れる範囲）
8. 結果の要約1行を固定表示し、入力中も日数が動くのを見せる（構造層）
9. タンクが満たされるバーを演出として1つだけ入れる。`prefers-reduced-motion` ではアニメーションを止める（表層：Day21–30の「演出1つ」）
10. 赤は期限切れにだけ使い、不足は琥珀で示す。「危険」「死」などの語を使わない（表層：煽らない）

## 機能要件

**世帯と目標**
- 人数: 1〜20 の整数。ステッパー（−/＋）＋直接入力。既定 2
- トグル: 乳幼児がいる／ペットがいる（自由行の候補チップの出し分けだけに使う）
- 目標日数: 3日／7日（既定 7日）

**必須3行**（常に表示・削除不可）
| 行 | 手持ちの単位 | 1人1日 | 不足量の表記 |
|---|---|---|---|
| 飲料水 | L（小数可・2Lペット本数のヒントを添える） | 3L | 「+◯L（2Lペット◯本）」 |
| 食料 | 食 | 3食 | 「+◯食」 |
| 簡易トイレ | 回 | 5回 | 「+◯回」 |

**自由行**（0〜4行）
- 名前（チップ: カセットボンベ／粉ミルク・液体ミルク／おむつ／ペットフード／常備薬／その他＝自由入力・20字まで）
- 手持ちの量・単位（本/回/枚/日/袋/個 から選ぶ or 4字まで自由）・**1日に使う量（世帯合計）**・期限（任意）
- 1日に使う量が 0 または空の行は計算から除外し、「1日に使う量を入れると日数が出ます」と行内に表示
- 候補のヒント（出典つき・任意）: カセットボンベ＝農水省ガイドの例で大人1人1週間に6本程度

**計算**
- 必要量/日 = 1人1日量 × 人数（必須行）／自由行は入力値そのまま
- 日数 = 手持ち ÷ 必要量/日。**小数1桁で切り捨て**（2.47→2.4）。手持ち0は0.0日
- 全体の日数 = 有効な行の最小値。先に尽きる行 = 最小の行（同点は 水→食料→トイレ→自由行 の順で先）
- 不足量 = max(0, 必要量/日 × 目標日数 − 手持ち)。水は L と「2Lペットボトル本数 = 切り上げ(L÷2)」
- 目標をすべて満たしたら、不足量の代わりに「7日分そろっています」を静かに出す（祝福の派手な演出は不要）

**期限**
- 各行に「いちばん早い期限」（`<input type="date">`・任意）
- 今日より前＝「期限切れ」（赤バッジ）、30日以内＝「期限が近い」（琥珀バッジ）
- 期限切れがある行は日数の計算からは**外さない**（在庫としてはある）が、サマリーに「期限切れ: 飲料水」を1行添える

**保存**
- キー `day022.stock.v1`。内容: `{ v:1, people, targetDays, flags:{infant,pet}, rows:{water,food,toilet:{stock,expiry}}, custom:[{id,name,unit,stock,perDay,expiry}], updatedAt }`
- 壊れたJSON・未知のバージョンは無視して初期状態から始める（例外で画面を止めない）
- 「入力を消す」は同じボタンを2回押す方式（1回目で「もう一度押すと消えます」に変わり、3秒で戻る）

**4状態**
- 空: 在庫が1つも入っていない → サマリーに「人数と在庫を入れると、ここに日数が出ます」
- 不正入力: 負数・数値でない・100000超 → 行内にエラー文、その行は計算から除外し、サマリーは「入力を直してください」
- エラー: localStorage 不可 → 上部に「この環境では保存できません。入力は画面を閉じるまで有効です」
- 読込中: 該当なし（通信なし・同期読み込み）。ただし保存済みデータの復元直後に一瞬でも空状態を見せない

**シェア・OGP**
- `index.html` の `</head>` 前に `shared/share.css` と `shared/share.js`。`<meta name="share:text">` にアプリ名を含める。`<main>` 末尾に `<div id="share"></div>`
- OGP・canonical は build が入れるのでアプリ側に書かない

## 非機能・技術

- 依存ゼロ・ビルドなしの vanilla JS（ES modules）。`index.html`＋`app.css`＋`app.js`＋`lib/`（純ロジック: 計算・不足量・期限判定・保存の直列化。DOMに触れない）
- 外部通信ゼロ（fetch 無し・外部フォント無し・画像も無し）。CSP はリポジトリ既定のまま
- アクセシビリティ: すべての入力に `<label>`、サマリーは `aria-live="polite"`、ボタンは44px以上、文字と背景のコントラスト 4.5:1 以上、フォーカスリング可視
- レスポンシブ: 320 / 390 / 1280px で横スクロール無し
- `alert/confirm/prompt` を使わない。ユーザー入力を `innerHTML` に入れない
- テストゲート: `node --test`（lib、20本以上）＋ Playwright E2E（`tests/e2e/day-022-stock-days.spec.mjs`、10本以上：空状態・計算と先に尽きる行・不足量とペット本数・目標切替・自由行・不正入力・再読込で復元・消去の2回押し・期限バッジ・localStorage不可・3幅で横はみ出し無し）

## やらないこと

- 品目ごとの在庫台帳・バーコード登録・通知（期限は行ごとの1日付だけ）
- 年齢・性別による必要量の係数（公式目安に無い数字を作らない）
- 生活用水・燃料・電源の必要量計算（自由行で本人が扱う範囲に留める）
- 買い物リンク・商品の推薦・アフィリエイト
- アカウント・同期・サーバー保存
