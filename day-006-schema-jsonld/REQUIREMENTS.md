# Day 006 要件定義：構造化データ、いま出るやつだけ

## 1. 何を解くか

「構造化データを入れましょう」と言われた制作者・店舗が、貼るだけのJSON-LDを手に入れられるようにする。

ただしJSON-LDジェネレーターは無料のものが大量にある。**このアプリの存在理由は「いま実際に効くタイプだけを出す」こと。** 制作時（2026-08-13）にGoogle検索セントラルを確認したところ、**FAQの構造化データは2026年5月7日にGoogle検索から廃止**され、リッチリザルトテストとSearch Consoleレポートからは2026年6月に、Search Console APIからは**2026年8月**に削除されると告知されていた。既存のジェネレーターの多くはいまもFAQPageを主力メニューとして出している。そこを止めるのがこのアプリの主題。

ネタの出どころは需要ベースWebアプリ100案（2026-08-11作成）の **#086 Schema.org 構造化データ生成**（需要★★★）。3回の候補提示を経て本人が選定した。

## 2. 主要アクション（1本のハッピーパス）

ページの種類を選ぶ → フォームを埋める → JSON-LDが出る → コピーする。

## 3. Day 1–10 の解禁範囲との対応

| 軸 | 今回 | 解禁範囲 |
|---|---|---|
| 外部依存 | 0個（ライブラリ・フォント・通信・画像ファイルなし） | Lv.1 ✓ |
| データの持ち方 | ハードコード（業種一覧・必須/推奨の定義・廃止情報はコード内） | Lv.1 ✓ |
| UIの状態 | 選んだ種類のフォームと出力のみ | Lv.1 ✓ |
| 専門性との接続 | 受託HP制作の実務ネタ（薄く） | Lv.1〜2 |
| AIの使わせ方 | 仕様調査とコーディングの補助 | Lv.1 ✓ |

**4状態対応（空／読込中／エラー／不正入力）はDay 11以降の解禁**なので作らない。代わりに不正入力を構造で減らす：

- 種類は5つのボタンから選ぶ（自由入力させない）
- 業種・著者種別・曜日の営業区分はすべて `select`
- 日付は `datetime-local`、URLは `type="url"`、電話は `type="tel"`
- 必須が未入力のときは、出力欄に「◯◯を入れると出ます」と1行出すだけ。エラー画面・再試行導線は作らない

## 4. 対応するページの種類

種類の選択は5つのボタン。**廃止された2つにも入口を用意するのが設計の意図**——選ばせて、止めて、理由を見せる。

| ボタン | schema type | 挙動 |
|---|---|---|
| 店舗・事業所 | `LocalBusiness`（＋サブタイプ） | 生成する |
| 記事・お知らせ | `Article` / `NewsArticle` / `BlogPosting` | 生成する |
| パンくず | `BreadcrumbList` | 生成する |
| よくある質問 | `FAQPage` | **生成しない**。警告カード |
| 手順・使い方 | `HowTo` | **生成しない**。警告カード |

廃止2つのボタンは、見た目で「これは違う」と分かるようにする（打ち消し線やグレー等）が、押せる状態にしておく。

## 5. 生成する3タイプの仕様

Google検索セントラルで2026-08-13に確認した内容。**ここから推測で足さない。**

### 5-1. 店舗・事業所（LocalBusiness）

**必須は2つだけ。** これは非自明なので画面に明記する。

| 欄 | プロパティ | 備考 |
|---|---|---|
| 店名・事業所名 | `name` | 必須 |
| 郵便番号 | `address.postalCode` | 住所4欄で `PostalAddress` を組む。必須 |
| 都道府県 | `address.addressRegion` | |
| 市区町村 | `address.addressLocality` | |
| 番地・建物 | `address.streetAddress` | |

`address.addressCountry` は `"JP"` を自動で付ける（画面に入力欄は作らず、説明に書く）。

推奨（空ならJSONにキーを出さない）：

| 欄 | プロパティ | 仕様 |
|---|---|---|
| 業種 | `@type` | 下記の一覧から選ぶ。**最も具体的なサブタイプを使う**のがGoogleの推奨 |
| 電話番号 | `telephone` | 市外局番を含める |
| サイトURL | `url` | |
| 価格帯 | `priceRange` | **100文字未満**。例「¥1,000〜¥2,000」 |
| 営業時間 | `openingHoursSpecification` | 下記 |

業種サブタイプ（ハードコード。日本の中小・店舗で頻出のものに絞る）：
`LocalBusiness`（指定しない）／`Restaurant` 飲食店／`CafeOrCoffeeShop` カフェ／`Bakery` パン屋／`BarOrPub` バー・居酒屋／`Store` 小売店／`ClothingStore` 衣料品店／`BeautySalon` 美容室・サロン／`Dentist` 歯科／`MedicalClinic` クリニック／`RealEstateAgent` 不動産／`ProfessionalService` 士業・専門サービス／`AutoRepair` 自動車整備／`Florist` 花屋

**営業時間の仕様**（間違えやすいので厳密に）：

- 曜日7行。各行は区分 `select`（営業 / 定休 / 24時間）＋開店 `time` ＋閉店 `time`
- 時刻は24時間表記の `HH:MM` で出力する
- **24時間営業は `opens: "00:00"` / `closes: "23:59"`**
- **定休日は `opens: "00:00"` / `closes: "00:00"`**
- `dayOfWeek` は `"Monday"`〜`"Sunday"`
- **同じ開店・閉店時刻の曜日はまとめて1つの `OpeningHoursSpecification` にし、`dayOfWeek` を配列にする**（月〜金が同じなら1件）。並び順は月曜始まり
- 全曜日が「営業」で時刻未入力なら `openingHoursSpecification` 自体を出さない

`aggregateRating` と `review` は**作らない**。Googleの案内では第三者のレビューを集めているサイト向けで、自分のサイトに自分の星を書くものではないため。この判断は画面の注記にも書く。

### 5-2. 記事・お知らせ（Article）

**必須プロパティは1つも無い。** Googleの記述は「必須はなく、内容に当てはまるものを追加する」。これも非自明なので、フォームの先頭に明記する。

| 欄 | プロパティ | 仕様 |
|---|---|---|
| 種類 | `@type` | `Article` / `NewsArticle` / `BlogPosting` |
| 見出し | `headline` | 長いと端末で切られる旨を注記 |
| 画像URL | `image` | クロール可能なURL。16:9／4:3／1:1 が好ましい旨を注記 |
| 公開日時 | `datePublished` | `datetime-local` → **ISO 8601（`+09:00` 付き）** |
| 更新日時 | `dateModified` | 同上 |
| 著者の種類 | `author.@type` | `Person` / `Organization` |
| 著者名 | `author.name` | |
| 著者URL | `author.url` | プロフィールページ等 |

`author` は名前が空なら丸ごと出さない。日付は `2026-08-13T10:00:00+09:00` の形にする。

### 5-3. パンくず（BreadcrumbList）

- 段数を 2〜6 の `select` で選び、選んだ数だけ行（名前＋URL）を出す
- `itemListElement` に `ListItem` を並べ、`position` は**1始まりの連番**を自動で振る
- **最後の項目だけ `item` を省略する**（Googleの仕様。省略するとそのページ自身のURLが使われる）。最終行のURL欄は `disabled` にして「このページ自身になるので不要」と表示する＝仕様を画面で教える
- 名前が空の行はスキップせず、空文字のまま出す（連番が崩れるほうが実害が大きいため）。必須未入力の1行通知で促す

## 6. 廃止2タイプの警告カード

生成欄の代わりに警告カードだけを出す。**今日の山場なのでフォームより目立たせる。**

### 6-1. よくある質問（FAQPage）

- 見出し：**これは2026年5月7日に廃止されました**
- 本文の要点：
  - FAQのリッチリザルトはGoogle検索に表示されなくなった
  - 2026年6月にリッチリザルトテストとSearch Consoleのレポートから削除、2026年8月にSearch Console APIからも削除される
  - **貼っても検索結果の見た目は変わらない**
  - Q&Aとしてページの中身を整えること自体には意味があるが、それは構造化データの仕事ではない
- 出典リンク（Google検索セントラルのFAQPageページ）
- 「代わりに記事で作る」ボタン（Articleフォームへ切り替える）

### 6-2. 手順・使い方（HowTo）

- 見出し：**これは2023年9月13日に廃止されました**
- 本文の要点：
  - 2023年8月にモバイルでの表示が終わり、デスクトップ限定になった
  - その1か月後の**2023年9月13日にデスクトップからも表示されなくなった**＝完全廃止
  - スキーマ自体は書けるが、検索結果に対する効果はない。**現在の対応タイプ一覧にも載っていない**
- 出典リンク（2023年8月のGoogle検索セントラルブログ、および現行の対応タイプ一覧）
- 「代わりに記事で作る」ボタン

## 7. 出力

```
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Restaurant",
  ...
}
</script>
```

- `<script>` タグごとコピーできる形で出す（貼る側がタグを書かなくてよい）
- インデント2スペース。**日本語はエスケープせずそのまま出す**
- 空の推奨欄は**キーごと出さない**（`""` を残さない）
- コピーボタン：`navigator.clipboard.writeText`、使えない環境（`file://` 直開き等）は `document.execCommand('copy')` にフォールバック。押したら「コピーしました」を短く表示（Day 005と同じ実装方針）
- 必須未入力時は出力欄に「店名と住所を入れると出ます」等の1行だけ

出力の下に、貼り方と確かめ方を置く：

- `<head>` の中に貼る（`<body>` でも読まれるが `<head>` が基本）
- リッチリザルトテスト https://search.google.com/test/rich-results
- Schema Markup Validator https://validator.schema.org/

## 8. 画面

縦1カラム。`Day 006` ／ タイトル ／ リード ／「入力はこの画面の中だけで組み立てており、どこにも送信していません」を常時表示（店名・住所を入れるため必須）。

その下に「種類の選択 → フォーム（または警告カード）→ 出力 → 貼り方 → この仕組みについて → 一覧へ戻るフッター」。

- `<title>`：構造化データ、いま出るやつだけ
- `description` / OG：2026年8月時点でGoogleがサポートしているタイプだけを出す旨と、FAQ・HowToは廃止済みで生成しない旨
- favicon：SVGのdata URI（外部ファイルを持たない）
- ダークモード対応・`prefers-reduced-motion` 対応

## 9. 扱わないもの

- `Product`・`Event`・`Recipe`・`JobPosting` などの他タイプ（1日の枠に収めるため3タイプに絞る）
- `aggregateRating`・`review`（§5-1の理由）
- 入力内容の保存・履歴（localStorageはDay 21以降の解禁）
- URLを読み込んで既存の構造化データを検証する機能（外部通信はDay 31以降の解禁）
- 生成したJSON-LDの正しさの保証（検証は公式ツールへ誘導する）

## 10. 法務・公開前の整理

- 入力は送信も保存もしない（外部通信・localStorage・Cookieゼロ）
- **Googleドキュメントの文言をコピペしない。** プロパティ名は技術用語としてそのまま使い、説明は自分の言葉で書く。出典はリンクで示す（Day 004でJASSOの算出表の全体再現をやめた判断と同じ配慮）
- 他者のコード・画像・フォントを同梱しない
- 「Google公式ツールではない」旨と、仕様は変わりうる旨（確認日 2026-08-13）を明記する
