# Day088「Bouquet Studio」の宣伝動画

32秒の縦型動画（1080×1920・30fps）を作る道具です。画面はすべて実際のアプリで、字幕・窓の枠・「あるある」の場面の質問カード・終わりのカードだけを、後から重ねています。
機能を順に並べる紹介ではなく、見た人が「使いたい」と思う気持ちの流れで組みました。
問いかけ（このあと作る花束がひらく）→ あるある（迷いが画面を埋めていく。アプリは映さない）→ 気分を選ぶと花束ができる（音のドロップ）→ ドラッグ・色・写真で自分好みに → 名前とひとことを書いてリンクで贈る → 受け取った側で指で押すと花束がひらき、ひとことが届く → 無料・ログイン不要。
絵コンテは `timeline.mjs` の1つの表で、映像（`render-promo.mjs`）とBGM（`promo-audio.mjs`・2案）が同じ表を読みます。

## 再生成

アプリの公開用ビルドは読むだけで、ビルドし直しません（最新の画面で撮るときは、先にアプリ側でビルドして、そのコピーを渡します）。
必要なもの: 公開用ビルドのコピー、アプリのリポジトリ（配信の `scripts/serve.mjs` と Playwright を使います）、ffmpeg / ffprobe（`FFMPEG`・`FFPROBE`、なければ PATH）、ローカルの Zen Kaku Gothic New（Bold・Black。`PROMO_FONT`・`PROMO_FONT_BLACK`）、背景の写真。場所は引数か環境変数（`PROMO_SITE_DIR`・`PROMO_APP_DIR`・`PROMO_FRAMES_DIR`・`PROMO_OUT_DIR`・`PROMO_PHOTO`）で渡します。

1. BGMを先に作る（追加パッケージも通信も要りません。下の「BGM」）。映像の書き出しで重ねる `bgm_a`・`bgm_b` が書き出し先に必要です。
2. 映像と書き出し:

```sh
node day-088-bouquet-studio/tools/promo/render-promo.mjs --site-dir <公開用ビルド> --app-dir <アプリのリポジトリ> --frames-dir <コマの置き場> --out-dir <書き出し先> --photo <写真.jpg> --mux a,b
```

- `--only studio,gift,cards,overlay` で一部だけ撮り直せます（gift は studio のリンクを使い、overlay は両方の記録を使います）。`--compose-only` は重ねと書き出しだけ、`--no-compose` は撮影だけです。
- `--no-camera` は、実画面を切り出して拡大しない版です（「カメラ」）。書き出し先を分け、重ね（`--only overlay`）を撮り直します。
- 配信はアプリの `scripts/serve.mjs`（127.0.0.1・既定のポート 4688・`--port`）。終わると自分の子プロセスだけを止めます。ブラウザは同時に1つです。
- 書き出し: `Day088_bouquet-studio_promo_{silent,a,b}.mp4`・`first-frame.png`・`contact-sheet.jpg`（1秒ごと）・`cut-check.jpg`（各カット・ドロップ・開き始めの前2コマ・後2コマ）・`capture-report.json`。100日の一覧用に `screenshot.webp`（PC幅1200×750・150KB以内）と `demo.mp4`（字幕なし・540×960・15〜18秒）。

## 撮影の仕組みと理由

- **本番の住所で撮る**: ページは `https://day88.rairakku.com/` として開きます。その住所への要求は、ローカル配信から Node の `fetch` で取って `route.fulfill` で返します（転送は拒否し、`content-encoding` などは外します）。本物のホストへは1件も出さず、ほかの外部通信は止めて数えます。アプリはリンクを `location.origin` から作るので、試験用のアドレスで撮ると完成画面のリンクに `127.0.0.1` が映ります。本番の住所なら映りません。画面の書き換えはしません。完成画面で `document.body.innerText` と入力欄の値に `127.0.0.1`・`localhost` が無いことを確かめ、`capture-report.json` に `appOrigin`・`linkOutputPrefix`・`realNetworkRequests`（0）を残します。
- **窓**: 全場面で同じ矩形（x=108・y=380・864×1320、下端1700）。Studio は CSS 540×825・DPR 2 で撮って、そのまま0.8倍で入れます。受け取り画面は CSS 540×960 で撮り、CSS y=825（カードの下の注記と、アプリ紹介・共有ボタンの足元の間）で切ります。切り位置が文字を割るなら止まります。窓のコマはすべて 1080×1650 にそろえてから重ねます（途中で大きさが変わると ffmpeg がフィルターを組み直し、コマを落とすため）。
- **時計**: 読み込みと3Dの準備は実時間で行い、3Dが ready になってから時計（`requestAnimationFrame`・`performance.now`・`Date.now`・`setTimeout`・CSS/Web Animations）を止め、1/60秒×2回ずつ進めては撮ります（33msを一度に進めると、アプリの3D品質調整が遅い端末と判断します）。気分の花束の種は起動時の `Date.now()` なので、止める前の `Date.now()` を固定値にして毎回同じ花束にします。Chromium は `--use-angle=metal`。
- **Studio**: 空の花束（背景さくら）で起動し、映さない所で「見本」タブを開いて気分ボタンを見える位置にしておきます。窓は bar 2 の0.25秒前に白い閃光で現れ、5.333秒に「かわいい」を押します。タップは CDP のタッチで、指が3コマ前に下りて、絵コンテの時刻に離れます（アプリは離したときに反応します）。ドラッグは CDP のタッチを1コマずつ。動かすのは花びらの色が濃い大きな花です（白や淡い花びらは桃色の背景で灰色にしか見えません）。舞台の広い側へ最大135px動かし、後半は1コマごとに振り幅48pxで揺らして花びらを落とします。写真は「写真」タイルを押してファイル選択に渡します。「リンクを作る」は17.867秒（hush の小節より前）で、完成画面を1.4秒見せます。
- **受け取り（gift）**: 新しい文脈で Studio のリンクを開きます。準備ができるまで `document.visibilityState` を hidden に見せ、アプリの1.8秒の自動オープンのタイマーを止めておきます。見えるようにしてから1.0秒後に、指（CDP のタッチ）が「押して開く」に下り、4コマ後に離れます。アプリはそのタップで開き、開き始めたコマ（`teaser` が消えたコマ）を bloom（21.333秒）に置きます。タップで開かなかったときは、指と輪を描かず、自動オープンのまま使い、`capture-report.json` の `takes.gift.openedByTap` が false になります。
- **フック**: 受け取りテイクの開き始めの0.4秒後（消えかけの「押して開く」が残らない位置）からの2.667秒です。冒頭の花束を後で作る花束と別物にすると、つながりません。21秒台にもう一度同じ花束がひらきます。
- **カメラ**: 実画面のコマを切り出して拡大するだけで、アプリの中には何も描きません。中心（軸）を決めて、その点が動かないように寄ります。フックは1.00→1.05倍で、窓の上端が軸です（小さな「Bouquet Studio」の文字を欠かさないため）。Studio は、ドラッグの間だけ舞台の中心を軸に1.25倍へ寄って戻り、各タップで押した点を軸に0.15秒の「ぽん」（1.00→1.08→1.00倍）。受け取りは、閉じた花束で窓の下端を軸に1.00→1.015倍。カードが出て0.4秒（全体を見せる）のあと、0.7秒でカードを「読む」位置へ寄ります（窓の左下隅を軸に1.5倍。見える範囲の下端をアクションボタンの4px手前まで上げて、ボタンや注記の言葉が右端で途中から切れるのを避けます）。そのあと終わりのカードまで1.62倍までゆっくり寄ります。カードは窓の左右16pxまで広く、中心を軸にした寄りでは1.04倍までしか欠けずに寄れず、文字が小さいままです。そこで右側（差出人の行）が窓の外へ出るのを許して、「はなこさんへ／いつもありがとう。」を大きくしました。どれも2倍に広げてから切り出します。`--no-camera` は、これらの切り出しをすべてやめた版です（フックの押し込みは残ります）。
- **重ね**: 字幕は窓の上の帯（y≈150〜350）。字幕は小節ではなく画に合わせて替えます（S2 は窓が現れたコマ、「リンクを開くと——」は受け取りへ切り替わったコマ）。替わるときは、新しい字幕を切替のコマで7割5分まで出し、古い字幕はそのコマだけ2割で残して次のコマで消します（空白のコマも、古い字幕だけが新しい画に乗るコマも作りません）。同じ文の場面（S3・S4）は字幕を出し直しません。S4 は写真を入れた直後から、字幕の下に小さな灰色の注記（受け取る人にはぼかした色合いで届く）を出します。タップの輪と指は、その時のカメラを通した実座標に出し、輪は押したコマに出て0.27秒で消えます。S1 は重ねが全面を覆い（終わりのカードと同じやわらかいグラデーション）、白い丸薬の「迷い」8つを約0.3秒ごとに少し重ねて傾けて出し、後半は全部を小さく揺らします。重ねのコマは全部 rgba にそろえます（不透明なコマが混じると、フィルターの組み直しで重ねが1〜2コマ抜けるため）。どのカットも同じ白い閃光で切り替え、終わりのカードも溶かさず一度に出します（溶かすと二重に見えました）。
- 撮り直したら `capture-report.json` の `tapCueDrift`・`visualCues`・`musicSync`・`windowByScene`・`hookMotion`・`captions`・`captionGapFrames`（空のはず）・`rings` を見ます。タップの音（`TAP_CUES`）はタップの時刻です。絵コンテの時刻を変えたら BGM も作り直します（hush の小節にタップを置くと verify-audio が不合格になります）。

## 画面と字幕の照合

字幕は、その時に画面で起きていることか、アプリの機能の事実だけを書きます。サービス名・他より優れる・必ず喜ばれる、は書きません。
受け取る人に届く背景は写真の「ぼかした色合い」なので、字幕で「写真が届く」とは言いません。

| 秒 | 字幕 | 実画面で確認すること |
|---|---|---|
| 0–2.67 | 言いにくい「ありがとう」、／花束にしてみない？ | 1コマ目から、後で作る花束（水玉の包み紙）が受け取り画面でひらいて動き、ゆっくり寄る |
| 2.67–5.08 | でも花束って、／選ぶのも並べるのも大変。 | アプリは映さない。迷いの丸薬8つ（どの花・何本・色・包み方・花屋・予算・いつ届く・言葉）が増えて画面を埋める |
| 5.08–8.0 | 気分を選ぶだけで、／花束ができる。 | 5.08秒に閃光で空の花束の Studio が現れ、同じコマで字幕が替わる。5.333秒に「かわいい」を押し、花束が一度に現れる（ドロップ） |
| 8.0–13.33 | ドラッグ、色、写真で、／自分好みに。 | 大きな花を動かして揺らす →「包み紙」→ 色（ラベンダー）→ 背景タブ →「写真」。写真を入れた11.4秒から注記「背景の写真は、受け取る人にはぼかした色合いで届く。」 |

| 19.3–21.33 | リンクを開くと—— | 19.3秒に閃光で受け取り画面（閉じた花束・押して開く）へ切り替わり、同じコマで字幕が替わる。21.2秒に指が「押して開く」に下りる |

## BGM

32秒・90BPM・12小節。48kHz・16bitステレオのWAVと192kbpsのMP3を作ります。`timeline.mjs` が音の仕様で、映像・絵コンテは音の側から変えません。
A「やさしいポップ」はハ長調のFMエレピ・弦パッド、B「はずむアコースティック」はト長調のプラック・木琴・ベル。どちらも自作の6音の反復、軽いベースとドラム。固定seed（A=0x88a、B=0x88b）で全音を計算するので、同じ入力から同じ音になります。
展開は、ドラム無しのフック → ノイズのbuild → drop → groove → lift → chorus → パッドだけのhush → 全楽器が戻るbloom → 終止和音。`STORYBOARD.music`・`MUSIC_CUES`・`TAP_CUES` は実行時に読みます（dropは5.333秒、hushは18.667秒、bloomは21.333秒）。bloomに6音が上昇する短いベルの「きらっ」を1つ足し、Studio のタップごとに調に合う小さなチックを入れます（受け取り側の「押して開く」は bloom そのものが音なので足しません）。最後の1.6秒でフェードし、末尾のサンプルは0です。

リポジトリのルートで1本ずつ実行します。

```sh
timeout 180s node day-088-bouquet-studio/tools/promo/promo-audio.mjs --variant a --out-dir <out>
timeout 180s node day-088-bouquet-studio/tools/promo/promo-audio.mjs --variant b --out-dir <out>
timeout 360s node day-088-bouquet-studio/tools/promo/verify-audio.mjs --out-dir <out>
```

検査は −16 LUFS±1、真のピーク≤−1.5dBTP、クリップ0、開始/末尾/無音、dropとbloomの小節・拍の音量差≥3dB（dropの小節の差は、Aで8.5dB以上・Bで9.5dB以上）、低域比（120Hz以下）−9〜−6dB、高域（8kHz以上）の目安−43〜−38dBFS、MP3形式、hush/キュー配置です。帯域値はステレオの4次Butterworthフィルター後のRMSです。Aの高域は目安をわずかに下回るので、下側1dBまで許容し、`audio-report.json` の deviations に理由と差を残します。検証中にA・Bを順番に再生成して、WAV・MP3のSHA256の一致も確かめます（一時ファイルは書き出し先で消します）。結果は `audio-report.json` と `spectrogram-a.png`・`spectrogram-b.png`。
測るのはPCM（数値とスペクトログラム）です。聴いて確かめたわけではないので、聴感は人が確かめてください。

## 使用素材と権利

- 映像: Bouquet Studio の公開用ビルドをローカルで配って操作した実画面。作り物の画面・AI生成映像は使いません。花の3Dはアプリ自作のものです。
- 背景の写真（S4）: Poly Haven「Qwantani Dusk 2」（https://polyhaven.com/a/qwantani_dusk_2）のトーンマップ済みJPG（8192×4096）から5:6（1500×1800）を等倍で切り出したもの。CC0（https://polyhaven.com/license ）。人・ロゴ・読める文字は写っていません。写真もフォントもこのリポジトリには入れません。切り出しは `ffmpeg -i qwantani_dusk_2.jpg -vf "crop=1500:1800:4165:380" -q:v 3 background.jpg`。地平線を下から約7%まで下げたのは、受け取り画面が写真を5×6にぼかした色を背景にするため、下の行に暗い地面が入ると窓の下が濁るからです。
- 字幕・終わりのカード: Zen Kaku Gothic New（Bold・Black）、SIL Open Font License 1.1。終わりのカードの小さな花束の図は自作の図形です。
- BGM: `promo-audio.mjs` がNodeの計算だけで合成します（第三者の音源・サンプルなし）。
