# Day 026「今夜の月」要件定義

開いた瞬間に、**今夜の月がその形で昇ってくる**。月齢・呼び名・輝面比と、**自分の場所での月の出・月の入り時刻**、**中秋の名月（9/25）までの日数**を1画面で出す。日付をなぞると月が満ち欠けし、見た夜は「見た月」帳に残る。計算はすべて端末内で、通信は一切しない。

## 背景と狙い

- 中秋の名月が 2026-09-25。今年は満月（9/27 01:49）と2日ずれる年で、「名月は満月とは限らない」がそのまま小ネタになる（国立天文台の解説ページが今年の話題として扱っている）。
- 既にあるものとの違い。国立天文台 暦計算室は数字の表で、形は描かないし場所も覚えない。天気アプリの月相は8種類のアイコンで、時刻は出ない。天文アプリは重く、登録が要る。**このアプリは「今夜の月の形」を主役に、自分の場所の出入り時刻と名月までの日数を、開いて3秒で見せる**。位置も見た記録も端末の外に出さない。
- 難易度設計（Day21–30）: **演出のこだわり**（Canvasで輝面を正しく描き、昇る動きを付ける）＋ **localStorage**（場所と「見た月」帳）。外部依存は0。

## ユーザーストーリー

1. 夜に空を見上げようとしている私は、開いた瞬間に「今夜の月はどんな形で、何時にどっちから出るか」を知りたい。数字の表を読み解きたくはない。
2. 東京ではない街に住む私は、自分の場所の時刻が欲しい。ただし住所を入れたくないし、位置をどこかに送ってほしくない。
3. 中秋の名月にお月見をしたい私は、あと何日か、その夜の月がどのくらい丸いか、満月とどれだけずれるかを知りたい。
4. 週末の予定を立てる私は、日付をなぞって「その夜の月」を先に見ておきたい。
5. 月を見たことを残したい私は、「見た」を1回押すだけで、その夜の月の形が帳に貯まってほしい。登録も同期も要らない。

## UX5階層

- **戦略**: 「月を調べる」道具ではなく、**「今夜、月を見に出るか」を3秒で決めさせる**道具。成功＝開いて「8割の月が 20:38 に東南東から出る」まで分かり、夜に外へ出て「見た」を押す。数字より形。表より1画面。通信より端末内。
- **要件**: 基準日（日本時間の暦日）の月齢・輝面比・満ち欠けの向き・旧暦の呼び名／選んだ地点の月の出・入り時刻と方位、日の入り時刻、いま月が出ているか／基準日を ±30 日動かせる／中秋の名月までの日数と、その年の満月とのずれ／「見た月」帳（端末内保存）。
- **構造**: 単一画面。上から「空（月の描画＋月齢の大きな数字）」→「時刻（月の出・入り・地点切替）」→「日付スライダー」→「名月カード」→「見た月帳」→「計算方法・精度・出典」→シェア。900px以上は空を左、カードを右の2列。
- **骨格**: ヘッダー／空キャンバス（正方形、min(80vw, 360px)）＋月齢・呼び名・輝面比の帯／時刻カード（地点セレクト＋「現在地」ボタン、出入りの2行、日の入りとの差、いまの状態）／日付レンジ（‹ › と「今夜に戻る」）／名月カード（日数・日付・満月とのずれ）／「今夜の月を見た」ボタンと帳（小さな月のスタンプ列）／注記／シェア。
- **表層**: 濃紺の夜空のグラデーションに細かな星、月は温かい白で海（暗い模様）を薄く、輝面の境目は滑らかに、周りに淡い光芒。名月までの日数だけ金色。文字は生成り色でコントラスト 4.5:1 以上。数字は等幅。**開いたときに月が地平線から昇る**（1.4秒・ease-out）。`prefers-reduced-motion` では昇らせず、星のまたたきも止める。

### UX5階層を通したことで決まった実装（12件）

1. 主役は数字ではなく**形**。8種のアイコンではなく、輝面比から**境界線（ターミネーター）を計算して Canvas に描く**（戦略層）
2. 「今夜見に出るか」を決めるには時刻だけでは足りないので、**月の出の方位（16方位）**と**日の入りとの時間差**、**いま出ているか**を添える（戦略層）
3. 時刻は自分の場所のもの＝**現在地ボタン＋主要都市のプリセット**。逆ジオコーディングはしない（通信ゼロ・地名を出さず座標だけ使う）（要件層）
4. 「今夜」の定義は**日本時間の暦日**。表示時刻も日本時間固定にし、海外では合わないことを注記に書く（要件層：CIや端末のタイムゾーンで結果が変わらない）
5. 日付は**1本のレンジ（±30日）**だけ。年月日の入力欄やカレンダーは作らない（構造層：1日アプリの枠）
6. 中秋の名月の日付は**国立天文台の表（2024–2032）を同梱**し、旧暦計算は実装しない。表に無い年は「名月の日付は未収録」と出す（要件層：正確さと工数）
7. 満月とのずれは、同梱表の満月時刻ではなく**自前の望の計算**で出し、表の値をテストの正解に使う（要件層：計算が合っている証明を兼ねる）
8. 「見た」は**基準日が今夜のときだけ**押せる。未来や過去の日にスタンプは押せない（戦略層：帳は日記であって図鑑ではない）
9. 位置は**小数2桁（約1km）に丸めて**保存する（要件層：時刻の精度に影響しない範囲で、個人を特定できる精度を持たない）
10. 演出は「月が昇る」1つ＋星のまたたき。`prefers-reduced-motion` で両方止める（表層：Day21–30の「演出1つ」）
11. 4状態：現在地取得中（読込中）／取得拒否・失敗（エラー、前の地点に留まる）／保存不可（エラー、計算は動く）／`?at=` の不正値（無視して現在時刻）（要件層）
12. 精度は**分単位で表示**し、「国立天文台の暦と1〜2分ずれることがあります」を注記に書く。テストは暦の値に対して ±3分（要件層）

## 機能要件

**基準日と時刻**
- 基準時刻 `now` は端末時計。開発・テスト・デモ用に `?at=YYYY-MM-DDTHH:mm`（日本時間）で上書きできる。書式が違えば無視
- すべての暦日・表示時刻は **UTC+9 固定**（`Date` のローカルタイムゾーンに依存しない。`Intl` にも依存しない）
- 基準日 = `now` の日本時間の暦日 + スライダーのオフセット（−30〜+30 日）。表示は「9月2日（水）・今夜」「9月25日（金）」。今夜以外のときは「今夜に戻る」ボタンを見せる

**月の計算（`lib/astro.js`・純関数・DOM に触れない）**
- 太陽・月の位置: Jean Meeus『Astronomical Algorithms』第2版の方法を自前実装。太陽は第25章、月は第47章の周期項（**黄経・距離・黄緯とも上位30項以上**）。ΔT は 2026 年の推定値（約69秒）を定数で持つ
- 朔弦望の瞬間: 第49章（平均位相＋補正項をすべて）。「直前の朔」「次の望」「次の朔」を返す
- 月齢 = `now` − 直前の朔（日単位・小数1桁で表示）。輝面比 k = (1 + cos i) / 2（i は位相角。第48章）
- 満ち欠けの向き: 朔→望は「右が明るい」、望→朔は「左が明るい」（北半球の地上から見た標準の向き。厳密な傾きは扱わない）
- 旧暦の呼び名: 旧暦日 = （基準日 − 直前の朔の日本時間の暦日）+ 1。特別な名を持つ日は名で、それ以外は「二十一日の月」のように数で。名: 1 新月（朔）／2 二日月／3 三日月／7 七日月／8 八日月／10 十日夜／13 十三夜／14 小望月／15 十五夜／16 十六夜／17 立待月／18 居待月／19 寝待月／20 更待月／23 二十三夜／26 二十六夜／30 三十日月。あわせて状態の一言「満ちていく途中」「欠けていく途中」「満月のころ」「新月のころ」「上弦のころ」「下弦のころ」
- 出・入り: 高度が h0 になる時刻を、当日 0:00〜24:00（日本時間）を2分刻みで走査し二分法で詰める（第15章の補間でもよい）。基準高度は国立天文台の暦の定義に合わせる：地平大気差 35′8″、太陽は上辺（h0 = −(35′8″ + 16′)）、月は**中心**（h0 = π − 35′8″。π は実際の地平視差）。※Meeus の 0.7275π − 34′ は月の上辺基準で、暦より月の入りが約2分遅れる（2026-09-02 実測・JPL Horizons で裏取り）。出・入りが無い日は「この日は月の入りがありません」と出す
- 方位: 出の瞬間の方位角を16方位（東／東南東／南東…）の日本語で
- いまの状態: 基準日が今夜のとき、`now` の月の高度から「いま出ています（高度 32°・南東）」または「いま地平線の下。20:38 に東南東から出ます」

**地点**
- プリセット（`<select>`）: 札幌／仙台／秋田／東京／新潟／名古屋／大阪／広島／高知／福岡／鹿児島／那覇。既定は東京
- 東京の座標は国立天文台 暦計算室の東京地点に合わせる（北緯 35.6581・東経 139.7414 を起点に、実装時に同室「こよみの計算」の地点定義を確認して合わせる）
- 「現在地」ボタン: `navigator.geolocation.getCurrentPosition`（タップ時のみ・timeout 8秒・maximumAge 10分）。取得中は「現在地を取得中…」、成功で地点名を「現在地」に、失敗（拒否・タイムアウト・非対応）で「現在地を取得できませんでした。地点を選んでください」と出し前の地点のまま
- 地点は localStorage に保存（現在地は小数2桁に丸めた緯度経度で）

**中秋の名月**
- 同梱表（2024–2032）から、基準日の年の名月を引く。基準日 ≤ 名月なら「中秋の名月まで あと N 日（9月25日・金）」、当日は「今夜が中秋の名月」、過ぎていれば「次の中秋の名月は 2027年9月15日」。表に無い年は「この年の名月の日付は未収録です」
- 満月とのずれ: 名月の日付と、自前計算の「名月の前後で最も近い望」の日本時間の日付の差を「満月は 2日後（9/27 01:49）」「満月と同じ日」のように出す。2026 は「2日後」

**見た月帳（localStorage）**
- キー `day026.moon.v1`: `{ v:1, place:{ id:'tokyo'|'geo'|…, lat, lon, label }, stamps:[{ date:'2026-09-02', age:20.6, illum:0.78, waxing:false }], updatedAt }`
- 「今夜の月を見た」は基準日が今夜のときだけ有効。押すと今夜の月の小さな絵（同じ描画関数・48px）と日付が帳に増える。同じ日は1回だけ（2回目は「今夜はもう記録済み」）。スタンプは新しい順・最大 60 件
- 「帳を消す」は同じボタン2回押し（1回目で「もう一度押すと消えます」に変わり、3秒で戻る）。`alert/confirm` 禁止
- 壊れたJSON・未知のバージョンは無視して初期状態から。localStorage 不可でも表示と計算は動き、「この環境では保存できません」だけ出す

**4状態**
- 空: 帳が空 → 「今夜の月を見たら、ここに残ります」
- 読込中: 現在地取得中（ボタンを無効化して文言変更）
- エラー: 現在地失敗／保存不可（上記）
- 不正入力: `?at=` の不正値は無視。スライダーは範囲外にならない

**シェア・OGP**
- `index.html` の `</head>` 前に `shared/share.css` と `shared/share.js`。`<meta name="share:text">` に「今夜の月」を含める。`<main>` 末尾に `<div id="share"></div>`。OGP・canonical は build が入れるので書かない

## 非機能・技術

- 依存ゼロ・ビルドなしの vanilla JS（ES modules）。`index.html`＋`app.css`＋`app.js`＋`lib/`（`astro.js` 天文計算／`koyomi.js` 名月表・呼び名・日本時間の暦日／`draw.js` Canvas 描画（(ctx, size, {illum, waxing, glow}) の純関数）／`store.js` 保存）
- **外部通信ゼロ**（fetch 無し・外部フォント無し・画像も無し。星と月は全部コードで描く）。CSP はリポジトリ既定のまま（`connect-src 'self'`）。`Permissions-Policy` の `geolocation=(self)` はそのまま使える
- 描画: `devicePixelRatio` 対応。月の海は**決定的な擬似乱数**（固定シード）で描き、毎回同じ模様にする。1コマ描くのに 16ms を超えない（スライダー操作で毎フレーム描く）
- アクセシビリティ: Canvas に `role="img"` と `aria-label`（「月齢 20.6、二十一日の月、輝面 78%」）。数値の帯は `aria-live="polite"`。スライダーは `<input type="range">` でキーボード操作可。ボタンは 44px 以上。コントラスト 4.5:1 以上。フォーカスリング可視
- レスポンシブ: 320 / 390 / 1280px で横スクロール無し
- `alert/confirm/prompt` を使わない。ユーザー入力を `innerHTML` に入れない
- テストゲート:
  - `node --test`（`tests/`、25本以上）: 朔弦望9件が国立天文台の値に対し **±3分**／2026-09-02 12:00 JST の月齢 20.4 ±0.05／東京 2026-09-02 の月の出 20:38・月の入り 10:16・日の出 5:13・日の入り 18:08 が **±3分**／望の瞬間の輝面比 ≥ 0.99・朔で ≤ 0.01・上弦/下弦で 0.50 ±0.03／名月の表引きと日数・満月とのずれ（2026=2日後、2030=同日）／呼び名（旧暦日1・3・13・15・16・21・30）／方位の16分割／保存の直列化・復元（壊れたJSON・未知バージョン・60件上限・重複日）／`?at=` の解釈と不正値／出入りが無い日の扱い。可能なら国立天文台「こよみの計算」で**別の日付か別の地点**（例: 札幌 9/25）を1件追加で取り、同じ ±3分で固定する
  - Playwright E2E（`tests/e2e/day-026-tonight-moon.spec.mjs`、12本以上）: `?at=2026-09-02T21:00` で月齢「20.8」と「二十一日の月」・東京の月の出 20:38／月の入り 10:16 が出る／名月カードが「あと 23 日」／`?at=2026-09-25T20:00` で「今夜が中秋の名月」と「満月は 2日後」／スライダーで +1 日すると日付と月齢が変わり「今夜に戻る」で戻る／地点を大阪にして再読込しても大阪のまま／`context.setGeolocation` で現在地にすると「現在地」になり時刻が変わる／現在地を拒否するとエラー文を出し前の地点のまま／「見た」で帳に1件増え、再読込しても残り、同日2回目は増えない／帳を2回押しで消せる／localStorage を封じても画面が出て保存不可の文言が出る／320・390・1280 で横はみ出し無し／コンソールエラー 0／`prefers-reduced-motion` で昇る演出が即座に終わる

## デモ動画とスクショ

- `demo-scenario.mjs`: `?at=2026-09-02T21:00` で開く（file:// で ES modules が動かないので Day 022 と同じくミニHTTPサーバーで開き直す）。振り付け: 月が昇り切る（1.5秒）→ スライダーを +23 日まで 1 日ずつ進めて名月まで満ちていく（`h.slide`）→ +25 日（満月）→ 「今夜に戻る」→ `page.context().setGeolocation({latitude:39.72, longitude:140.10})`＋`grantPermissions(['geolocation'])` で「現在地」を押し、時刻と方位が変わる → 「今夜の月を見た」で帳にスタンプが乗る → 帳までスクロールして終わり。尺 15〜20 秒
- 1コマ目は「月が昇っている途中」にする。`tools/trim-demo.mjs`（Day 024 のものを流用）で頭を約 0.6 秒切り、`ffmpeg -i demo.mp4 -frames:v 1 thumb.png` で目視する
- `shotSetup`: 同じ `?at` で開き、昇り切ってから撮る。1200×750 では2列レイアウトで、左に月、右に時刻カードと名月カードが写ること
