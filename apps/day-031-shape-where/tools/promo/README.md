# 「この形、どこ？」プロモーション動画

Playwright で決定的な1コマを撮り、ffmpeg で36秒・1080×1920の MP4 にします。音声は本番描画時に未生成なら自動で合成されます。

```sh
PLAYWRIGHT=/path/to/playwright/index.js node tools/promo/render-promo.mjs --preview
PLAYWRIGHT=/path/to/playwright/index.js node tools/promo/render-promo.mjs
```

リポジトリ直下からは `node apps/day-031-shape-where/tools/promo/render-promo.mjs` と実行できます。プレビューは `preview-contact.jpg`、本番は `promo.mp4`、`promo-first-frame.png`、`promo-audio.wav` を同じフォルダへ出力します。部分確認には `--from 19 --to 23`、別の出力先には絶対パスで `--out <mp4>` を指定できます。配信は毎回空きポートを取るミニサーバーなので、E2E の 4173 とは取り合いません。

1コマは時刻 t の純関数です。アプリ側は「t における場面を計算し、場面が変わったときだけ読み直して同じ順にボタンを押す」ので、途中の t から撮り始めても同じ画になります。撮影は `reducedMotion: 'reduce'` なので**アプリ自身のアニメーションは動きません**。見せたい動きは全部この合成ページ側で描きます。アプリ本体（`index.html`・`app.js`・`app.css`・`lib/`）には手を入れず、iframe の DOM へ毎コマ上書きするだけです。

## このアプリで足りない3つの仕掛け

**出題を種で固定し、正解を先に知っておく。** `?seed=156`（都道府県＝静岡県・北海道…）と `?seed=20&p=05`（秋田県の市町村＝仙北市・男鹿市…）で10問が決まります。`promo.js` は同じ種で `lib/quiz.js` の `buildRound` を回し、正解のコードを先に持っておくので、指を必ず正解のボタンへ運べます。結果画面は同じ1ラウンドを最後まで通したもので、ヒントを1問だけ使うので必ず 9.5 / 10 になります。ベストは端末に残るため、読み直しのたびに `day031.best.v1` を消して「ベスト更新！」が撮る順番で変わらないようにしています。

🔴 **出題規則を変えたら種の中身が変わります。** 1問目は `lib/quiz.js` が「分かりやすい形」から選びます（都道府県は `LEAD_PREFS` の9県、市区町村は県内で大きい上位 `LEAD_TOWN_COUNT` 件）。ここを触ると同じ種でも別の県・別の町になり、下の固定応答と食い違います。

**Wikipedia は実APIを叩かない。** `render-promo.mjs` の `context.route` が `timeline.mjs` の `WIKI_SUMMARIES`（本文は 2026-09-07 に REST API が返した要約そのまま）を返し、載っていない記事名には 404 を返します。**写真は CC BY-SA の作品なので動画に焼き込みません**——固定応答に `thumbnail` を持たせず、`*.wikimedia.org` は `abort` し、想定外の通信先が出たら撮り終わりに報告します。記事名が出題とずれると画面は「解説は取れませんでした」になるので、**正解表示を撮る場面では `data-status` が `ready` でなければ描画を止めます**（静かに壊れた動画を作らないため）。

**解説が届く時刻だけ合成側で決める。** アプリは正解表示と同時に取りに行き、枠は「読み込み中→本文」と顔だけ変わります（高さは変わらないので画面は動きません）。S4 を見せ場にしたいので、市区町村の正解表示だけ `T_WIKI` まで「読み込み中」に留め、そこで本文へ入れ替えます。都道府県の2回はアプリのまま（届いた本文をそのまま出す）です。

**動きと表示位置は合成側で描く。** シルエットのフェード（`shapeFadeAt`）、正解表示のせり上がり（`revealFadeAt`）、指のカーソルと波紋、正解した選択肢を囲う輪、投稿ボタンの光は `promo.js` が毎コマ描きます。表示位置は「`#reveal` の下端が画面の下端に来る量」を毎コマ測って決めるので、UI の高さが変わっても追従します。指の待機位置は「これから押す札の真下」なので、1コマ目でどのボタンへ向かっているかが分かります。

## 気をつける点

- **1コマ目がXのサムネ**です。静岡県のシルエットと4択が出ていて、指が「静岡県」へ向かう途中の画にしてあります。指の待機位置を端末の外に置くと字幕の札に隠れるので、端末の中の下寄り（`targetPoint('idle')`）から出しています。
- 字幕は1行16字以内・2行以内。左右108px（10%）のセーフ領域の内側です。
- 固定応答は写真を持たないので、画面には本文と「Wikipedia で読む」「Wikipedia · CC BY-SA 4.0」だけが出ます。動画としての帰属は S6 の「解説：Wikipedia（CC BY-SA 4.0）」でも出しています。
- **アプリの UI を変えたら、この動画も撮り直しが要ります。** 指の的（`#hint-button` と入れ替わる `#hint-text` など）と場面の手順は要素の id を見ています。
- 端末の下端にはアプリの共有ボタンが映り込みます（アプリのとおりで、隠していません）。

## BGM（音）

`promo-audio.mjs` が依存ゼロの純JSで合成する（サンプル・外部音源は使わない）。同じ入力なら必ず同じ WAV になるので、動画を撮り直しても音と画がずれない。

- **2案**：`--variant a`（既定・ローファイなエレピの FM 合成）と `--variant b`（アコースティック寄り・カープラス–ストロングの撥弦。A よりわずかに静かで暖かい）。`render-promo.mjs` は常に A を使う。
- **構成は `timeline.mjs` の絵コンテに追従する。** `STORYBOARD` の場面境界・`TAPS`（タップの時刻と正解／ヒントの種別）・`RESULT_START` を読み、静かなフック（S0）→ フルのグルーヴ（S2〜S5）→ 終止和音（S7）まで組み立てる。絵コンテを差し替えれば曲の展開も自動でついてくる。
- **正解タップだけ、直前に伴奏をダッキングしてチャイムを前に出す。** 一番賑やかな場面（S3・フィルの小節）でも「当たった」の2音が埋もれないよう、タップごとにチャイムの強さとダッキングの深さを変えてある（`chimeBoost`・`TAP_DUCK_DEPTH`）。均一な音量だと静かな場面（S0）では効きすぎて場面の弧を壊し、賑やかな場面（S3）では負けて聞き取れない。
- **音量は RMS 基準＋ピーク上限**（`TARGET_RMS` / `PEAK_CEILING`、上限 -1.5dBTP）。ピーク基準にすると音を1つ足しただけで統合ラウドネスが数dB動く（Day 029 の実例）。直近の実測：A＝統合 -16.9 LUFS・True Peak -3.0dBTP、B＝-17.2 LUFS・-1.8dBTP（ともに目標 -17.0±0.5 LUFS）。
- ⚠️ **一次フィルタの内部状態は使い回さない。** バス全体に掛けるハイシェルフEQで、ハイパスの再帰状態（前サンプルの出力）とシェルフ後の出力を同じ変数に入れたところ、ブースト後の値がハイパスの再帰へ巻き戻ってフィードバックが発散し、0.1秒足らずで全サンプルが NaN になった（実際に踏んだ）。フィルタが自分の再帰に使う状態と、外へ出す出力は必ず別変数にする。
- **検証は耳だけに頼らない。** ffmpeg の `loudnorm`（統合ラウドネス・True Peak）、帯域を切った `astats` の RMS（低域 <120Hz・高域 >8kHz と全体の差）、`STORYBOARD` の区間で切り出した場面ごとの RMS、正解タップ前後の RMS 差（チャイムが実際に聞き取れる音量まで上がっているか）を数値で確認する。`showspectrumpic` のスペクトログラムも目で見て、場面の変わり目で層が変化していること・特定帯域だけが刺さる縦筋が無いことを確かめる。

## 他の Day へ流用するときに差し替える場所

- `timeline.mjs` — 絵コンテ（`STORYBOARD`）・字幕（`CAPTIONS`）・タップと指の道筋（`TAPS`・`FINGER`）・場面の切れ目（`appSceneAt`）・種（`PREF_SEED`・`TOWN_SEED`）・固定応答（`WIKI_SUMMARIES`）
- `promo.js` — `PLANS`（どのURLで開き、どのボタンを順に押すか）・`targetBox`（指と輪の的）・`overrideApp`（毎コマ上書きする内容）・`scrollFor`（表示位置の決め方）
- `promo.html` / `promo.css` — iframe の URL、背景に置くシルエット、タイトル・約束・エンド画面の文言と配色
- `promo-audio.mjs` — 音列とシード、効果音を鳴らす時刻
