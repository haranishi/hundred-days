# Day 024「読めない地名が、向かってくる」

全国の地名が奥から迫ってくる。**読みは伏せてある。** ローマ字で打ち切ると弾ける。近づくにつれて読みが左から1文字ずつ開くので待てば誰でも打てるが、**開いた文字が少ないほど点が高い**。そして**打ち間違えるほど、その地名で入る点は下がる**。問われているのは打鍵の速さではなく、読めるかどうか。

## 先に権利関係

出題データは日本郵便の郵便番号データ。説明ページに逐語で「郵便番号データに限っては日本郵便株式会社は著作権を主張しません。自由に配布していただいて結構です」とあり、同梱・加工・再配布いずれも可。商用利用の制限・自動取得の禁止・出典表示の義務はいずれも記述なし。それでも出典と更新日は画面に出している。**出どころが追えないと、読みの正しさを誰も検証できない**から。

読みは郵便局側の表記であって、地元の読みと必ずしも一致しない。その旨も画面に書いてある。

ゲームのルール自体は著作権で保護されない（釣りゲータウン2事件・知財高裁 平成24年8月8日）。そのうえで名称・配色・意匠・効果音は既存作に寄せていない。

## 難読度を、漢字辞典なしで出す

このアプリの中身はここ。外部の漢字辞典を持ち込まず、**地名データだけ**から「読みの珍しさ」を出す。

1. **漢字1字あたりの期待かな長を連立方程式で解く。** 「かなの総数＝含まれる各漢字のかな数の和」という式が地名ごとに立つ。全国12万件ぶんを漢字約2,250種についてJacobi反復で最小二乗解を得る
2. **その期待長で漢字とかなを動的計画法で対応づけ、漢字ごとの読み出現頻度を数える。** 対応づけは2周まわす（1周目は長さだけ、2周目は1周目の頻度表を費用に足して切り直す）

難読度 ＝ 珍しさ（−log 出現確率）の平均 ＋ かな長の意外さ。

この式のおかげで、降参したときの「なぜ読めないか」が自動で出る。「『母』を『ぼ』と読む地名は全国で13件」は、頻度表をそのまま読んだもの。

## 読みを隠すと、読めない人が詰む

Day018で実測した「遅い人ほど消える寸前の皿に縛られ続ける死のループ」と同じ構造が、ここでは「読めない人は1文字も打てないループ」として出る。手当ては2つ。

- **ヒントの段階開示。** 開き切るのは着弾ではなく「着弾 − 打ち切るのに要る時間」。待てば必ず打てるが、待つほど点は減る
- **降参。** 正解と理由が出て、その地名は4問あとに出し直される

**開き切っても2割は点が入る。** 0点にすると、開き切ったあとに打つ理由が消えて「見ているだけ」になる。

## 打ち間違いは、点で効かせて画面には出さない

打ち間違えるたびに、**その地名で入る点に 0.85 が掛かる**（複利。下限は開示と同じ満点の2割）。満点500なら 500 → 425 → 361 → 307。**減るのはその地名の持ち点だけで、総スコアからは引かない**。次の地名に移ると0に戻る。

総スコアから直接引かなかったのは、このアプリが**読みを伏せている**からで、プレイヤーは当てずっぽうで打つことが前提になっている。1回の誤打で総額が削られると「読めないなら手を出すな」というゲームになり、伏せている意味と引っ張り合う。持ち点を削る形なら、迷って連打するほど静かに損をするだけで済む。

**ミスの回数は、遊んでいる最中には出さない。** Day018はミスの瞬間に「押してほしかったキー」を出していたが、読みが表示されている前提の作りで、ここでやると答えが漏れる。記録だけ残して結果画面の「つまずいた打鍵」で使う。`lib/game.js` の `press()` が `expected` を返さないのはそのため（テストで固定してある）。

## 鳴らすのは、見えていないものだけ

音は `lib/sound.js`。音源ファイルは1つも持たず、Web Audio API でその場で組み立てる（他人のアセットを持ち込めないので、鳴らすなら生成するしかない）。Day018 と同じく「決める部分（純関数・テストできる）」と「鳴らす部分（AudioContext）」に割ってある。

**打鍵そのものには音を付けていない。** 見えているものに音を重ねても情報は増えないから。鳴らすのは、プレイヤーの目が漢字と伏せ字に釘付けになっているあいだ、**視線の外で起きていること**だけ。

| 音 | 何を伝えるか |
|---|---|
| 読みが1文字開いた | 低いチク音。**開くほど音が下がる**＝持ち点が減っている |
| 着弾が近い | 心拍のような低音。近いほど速い（0.55より奥では鳴らさない） |
| 打ち間違えた | 短いノイズ。音階に乗らない唯一の音で、揃いを崩す |
| 打ち切って弾けた | 律音階の上行3音。伏せたまま残せたぶんだけ高い |
| 手前まで来られた・降参 | 下行型。弾けた音と向きを逆にする |

`AudioContext` は「はじめる」を押すまで1つも作らない（開いただけの人のタブに音の権利を握らせない。E2Eで固定してある）。HUDの「音あり／音なし」で切れるほか、`?sound=off` で最初から鳴らさずに始められる。

### デモ動画の音は、アプリが鳴らした音そのもの

Playwrightは音を録らないので、動画は無音で上がる。別の効果音を被せるのではなく、**録画中にアプリが実際に鳴らした音を控えておき**（`?sound=log`）、`tools/render-demo-audio.mjs` が同じ波形・同じ包絡線で組み立て直して重ねる（day-007/008/010/012と同じ手）。

位置合わせは**動画の末尾から逆算する**。録画は振り付けが返った直後に止まるので、「盤面が始まってから振り付けが終わるまで」だけ末尾から戻った点が音の t=0 になる。頭を切っても末尾は動かないので、`trim-demo.mjs` のあとでも合う。

⚠️ ブラウザ側のマスター音量（0.22）は再現に掛けない。掛けると −50 LUFS まで落ちてXでは何も聞こえない。全体を1つの係数で持ち上げるので、**音どうしの大小の関係はアプリと変わらない**（実測 −23.7 LUFS。既存の音付きDayは −19.5〜−22.2）。

## 打つ場所は、盤面そのもの

打鍵を受ける `#keys` は透明だが、**盤面と読みの全面を覆っている**。親の `.play-area` を `position: relative` にして、`#keys` 自身を `inset: 0` で敷いてある。

最初は1px・`opacity:0` の隠し入力にしていた。デスクトップでは `document` の keydown で拾えるので動くが、**スマホでは詰む**。触っても入力欄に当たらないので仮想キーボードが出ず、打つ場所が画面のどこにも無い。さらに盤面の `pointerdown` で `preventDefault()` してから `focus()` していたのが致命傷で、iOS/Androidは「入力欄への直接の操作」でしか仮想キーボードを開かないため、既定の動作を止めると二度と出ない。**この `preventDefault()` はデスクトップのフォーカス外れを直すために入れたもので、直した先で別の端末を壊していた。**

いまは入力欄そのものを触ったときだけ既定の動作に任せ、その外（HUDや余白）を触ったときだけ `preventDefault()` する。`font-size` は 16px（iOSがフォーカス時に勝手にズームするのを防ぐ）。タッチ端末には「ここをタップしてキーボードを出す」を、**1打も受け取れていないあいだ**出す（`focus()` を呼んでも仮想キーボードを開かない端末があるので、フォーカスの有無だけでは消さない）。

## 日本語入力は、変換を始めた瞬間に知らせる

IMEがオンだと、確定するまでどのキーもゲームに届かない。以前は `compositionend`（確定した瞬間）でしか警告を出しておらず、**確定せずに打ち続ける人には「打っても何も起きない」画面にしか見えなかった**。いまは `compositionstart` で即座に出す。

⚠️ **この2つは自動テストで見つけられなかった。** Playwrightはキーイベントを直接注入するので、仮想キーボードが出ているかもフォーカスがどこにあるかも関係なく打ててしまう。だから回帰テストは「打てたか」ではなく、**実機でキーボードが出るための条件**（入力欄が全面を覆っているか・16px以上か・タップでフォーカスが入るか・変換開始で警告が出るか）を直接見ている。

## 難易度は式ではなく実測で決めている

全件から等間隔に採ると1問目が「板山＝いたやま」「太郎＝たろう」級で退屈だった。難読度が「読みの珍しさ」と「かな長の意外さ」の和なので、**読みが素直でも長さだけで点が付く**ため。出題の在庫には別に2つの条件を課している。

1. 全国順位で上位20%
2. 少なくとも1文字は珍しい当て方（その字にその読みを当てる地名が全国100件以下）

結果の坂（東北・在庫395件を等間隔に見たもの）：南外若林 → 栗生 → 羽白 → 太郎布 → 内越。

## 4つの状態

| 状態 | いつ |
|---|---|
| 読込中 | 出題データ（465KB）の取得中。進捗を出す |
| エラー | 取得に失敗。原因と再試行 |
| 空 | 選んだ地方の在庫が足りない。件数を出して全国へ誘導 |
| 不正入力 | 読みに無いキー・日本語入力がオン。**何を押すべきかは言わない** |

## 動かし方

```bash
npm run test:unit                       # ユニット24本
npx playwright test tests/e2e/day-024-unreadable-places.spec.mjs

# 出題データを作り直す（元データはリポジトリに入れない）
curl -sSL -o /tmp/utf_ken_all.zip \
  "https://www.post.japanpost.jp/service/search/zipcode/download/utf/zip/utf_ken_all.zip"
unzip -o /tmp/utf_ken_all.zip -d /tmp/kenall
node apps/day-024-unreadable-places/tools/build-places.mjs \
  --csv /tmp/kenall/utf_ken_all.csv --out apps/day-024-unreadable-places/assets/places.json
```

⚠️ 配布URLは移転している。`/zipcode/dl/utf/zip/...` は404を返し、**404ページのHTMLが zip という名前で保存される**。落としたら `file` で中身を確かめること。

⚠️ 全国12万件もあると、実在の地名が非公開語（`.precheck-ng.txt`）と偶然一致する。ビルド時に除外している（48件）。リストが手元に無い環境では素通しになるので、そのときは `npm run precheck` が止める。
