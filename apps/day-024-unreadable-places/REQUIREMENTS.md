# Day 024 — 読めない地名が、向かってくる（仮題）

## 一言で

奥から**地名（漢字だけ）**が近づいてくる。読みをローマ字で打ち切ると弾けて消える。**読みは最初は見えない。** 近づくほど1文字ずつ開くので待てば誰でも打てるが、開くほど点は減る。**知っている人がいちばん強い**タイピングゲーム。

参照した既存作は「漢字でGO!」（PLiCy）。ゲームのルール自体は著作権で保護されない（釣りゲータウン2事件・知財高裁 平成24年8月8日／Day017・018で確認済みの整理）。そのうえで**名称・配色・意匠・効果音・ステージ構成は寄せない**。Day017と同じ「似せないほうが説明コストが低い」判断。

## データ

日本郵便の郵便番号データ（UTF-8版・全国一括）。利用条件は説明ページに逐語で次のとおり。

> 郵便番号データに限っては日本郵便株式会社は著作権を主張しません。自由に配布していただいて結構です。

同梱・加工・再配布いずれも可。取得はビルド時に1回だけ。

```
curl -sSL -o utf_ken_all.zip https://www.post.japanpost.jp/service/search/zipcode/download/utf/zip/utf_ken_all.zip
```

⚠️ 旧URL（`/zipcode/dl/kogaki/zip/ken_all.zip`）は404。配布ページは `/service/search/zipcode/download/utf-zip.html` へ移っている。

**読みは郵便局側の表記**で、地元の読みと違うことがある。画面に明記する。**地名を笑わない。**「難読」は初見で読めるかの指標であって地名の良し悪しではない、という一文を添える（Day015の「良い悪いは言わない設計」と同じ姿勢）。

## ユーザーストーリー

> **地名に詳しいと思っている人**として、
> **自分の知識がそのまま点数になる遊びが欲しい**。
> なぜなら**クイズは1問ずつ間が空いて冷めるし、タイピングゲームは読みが最初から書いてあって知識が要らない**から。

補助ストーリー：

> **地名を全然知らない人**として、
> **読めなくても最後まで遊べて、終わったときに1つか2つ覚えていたい**。
> なぜなら**知識ゲームは開始10秒で「自分向けではない」と分かると閉じる**から。

> **自分の地元が読まれないことに慣れている人**として、
> **地方を選んで出題させたい**。
> なぜなら**全国だと自分の知らない土地ばかり出て、自分の土地が来ない**から。

## UX 5階層

### ① 戦略層（なぜ作るか）

| | 内容 |
|---|---|
| 提供側の目的 | Day11–20の区間テーマ**4状態対応**の締め。Day018のタイピング判定エンジンを流用し、**問いだけ差し替えると別ジャンルになる**ことを確かめる |
| ユーザーの目的 | 速くなりたいのではない。**「自分は読めるほうか」を確かめたい** |
| 差別化 | Day018は読みを最初から見せる＝**運動能力**を問う。ここは読みを隠す＝**知識**を問う。同じエンジンで問いが逆になる |

> 🔴 「読みを隠す」と決めたことが以降を全部決めている。隠すと**読めない人が1文字も打てずに終わる**ので、ヒントの段階開示と降参が必須になり、得点は「どれだけ開かずに打てたか」で決まる形に変わる。速さで点を付ける実装はここで却下された。

### ② 要件層（何が要るか）

必須：

1. 地名（漢字のみ）が奥から近づき、読みをローマ字で打ち切ると弾けて消える
2. **読みは初期状態で全部隠す。** 近づくにつれて1文字ずつ開く
3. **「わからない」で降参できる。** 正解と**なぜ読めないか**（その字にその読みを当てる地名が全国で何件か）が出る
4. **地方ブロックを選べる**（全国／北海道／東北／関東／中部／近畿／中国／四国／九州・沖縄）
5. 得点は**開示した文字数が少ないほど高い**。速さでは決めない
6. 4状態（空・読込中・エラー・不正入力）が全部ある

削る順（下から捨てる）：地方別の難読度ランキング表示 → 降参した字の再出題 → 「なぜ読めないか」の内訳。**1・2・5は捨てない**（これが本体）。

やらない：

- ハイスコア保存・ランキング投稿・アカウント（localStorageはDay21–30まで未解禁）
- 実行時の通信（難読度はビルド時に計算して同梱。Day31まで外部API未解禁）
- 制限時間制。Day018が60秒の時間制なので、ここは**ライフ制（3ミス終了）**にして遊びの形を変える

### ③ 構造層（難読度をどう決めるか＝レベルデザイン）

出題順と点数配分の土台。**外部の漢字辞典を使わず、地名データだけから読みの珍しさを出す。**

**第1段：漢字1字あたりの「読みの長さ」を連立方程式で解く。**
地名ごとに「かなの総数 = 含まれる各漢字のかな数の和」が成り立つ。全国12万件ぶんの式を漢字約3千種について最小二乗で解き、1字あたりの期待かな長を得る。予測と実測の差が**長さの意外さ**（男鹿＝おが は予測より短い）。

**第2段：解いた期待長で漢字とかなを対応づけ、読みの頻度表を作る。**
動的計画法で「各漢字の割当長と期待長のずれが最小になる切り方」を選び、漢字ごとの読み出現頻度を数える。難読度は **平均の珍しさ（−log 出現確率）＋ 長さの意外さ**。

この式から要件3の「なぜ読めないか」が自動で出る。

**出題する在庫の条件は実測して決めた**（机上で決めない）。全件から等間隔に採ると1問目が「板山＝いたやま」「太郎＝たろう」級になって退屈だった。原因は、難読度が「読みの珍しさ」と「かな長の意外さ」の和なので、**読みが素直でも長さだけで点が付く**こと。そこで2つの条件を課している。

1. 全国順位で**上位20%**（`difficulty >= 0.80`）
2. **少なくとも1文字は珍しい当て方**をしている（その字にその読みを当てる地名が全国100件以下）

結果の坂（東北）：南外若林（なんがいわかばやし）→ 大雄大関（たいゆうおおぜき）→ 大笹生（おおざそう）→ 五月雨（さみだれ）→ 内越（うてつ）。

### ④ 骨格層（画面）

1画面。奥（小さい・薄い）→手前（大きい・濃い）へ地名が来る。**漢字は最初から大きく、読みは伏せ字（○○○）で下に。** 開示は左から1文字ずつ。ライフと得点は上端、「わからない」は親指の届く下端に置く。

奥行きは `scale` と `translate` で作る。物理エンジンは使わない。

### ⑤ 表層

Day018（暖色・食べ物・皿）と並べても別物に見えるように、**寒色・余白・明朝の漢字**で組む。地名を素材として扱い、装飾で茶化さない。

## 4状態の中身

| 状態 | いつ | 出すもの |
|---|---|---|
| 読込中 | 難読度データの取得中 | 進捗つき。盤面の枠だけ先に描く |
| エラー | データ取得に失敗 | 原因と再試行。「回線を確認」で終わらせない |
| 空 | 選んだ地方に出題できる地名が足りない（四国など母数が小さい地方で起きる） | 何件あるかを数字で出し、全国モードへ誘導する |
| 不正入力 | 判定器が扱えない読み・IME変換中の入力・押してほしくないキー | 何が通らなかったかを具体的に書く（Day018の「押してほしかったキー」を流用） |

## 実装の落とし穴（先に潰す）

- 町域名に `以下に掲載がない場合` `（次のビルを除く）` などの注記が混じる。除外しないと出題が注記で埋まる
- `一丁目` などの丁目、ひらがな・カタカナだけの町名、数字入り、`大字` などの接頭は対象外にする
- 同じ町域名が郵便番号違いで重複する。市区町村つきで名寄せする
- 読みは全角カタカナ。ひらがなへ直したうえで `isSupported()` で弾く（`ヶ` `ヵ` `ー` に注意）
- 難読度の上位は**1字地名**に偏りやすい（1字なのに読みが長い）。字数ごとに正規化しないとティアが崩れる
- ヒントを開き切った瞬間に打てるようにすると、待つのが最適戦略になる。**開き切っても着弾までの猶予は短く保つ**
- 地名は2〜5文字ある。字の大きさを固定すると4文字で画面幅を超え、文字数で割るだけだと枠の半分しか使わず小さくなる
- **全国12万件もあると、実在の地名が `.precheck-ng.txt` の非公開語と偶然一致する**（48件あった）。ビルド時に除外しないと `npm run precheck` が公開を止める
