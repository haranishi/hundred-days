# 「この道、誰がケガしてる？」プロモーション動画

縦型1080×1920・35秒・BGM付き。絵コンテは `timeline.mjs`、音は `promo-audio.mjs`、画は `render-promo.mjs` の3本で完結する。

```sh
PLAYWRIGHT=/path/to/playwright/index.js node apps/day-041-who-got-hurt/tools/promo/render-promo.mjs
```

出力は `promo.mp4` と `promo-first-frame.png`（どちらも gitignore 済み）。`promo-audio.wav` が無ければ `--variant a` で自動生成する。

## このDayで気をつけること

- **事故のデータは同梱ファイル**なので、撮り直しても数字は動かない。外へ出るのは地図タイルと住所検索の2系統だけ
- **住所検索は `tests/fixtures/address-kochi-eki.json` に差し替えて撮る。** 相手のサーバーを何十回も叩かないため、
  そして候補の並びが変わって「高知駅」を押し損ねないため
- **地図タイルだけは本物を読む。** ここをベタ塗り（`blank-tile.png`）にすると地図が真っ白になり、
  「その場所の周りの事故」という絵が成立しない
- 東京駅は現在地、高知駅は住所検索の候補から押す。地図のタイルが描き切るまで2.4秒待つ
- 冒頭のスクロールは `panTo()` が秒数を指定して動かす（`smooth` は数百msで着いてしまい1コマ目が静止画になる）

## 字幕の数字は画面と突き合わせてある

`render-promo.mjs` の `expect()` が、書き出す前に画面の文字と字幕の数字を照合して、違っていたら止まる。

| 場面 | 字幕 | 画面のどこ | 照合する文字 |
|---|---|---|---|
| S1 | 6年間に351件 | `#answer-text` | `6年間に351件` |
| S2 | 歩行者78件、自転車76件 | `#answer-sub` | `歩行者78件・自転車76件` |
| S3 | 北東440mの交差点に16件 | `#spots-list`（1位） | `北東へ440m・交差点 — 16件（歩行者3）` |
| S4 | いちばん多いのは18時台 | `#hours-peak` | `いちばん多いのは18時台で、30件です。` |
| S5 | 高知駅は132件。／でも61件が自転車 | `#place-name` `#answer-text` `#answer-sub` | `選んだ場所：高知駅` `132件` `自転車61件` |

### 高知の数字は「高知駅」候補の座標で出したもの

絵コンテの下書きは高知を **129件・歩行者11・自転車63・死亡1** としていたが、
住所検索の候補「高知駅」（133.543308, 33.567126）で実際に数えると **132件・歩行者12・自転車61・死亡1** になる。
半径500mの円を高知駅の周り±5kmで動かしても 129/11/63/1 になる点は無いので、
下書きの数字の出どころは不明。**画面の値（132・61）を採った。**
座標を変えると数字も変わるので、字幕を書き換えるときは上の表の照合文字も一緒に直す。

## 判断は書かない

このアプリは記録を出すだけで、危ない・気をつけようといった評価はしない。字幕も同じ方針で、
件数と場所と時刻しか言わない。S6 では「件数は交通量で割っていません」を画面と一緒に出す。

## BGM

Day 039・040 と同じ生成器（F メジャー・92BPM）。場面の秒数は `timeline.mjs` の `STORYBOARD` と
`T_CONFIRM_TAP` から読むので、絵コンテを動かせば音も一緒に動く。A案（ローファイ鍵盤）と
B案（アコースティック寄り）の2本を書き出せる。

```sh
node promo-audio.mjs --variant a --out promo-audio-a.wav
node promo-audio.mjs --variant b --out promo-audio-b.wav
```
