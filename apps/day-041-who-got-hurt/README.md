# Day 041 この道、誰がケガしてる？

場所をひとつ決めると、その周りで2019〜2024年に実際に起きた人身事故を地図に出し、
「誰が巻き込まれたか」を件数で答える。半径（300m／500m／1km）と誰が（すべて／歩行者／自転車／65歳以上）で絞れる。

## なぜ作ったか

警察庁は6年ぶんの人身事故を、1件残らず緯度経度つきで公開している。
それでも普通の人は開けない。1年ぶんで56〜70MB、文字コードは Shift_JIS、
座標は `430607590`（43度06分07.590秒）という形で数字に潰してある。

自治体の事故マップは県ごとにばらばらで、「歩行者だけ」で全国横断に絞れるものは少ない。
毎日通る道について、**手元で数えられる**状態にするのがこのアプリの仕事。

## やらないと決めたこと

- **危険かどうかを判定しない。** 件数は交通量で割っていないので、多い場所は「危ない」のではなく
  「通る人が多い」だけかもしれない。出すのは過去の記録だけで、予測も評価もしない。この但し書きは答えの真下と限界の両方に置いた
- **子ども（小学生）で絞らない。** 年齢は6年とも階級値で、いちばん若い区分が **0〜24歳**。
  中学生と大学生が同じ箱に入るので「子ども」と名乗れない
- **日付を持たない。** 持っているのは年まで。死亡事故の日付と場所が揃うと、遺族にとっては個人の記録になる
- **交差点を名前で呼ばない。** データに交差点名が無い。方角と距離（「北東へ180m・交差点」）で名指しする

## 設計で迷ったところ

**データをどう積むか。** 全6年・約375MBのCSVを実行時に読むのは無理で、警察庁のサーバーには
CORSヘッダが無いのでブラウザから直接も読めない。**1件6バイトの固定長**に詰め、
地域メッシュで割って同梱した（1,884,647件・371ファイル・10.8MB）。端末は自分の周りの1〜4本だけ取る。

**メッシュの割り方。** 全部を2次メッシュ（約10km四方）で割ると3,800本を超えてリポジトリが荒れる。
2,000件未満のメッシュは親の1次メッシュ（約80km四方）へまとめて371ファイルにした。
そのぶん索引の引き方が「2次にあればそれ、無ければ親の4桁」の2段になる（`lib/mesh.js`）。

**地図のピンをDOMにしない。** 東京駅の半径1kmは1,724件ある。`maplibregl.Marker` を1,700個置くと重い。
canvas で6種類の絵を作って `addImage` し、記号レイヤーに載せている。形は歩行者＝丸／自転車＝ひし形／
そのほか＝小さな点、死亡事故は外側に縁取りを足す（色だけで区別しない）。

**「集まっている地点」を出す。** ただの点の海では「どの角か」が分からない。
およそ40mの近さにあるものを1つにまとめ、件数の多い順に上位5件を出す。
総当たりだと1,700件で百万回の距離計算になるので、40m四方の桝に入れて周り9桝だけ見る。

## 落とし穴（次に触る人へ）

- 🔴 **ファイル名の年は、事故が起きた年ではない。** 警察庁のファイルは事故が確定した「統計年」で
  分かれていて、`honhyo_2024.csv` には2023年の事故が8,477件、2018年以前のものまで入っている。
  **重複は無い**（全190万件を都道府県・警察署・本票番号・日時・座標で突き合わせて0件を確認）ので、
  発生年の列から取って数え直す。2019年より前に起きた10,460件は端数なので落とした
- 🔴 **いちばん新しい年は数%少なく出る。** 2024年に起きた事故のうち2025年に確定するぶんは、
  2025年のファイルが出るまで入らない（2024年282,376件に対し、2019〜2023年は各30万件台）。画面の限界に書いてある
- **4桁のファイルには、単独ファイルを持つ2次メッシュのぶんが入っていない。** `4930.bin` は
  「4930のうち2,000件に満たなかった2次メッシュ」だけを持つ。円がまたぐときは両方取る必要がある
  （`filesForCircle` は円の四隅のメッシュを引くので漏れない）
- **`readPack` は桁数が食い違うと投げる。** ファイルの見出しに桁数が書いてあり、
  4桁のファイルを6桁のつもりで読むと座標が全部ずれる。黙って壊れないよう例外にしてある
- **時刻不明は24として入っている。** 帯に混ぜると「0時台」が膨らむ。`hourBand` が外して別に数える
- **CSPは `connect-src` だけでなく `worker-src blob:` も要る。** MapLibre が blob から Web Worker を起こす。
  足りないとローカルでは動いて本番の地図だけが黙って白くなる。`scripts/build.mjs` の3つの表に登録する
- **地図の帰属に `customAttribution` を足さない。** タイルのソースが持つ文言が常設表示に出る（Day 039・040で踏んだ）
- **録画スクリプトは `file://` で開く。** ESモジュールと fetch が動かないので、
  `demo-scenario.mjs` の中でミニHTTPサーバーを立てて開き直している

## データと利用条件

警察庁「[交通事故統計情報のオープンデータ](https://www.npa.go.jp/publications/statistics/koutsuu/opendata/)」
本票 2019〜2024年。[公共データ利用規約（第1.0版）](https://www.npa.go.jp/rules/index.html)。

この規約は**出典の記載だけでは足りない**。「編集・加工等を行ったこと」を出典とは別に書くことと、
加工した情報を国が作成したかのような態様で公表しないことを求めている。画面の出典欄はこの3つを常時出している。

1. 出典：警察庁「交通事故統計情報のオープンデータ」（2019〜2024年）
2. このページは、同データを加工して作成しています（緯度経度の形式変換、月日を落として年だけにする、地域メッシュごとの再編成）
3. この加工と表示を行ったのはこのページの作成者（個人）で、警察庁や国が作成・監修したものではありません

地図タイルと住所検索は国土地理院（[コンテンツ利用規約](https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html)）。
加工の内訳とテスト用の実応答の出どころは [`data/SOURCES.md`](data/SOURCES.md)。

**現在地の座標は端末の外に出さない。** 事故データが手元にあるので照合は端末内で終わる。
外へ出るのは地図タイルの番号と、住所検索を使ったときの入力した語だけ。
