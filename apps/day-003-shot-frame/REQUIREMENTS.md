# Day 003「スクショ映えメーカー」要件定義

> 100日チャレンジ Day3。スクリーンショットを1枚入れると「余白＋角丸＋影＋グラデ背景」つきのSNS映え画像に整形し、PNGで保存できる単機能Webアプリ。
> ハッピーパスは1本だけ：**スクショを入れる → 整形された画像が出る → PNGで保存する**。

## 1. 共通制約（Day1-10フェーズ・変更禁止）

- **外部依存0個**：ライブラリ・CDN・Webフォント・外部API・アナリティクス一切禁止。ブラウザ内蔵API（Canvas 2D等）のみ。
- **画像は完全クライアントサイド処理**。サーバーへ送信しない。`fetch`/`XMLHttpRequest` を書かない。
- アカウント不要・課金なし・**localStorage等の永続化も使わない**（設定はハードコード）。
- 構成は day-001/002 と同じ **プレーン3ファイル**：`index.html` / `style.css` / `script.js`（`defer`読み込み）。ビルド工程なし。
- サブディレクトリ配信（`/day-003-shot-frame/`）で動くよう**相対パスのみ**使用。
- ファイル内に絶対ローカルパス・個人名・大学名・他案件名を書かない（公開リポジトリ前提）。

## 2. 機能要件

### 2-1. 画像入力（3経路）

- ドロップゾーン1つ：**ドラッグ&ドロップ**と**クリックでファイル選択**（`<input type="file" accept="image/*">`）の両対応。
- 加えて**クリップボード貼り付け（Cmd/Ctrl+V）**に対応する（`paste`イベント→`clipboardData.items`から`image/*`を拾う）。スクショは「撮ってすぐ貼る」が最短導線なので、この企画では貼り付けが主役級。ドロップゾーン内に「⌘V で貼り付けもOK」と一言添える。
- 対応形式はブラウザがデコードできる画像（png / jpg / webp 等）。判定は `file.type.startsWith("image/")` 程度でよい。
- 画像以外の入力は黙って無視するか、ドロップゾーン内に短い一言を出す程度（エラー状態の作り込みはしない＝Day1-10の「1状態」ルール）。
- 2枚目以降を入れたら**そのまま差し替え**（確認ダイアログなし）。
- 巨大画像対策：長辺4096pxを超える場合は読み込み時に4096pxへ縮小してから扱ってよい（Retinaスクショは3000px級が普通に来るため、2048では切りすぎ）。

### 2-2. 整形（コア）

canvasへの**4層描画**で合成する。描画順序を固定：

1. **背景**：キャンバス全面にグラデーション（または単色）を塗る
2. **影**：`shadowColor`/`shadowBlur`/`shadowOffsetY` を設定した状態で角丸矩形を塗る
3. **クリップ**：同じ角丸矩形パスで `clip()`
4. **画像**：`drawImage()` でスクショを描く（＝角丸に切り抜かれる）

パラメータは4つ。**すべて元画像の解像度基準で計算**する（出力＝元解像度＋余白。プレビューはCSSで縮小表示するだけ）：

| パラメータ | UI | 仕様 |
|---|---|---|
| 背景プリセット | チップ（色見本つきボタン）6個 | グラデ4種＋単色2種。具体色は実装側で決めてよいが、**チップ自体に実際の背景色/グラデを表示**する（ラベルと実物の一致原則）。初期値は1番目のグラデ |
| 余白 | スライダー | 元画像**長辺の 4〜20%** / step 1 / **初期値 10%**。現在値を数字で併記（例「余白 10%」） |
| 角丸 | スライダー | 元画像**短辺の 0〜6%** / step 0.5 / **初期値 2.5%**。0で四角。内部で「短辺の半分」を上限にクランプ |
| 影 | スライダー | 0〜100 / **初期値 55**。内部で blur・offsetY・不透明度に線形マッピング（0で影なし）。マッピング式はコード内コメントに明記 |

- スライダー/プリセット変更時は**即時再描画**（`input`イベント）。4096px級でも1回の再合成は軽いのでデバウンス不要。ただし体感で重い場合のみ `requestAnimationFrame` でまとめてよい。
- 透過PNGが来た場合は背景がそのまま透けて見える（それで正しい。特別対応不要）。
- プレビューのぼやけ対策：プレビュー用canvasは `devicePixelRatio` を考慮して描くか、出力canvasをCSS縮小するだけの方式にする（にじんだプレビューはデモ動画映えを損なう）。

### 2-3. 表示

- 加工結果の**単一プレビューが主役**（Before/After並びは不要。Beforeは視聴者が知っている「素のスクショ」なので）。
- 初期表示はドロップゾーンのみ。画像が入ったらプレビュー＋操作パネルに切り替わる（画面遷移1本、状態分岐はこれだけ）。
- どこかに小さく**「画像はブラウザの中だけで処理されます」**の一文を置く（このアプリの売り文句・事実と一致）。

### 2-4. ダウンロード

- 「PNGで保存」ボタン。`canvas.toBlob("image/png")` → `<a download>` で保存。
- 出力解像度：**元画像の解像度＋余白**（プレビュー縮小の影響を受けない）。
- ファイル名：`shot-{出力幅}x{出力高さ}.png`（例 `shot-3024x1964.png`）。

## 3. UI/デザイン要件

- 単画面・日本語UI。タイトルは「スクショ映えメーカー」、どこかに小さく `Day 003` 表記。
- 配色はチャレンジ一覧ページとトーンを合わせた**ダーク系**（`--bg:#14161c` / `--panel:#1d212b` / `--text:#eef1f6` / `--accent:#4f9cff` を基調に流用可）。背景プリセットのチップだけは実物の色を出す。
- day-001/002 の流儀に合わせる：BEM風クラス命名、`aria-*` の最低限の配慮、システムフォントスタック。
- レスポンシブ（375px幅〜PC）。タッチ操作でもファイル選択・スライダーが使えること（貼り付けはPC向け機能としてOK）。
- フッターに一覧へ戻るリンク `<a href="../">← 100 DAYS / 100 APPS</a>`。

## 6. 検収基準（実装者セルフチェック）

1. ローカルで `index.html` を開き（file:// または簡易HTTPサーバ）、**ドロップ→整形プレビュー→4パラメータ全部動く→PNG保存**、まで一連で動く。**貼り付け（Cmd+V）でも入力できる**。
2. 保存したPNGが「元解像度＋余白」になっている（プレビューの縮小サイズで出力されていない）。
3. 外部リクエストが1本もない（コード上 `http` 参照なし）。
4. リポジトリルートで `npm run build` が通り、一覧に Day 003 が「制作記録のみ」として載る（draftのため）。
5. スマホ幅（375px）でレイアウト崩れなし。
6. ファイル内に絶対ローカルパス・個人情報・他案件情報がない。
7. **git操作（add/commit/push）・デプロイ（wrangler）・PR作成は一切しない**（本人指示：ローカルに留める）。
