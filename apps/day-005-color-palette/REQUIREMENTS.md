# Day 005 要件定義：その写真、何色でできてる？

## 1. 何を解くか

デザイン・資料・SNS投稿で「この写真の色をそのまま使いたい」とき、デザインソフトやスポイトツールを開かずに、ブラウザに画像を落とすだけで主要色のカラーコード（HEX）が取れるようにする。

ネタの出どころは100日チャレンジのアプリバックログ（2026-08-08整理。当初Day 1の題材に採用→再選定で在庫戻し）。需要ベース100案とは別系統の在庫で、**公的統計による需要の裏づけは取っていない**。

## 2. 主要アクション（1本のハッピーパス）

画像を入れる → 主要な6色が出る → 色をタップするとHEXがコピーされる。

**4状態対応（空／読込中／エラー／不正入力）はDay 11以降の解禁**なので作らない。その代わり、不正入力を構造で減らす：

- ファイル選択は `accept="image/*"` で画像に絞る
- ワンタップで試せる**サンプル3種**を置く（ファイルを持っていなくても主要アクションが完結する）
- それでも読めない入力（ドロップされた非画像など）は**黙って無視せず1行の通知だけ**返し、画面状態は変えない。エラー画面・再試行導線は設計しない

## 4. 入力

| 経路 | 形式 |
|---|---|
| ドラッグ＆ドロップ | 画面のドロップゾーンへ画像ファイルを落とす |
| ファイル選択 | ドロップゾーンをタップ → OSのファイル選択（`accept="image/*"`） |
| ペースト | Ctrl/Cmd+V（クリップボードの画像） |
| サンプル | 「夕焼け」「新緑」「夜の街」の3チップ。**実行時にcanvasで手続き的に描画**する（画像ファイルを同梱しない＝著作権・EXIFのリスクをゼロにする） |

サンプルの描画は乱数を使う場合も**固定シード**にして、毎回同じ絵・同じパレットになるようにする（デモ録画と表示の再現性のため）。

## 5. 出力

- 読み込んだ画像のプレビュー
- 6色のパレット：
  - 占有率に比例した幅の**帯**（パレット全体の見た目）
  - **スウォッチ6枚**：色面にHEX（大）・RGB（小）・占有率%を表示。文字色は背景色との相対輝度で黒/白を自動切替
  - スウォッチをタップ → HEXをクリップボードへコピー →「コピーしました」を短く表示
  - 「6色まとめてコピー」ボタン（HEXを改行区切りで）
- 「画像はどこにも送信されません。すべてこの画面の中だけで処理されます」を明記

## 6. 抽出仕様（メディアンカット法）

1. 画像を最大辺 **120px** に縮小してcanvasに描画（アスペクト比維持）
2. `getImageData` で画素を取得し、**alpha < 128 の画素は除外**
3. 全画素を1つの箱に入れ、**箱が6個になるまで分割**を繰り返す：
   - 分割する箱は「画素数 × RGBレンジ最大値」が最大のもの
   - 分割軸はその箱でレンジが最大のチャネル（R/G/B）
   - 分割点はそのチャネルの**中央値**
   - 画素数2未満の箱は分割しない（6個に満たないまま終わってよい。単色画像なら1色だけ出る）
4. 箱ごとに画素の**平均色**を代表色とし、画素数を占有率とする
5. 占有率の降順に並べる

文字色の判定はWCAGの相対輝度（`0.2126R + 0.7152G + 0.0722B`、sRGBリニア化あり）で、輝度 > 0.4 なら黒文字、以下なら白文字。

クリップボードは `navigator.clipboard.writeText` を使い、使えない環境（file://直開きなど）では `document.execCommand('copy')` にフォールバックする。

### 実装後の追記（2026-08-12）

- 手順3の分割候補から、画素数2未満に加えて**色幅（レンジ）0の箱も除外**した。同一色の箱を割っても色は増えないため（除外しないと単色画像で同一色の箱が量産される）
- **平均色が丸めの結果おなじHEXになった箱は1つにまとめ、画素数を合算する**（仕様からの逸脱）。べた塗り3色の画像で同じ色のスウォッチが2枚並ぶ実害が出たため。まとめた分だけ色数は6より減ってよく、UIの表示（まとめてコピーのボタン文言）は実際の色数に追従する
- この分割方式の性質上、**占有率は25%・12.5%のような2の冪の刻みに揃う**。バグではないことをアプリ内notesとREADMEに明記した

## 7. 扱わないもの

- 色数の変更（6色固定。設定を持たないことで状態を増やさない）
- パレットの保存・履歴（localStorageはDay 21以降の解禁）
- HEICなど**ブラウザが表示できない画像形式**（ブラウザのデコーダに依存する。読めない場合は§3の1行通知）
- スポイト（1ピクセル単位の色取得）、画像編集

## 8. 法務・公開前の整理

- 画像は送信も保存もしない（外部通信・localStorage・Cookieゼロ）。個人情報保護法の論点なし
- 他者の画像・フォント・コードを同梱しない（サンプルは自前の手続き描画）
- ユーザーが読み込ませた画像はDOM上のプレビューにのみ使い、ページを離れれば消える
