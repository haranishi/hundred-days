# Day 023「MAGTRACE」要件定義

気になる言葉を1つ入れると、その言葉を**題名に含む雑誌記事が、この30年で「いつ・どれだけ」現れたか**を年別の推移グラフにし、**転機の年**と、その年の**代表記事（原典リンク付き）**まで出す。一文で言うと「雑誌版のトレンド検索」。データは国立国会図書館サーチ（NDLサーチ）の雑誌記事索引メタデータだけを使い、本文や表紙は扱わない。

## 背景と狙い

- SNSで見かけた言葉（推し活・サウナ・腸活・生成AI…）が「いつから」「どんな文脈で」語られてきたかは、検索しても断片しか出ない。雑誌は時代の空気を毎月切り取ってきた媒体で、その記事タイトルの件数推移は「社会の空気の変化」の一次資料になる。
- 既にあるものとの違い。Googleトレンドは検索量（2004年以降・出典なし）。NDLサーチ本体は検索結果の一覧で、推移は見えない。**このアプリは「30年の年別推移」「転機の年」「その年の代表記事と原典リンク」を1画面にまとめ、件数の根拠（収録範囲・取得日時・出典）を隠さない**。
- 難易度設計（Day21–30）: **localStorage（最近調べた言葉）**＋**演出1つ（折れ線が描かれる）**。外部APIはこのリポジトリではDay009以降に前例あり。サーバー中継（Pages Function）はDay009方式。

## データの出典と扱い（画面にも出す）

| 項目 | 内容 |
|---|---|
| データ提供元 | 国立国会図書館サーチ（NDLサーチ）外部提供インタフェース。データセットは雑誌記事索引 `dpid=zassaku` |
| 数えるもの | **記事タイトルに検索語を含む記事の件数**（`title` 索引）。本文・件名・掲載誌名は対象外＝「美術」と入れて『美術手帖』の全記事を数えない |
| 期間 | **1997〜2026年の30年**（年別）。今年（2026年）は集計途中として区別する |
| ライセンス | メタデータは CC BY 4.0。クレジット「出典：国立国会図書館サーチ（雑誌記事索引）」を表示する |
| 取り扱い | 本文・表紙は取得しない。「社会全体の傾向」と断定せず、常に「NDLサーチの収録範囲内の件数」と書く |
| 利用条件 | APIキー不要。継続利用の前に提供元へ利用内容を連絡する（公開前の人間のタスク） |

## ユーザーストーリー

| ユーザー | 欲しいこと（理由） | 受け入れ条件 |
|---|---|---|
| 本命：SNSで言葉を見つけた学生・一般の人 | 気になる言葉を入れるだけで「いつから・どれくらい」語られてきたかを知りたい（背景を知って会話や投稿に使いたい） | 1語入力→数秒で年別グラフと一文の発見が出る。最初に読むのは数字の羅列ではなく一文 |
| 企画の切り口を探す編集者・マーケター | 「転機の年」と、その年に何が書かれたかを、根拠（原典）ごと押さえたい | 転機の年に印が付き、その年の記事3件が題名・掲載誌・NDLの原典リンク付きで並ぶ。件数の出典と収録範囲が明記される |
| 言葉を持っていない人（救う相手） | 何を調べればいいか分からないが、面白い発見には出会いたい | 検索語なしでも「きょうの一語」とテーマ別の入口から1クリックで結果に行ける |
| もう一度来た人 | 前に調べた言葉をまた見たい。共有したURLからそのまま開きたい | 最近調べた言葉が端末内に5件残る（消せる）。`?q=言葉` のURLで直接結果が開く |
| 0件・障害に当たった人 | 行き止まりで終わりたくない | 0件なら言葉を短くする提案と候補語、障害なら入力を保持したまま再試行とホームへの導線が同じ場所に出る |

## UX5階層

- **戦略**: 「雑誌記事の検索窓」でも「グラフの置き場」でもなく、**言葉1つから"社会の空気がいつ変わったか"を一文で理解させ、根拠の原典まで1画面で降りられる**道具。差別化の源泉は①30年の年別推移②転機の年の名指し③代表記事の原典リンク④件数の根拠を隠さないこと。断定しない（「社会全体」と言わない）。
- **要件**: 1語検索／年別件数（30年）／今回の発見（一文）／注釈付き折れ線グラフ＋表表示／転機の年の代表記事（最大3年×3件・NDLリンク）／最近調べた言葉（端末内5件）／URL共有／4状態（読込・0件・障害・保存済み）／出典と収録範囲の明示／SNSシェア。**対象外**: 2語比較、関連語の自動抽出、共有用画像の生成、本文・表紙・要約、アカウント、年代の粒度切替。
- **構造**: 1ページ2ビュー。ホーム（検索＋きょうの一語＋テーマ別入口＋データについて）→ 分析（発見→推移→手がかり→代表記事→もう一度検索）。分岐は「0件」「障害」の2つで、どちらも同じ場所に次の一手（候補語／再試行／ホーム）を置く。ブラウザの戻るでホームへ戻れる。
- **骨格**: 分析ビューでいちばん大きい要素は**「今回の発見」の一文**（墨色カード）。その下に折れ線（転機に朱色の印と注釈）、表への切替、手がかり3つ、記事リスト、再検索。ホームでいちばん大きいのは見出しと検索欄で、Primary CTAは「雑誌の流れを見る」1つ。
- **表層**: 紙色の背景（#F6F1E8）に墨色（#191817）、朱色（#B64027）はCTA・グラフの主系列・転機の印・リンクだけ。見出しは明朝（端末の日本語明朝）、本文とデータはゴシック。グラフは灰色の目盛に朱色の1本。色だけで意味を持たせない（転機は印＋ラベル）。`prefers-reduced-motion` では線を描くアニメーションを止める。

### UX5階層を通したことで決まった実装（11件）

1. 分析ビューの最上部を「今回の発見」の**一文**にし、数字は一文の下に3つ（合計・ピーク年・転機の年）だけ置く（戦略：先に一文、根拠は後）
2. **転機の年は機械的な規則で決める**（前年からの増加数が最大の年。条件は下記）。「文脈が変わった」などの解釈はサーバーもUIも書かない（戦略：断定しない）
3. 代表記事は「転機の年」「ピークの年」「初めて現れた年」の**最大3年×各3件**に絞り、「その年の検索適合順の上位3件で、社会的な代表性を示すものではない」と選定基準を画面に書く（要件）
4. 数えるのは**記事タイトル一致**に限定し、そのことを画面に書く。掲載誌名や本文を数えると『美術手帖』問題が起きる（要件）
5. 検索語を持たない人のために**「きょうの一語」（日付で決まる1語）と4テーマ×3語の入口**を置く。すべて実データで動く語だけ（構造：救う相手の入口）
6. 0件と障害を**同じ位置・同じ型（状態名／原因／次の一手）**で出す。障害時は入力を消さない（構造：復帰路）
7. 結果は `?q=` のURLに載せ、`pushState` で履歴に積む。共有されたURLからそのまま結果を開ける（構造：共有＝URL。画像生成はしない）
8. 折れ線に加えて**「表で見る」**を付け、正確な値を確認できるようにする。グラフだけだと値を読めない（骨格・アクセシビリティ）
9. 今年（2026年）は**集計途中**として点線・注記で区別し、ピークや転機の判定から外す（骨格：誤読を防ぐ）
10. サーバーは**同じ言葉の結果を24時間キャッシュ**し、画面には取得日時と「保存済みの結果」の表示を出す（表層の前提：提供元への負荷配慮と、状態を隠さない）
11. Webフォントは読み込まず、端末の明朝・ゴシックを使う（表層：外部通信を増やさない。CSPの `font-src 'self'` も守る）

1. **ヘッダー**: チップ「推し活」「1997–2026」／h1「「推し活」の雑誌トレンド」／サブ「154件の記事タイトルを、発行年ごとに数えました。」／メタ行「取得 2026.08.29 19:40 ｜ NDLサーチ 雑誌記事索引 ｜ 記事タイトル一致」。**保存済み**のときはメタ行の先頭に緑のバッジ「保存済みの結果」。

4. **流れを読む手がかり**（最大3枚・`repeat(auto-fit,minmax(260px,1fr))` で枚数が2枚でも横幅を余らせない）: 「01 2020年｜収録範囲で初めて題名に現れた年」「02 2024年｜前年18件→45件（約2.5倍）」「03 2024年｜最多の45件」（重複する年は1枚にまとめる）。

## API（Pages Function）

`functions/api/day-023/trend.js` — `GET /api/day-023/trend?q=<言葉>`

### 入力

- `q`: 1〜30文字。前後の空白除去、NFKC正規化、制御文字と `"` `'` `<` `>` `\` を除去。除去後が空なら 400。
- ほかのパラメータは受け付けない（期間は固定）。

### 上流（NDLサーチ）

1. **判定**: SRU `https://ndlsearch.ndl.go.jp/api/sru?operation=searchRetrieve&query=dpid%3Dzassaku%20AND%20title%3D%22<q>%22&maximumRecords=1&recordSchema=dcndl` → `<numberOfRecords>` を読む。**0件のとき本文は `<diagnostics>` のみ（`Record does not exist`）＝0件として扱う。** `maximumRecords=0` は `illegal maximumRecords value` になるので使わない。
2. **exactモード（総数 ≤ 500）**: 同じSRUを `maximumRecords=500` で取得し、各 `<recordData>` をHTMLアンエスケープしてから読む（中身はエスケープされたXML）。年は `<dcterms:issued rdf:datatype="…W3CDTF">2016-12</dcterms:issued>` の先頭4桁。題名は `<dc:title><rdf:Description><rdf:value>…</rdf:value>`。掲載誌は `<dcndl:publicationName>`（「 = 」以降と「 / 」以降を落とす）＋`<dcndl:number>`。著者は `<dc:creator>`（複数）。原典URLは `<rdfs:seeAlso rdf:resource="https://ndlsearch.ndl.go.jp/books/…"/>`（`#material` なし・最初のもの）。年が読めない記録は年別件数に入れない。
3. **countsモード（総数 > 500）**: 年ごとに OpenSearch `https://ndlsearch.ndl.go.jp/api/opensearch?dpid=zassaku&title=<q>&cnt=1&from=YYYY-01-01&until=YYYY-12-31` → `<openSearch:totalResults>`。30年分を**同時実行は最大5本**で取得（提供元への配慮。1本ずつだと約30秒かかる）。各要求は8秒でタイムアウト、429/5xx/タイムアウトは1回だけ再試行（600ms待つ）。失敗した年は `count: null`。**失敗が7年以上なら 502**、6年以下なら `partial: true` で返す。
4. **代表記事**: `analysis.turningYears`（下記）の各年について、exactモードは取得済みの記録からその年のものを先頭から3件、countsモードは OpenSearch `cnt=3&from=YYYY-01-01&until=YYYY-12-31` を1年1本（`<item>` の `<dc:title>`／`<dc:creator>`／`<dc:description>` の「掲載誌：」以降（末尾の ` p.…` と巻号を落とし、「 = 」「 / 」以降を落とす）／`<link>` が原典URL）。
5. すべての上流要求に `User-Agent: hundred-days-day023 (+https://hundred-days.pages.dev/day-023-magtrace/)` を付ける。

### 分析（サーバーで決定的に計算し、UIは表示だけ）

- `window = {from: 1997, until: 2026, partialYear: 2026}`。判定に使う「確定年」は 1997〜2025。
- `first`: 確定年で件数 > 0 の最初の年（なければ null）。
- `peak`: 確定年で最大件数の年（同数なら新しい年）。件数0なら null。
- `jump`: `first` より後の確定年 y で、前年が数値、`count[y] ≥ 5`、`count[y] − count[y−1] ≥ 3` を満たすもののうち、`count[y] − count[y−1]` が最大の年。同点なら新しい年を選ぶ。`ratio` は `count[y] / max(count[y−1], 1)` を小数1桁に丸める。`jump = { year, from, to, ratio }` とし、該当なしは null。
- `trend`: 確定年の直近3年（2023–2025）の平均を、その前の3年（2020–2022）の平均で割る。前の平均が0で直近が>0なら "up"。比 ≥ 1.2 → "up"、≤ 0.8 → "down"、それ以外 "flat"。全部0なら null。
- `headline`（推移カードの見出し）: jump があり `ratio ≥ 1.5` なら「{jump}年を境に、掲載数が約{ratio}倍へ」、`ratio < 1.5` なら「{jump}年に、前年からいちばん増えた（{from}件→{to}件）」。jump がなければ peak があれば「{peak}年に最も多く語られた（{n}件）」。それも無ければ「この30年で{total}件」。
- `finding`（今回の発見）: `lead` と `support` の2文。
  - `lead`: first と peak が同じなら「「{q}」を題名に含む雑誌記事は、{first}年に現れ、その年が最多です（{n}件）。」。違えば「「{q}」を題名に含む雑誌記事は、{first}年に現れ、{peak}年に最も多くなりました（{n}件）。」。first が null（確定年に0件で今年だけ）なら「「{q}」を題名に含む雑誌記事は、2026年になって現れました（{n}件・集計途中）。」
  - `support`: jump があり `ratio ≥ 1.5` なら「{jump}年には前年の約{ratio}倍に増えました。」、`ratio < 1.5` なら「{jump}年には前年から最も増えました（{from}件→{to}件）。」＋ trend を「直近3年は増えています／減っています／ほぼ横ばいです。」で続ける。jump が無ければ trend の文だけ。
- `clues`（手がかり・最大3件・年の昇順）: first「収録範囲で初めて題名に現れた年」／jump「前年{prev}件→{n}件（約{ratio}倍）」／peak「最多の{n}件」。同じ年は1件にまとめ、説明を「・」でつなぐ。
- `turningYears`: [jump, peak, first] から null と重複を除いた昇順（最大3件）。
- 文章はすべてテンプレート固定。因果・媒体ジャンル・「社会全体」は書かない。

### 応答（200・JSON）

```json
{
  "query": "推し活",
  "field": "title",
  "dataset": "zassaku",
  "mode": "exact",
  "window": { "from": 1997, "until": 2026, "partialYear": 2026 },
  "total": 154,
  "years": [ { "year": 1997, "count": 0 }, { "year": 2026, "count": 38 } ],
  "partial": false,
  "analysis": {
    "first": { "year": 2020, "count": 1 },
    "peak": { "year": 2024, "count": 45 },
    "jump": { "year": 2024, "from": 18, "to": 45, "ratio": 2.5 },
    "trend": "up",
    "headline": "2024年を境に、掲載数が約2.5倍へ",
    "finding": { "lead": "…", "support": "…" },
    "clues": [ { "year": 2020, "text": "収録範囲で初めて題名に現れた年" } ],
    "turningYears": [2020, 2024]
  },
  "records": [
    { "year": 2024, "title": "…", "magazine": "…", "creators": ["…"], "url": "https://ndlsearch.ndl.go.jp/books/R000000004-I0…" }
  ],
  "source": {
    "name": "国立国会図書館サーチ（雑誌記事索引）",
    "provider": "国立国会図書館",
    "license": "CC BY 4.0",
    "url": "https://ndlsearch.ndl.go.jp/"
  },
  "fetchedAt": "2026-08-29T10:40:00.000Z"
}
```

- `years` は必ず30要素（1997〜2026）。`total` は `years` の合計（countsモードでは失敗年を除く）。
- 0件: `total: 0`・`years` 全て0・`analysis` の各値は null・`records: []`（200で返す。UIが0件状態を出す）。
- 400: `{ "error": "invalid_query" }`。502: `{ "error": "upstream_unavailable" }`。いずれも `Cache-Control: no-store`。
- 200 の見出し: `Content-Type: application/json; charset=utf-8`、`Cache-Control: public, max-age=3600, s-maxage=86400`、`X-Content-Type-Options: nosniff`。
- キャッシュ: 正規化した `q` をキーに `caches.default` へ24時間保存し、ヒットしたらそれを返す（`fetchedAt` は保存時のまま＝UIの「保存済み」判定に使う）。`caches` が無い環境（Nodeでの直接実行）では素通し。
- 純粋関数（クエリ正規化・SRU/OpenSearchの解析・年別集計・分析文の生成）は同じファイルから `export` し、ユニットテストは `apps/day-023-magtrace/tests/*.test.mjs` から `../../../functions/api/day-023/trend.js` を import する（Day009と同じ）。`onRequestGet(context)` は `context.request` だけを使い、`fetch` は差し替え可能にする（テストで上流を偽装するため。例: `export async function buildTrend(q, { fetchImpl, now })`）。

## 実装メモ

- 依存ゼロ・ビルドなし。`index.html`／`app.css`／`app.js`（ESモジュール）／`lib/chart.js`／`lib/history.js`／`lib/format.js`／`demo-scenario.mjs`／`README.md`／`meta.json`／`shared/`（`npm run shared:sync` で複製）。
- インラインscriptは書かない（CSP `script-src 'self'`）。`style` 属性はSVGの座標程度に留める。
- `index.html` の `</head>` 直前に `<link rel="stylesheet" href="./shared/share.css">` と `<script src="./shared/share.js" defer></script>`。`<meta name="share:text">` には「MAGTRACE」を含める。OGPとcanonicalはビルドが入れるので書かない。
- `[hidden]{display:none !important}` を全体ルールに置く。固定要素は使わない。
- 文字列の組み立てはすべて `textContent`／`createElement`。応答の題名をHTMLとして挿入しない。
- `demo-scenario.mjs`: Day022と同じくローカルHTTPサーバーを立て、`/api/day-023/trend` は Function のモジュールを import して Node の `fetch` で本物のNDLサーチに繋ぐ（`caches` は無いので素通し）。振り付け＝ホーム→「推し活」を入力→結果→グラフへスクロール→表で見る→記事へスクロール→「サウナ」で再検索→グラフへスクロール。`shotSetup` は「推し活」の結果を出し、推移カードの上端を画面上から24pxに合わせる。
- `README.md`（アプリ内）: なぜ作ったか／設計の判断（記事タイトル一致・転機の規則・代表記事の選び方・キャッシュ）／データの出典／やらないこと。
