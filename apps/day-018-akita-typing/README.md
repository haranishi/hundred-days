# Day 018「秋田の飯は、打てた分だけ」

流れてくる**秋田の郷土料理**の名前をローマ字で打つと、その料理を食べたことになる。60秒で**コース料金の元が取れたか**を会計で判定する。

終わったあとに残るのは速さの数字ではなく、**どの打鍵でつまずいたか**の上位3つ。

## 先に権利関係

**ゲームのルールは著作権で保護されない。** 釣りゲータウン2事件（知財高裁 平成24年8月8日）で確定した整理で、Day017のリバーシでも同じ確認をしている。だから「流れてくる語をタイプして制限時間内に金額を競う」という仕組み自体は自由に作ってよい。

そのうえで**寄せない**。名前・配色・皿やレーンの意匠・効果音を既存のタイピングゲームに似せていない。寄せない方が、説明する必要すら無くなる。

料理名は**一般名称だけ**を使っている。特定の製造元の登録商標にあたりうる呼び名も、品種名・ブランド名も入れていない。**値段はこのゲームの中の目安**で、実際の価格ではない。

## 何が難しかったか：ローマ字判定

「1つの正解と文字列を比べる」では成立しない。`しょっつるなべ` は `shottsurunabe` でも `syotturunabe` でも通らないと、実際のIMEを使っている人の指が拒否される。

かなを1〜2文字の**チャンク**に切り、チャンクごとに**通る書き方の集合**を持たせた。打鍵のたびに「バッファ＋そのキー」が候補のどれかの前方一致なら受理する。判断が要ったのは3か所。

判断が要ったのは3か所。**①`ん` を `n` 1個で通してよいかは次のかなで変わる**（`tonburi` は通すが `konyaku` は `にゃ` と区別できない。次チャンクの先頭が母音・n・yのときだけ `n` 単独を外す）。**②`n` を打った瞬間に確定してはいけない**（`nn` と打つ癖の人が全員弾かれる。完全一致でも長い候補が生きているうちは保留する）。**③`っ` は次のチャンクと合体する**（`がっこ` の `っこ` は `kko` で1チャンク）。

## ベルトの設計

**走行時間 ＝ 投入間隔 × 4枚。** コースが速くなっても詰まり方は変わらず、速さだけが変わる。4枚は、幅375pxの画面でも皿が重ならない上限。走行時間を固定値にしていた頃は、速い人がレーンを空にして1〜2秒なにも打てない時間が生まれていた（デモを録画して気付いた）。レーンが空のときだけ間隔を待たずに次を出す逃げ道も入れてある。

## 打ち始めた皿は取り上げない

このアプリでいちばん大事な一行がこれ。**1文字でも打った皿は、左端に着いてもそこで止まって待つ。**

最初はこれが無かった。すると的が常に左端＝残り時間が最も短い皿に固定されるので、**遅い人ほど「消える寸前の皿」に縛られ続ける**。打ち始めた数秒後に皿が消えて進捗が没収され、次の的もまた消えかけの皿。1打/秒だと60秒で18皿中1皿しか食べられなかった。速度を落としても語を短くしてもこの構造は直らない。皿を取り上げないようにして初めて、**打った分だけ食べられる**という題名どおりの形になった。1打も入れていない皿は今までどおり逃すので、時間の緊張は残っている。

## そのうえで、どの皿から打ち始めるかを選ばせる

取り上げないだけだと、**プレイヤーが決めることが1つも無い**。的は自動で左端に固定され、入力変数は打鍵速度だけ。得点は打鍵速度のほぼ線形関数になる（おすすめ・seed7を回すと 0.8打/秒→¥930 ／ 2.5→¥3,460 ／ 5.5→¥6,430）。

そこで走行中の皿に**先頭キー1文字の札**を出した。**語の1打目でその札を押すと、そこから打ち始められる**。押したキーは移った先の1打目になり、**ミスにも「打ち損ねたキー」にも入らない**（つまずきではなく選択なので）。選ぶのは「左端の消えかけを拾うか、奥の高い皿へ手を伸ばすか」で、賭けるのは打鍵そのものではなく**時間**になる。

**語の途中では移らない。** 最初は語の途中でも札を押せば移れるようにしていたが、それだと**打ち間違いと選択が区別できない**。隣接キーの誤打を10%混ぜて実際に1試合遊ぶと、誤打19回のうち3回（16%）が乗り換えとして発火し、ハタハタずしを `hata` まで打ったところで `g` を叩いて ぎばさ へ飛ばされた。打ちかけの語は無言で全部消え、捨てた皿は次の tick で逃した扱いにまでなる。**指がずれただけで語を丸ごと失う**のは選択の代償ではなく事故なので、判定を「1打目だけ」に寄せた。おかげで皿の札の意味も「押せばこの皿から始まる」の一つに揃った。

移った瞬間は料理名も打鍵行も一斉に別の語へ入れ替わるので、**打鍵行を琥珀色に一瞬光らせる**（`res.switched` → `.target[data-switch]`）。色を一定時間置くだけでアニメーションにしていないのは、`prefers-reduced-motion` で合図ごと消えないようにするため。

副作用として、**手の出しようがなかった警告が意味を持った**。消えかけの皿の警告は、打ちかけを抱えているあいだ「見えるのに触れないもの」だった（1試合34件のうち23件）。いまはそれが「次にどれから始めるか」の合図になる。

**「いちばん高い皿だけを狙う」打ち方も回してみた**が、伸びは0〜9%（平均5%）で、どのコース・どの速さでも勝敗はひっくり返らなかった。値段は打鍵数で決めているので、高い皿は語も長く、1打あたりの取り分がほとんど変わらないため。壊れるとしたらここだったので先に測った。

難易度の梯子（`tests/difficulty.test.mjs`）の擬似プレイヤーは、**押すはずのキーの隣を叩いて**間違える。誤打が `z`/`q` 固定だった頃は、20品の先頭キー `{a,b,d,g,h,i,j,k,m,s,t}` に一度も当たらず、**選択の経路がテストの中で構造的に発火しなかった**——梯子が1行も変わらずに通っていたのはそのせいで、実プレイで起きていた事故を1件も捕まえていなかった。隣接キーに替えて測り直すと、お手軽・1打/秒・ミス率30%は旧仕様で 3/5勝（平均¥734・目標¥700）、1打目だけに寄せた今は 5/5勝（平均¥792）。**この誤打表は元に戻さないこと。**

## 打つところの上に、何を置かないか

**レーンのすぐ下が打鍵行**というのは最初からの方針だったが、実際には283px離れていた。あいだに料理の絵（104px）と豆知識とよみが挟まっていたからで、**1皿につき1度しか見ないものが、1文字ごとに見るものを画面の外へ押し出していた**。

3つとも打鍵行から外した。絵はレーンの皿に残し、豆知識は結果画面へ移した。よみは20品中13品が名前とまったく同じ重複だったので行ごと捨て、**名前に漢字を含む5品だけ**（秋田ふき・比内地鶏・稲庭うどん・しょっつる鍋・きりたんぽ鍋）を `<ruby>` で名前の上に乗せている。カタカナの品にふりがなを振っても情報は増えない。

打鍵行のyは動かしてはいけないので、**つかみ中バッジは `hidden` ではなく `visibility` で場所を取ったまま隠し**、HUDの1行も折り返さないよう固定してある。対戦中はヘッダーとシェア欄を畳む（DOMは消さない）。

そのバッジは**ラウンドの最初のつかみでだけ**出す。毎回出していた頃は試合の70.7%で点灯して1試合に22回出入りしており、しかもその位置が料理名と打鍵行のちょうど間＝**1文字ごとに見る場所の真上**だった。ほぼ常時光る印は状態を伝えない。2回目からは左端の琥珀の太枠スロットが同じことを示している。

## 明るいレーンの上では、明るい色は合図にならない

皿もレーンも明るいので、琥珀（1.6:1）や赤（2:1）では状態が見えない。**合図はすべて濃い茶の縁を軸にした**。皿の縁は約16:1、選択中は暗い縁で琥珀のリングを挟み、消えかけは点滅をやめて濃い赤の縁＋沈んだ面にした。

点滅をやめた理由は3つある。①レーンの上で赤は2:1しか出ない ②`prefers-reduced-motion` の `animation: none` で警告ごと消える ③減点なしと書いてあるものを罰の色で光らせることになる。**reduced-motion で止めるのは装飾だけで、レーンの横移動は止めない**——止めたら「動きを減らす」ではなく「遊べなくする」になる。

つかんだ皿はレーンから消していたが、それだと**プレイヤーが構造的に触れない皿にだけ警告が付く**状態になる。名前だけ隠した「つかみ中スロット」として左端に残し、後続はその手前から**列にして詰める**。ここを「全部同じ下限で止める」と書いていた頃は、2枚目以降が同じ位置に積み上がって名前が重なっていた（20px以上の重なりが全フレームの47%）。

皿は**レーンの左端で止まる**位置計算にしてある。走り切った位置（皿の幅ぶん外）へ置く式だと、つかんだ瞬間に画面外から左端へ**瞬間移動**して見えた（1試合11回）。逃した皿だけは、着いたところから時間をかけて左へ抜ける。

## 音は生成する。そして止められるようにする

音源ファイルは持てないので Web Audio API で組み立てている。鳴らすのは5つだけ（食べた／逃した／もうすぐ流れる／元が取れた／ミス）で、**打鍵音は鳴らさない**——見えているものに音を重ねても情報は増えない。運ぶのは、視線が打鍵行に釘付けのあいだ見えていないもの（金額・残り時間・逃した皿）だけ。

BGMはループ素材を持たず、seedから拍ごとに組み立てる。BPM96・旋律なし・3声部で、平常は律音階、経過0.75からは民謡音階へ倒す（0.75は残り時間の表示が警告に変わるのと同じ時刻。画面と音で別々の「終盤」を作らない）。

**60秒鳴り続ける音には停止手段が要る**（WCAG 1.4.2）。しかも開始はクリックなので、ブラウザの自動再生ブロックは効かない。だから入口を3つ用意した：開始画面の「音 あり／なし」（押す前に選べる）・HUDの常設トグル（対戦中に押せる）・`?sound=off`。<kbd>Ctrl</kbd>+<kbd>M</kbd> でも切り替わる。**AudioContext は「はじめる」を押すまで1つも作らない**（E2Eで数えている）。

## 難易度は式ではなく実測で決めている

最初は「1皿あたり60秒÷必要皿数の時間が使える」という式で設計した。式では0.8打/秒で元が取れるはずだったが、**実測では1.9打/秒必要だった**。式に上の構造が入っていなかった。

いまは `tests/difficulty.test.mjs` が**実際にゲームを1分間回して**測る。打鍵速度だけでなく**ミス率10〜30%の初心者**も再現する（ミス0の人だけを想定すると、実際の初心者は負ける）。

始める前に**ためし打ち**（1品だけ）ができる。測った速さに合うコースを先に選んでおくためで、飛ばしてもよい。何も選ばずに始めた既定は「おすすめ」（要2.5打/秒）で、1.2打/秒の人はそこで必ず負ける——結果画面の助言は**負けた60秒のあと**にしか出せないので、始める前に測れる場所を作った。測った値は保存しない。

## 4つの状態

Day11–20は「空・読込中・エラー・不正入力の4状態に対応する」区間なので、それが全部自然に出るお題を選んでいる。

| 状態 | いつ |
|---|---|
| 空 | 開いた直後。コース選択と遊び方 |
| 開始前 | 3・2・1 のカウント。**通信をしないので「読込中」は作らない**。嘘の待ち時間を置くより、開始前の待ちを正直にそう呼ぶ |
| エラー | 料理データを読み込めなかったとき |
| 不正入力 | 日本語入力がONのまま打ったとき。打鍵は捨てるが、ミスには数えない |

## 体験評価をまわしている

別セッションのAIが**コードを見ずに実際に遊んで**10項目で採点する工程を通している（1周目12/20で不合格→2周目18/20で合格）。「打ち始めた皿は取り上げない」も「食べた瞬間の演出が無い」も、ここで出た。自分でテストを書いているだけでは見つからない——テストは「仕様どおり動くか」しか見ないので、**仕様そのものが間違っている**ときに気付けない。上の打鍵行・コントラスト・音の3つも、同じやり方の3周目で出た指摘への答え。

## 動かし方

そのまま `index.html` を開けば動く。ビルドも依存パッケージも無い。

クエリの入口が4つあり、どれも遊びやすさを変える方向には働かない。

- `?force=error` … 料理データの読み込み失敗を再現する
- `?seed=7` … 皿の出る順を固定する（デモを同じ流れで撮り直すため）
- `?duration=15` … 1回の長さを秒で上書きする（5〜120秒）。**コース料金も同じ比率で按分される**ので、短い回でも公平に判定できる
- `?sound=off` … 音を鳴らさずに始める（既定は on）。デモ収録とE2Eで要る

```bash
node --test tests/            # ユニットテスト
node tools/trim-demo.mjs 3.3  # デモ動画の頭を切り落とす
```

## 絵

すべて生成した画像で、文字は1枚も焼き込んでいない。`assets/key-visual.webp`（52KB・開始画面）と `assets/dish/*.webp`（20枚・計82KB・レーンの皿）。

**作り直すときは20枚に同じ作法を効かせること。** 「真俯瞰・器を1つだけ中央に・背景は無地の淡いベージュ(#e8d9be)・やわらかい自然光・彩度は控えめ・正方形・文字とロゴと箸と手は描かない・器の色味と光の向きを揃える」。生成物は1254pxで出てくるので、**中央を切り詰めてから**224pxのWebPに落とす（切り詰めないと、円く切り抜いたとき背景のベージュが輪になって「皿の上に皿」に見える）。

絵が1枚も読み込めなくても文字だけで遊べる。読み込みに失敗した絵はDOMから取り除いている。
