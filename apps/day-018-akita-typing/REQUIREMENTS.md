# Day 018 — 秋田の飯は、打てた分だけ

## 一言で

流れてくる**秋田の郷土料理**の名前をローマ字で打つと、その料理を食べたことになる。制限時間内に**コース料金の元が取れたか**を会計で判定する。終わったあとに、自分が**どの打鍵でつまずいたか**が残る。

## 先に法務

ゲームの**ルールそのものは著作権で保護されない**（釣りゲータウン2事件・知財高裁 平成24年8月8日）。Day017でリバーシを作ったときに確認済みの整理をそのまま使う。したがって「流れてくる語をタイプして制限時間内に金額を競う」という仕組みは自由に作ってよい。

そのうえで**寄せない**方針を採る。名称・画面の配色・皿やレーンの意匠・効果音は既存タイピングゲームに似せない。似せないほうが説明コストが低い、というDay017と同じ判断。

料理名は**一般名称のみ**を使う。特定の製造元の登録商標である可能性がある名称（「ババヘラ」など）と、品種名・ブランド名（「あきたこまち」など）は入れない。値段は**ゲーム内の目安**であり実際の価格ではない旨を画面に書く。

## ユーザーストーリー

> **タイピング練習が続かない人**として、
> **打ち終わったときに「何円ぶん食べた」という結果が欲しい**。
> なぜなら**「1分間に何打」では速くなった実感がわかず、金額なら1回ごとに勝ち負けがはっきりする**から。

補助ストーリー：

> **自分のタイピングのどこが遅いのか分からない人**として、
> **終わったあとに「どの打鍵でつまずいたか」を見たい**。
> なぜなら**速さの数字だけ見せられても、次に何を直せばいいのか分からない**から。

> **秋田を知らない人**として、
> **打っているうちに郷土料理の名前が頭に入る状態になりたい**。
> なぜなら**説明を読む気はないが、20回打った言葉は覚えてしまう**から。

### ② 要件層（何が要るか）

必須：

1. 料理が流れてきて、ローマ字で打つと食べたことになる
2. **IMEと同じ寛容さで判定する**（`し`＝shi/si/ci、`ん`＝n/nn、`っ`＝子音重ね、`じゅ`＝ju/jyu/zyu をすべて通す）
3. 制限時間の終わりに**コース料金と食べた総額を突き合わせて得か損かを出す**
4. **つまずいた打鍵**を上位3つ出す
5. 4状態（空・開始前カウント・エラー・不正入力）が全部ある

やらない：

- ランキング・保存・アカウント（Day21–30までlocalStorageは未解禁）
- 通信（Day31まで外部API未解禁）。料理データはアプリに同梱する
- かな入力方式（ローマ字入力のみ。かな入力は対応表が別物になり1日に収まらない）

### ③ 構造層（どう並ぶか）

```
[ 空 ] コース選択 → 遊び方 → はじめる
   ↓
[ 開始前 ] 3・2・1 のカウント
   ↓
[ 対戦中 ] 会計（食べた額 / コース料金）・残り時間
           レーン（右から左へ流れる料理・先頭が的）
           打つところ（料理名・よみ・ローマ字の進み）
           └ [ 不正入力 ] 日本語入力がONのとき、ここに警告が割り込む
   ↓
[ 結果 ] 得か損か → 打鍵速度・正確率 → つまずいた打鍵TOP3 → もう一度／シェア

[ エラー ] 料理データが読めなかったとき。再読み込みボタン
```

- **打つところはレーンの下に固定**する。目線がレーンと文字の間を往復すると打てなくなるので、的の料理はレーン内でも強調して**2か所で同じものを指す**。

### ④ 骨格層（画面の要素）

| 要素 | 決めたこと | 理由 |
|---|---|---|
| ローマ字の進み | 打てた部分を**色を変えて残す**。消さない | 消すと自分がどこまで打ったか見失う |
| 次に押すキー | 進みの直後の1文字を**枠で囲う** | ミスしたとき何を押すべきだったかが同じ場所で分かる |
| ミス | 画面を赤く光らせるが**打ち直しは要らない**（間違ったキーは無視して先に進める） | やり直しを強制すると詰まって時間だけ溶ける |
| 残り時間 | 数字ではなく**バーの残量**を主にする | 数字は読むのに視線を奪う |
| 会計 | 食べた額を**大きく**、コース料金は小さく添える | 見るべきは「あといくら」 |
| 逃した料理 | レーンから落ちるときに**灰色にして流す**。ペナルティなし | 打てなかった事実だけ伝われば十分 |

### ⑤ 表層（見た目）

- 木のカウンターを思わせる**濃い茶色の背景に、白木のレーン**。緑の皿・回転寿司の意匠には寄せない
- 文字は等幅を使わない。**料理名は大きく、ローマ字だけ等幅**（1文字ずつ位置が動かないため）
- 効果音は入れない（Day007・012で音は扱ったので、ここで伸ばす軸ではない）

## 実装で難しいところ：ローマ字判定

「1つの正解と文字列比較」では成立しない。`しょっつるなべ` は `shottsurunabe` でも `syotturunabe` でも通さないといけない。

**採る方式**：かなを「チャンク」に切り、チャンクごとに**通る書き方の集合**を持つ。打鍵のたびに「今のバッファ＋そのキー」が候補のどれかの**前方一致**なら受理する。

**判断が要る3か所**：

1. **`ん` を `n` 1個で通してよいか**は次のかなで変わる。`とんぶり`＝`tonburi` は通すが、`きんいろ` を `kniro` と打てては困る。→ **次のチャンクの先頭が母音・n・y のときだけ `n` 単独を候補から外す**
2. **`n` を打った瞬間に確定してはいけない**。`nn` と打つ癖の人が弾かれる。→ **完全一致しても、より長い候補が生きているうちは確定を保留する**。次のキーがどの候補にも当たらなかったときに初めて、保留していた一致で確定してから打ち直す
3. **`っ` は次のチャンクと合体する**。`がっこ`＝`gakko` は `っ` 単独ではなく「`っ`＋`こ`」で1チャンク。→ `っ` の候補を**次チャンクの子音を重ねた形**として生成する（`ltu`/`xtu` も残す）

## ベルトの設計（実装後に組み直した）

当初は走行時間を固定値（11秒）にし、コースごとに速さの倍率を掛けていた。デモを録画して**レーンが空のまま進む時間**が写り、設計の穴だと分かった。速い人は供給より速く食べ切るので、打つものが無い時間が生まれる。

投入間隔だけ詰めると今度は皿が重なって読めなくなるので、**走行時間 ＝ 投入間隔 × 4枚**に変えた。コースが速くなっても**詰まり方は変わらず、速さだけが変わる**。4枚なのは幅375pxの画面でも重ならない上限だから。あわせて、レーンが空のときだけ間隔を待たずに次を出す逃げ道（0.45秒）を入れた。

## 短い回の会計

`?duration=` で回を短くしたとき、コース料金を60秒ぶんのまま置くと**どれだけ打っても足が出る**。結果が実力ではなく設定で決まってしまうので、**コース料金も同じ比率で按分する**（15秒なら¥3,000→¥750）。50円単位に丸めて読みやすくしている。

## 4状態の中身

| 状態 | いつ | 出すもの |
|---|---|---|
| 空 | 開いた直後 | コース選択と遊び方。まだレーンは動かさない |
| 読込中に相当 | はじめるを押してから | 3・2・1 のカウント。**通信がないので「読込中」は作らない**。開始前の待ちがこの区間の代わり |
| エラー | 料理データの読み込みに失敗 | 何が起きたかと再読み込み。`?force=error` で再現できる |
| 不正入力 | 日本語入力がONのまま打った | 「半角英数に切り替えてください」。打鍵は捨てるがミスには数えない |

> 通信をしないアプリで「読込中」を演出として作ると嘘になるので、**開始前カウントを正直にそう呼ぶ**。Day017で「AIの思考中に見せるための待ち時間」を却下したのと同じ理由。

## 体験評価で分かったこと（実装後）

別セッションのAIがコードを見ずに実際に遊んで採点する工程を2周通した。**設計の穴が2つ、ここで初めて出た。**

**1周目 12/20点・不合格**

- 打ち切った瞬間の演出を1つも作っていなかった。狙いの中心（「増えるのが気持ちいい」）が死んでいた
- **難易度の設計が間違っていた。** 式では0.8打/秒で元が取れるはずが、実測は1.9打/秒。的が常に左端＝残り時間が最短の皿に固定されるので、遅い人は打ちかけの皿を取り上げられ続ける

→ **1打でも入れた皿は取り上げない**（左端で止まって待つ）を入れた。速度と収穫が切り離され、お手軽は1打/秒でも元が取れるようになった。難易度のテストも、式ではなく実際にゲームを回して測る形に作り直した。

**2周目 18/20点・合格**

- 残った指摘：初心者はミスをする（正確率79.7%だと負ける）／保持皿と後続皿の文字が重なる／スマホでソフトキーボードの入力が拾えない／ローマ字の案内が打鍵中に書き換わる → すべて対応済み

> 🔴 **テストは「仕様どおり動くか」しか見ない。仕様そのものが間違っているときは、遊んでみるまで分からない。**
