# Day 034「潮、いまどっち？」要件定義

**いまの潮は、満ちているのか引いているのか。** 地点を決めると、気象庁の潮位表から「いま、満ち潮」「次の満潮は 16:57（201cm）」「あと1時間57分」を1行ずつで答える。その下に、きょうの潮位カーブに「いま」の印、潮名（大潮・中潮・小潮・長潮・若潮）、きょうの干満差、きょうとあすの満潮・干潮の表。

## 背景と狙い

- 100日チャレンジ Day 34。S2（Day 31〜40）＝**外部API（無料・認証不要・読み取り専用）を1個**。その1個が気象庁ホームページの潮位表テキスト `https://www.data.jma.go.jp/kaiyou/data/db/tide/suisan/txt/{YYYY}/{地点記号}.txt`
- 困りごとは、釣り・潮干狩り・磯遊び・海辺の散歩で「いま潮は動いているのか、次の干潮は何時か」。潮見表のサイトは月間の表と広告が先に来て、「いま」が埋もれる。答えは「満ち／引き」「次の干満の時刻」「きょうの潮（大潮か小潮か）」の3つだけ
- 差がつくのは**「いま」を主役にする**こと。表を見せるのではなく、見出し1行と、いまの位置を打ったカーブ
- 地名から座標を引く外部サービスは使わない。潮位表地点239か所の座標を同梱し、現在地からは端末の中で最寄りの地点を選ぶ
- 候補のAPIは提案前に実際に叩いてCORSを確かめた（2026-09-10。`Access-Control-Allow-Origin: *`・`Cache-Control: max-age=600`・1ファイル50,005バイト・365行。全239地点に2025・2026・2027年のファイルがある）

## データ（潮位表テキスト）

1行＝1日。**136文字固定**、改行LF、365（閏年366）行。`9999`／`999` は「該当なし」。

| カラム | 内容 |
|---|---|
| 1〜72 | 毎時潮位 3桁×24（0時〜23時）。cm、**潮位表基準面上**。負の値あり（` -2`） |
| 73〜78 | 年月日 2桁×3（`26 910`＝2026年9月10日。空白詰め） |
| 79〜80 | 地点記号（`TK`） |
| 81〜108 | 満潮 時刻4桁（時分）＋潮位3桁 ×4（` 353200`＝03:53・200cm） |
| 109〜136 | 干潮 同じ形 ×4 |

例（東京 2026-09-10）：満潮 03:53 200cm／16:57 201cm、干潮 10:30 30cm／22:53 81cm。毎時 119 144 172 193 200 189 161 123 84 51 33 33 52 87 128 166 192 201 191 168 138 109 88 81。

1日の回数は「満2・干2」が大半だが、東京でも「満1・干1」が年7日あり、日本海側では**満潮だけ・干潮だけの日**がある（秋田 2026 年は「満0・干1」「満1・干0」が各5日）。**満潮も干潮も欠ける日を前提に組む。**

### 取得（`lib/jma.js`）

- `fetchYear(code, year)`：`GET …/txt/{year}/{code}.txt`。8秒で中断。全行が136文字で、79〜80桁が `code` と一致しなければ「形の不一致」。HTTP エラーは `error.status` に応答の番号を添えて投げ、地点名入りの文言と次の行動は画面側で決める
- 必要な日付窓＝**きのう・きょう・あす**（日本時間）。窓が年をまたぐときだけ隣の年も取る。隣の年が取れなくても、取れた分で答えを出す（前後の満干が片方欠けた扱い）
- メモリ以外に保存しない。同じ `code`・`year` は画面が開いている間は再取得しない

### 解析（`lib/tide.js`・純関数・DOMに触れない）

- `parseLine(line)` → `{ date: 'YYYY-MM-DD', code, hourly: number[24], highs: [{ time: 'HH:MM', cm }], lows: [...] }`。`parseYear(text, code)` → 日付をキーにした Map か Object
- `eventsAround(days, now)`：きのう〜あすの満干を絶対時刻順に1本にまとめ、`prev`（いま以前で最新。同時刻は prev）と `next`（いまより後で最初）を返す
- `stateOf({ prev, next, now })`：
  - `slack-high` / `slack-low`：いまから**30分以内（前後）**に満潮／干潮がある（prev・next のうち近いほう。30分ちょうどは含む）
  - `rising`：next が満潮。next が無ければ prev が干潮
  - `falling`：next が干潮。next が無ければ prev が満潮
  - どちらも無い → `unknown`
- `levelNow({ prev, next, hourly, now })`：prev と next があれば**余弦補間** `h = h1 + (h2 − h1) × (1 − cos(π × (t − t1) / (t2 − t1))) / 2`。片方欠けは毎時値の線形補間。表示は「およそ◯cm（推定）」
- `dailyRange(day)`：満潮の最大 − 干潮の最小。片方欠けは毎時値の最大・最小で代用
- `rangeRank(yearDays, date)`：その年の全日の干満差に対する位置。上位1/3「大きい方」、下位1/3「小さい方」、それ以外「ふつう」
- `tideName(nowMs)`：**月と太陽の黄経差** `D = (月の黄経 − 太陽の黄経) mod 360` を Day 026 の `lib/astro.js`（`moonPosition(utcMs).longitude`・`sunPosition(utcMs).longitude`。ファイルごと複製）で求め、次の区分で名前を付ける。根拠は Wikipedia「潮汐」の「黄経差を用いた方式」（日本水路協会MIRC方式の表に、気象庁方式との差5°を足した値）

  | 黄経差 | 潮名 |
  |---|---|
  | 348〜36 | 大潮 |
  | 36〜72 | 中潮 |
  | 72〜108 | 小潮 |
  | 108〜120 | 長潮 |
  | 120〜132 | 若潮 |
  | 132〜168 | 中潮 |
  | 168〜216 | 大潮 |
  | 216〜252 | 中潮 |
  | 252〜288 | 小潮 |
  | 288〜300 | 長潮 |
  | 300〜312 | 若潮 |
  | 312〜348 | 中潮 |

  下限を含み上限を含まない。実測値（astro.js）：2026-09-10 15:00 JST＝348.51→大潮／09-10 14:00＝347.97→中潮（境目）／09-18 12:00＝81.94→小潮／09-21 12:00＝114.69→長潮／09-22 12:00＝125.79→若潮／09-25 12:00＝160.59→中潮／12-31 23:45＝279.78→小潮／2026-01-01 00:30＝141.21→中潮。画面では「黄経差から」と小さく添え、新聞・雑誌の旧暦方式と1日ずれうることを README に書く
- 時刻は Day 033 の `lib/time.js` 方式（`Asia/Tokyo` の壁時計文字列・比較は絶対時刻）。`TZ=UTC` でも結果が同じ。「あと」は 60分以上「あと◯時間◯分」（分が0なら「あと◯時間」）、60分未満「あと◯分」、1分未満「まもなく」。次の干満が翌日なら時刻の前に「あす 」

### 地点（`data/stations.json`・`lib/stations.js`）

- `tools/build-stations.mjs` が station.php と Day 033 の `places.json` から生成済み（239地点・39都道府県）。各地点 `{ code, name, lat, lon, pref, msl, remark? }`。`pref` は最寄りの市区町村代表点の都道府県。内陸8県（栃木・群馬・埼玉・山梨・長野・岐阜・滋賀・奈良）には地点が無い。南鳥島は東京都
- `groupByPref(stations)`、`findByCode(stations, code)`、`nearest(stations, point)`（Day 033 `places.js` と同じ球面近似。距離 km を返す）。現在地から最寄り地点まで**50km以上**なら「海から離れています。参考程度に」を出す
- `stations.json` は地点を選ぶか現在地を使うときに初めて読む（保存済みの地点で開いたときは名前の表示に必要なので読む）

## ユーザーストーリー

| ユーザー | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| 海に着いた釣り人（本命） | いま潮が動いているか、次の干満は何時か | 開いて1秒で「いま、満ち潮」「次の満潮は 16:57（201cm）」「あと1時間57分」 |
| 潮干狩りに行く家族 | 干潮の時刻と、きょうが大潮かどうか | 「次の干潮」と潮名のタグ、干満差。あすの干潮も表に出る |
| 海辺を散歩する人 | 潮位の流れをひと目で | きょうのカーブに「いま」の印と満干の点 |
| 位置情報を渡したくない人 | 地点を自分で選びたい | 都道府県→地点の2段選択。選んだ地点は次回も残る |
| 海から遠い人 | 最寄りの地点がどこで、どれだけ離れているか | 「現在地 → 東京（32km）」と距離。50km以上なら但し書き |
| 日本海側の人 | 潮の差が小さいことを知りたい | 「きょうの干満差 27cm（秋田では ふつう）」 |
| 結果を人に言いたい人 | 「大潮で干潮は◯時」を共有したい | 投稿文に地点・見出し・次の干満・潮名が入る |

## UX5階層

- **戦略**: 潮見表アプリではなく**「いま、どっち？」の1問**。成功＝見出し1行が1秒で読めること。失敗＝月間表を見せて探させること。差別化の源泉は「いま」を主役にした1行とカーブ
- **要件**: 載せるもの＝見出し、次の干満、いまの潮位（推定）、潮名、干満差、きょうのカーブ、地点（現在地／選ぶ／外す）、きょう・あすの満干の表、出典と但し書き、投稿。対象外＝月間表、地図、天気・波・風、釣果、高潮・津波、実測潮位、複数地点、通知
- **構造**: `pick → loading → ready`＋`empty`・`error`。地点は `none / current / picked`。**地点が無いあいだは取得しない**。1分ごとに「いま」を再計算する（再取得はしない）
- **骨格**: いちばん大きい要素は**見出し**（30〜40px・ページ内で最大）。見出しカードの最上段に地点名と「· 15:00 現在」を続けて置き、見出しの下に副文（次の満干）、残り時間（22px・濃紺の塗りピル）、潮名のタグ（16px・枠なし）、いまの潮位とその注記。次にカーブ（高さ200px前後・0〜24時の目盛・満干の点と時刻・「いま」の縦線と潮位の数字）。次に地点の行（ボタン44px以上。「地点を変える」「現在地」を同じアウトラインで1行、その下にリンク風の段）。次に表（きょう／あす。720px以上は2列）。最後に投稿とフッター。地点が無いときは「どこの潮？」（28px）と、主ボタン「現在地でいまの潮を見る」（56px以上・幅420pxまで・見出しと同じ左端）、副ボタン「地点を選ぶ」。**ボタンの強さは塗り・アウトライン・リンク風の3段階だけ**にし、いま押してほしい1つだけを塗りにする（pick は「現在地でいまの潮を見る」、error・empty は「地点を変える」、ダイアログは「この地点にする」）。角丸は2値（カード・パネル・select・タグ 12px／ボタンとピル 999px）
- **表層**: 海の青と砂の色。地 `#f4f7f9`、文字 `#16303f`。見出しの下地は満ち潮 `#e3f1f8`（青系）、引き潮 `#f6ead8`（砂色系）、潮止まり `#eceff2`。カーブは線 `#0b6e99`、面 `#9cc3d9` から透明へのグラデーション、「いま」は `#c2410c` の縦線と丸。**色だけに頼らず文字で状態を書く**。文字の対比は 4.5:1 以上（Day 033 の教訓＝色の面と数字を分ける）。動きは見出しが下から現れる1つ。`prefers-reduced-motion` では即時

### UX5階層を通したことで決まった実装（10件）

1. **地点が無いあいだは取得せず「どこの潮？」の案内を出す**（戦略・構造）。全国共通の答えが無い題材なので、Day 033 の「場所なしでも答え」は採らない
2. **見出しは4つだけ**＝「いま、満ち潮」「いま、引き潮」「満潮のころ」「干潮のころ」（骨格）。「上げ・下げ」「漲潮・落潮」は初見で読めないので使わない
3. **潮止まりを別の状態にする**（要件）。満干の前後30分は「満ち潮」と言い切ると外れる。釣り人には「いま止まっている」が大事
4. **次の干満が翌日なら必ず「あす」を付ける**（要件）。23時台に開く人が「04:35」を今朝と読み違える
5. **いまの潮位は「およそ」と「推定」を添える**（要件）。公表値は毎時と満干だけで、その間は補間
6. **干満差は地点の1年の分布と比べて言う**（戦略）。絶対値だけでは秋田の27cmが小さいのか分からない
7. **潮名は黄経差で機械計算し、方式を添える**（要件）。新聞と1日ずれうることを README に書く
8. **カーブは「きょう」だけ描く**（要件）。月間表を置いた瞬間に潮見表サイトの劣化版になる
9. **満潮も干潮も無い日を前提にした状態機械**（構造）。日本海側では実在する
10. **最寄り地点の距離を必ず見せる**（骨格）。海から遠い人が「東京」の潮を自分の場所の潮と誤解しない

## 機能要件

### 画面と状態

- `<main id="app" data-state="pick|loading|ready|empty|error" data-place="none|current|picked">`
- **pick**（地点なし）: `#pick-title`「どこの潮？」、`#use-location`「現在地でいまの潮を見る」（主）、`#pick-station`「地点を選ぶ」、`#geo-note`（拒否・失敗の理由。`role="status"`）、注記「現在地の座標は端末の外に出しません」
- **loading**: 「潮位表を読んでいます…」。300ms 未満なら出さない
- **ready**:
  - `#answer`（h2・`data-kind="rising|falling|slack-high|slack-low|unknown"`）：「いま、満ち潮」「いま、引き潮」「満潮のころ」「干潮のころ」「潮の向きが分かりません」
  - `#answer-sub`：rising/falling「次の満潮は 16:57（201cm）」／翌日「次の満潮は あす 04:35（209cm）」／slack「16:57 が満潮（201cm）」／unknown「次の満干が潮位表にありません」
  - `#remaining`（副文の直下・22px・太字・濃紺の塗りピル）：rising/falling「あと1時間57分」（60分未満「あと◯分」・1分未満「まもなく」）／slack「このあと引き潮に」「このあと満ち潮に」／unknown は出さない
  - `#now-level`：「いまの潮位 およそ165cm」。直下に `#now-level-note`「推定・潮位表基準面から」
  - `#tide-name` タグ「大潮」（16px・枠なし）＋ `#range`「きょうの干満差 171cm（東京では大きい方）」
  - `#curve`：`<svg role="img" aria-label="…">`。`aria-label` 例「0時から24時の潮位。満潮 03:53 200cm、16:57 201cm。干潮 10:30 30cm、22:53 81cm。いまは15:00、満ち潮」。24の毎時値と満干の点を通る滑らかな線、面の塗り、満干の点と時刻、「いま」の縦線と丸と潮位の数字（白い縁取り）、横軸 0・6・12・18・24時（軸の文字は15px）、縦軸は cm。縦軸の目盛りは10・20・50・100（干満差の大きい地点は200・500）から刻みを選び、その倍数で3〜5本。**単位はいちばん上の目盛りにだけ付ける**（「200cm」・ほかは数字のみ）。満潮の時刻は点の上、**干潮の時刻は常に点の下**（プロットは y=40〜186 に収め、時刻の軸は y=228）。「いま」の縦線に近い時刻は縦線から離して置く
  - `#station-name`「東京」（16px・太字）／「現在地 → 秋田（4km）」（現在地・kmは四捨五入の整数）は見出しカードの最上段。その直後に「 · 」を挟んで `#as-of`「15:00 現在」（1分ごとに更新）を続ける
  - 地点の行：`#pick-station`「地点を変える」（地点が無いときは「地点を選ぶ」）、`#use-location`「現在地」を同じアウトラインで1行に。その下にリンク風の段（`#retry`・`#clear-station`「地点を外す」＝設定時のみ・高さ44px以上）、`#far-note`（50km以上のとき）。注記「現在地の座標は端末の外に出しません」は **pick の状態と現在地モードのときだけ**出す（地点を手で選んだ後は出さない）
  - `#events-today` 表（種類・時刻・潮位。見出し「きょう（9月10日）の満潮・干潮」）、`#events-tomorrow`（「あす（9月11日）」）。無い側は「—」ではなく「予測なし」
  - `#post-result`「いまの潮をXに投稿」（共通のシェア欄「Xで投稿」と読み分ける）（`shared/share.js` と同じ導線。文面は「『潮、いまどっち？』東京：いま、満ち潮。次の満潮は 16:57・201cm（大潮）」＋URL）
- **empty**: 「きょうの潮位表が見つかりません」＋ 回復の導線（error と同じ並び）
- **error**: `role="alert"`。左に4pxの帯（`#c2410c`）。`#error-text`（22px）は通信失敗「東京の潮位表が取れません」／404「東京の潮位表が見つかりません」／形の不一致「潮位表の形が変わったようです」（地点名は選んでいる地点）。その下の `#error-note` に次の行動＝404「別の地点を選んでください」／通信失敗「通信を確かめて、もう一度読んでください」／形「気象庁の配信が変わった可能性があります」。その下に回復の導線を**主→副→リンク**の順で置く＝塗りの `#pick-station`「地点を変える」（56px）、アウトラインの `#use-location`「現在地」、リンク風の `#retry`「もう一度読み込む」と `#clear-station`「地点を外す」
- **地点選び**（`<dialog id="station-dialog">`）: `#pref-select`（39都道府県・北から）→ `#station-select`（その県の地点）→ `#station-confirm`「この地点にする」／`#station-cancel`「やめる」。注記「内陸の県はありません。近くの海の県を選んでください」。Escape で閉じる（select に焦点があっても。Day 033 の教訓）
- **現在地**: `navigator.geolocation` → 同梱データで最寄り地点 → 保存 `{ code, mode: 'current' }`。座標は端末の外に出さない。拒否・失敗は `#geo-note` に理由を出し、pick のまま

### 保存（`lib/store.js`）

- `localStorage` の `day-034-tide-now` に `{ code: /^[A-Z][A-Z0-9]$/, mode: 'picked' | 'current' }` だけ。定数名は `STORAGE_NAME`（`key` を含む名前は使わない）。使えない環境でも動く
