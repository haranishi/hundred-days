# Day 032「いま干していい？」

## 何をするか

洗濯物をいま外に干したら**何時に乾くか**、そして**何時までに取り込むか**を出します。答えはこの2つだけです。干すものを薄手・ふつう・厚手から、干す場所を日なた・日かげから選び直すと、その場で時刻が変わります。下の帯は24時間ぶんで、乾いていく時間・夜・雨がそのまま並びます。

## なぜ作ったか

洗濯で面倒なのは干す作業ではなく、**いつ・どこに干すかの判断**だからです。天気アプリは降水確率を教えてくれますが、「降水確率30%」を見ても洗濯機の前の迷いは終わりません。「15:40に乾く、18:00までに取り込む」なら終わります。出すものを時刻ひとつに絞ったのはそのためです。

## 乾く時刻の出し方

大気が水を蒸発させる力を **ET0（FAO-56 基準蒸発散量・mm/h）** で受け取り、洗濯物が持っている水の量をそれで割ります。ET0 は気温・湿度・風速・日射を1本の式にまとめた値で、Open-Meteo が毎時で返します。風を別に足すと二重に数えることになるので足していません。

```
乾くまでの時間 ＝ 洗濯物が含む水の量(mm) ÷ ( ET0(mm/h) × 干し場所の倍率 )
```

| | 値 |
|---|---|
| 水の量：薄手（Tシャツ・下着） | 0.35 mm |
| 水の量：ふつう（タオル・ズボン） | 0.65 mm |
| 水の量：厚手（ジーンズ・パーカー） | 1.20 mm |
| 倍率：日なた | 0.55 |
| 倍率：日かげ・軒下 | 0.33（日なたの6割） |

⚠️ **この係数は実測ではありません。** ET0 は芝生を基準にした量で、物干しに掛かった布から蒸発する量そのものではないからです。次の3つに合うよう決めた目安で、アプリの「計算の根拠」にも同じ但し書きを出しています。

- 真夏の晴れた日、Tシャツは1時間ちょっとで乾く
- 秋の晴れた日の朝9時に干すと、ジーンズは昼過ぎに乾く
- 冬は晴れていても、厚手は1日では乾かない

雨が降っている時間（1時間に0.1mm以上）は乾かないものとして扱い、降った量の3割（1時間あたり0.5mmまで）が洗濯物に戻ります。戻る量は最初の水の量を超えません。

## 設計上の判断

- **主役は乾く時刻ひとつだけです。** 気温・湿度・風速・日射は最初の画面に出さず、折りたたんだ「計算の根拠」に入れました。数字を並べた時点で天気アプリになり、判断はまたユーザーの仕事に戻ってしまいます。
- **干し方・干し場所を変えても通信しません。** 1回の取得で3日ぶんを持ち、切り替えは計算し直すだけです。無料枠（1日1万回）に対して誠実であることと、切り替えの手応えを速くすることの両方が理由です。
- **取り込みの締切を必ず出します。** 乾いたあと干しっぱなしにすると、日が沈んでからの湿気や夜の雨で濡れ戻ります。締切は「乾いたあと最初に来る雨か日没の、早いほう」です。乾く時刻だけでは判断が半分しか終わりません。
- **夜は「乾きません」と言い切ります。** 日没まで1時間を切っていたら、計算上の12時間後を出しても意味がないので、明日の何時に干せば何時間で乾くかに切り替えます。
- **5時間を超えたら生乾きの注意を出します。** 「乾く」とだけ書くと干していいと読まれますが、長くかかる日は扇風機や乾燥機を足したほうが確実です。
- **雨の時間は帯を1コマまるごと塗ります。** 乾く速さに比例させると、雨のあいだは速さが0なので何も描かれず、いちばん大事な情報が消えてしまいました。
- **地名から座標を引く外部サービスは使いません。** Day 31 から解禁されているAPIは1個で、それは天気に使い切っています。代わりに全国1,741市区町村の代表点を同梱しました。現在地を使うときも、いちばん近い市区町村の名前を「現在地（秋田市あたり）」と画面に出します。
- **時刻は「日本時間の壁掛け時計の文字列」で持ちます。** `Date` に入れて比べると、動かす環境のタイムゾーンで結果が変わります（CIはUTCで動きます）。

## 保存するもの・プライバシー

端末の localStorage に残すのは、最後に選んだ市区町村コードと、干すもの・干す場所の選択だけです。位置情報の座標は保存しません。天気を問い合わせるときは、**座標を小数3桁（約100m）に丸めてから**送ります。保存できない環境でも、そのまま使えます。

外へ出る通信は Open-Meteo への予報1本だけです。
