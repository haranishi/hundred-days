# Day 032「いま干していい？」

## 何をするか

**いまの空気にどれだけ洗濯物を乾かす力があるか**を出します。日なたか日かげかを選ぶと、薄手・ふつう・厚手の3つについて「この勢いなら何時間ぶん要るか」が同時に出ます。

出さないものが2つあります。**「◯時に乾く」という時刻**と、**この先の雨**です。理由は次の節に書きました。

## なぜ「いま」だけなのか（2026-09-13に作り直した）

最初の版は「15:40に乾く／18:00までに取り込む」という**将来の時刻**を出し、24時間の帯に**この先の雨**を並べていました。これをやめました。

気象業務法17条は、**気象の予報業務**（観測の成果に基づいて現象を予想し、それを発表することを反復・継続して行うこと）に気象庁長官の許可を要求しています。気象庁の手引きは、この許可が要るかどうかは**その発表手段や営利か非営利かを問わない**と明記しています。無料の個人アプリだから対象外、とはなりません。

最初の版がやっていたのは、Open-Meteo の**予測値**を自前の係数で加工して将来の時刻を発表することでした。許可を取る道もありますが、19条の2が**気象予報士の設置**を義務づけているので、個人の100日チャレンジで現実的に取れる許可ではありません。

そこで、**将来の時刻の気象の値を取得も表示もしない**形に作り直しました。

- 予想をやめて、**いまの観測値からの割り算**だけにした。「この勢いが続くと仮定したら何時間ぶん」は、現在値を水の量で割っただけで、将来の気象の予想ではありません
- **将来の値をそもそも取ってこない**ようにした。取ってこなければ、うっかり画面に出すこともできません。API の呼び出しから `hourly` も `daily` も外し、`current`（いまの1時点）だけにしています
- この線が崩れたら気づけるよう、テストで固定しました。「URLに `hourly`／`daily`／`forecast_days` 等を付けない」「計算の戻り値にいま以外の時刻が入らない」の2本です

## 乾くまでの時間の出し方

大気が水を蒸発させる力を **ET0（FAO-56 基準蒸発散量・mm/h）** で受け取り、洗濯物が持っている水の量をそれで割ります。ET0 は気温・湿度・風速・日射を1本の式にまとめた値で、Open-Meteo が**いまの値**として返します。風を別に足すと二重に数えることになるので足していません。

```
要る時間 ＝ 洗濯物が含む水の量(mm) ÷ ( いまのET0(mm/h) × 干し場所の倍率 )
```

| | 値 |
|---|---|
| 水の量：薄手（Tシャツ・下着） | 0.35 mm |
| 水の量：ふつう（タオル・ズボン） | 0.65 mm |
| 水の量：厚手（ジーンズ・パーカー） | 1.20 mm |
| 倍率：日なた | 0.55 |
| 倍率：日かげ・軒下 | 0.33（日なたの6割） |

⚠️ **この係数は実測ではありません。** ET0 は芝生を基準にした量で、物干しに掛かった布から蒸発する量そのものではないからです。次の3つに合うよう決めた目安で、アプリの「計算の根拠」にも同じ但し書きを出しています。

- 真夏の晴れた日、Tシャツは1時間ちょっと
- 秋の晴れた日の昼なら、ジーンズは4〜5時間ぶん
- 冬は晴れていても、厚手は1日ぶんでは足りない

いま雨が降っているとき（1時間あたり0.1mm以上）と、ET0 が 0 のとき（夜など）は、時間を出さずに「乾きません」と言い切ります。0で割った数字を出しても意味がありません。

### ⚠️ `current` の値は mm/h ではない

Open-Meteo の `current` が返す ET0 と降水は、**直前の `interval` 秒ぶんの積算**です。2026-09-13に秋田・東京・札幌・那覇・シドニー・マドリードで実測したところ `interval` は常に 900 秒（15分）で、同じ時刻の `minutely_15` と完全に一致し、`hourly` とは一致しませんでした（秋田 22:45 の雨：`current` 0.9 ＝ `minutely_15` 0.9 ≠ `hourly` 0.2）。

そのまま mm/h として扱うと**4分の1に見積もります**。`lib/weather.js` の `perHour()` が `3600 ÷ interval` を掛けて直しています。

なお `current` の値は小数2桁に丸められているので、mm/h に直すと刻みが 0.04 になります。`hourly`（mm/h で2桁）より粗いですが、上の係数自体が実測ではない以上、ここの精度を理由に将来の値を取りに行く選択はしませんでした。

## 設計上の判断

- **主役は「いまの判定」1つだけです。** 気温・湿度・風速・日射は最初の画面に出さず、折りたたんだ「計算の根拠」に入れました。数字を並べた時点で天気アプリになり、判断はまたユーザーの仕事に戻ってしまいます。
- **薄手・ふつう・厚手を同時に出します。** 以前は選択式でしたが、それは「選んだ1つの乾く時刻」を大きく出すための切り替えでした。時刻をやめた以上、3行並べたほうが1画面で終わります。
- **干し場所を変えても通信しません。** 切り替えは取得済みの1時点から計算し直すだけです。無料枠（1日1万回）に対して誠実であることと、切り替えの手応えを速くすることの両方が理由です。
- **「ぶん」を必ず付けます。**「約2.5時間」と書くと予想に読まれますが、「約2.5時間ぶん」なら分量の話だと分かります。画面にも「いまの乾かす力がそのまま続くと仮定して、水の量を割っただけの値です」と添えています。
- **24時間を超えるものは数字を出しません。** いまの勢いが丸1日続く前提には無理があり、数字にすると仮定が見えなくなります。
- **地名から座標を引く外部サービスは使いません。** Day 31 から解禁されているAPIは1個で、それは天気に使い切っています。代わりに全国1,741市区町村の代表点を同梱しました。現在地を使うときも、いちばん近い市区町村の名前を「現在地（秋田市あたり）」と画面に出します。
- **時刻の計算をしません。** Open-Meteo が返した「いまの時刻」を日本時間の壁掛け時計の文字列のまま切り出して出すだけです。`Date` に入れて足し引きすると動かす環境のタイムゾーンで結果が変わりますが（CIはUTC）、そもそも将来の時刻を作らないので足し引きする理由がありません。

## 作り直しでやめたこと

| やめたもの | 理由 |
|---|---|
| 乾き上がりの時刻（「15:40に乾く」） | 将来の気象の予想の発表にあたる |
| 取り込みの締切（「18:00までに取り込む」） | 同上。将来の雨と日没から出していた |
| 24時間の帯 | この先の降水・夜をそのまま並べていた |
| 「いちばん早く乾くのは明日の10:00」 | 翌日の予報から出していた |
| 「明日9時に干すなら」 | 同上 |
| 干すもの（薄手／ふつう／厚手）の選択 | 3つ同時に出すようにしたので選ぶ意味が無くなった |
| 降水確率にもとづく判定 | 降水確率は将来の予想。いま降っているかどうかだけを見る |

## 保存するもの・プライバシー

端末の localStorage に残すのは、最後に選んだ市区町村コードと、干す場所の選択だけです。位置情報の座標は保存しません。天気を問い合わせるときは、**座標を小数3桁（約100m）に丸めてから**送ります。保存できない環境でも、そのまま使えます。

外へ出る通信は Open-Meteo への1本だけです。
