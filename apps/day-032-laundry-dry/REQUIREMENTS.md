# Day 032「いま干していい？」要件定義

**いま外に干したら、何時に乾くか。**それを1本の時間バーで出す。使うのは気温・湿度・風・日射を1つにまとめた「大気の乾かす力」で、そこに洗濯物が持っている水の量を割ると時間になる。降水確率は判断の材料であって、答えではない。

## 背景と狙い

- 100日チャレンジ Day 32。S2（Lv.2）の2日目で、解禁表のとおり**外部API（無料・認証不要）を1個**だけ使う。その1個が Open-Meteo の予報API（`https://api.open-meteo.com/v1/forecast`）
- 題材は「需要ベースWebアプリ100案」042「洗濯物の乾き予測」。困りごとは**干す作業ではなく「いつ・どこに干すかの判断」**。面倒な家事の3位が洗濯
- 天気アプリは既視感が強い。差がつくのは**「降水確率を見せる」ことではなく「乾く時刻を出す」こと**。降水確率60%と言われても洗濯物を干すかは決まらないが、「15:40に乾く・18:00までに取り込む」なら決まる
- 地名から座標を引く外部サービスは**使わない**。APIを1個に収めるため、市区町村の代表点（1,741件）を同梱する

## ユーザーストーリー

| ユーザー | 欲しいことと理由 | 受け入れ条件 |

| 朝、洗濯機の前で迷っている人（本命） | 外に干すか室内にするか、1秒で決めたい | 開いて「いま干す」を1回押すと「15:40に乾く／18:00までに取り込む」と判定バッジが出る |
| 夜に洗濯を回す人 | いま干しても無駄か知りたい | 夜は「今からだと乾きません」と言い切り、明日の何時に干せば何時間で乾くかを続けて出す |

## UX5階層

- **戦略**: 天気アプリではなく**「干す・干さない」を決める1問**。成功＝開いて1タップで「何時に乾く」が出て、洗濯機の前で迷いが終わること。失敗＝降水確率や気温の数字を並べてしまい、結局ユーザーが自分で判断させられること。差別化の源泉は「乾く時刻を出す」の一点で、そこが画面の主役
- **要件**: 載せるもの＝現在地または市区町村の選択、干し方3つ（薄手・ふつう・厚手）、干し場所2つ（日なた・日かげ／軒下）、乾き上がり時刻、取り込み締切、判定バッジ、24時間の時間バー、今日いちばんいい干し始め、明日の見通し1行、計算根拠の開示、出典。対象外＝室内干しの時間計算（屋外の値では出せない）、通知、複数地点の保存、週間予報、地図
- **構造**: 単一画面で `start → loading → ready` の3状態＋ `error`（通信失敗）。位置は「現在地」「選んだ市区町村」「未選択」の3値。干し方・干し場所を変えても**再通信せず**、取得済みの予報から計算し直す
- **骨格**: いちばん大きい要素は**乾き上がり時刻**（数字を最大級）。その真下に取り込み締切と判定バッジ。次に24時間の時間バー（横スクロールさせない・幅いっぱい）。干し方・干し場所の切り替えはバーの下（各44px以上）。根拠と出典は折りたたみの中とフッター
- **表層**: 晴れた日の物干し。地は空色に寄せた白（`#f4f8fb`）、文字は紺墨（`#1b2b3a`）。よく乾く＝晴れ色（`#e8a33d`）、五分五分＝曇り（`#7d8fa1`）、やめておく＝雨色（`#3f7ec4`）。時間バーは乾いた区間を晴れ色、雨の時間を雨色、日没後を薄墨。動きは時間バーが左から伸びる1つだけ。`prefers-reduced-motion` では即時表示

### UX5階層を通したことで決まった実装（8件）

1. **主役は「乾く時刻」1つだけ**（戦略層）。気温・湿度・風速は最初の画面に出さず、折りたたんだ「計算の根拠」の中に入れる。天気アプリに見えた時点で負け
2. **干し方・干し場所の変更で再通信しない**（構造層）。1回の取得で3日ぶんを持ち、切り替えは計算のやり直しだけ。API呼び出しを最小に保つ（利用条件の上限に対しても誠実）
3. **夜は「乾きません」と言い切る**（要件層）。日没後に干しても乾かないのに「12時間後」と出すのは嘘に近い。夜は明日の提案へ切り替える
4. **取り込み締切を必ず出す**（要件層）。乾いたあと干しっぱなしだと、日没後の湿気や夜の雨で濡れ戻る。「乾く時刻」だけでは判断が半分しか終わらない
5. **5時間を超えたら生乾きの注意を出す**（要件層）。乾く時刻だけでは「乾くから干していい」と読まれる。長くかかる日は臭いの理由まで書く
6. **市区町村は選んだら覚える**（構造層）。位置情報を断った人が毎回選び直すのは苦痛。localStorage に最後の1件だけ持つ
7. **計算式を画面から開ける**（戦略層）。「なぜその時刻なのか」を隠すと天気アプリと区別がつかない。使った値と係数をその場で見せる
8. **通信に失敗しても場所選びは残す**（構造層）。エラーで画面が空になると再試行の導線を失う

## 乾きの計算（`lib/dry.js`・純関数・DOMに触れない）

### 考え方

大気が水を蒸発させる力を **ET0（FAO-56 基準蒸発散量・mm/h）** で受け取る。ET0 は気温・湿度・風速・日射を1つの式にまとめた値で、Open-Meteo が毎時で返す。洗濯物が持っている水の量を「面積あたりの水の厚み（mm）」で表し、毎時 ET0 を引いていって 0 になった時刻が乾き上がり。

```
残り水分[mm] ← 洗濯物の水分量 W
各時刻 t について（1時間刻み）:
  乾く量 = ET0(t) × C(干し場所)
  雨(t) ≥ 0.1mm なら 乾く量 = 0、残り水分 += min(雨(t) × 0.3, 0.5)（W を超えない）
  残り水分 -= 乾く量
  残り水分 ≤ 0 になった時間帯を線形に按分して乾き上がり時刻とする
```

### 係数

| 記号 | 値 | 根拠 |
|---|---|---|
| W 薄手（Tシャツ・下着・シャツ） | 0.35 mm | 下の較正 |
| W ふつう（タオル・ズボン） | 0.65 mm | 下の較正 |
| W 厚手（ジーンズ・パーカー・バスタオル） | 1.20 mm | 下の較正 |
| C 日なた | 0.55 | 下の較正 |
| C 日かげ・軒下 | 0.33（日なたの6割） | 日射が無いぶん遅くなることの目安 |

⚠️ **この係数は実測ではない。** ET0 は芝生を基準にした値で、物干しに掛かった布の蒸発量そのものではない。次の3つの体感に合うよう決めた**目安**であることを README と画面の「計算の根拠」に明記する。

| 較正に使った体感 | この式での結果 |
|---|---|
| 真夏の晴れた日、Tシャツは1時間ちょっとで乾く | ET0 0.6 → 0.35 / (0.6×0.55) ≈ 1.1時間 |
| 秋の晴れた日の朝9時に干すと、ジーンズは昼過ぎに乾く | 秋田 2026-09-08 の実データで 09:00 → 約5時間 |
| 冬の晴れた日でも厚手は1日では乾かない | ET0 0.08 → 1.20 / (0.08×0.55) ≈ 27時間 |

### 出力

```
predict({ hours, sunset, startAt, fabric, place })
→ {
    driedAt,          // 乾き上がりの時刻。日没までに乾かなければ null
    hoursToDry,       // 乾くまでの時間（小数・null あり）
    bringInBy,        // 取り込み締切＝乾いた後の「最初の雨」か「日没」の早いほう
    rainRisk,         // 干している間の降水確率の最大値
    wetAgain,         // 干している途中で雨に当たる時刻（無ければ null）
    verdict,          // 'good' | 'fair' | 'bad'
    smell,            // 5時間を超えるか（生乾きの注意）
    timeline          // 1時間ごとの { time, dryRate, remaining, rain, isDay }
  }
```

### 判定バッジ

| verdict | 条件 | 文言 |
|---|---|---|
| `good` | 5時間以内に乾く かつ 降水確率の最大 < 30% | 「よく乾きます」 |
| `fair` | 10時間以内に乾く かつ 降水確率の最大 < 60% | 「乾きますが、様子見を」 |
| `bad` | 日没までに乾かない、または 降水確率60%以上、または 途中で雨に当たる | 「今日はやめておく」 |

## 機能要件

### 画面と状態

- `<main id="app" data-state="start|loading|ready|error" data-fabric="thin|normal|thick" data-place="sun|shade">`
- **start**: 見出し「いま干していい？」、説明1行、`#use-location`「現在地で調べる」（主要ボタン）と `#pick-place`「市区町村から選ぶ」
- **loading**: `aria-busy="true"`。300ms 未満なら出さない
- **ready**:
  - `#place-name`（「秋田市」または「現在地」）＋ `#change-place`「場所を変える」
  - `#dry-time` 乾き上がり時刻を最大級で（例「15:40」）。副文「あと4時間20分」
  - `#bring-in` 「18:00までに取り込む」
  - `#verdict` 判定バッジ
  - `#smell` 生乾きの注意（該当時のみ）
  - `#timeline` 24時間バー（`role="img"` と `aria-label` で文章にした説明を持つ）
  - `#fabric` 3ボタン・`#place-kind` 2ボタン（`role="radiogroup"`）
  - `#best-start` 「9時に干すと4時間で乾きます」（今より後の最良時刻。無ければ出さない）
  - `#tomorrow` 明日の見通し1行
  - `#why` `<details>`「計算の根拠」＝使った値（気温・湿度・風速・日射・ET0）と係数、較正の但し書き
- **夜**（今から日没まで1時間未満、または日没後）: `#dry-time` を「今からだと乾きません」に差し替え、`#best-start` を明日の提案にする
- **error**: `role="alert"`「天気を取れませんでした」＋ `#retry`「もう一度」＋場所の選び直しは残す
- **場所選び**（`<dialog id="place-dialog">`）: 都道府県 `<select>` → 市区町村 `<select>` → 「この場所にする」。`places.json` はここを開いたときに初めて読む

### API（`lib/weather.js`）

- `https://api.open-meteo.com/v1/forecast` に1回だけ。パラメータは
  `latitude` `longitude` `hourly=temperature_2m,relative_humidity_2m,precipitation_probability,precipitation,cloud_cover,wind_speed_10m,shortwave_radiation,et0_fao_evapotranspiration,is_day` `daily=sunrise,sunset` `timezone=Asia/Tokyo` `forecast_days=3`
- 座標は小数3桁に丸めて送る（現在地の精度をそのまま渡さない）
- 8秒で諦める。失敗・欠測は `error` 状態へ
- 同じ座標の応答は10分だけメモリに持つ（切り替えのたびに叩かない）

### 保存

- `localStorage` に最後に選んだ市区町村コードと、干し方・干し場所。使えない環境でも動く

## 非機能・共通ルール

- 外部APIは Open-Meteo の1個だけ。CSP の `connect-src` に `https://api.open-meteo.com` を足す（`scripts/build.mjs` の `CONNECT_BY_APP`）
- 依存ライブラリなし。`app.js` は ES モジュール
- 共通のシェア部品（`shared/share.css` / `shared/share.js`）を入れる
- 4状態（loading・empty・error・ready）を全部持つ
- 44px 以上のタップ領域、キーボード操作、`prefers-reduced-motion`
- フッターに出典2つ（Open-Meteo・国勢調査/e-Stat）と「公式の予報ではありません」
