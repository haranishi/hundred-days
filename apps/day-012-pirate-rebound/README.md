# Day 012: 海賊船の打ち返し係

敵船が撃つ**音**を聞いて、飛んでくる砲弾を**拍**で打ち返す1ボタンのリズムゲームです。

公開URL: `https://hundred-days.pages.dev/day-012-pirate-rebound/`

## なぜ作ったか

Day 11–20 で解禁されたのは「4状態（空・読込中・エラー・不正入力）」です。
フォームやファイル処理でこの4つを作ると、どうしても飾りが混じります。
音を鳴らすアプリでは飾りになりません。

- **空**：ブラウザは操作なしに音を出せない。だから「まだ音が鳴っていない」状態が必ずある
- **読込中**：音の時計が動き出してから拍が頭に来るまで、本当に待ち時間がある
- **エラー**：再生が拒否される／タブを離れて時計が飛ぶ、はどちらも実際に起きる
- **不正入力**：拍と関係ない入力（から振り）は、このゲームでは意味のある失敗

## 素材を1つも読み込んでいない

画像・音源・フォント・ライブラリを1つも読み込んでいません。曲も効果音も海も船も砲弾も、
すべてこのページのコードが組み立てています。理由は3つあります。

1. **音とゲームが同じ時計を共有できる。** 音源ファイルを再生する方式だと、譜面と音の対応を
   別に持つことになります。発振器で鳴らすなら、拍から直接音を作れます
2. **ライセンスの確認対象が存在しない状態になる。** このリポジトリは公開なので、
   借りてきた素材の権利を1つずつ確かめるより、作るほうが速くて確実です
3. **3Dも同じ。** ライブラリを使わず、自分で書いた透視投影で Canvas 2D に面を塗っています
   （Day 009 の秋田バス3Dと同じ手）。モデルは頂点をコードで置いて組み立てています

## 音の時計を正本にする

拍の位置は必ず `AudioContext.currentTime` から逆算します。`performance.now()` や
`setTimeout` で音を鳴らすと必ずよれます。音の予約は25msごとに100ms先まで入れています。

押した時刻は `getOutputTimestamp()` で音の時計へ直します。こうすると、
**耳に届いた音を基準に判定できる**ので、機器の出力遅れが自動で吸収されます。
それでも残るずれは、利用者が補正できるようにしてあります。

判定はドンピシャ ±35ms・おしい ±80ms。どちらからも遠い入力は「から振り」で、
打点を消費しません（連打で稼げないようにするため）。

## 保存しないので、URLに載せた

localStorage はまだ解禁されていない（Day 21から）ので、補正値を保存できません。
代わりに URL のハッシュ（`#cal=-20`）へ載せています。保存ではなくリンクなので制約の内側で、
合わせた値をブックマークすれば次回もそこから始められます。

## 遊び方

| 合図の音 | 飛んでくるもの | 操作 |
|---|---|---|
| 低い「ドン」 | 砲弾 | 2拍あとに1回押す |
| 速い「ドドン」 | 二連弾 | 2拍あとから半拍あけて2回押す |
| 鳥の鳴き声 | カモメ | **押さない** |

見た目でも区別はつきますが、見てから反応しても間に合いません。耳で数えてください。

## 開発用の入口

URL に `dev=` が入っているときだけ、`window.__day012` が開きます。
打点ちょうど（±35ms）で押したときに本当に当たりになるかは人の手では確かめられないので、
自動テストとデモ録画はここから叩いています。

- `#dev=short` … 20拍の短い譜面（テストとデモ用）
- `#dev=on` … 本編の譜面のまま、開発用の入口だけ開く

## デモ動画の音

Playwrightは音を録らないので、動画は無音で上がります。`tools/render-demo-audio.mjs` が
**アプリと同じ音符データ**（`lib/music.js` の伴奏・`lib/chart.js` の発射と打点）から、
同じ波形・同じ包絡線でWAVを組み立て直し、ffmpegで重ねています（Day 007/008/010と同じ手）。

位置合わせに要るのは「曲の頭が動画の末尾から何秒前か」だけで、これは録画の最後に
`songSeconds()` を読めば分かります。`-itsoffset` は音を作り直すときに効かなかったので、
WAV側の先頭に無音を入れて合わせています。
