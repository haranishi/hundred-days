# Day 025 ちかくの駐車場

現在地か地名から、近くの駐車場を地図と距離順のリストに同時に出す。選ぶと地図の同じ場所が光り、
そのままGoogleマップの経路へ抜けられる。

https://hundred-days.pages.dev/day-025-nearby-parking/

## 金額で比較しない理由

OpenStreetMapの駐車場に金額（`charge`）が書かれている割合は、実測で **0〜0.5%** しかなかった。
「有料か無料か」（`fee`）ですら地域差が大きく、**秋田駅の400m圏は81件中12件＝15%、東京駅は74%**。
`opening_hours` は0〜9%。

だから金額での比較はやらず、並べる軸は**有料・無料・料金不明の3値**にしている。
金額が書かれている稀な駐車場では、その値をそのまま添えるだけにとどめる（比較には使わない）。
埋まっていないものを推測で埋めると、外したときに「行ったのに停められない／思ったより高い」という
いちばん困る形で外れる。営業時間と収容台数は、書かれているときだけ出す。

## APIをブラウザから直接叩かない理由

Overpassの利用方針は「アプリやサイトの利用は**全利用者の合計**で数える」「常設利用なら
**1日100クエリ・10MB未満**」「アプリを一意に識別できるUser-AgentかRefererを付ける」
「キャッシュとレート制限をする」「429や406を受けたら30秒待つ」と定めている。
Nominatimも識別可能なUser-Agent（ライブラリ既定のUAは不可）と結果のキャッシュを要求する。

**ブラウザの `fetch` はUser-Agentを設定できず、キャッシュも利用者ごとに割れる。**
方針を満たせるのはサーバー側だけなので、`functions/api/day-025/` の中継を通す。

いちばん効いているのは**座標を約110m四方に丸めること**。同じ駅前から来た人はみな同じキャッシュを
引くので、上流には1回しか行かない。エッジのキャッシュは7日。返す項目も画面が使うタグだけに削って
いて、実測で49KB→29KBになった。

それでも上限に当たることはある。当たったら黙って再試行せず、
「30秒ほど待ってからお試しください」と出して止まる。

## 半径を段階的に広げない理由

所要時間は半径ではなく**Overpassの順番待ち**で決まる。実測で半径400mが4.8秒、3200mが1.9秒と、
広いほうが速いことがあった。400→800→1600→3200と広げる作りは往復回数を増やすだけで
何も買っていなかったので、**800m→（3件未満なら）3200m**の2段に減らした。
800mは徒歩10分圏で「ちかく」の実用上限、3200mは何もない土地のための保険。

## MapLibreを同梱している理由

このリポジトリのCSPは `script-src 'self'` で、外部スクリプトを読むアプリが1つも無い。
CDNを許可すると配信元が乗っ取られたときにこのサイト全体の話になるので、
BSD-3-Clauseの配布ビルドを `vendor/` へ置いた。地図タイル（OpenFreeMap）だけは外へ出る。

MapLibreは `blob:` からWeb Workerを起こす。`worker-src` は `child-src`→`script-src`→`default-src`
と落ちるので、`'self'` のままだと**地図が黙って出ない**。`scripts/build.mjs` の `WORKER_BY_APP` で
このDayにだけ `worker-src blob:` を足している。

## 触るときの注意

- **`js/` ではなく `lib/`**。DOMに触らない純関数（クエリ組み立て・タグ正規化・距離計算・半径拡大・
  表示上限）だけを分けてあり、Nodeから直接テストしている
- **Nodeから上流のOverpassを叩く通し確認は当てにならない**。同じクエリがcurlと実ブラウザでは
  200・2.7秒で返るのに、undici経由だと再現性なく406やAbortErrorになる。実ブラウザで見ること
- **遅さを測る前に `https://overpass-api.de/api/status` で空きスロットを確認する**。
  スロットは1IPあたり2枠で、自分のテスト実行で使い切ると以降の計測が全部遅く見える
- 中継APIを含めた通し確認は `npx wrangler pages dev dist --port 8788`（`serve-dist` では
  Functionsが動かない）
