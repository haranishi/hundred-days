# Day 009: 秋田バスライブ

いま秋田県を走っているバスの実測GPS位置を、地図ライブラリも地図タイルも使わない自前の3Dマップの上で走らせます。

公開予定URL: `https://hundred-days.pages.dev/day-009-akita-bus-3d/`

## 使い方

開くだけで、走行中のバスが3Dマップに現れて動き出します。ドラッグ（矢印キー）で視点を回し、ホイールや `+` `-` で拡大縮小、`R` で県全体の視点に戻ります。バスをタップするか右の一覧から選ぶと、事業者名・車両ID・速度・位置の送信時刻が出ます。

既定は必ず**県全体**を映します（実測位置があるのは秋田市周辺だけなので、バス群に合わせて寄せると県のほとんどが画面から消えるため）。近くで見たいときは「秋田市周辺にズーム」で寄れます。

## データの出どころと限界

- **実測位置**: 秋田中央交通・秋田市のGTFS-RT VehiclePosition。20秒ごとに取り直します
- **路線網**: 秋田県バス協会 公共交通オープンデータ（GTFS-JP・CC BY 4.0）から抽出した17事業者・618路線・5,923停留所

正直に見ておきたいことが3つあります。

1. **秋田県内18事業者のうち、実測位置を公開しているのは2事業者だけです。** ほかの路線は線として描かれますが、バスは走りません
2. **道なりの路線形状を公開しているのは17事業者中5事業者だけです。** 残りは停留所を直線でつないだ近似なので、線が角ばって見えます。実形状と区別できるよう細い破線で描いています
3. **1日のうち9時間前後は、走行中0台が正常な状態です。** 終バスは両事業者とも22時前で、始発は5時台。0台のときは時刻表の本数と突き合わせて「運行時間外」なのか「走っているはずなのに位置が届いていない」のかを出し分けます

表示位置は各事業者が送信した時刻のものなので、実際の車両より数十秒遅れます。地上の車体は目印として実物よりはるかに大きく描いています。

## 走行中に数えていない車両がある理由

上流には「止まったまま位置だけ送り続ける車両」が混ざります。そのまま描くと、動かないバスが夜通し「走行中」に見えます。除外は理由が2つあり、意味が違うので画面でも行を分けて台数を出しています。

**1. 位置が10分以上古い車両を捨てる**（中継API `functions/api/day-009/vehicles.js`）

秋田市のフィードは、フィード自体を数十秒ごとに作り直しているのに、中の車両の位置送信時刻が9時間以上前で止まったまま同じ座標を返し続けることがあります（2026-08-16 21:36 実測）。送信時刻が古いことが分かる車両は、ここで落とします。

**2. その事業者の運行時間外に届いた位置を数えない**（アプリ側 `lib/service.js` の `isOffService`）

1だけでは足りませんでした。同じ秋田市のフィードが、翌未明には**座標をまったく更新しないまま、車両の送信時刻だけを現在時刻に書き換える**ようになったためです。実測は次のとおりで、10分ルールは完全に素通りします。

| 実測時刻 | 車両1007の座標 | 車両の送信時刻 | 10分ルール |
|---|---|---|---|
| 2026-08-16 21:24 | (39.64194107055664, 140.1148223876953) | 11:54:58（9時間29分前） | 除外できた |
| 2026-08-16 21:36 | ビット単位で同一 | 11:54:58（9時間41分前） | 除外できた |
| 2026-08-17 00:44 | ビット単位で同一 | 00:44:34（3秒前） | 素通り |

秋田市の終バスは20:02、始発は5:55です（平日ダイヤ）。深夜0時台に位置が届いても、それは走っているバスではありません。そこで送信時刻を信じるのをやめ、`data/network.json` の `service`（GTFS-JPの時刻表から数えた1時間ごとの便数）を使って、**その事業者の運行時間外に届いた位置は走行中に数えない**ことにしました。事業者ごとに判定するので、秋田中央交通が走っている21時台でも、秋田市の車両だけを外せます。

前後1時間は猶予にしています。`hourly[h]` は「h時に走っている便数」の丸めた集計なので、21:53発の便が22時台まで走ることも、5:55発のために5時台から車両が動き出すこともあります。境界ちょうどで本当に走っている車両を消すほうが、幽霊を1台残すより害が大きいと考えました。

## プライバシー

位置情報の取得も送信もしません。利用者を識別する情報は扱いません。中継APIは上流のバイト列をそのまま返さず、必要な項目だけに絞ったJSONにして返します。

## 路線データの更新

Node.js 18以降で次を実行すると `data/network.json` を作り直します（ビルドやアプリ実行時には走りません）。

```bash
node apps/day-009-akita-bus-3d/tools/fetch-gtfs.mjs
```

## 上流への配慮

提供元が高頻度アクセスを断っているため、中継API（`functions/api/day-009/vehicles.js`）はCloudflare側で20秒キャッシュしてから上流へ行きます。利用者が何人いても上流への到達回数は増えません。
