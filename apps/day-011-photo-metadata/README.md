# Day 011: この写真、まだ場所を覚えている

写真をSNSやフリマに出す前に、その写真が抱えている位置情報・個人につながる情報を確かめて、**画質を落とさずに**取り除くページです。

公開URL: `https://hundred-days.pages.dev/day-011-photo-metadata/`

## なぜ作ったか

「Exif削除」を名乗るWebサービスには、消したい写真を他人のサーバーへアップロードさせる方式のものがあります（2026-08-18に調べた範囲では、海外の2件がこの方式でした）。消したいのに渡している、という点で目的と手段が噛み合いません。

このアプリはブラウザの中だけで完結し、**外部へは通信を1本も出しません**。同一オリジン以外へのリクエストが0本であることと、通信を遮断しても動くことをE2Eテストで固定しています。

日本語のExif削除ツール7件を調べたところ（2026-08-18時点）、次の3点を書いているサービスは1件もありませんでした。ここがこのアプリの中身です。

- メタデータの**完全な除去を保証しない**こと
- **Exifを消してもXMP・IPTCに同じ撮影者名・著作権表示が残る**こと（このアプリは3つとも消します）
- 他人の写真の**権利表示を消すリスク**（`Copyright` / `Artist` を見つけたら消す前に警告します）

「ブラウザ内で完結」は、この7件はすべて書いています。それ自体は差別化になりません。差別化は上の3点と、無劣化であることです。

## 設計で決めたこと

- **画像を描き直さない。** canvasに描いて書き出す方式だと、画素は必ず再圧縮され、元の量子化テーブルもICCプロファイルも失われます（HTML仕様上、canvasの書き出しに入るのは画素とcanvasの色空間だけ）。ここではJPEGのセグメント構造を直接編集し、**SOS（0xFFDA）から末尾までを1バイトも変えずに写します**
- **ICCプロファイルは残す。** 色の再現に使う情報で、個人には結びつきません。消すと色が変わる実害の方が大きい
- **向きだけは作り直して残す。** CSS `image-orientation` の初期値は `from-image` なので、Exifをまるごと消すと縦写真がブラウザで横倒しになります。元の `Orientation` が1以外のときだけ、**その1件だけを持つ32バイトのExif**を組み立てて差し込みます（消すチェックボックスも別に置いてあります）
- **「見つからなかった」と「調べられない」を別の答えにする。** PNG・HEIC・WebPは「このツールでは調べられません」と返します。**「情報はありません」と言ってはいけません**——PNGにも `eXIf` チャンクがあり得るので、それは嘘になり、安全だと誤解させます
- **MakerNoteの中身は読まない。** メーカー独自形式で規格が公開されていないため、存在の有無だけ出します

## できること・できないこと（2026-08-18 時点で分かっていること）

| | 中身 |
|---|---|
| **調べられる形式** | JPEG のみ（先頭が `FF D8 FF`）。判定は拡張子ではなく先頭バイトで行う |
| **取り除く区画** | Exif（APP1 `Exif\0\0`）／XMP（APP1 `http://ns.adobe.com/xap/1.0/`）／ExtendedXMP（APP1 `http://ns.adobe.com/xmp/extension/`）／IPTC・Photoshop（APP13 `Photoshop 3.0`）／MPF（APP2 `MPF`）／コメント（COM）。同じ種類が複数あれば全部 |
| **残す区画と理由** | ICC プロファイル（APP2 `ICC_PROFILE`）＝消すと色が変わるため。JFIF（APP0 `JFIF`）・JFXX（APP0 `JFXX`）・Adobe（APP14）＝復号や表示に関わるため。**向きの情報**＝Exif をまるごと消すと縦写真が横倒しで表示されるため、元の `Orientation` が1以外のときだけ、その1件だけの32バイトの Exif に作り直して残す（消す選択肢も画面にある） |
| **取り除けないもの** | 上に挙げていない APP セグメント（APP3〜APP12 などにメタデータを書くカメラは実在する）。JPEG 以外（HEIC・PNG・WebP）の中身。**画像そのものに写り込んだ情報**（表札・ナンバープレート・書類の文字） |
| **検出できないもの** | IPTC の中身（区画があることだけを示し、中身は読んでいない）。MakerNote の中身（メーカー独自形式で規格が公開されていない）。XMP は権利表示の名前（`dc:rights` など）が出てくるかを文字列で見るだけで、値は読んでいない |

「メタデータが見つかりませんでした」は、**このアプリが探した5種類の区画に無かった**という意味です。写真に何の情報も無いという意味ではありません。

## 権利表示（Copyright / Artist）を別扱いにしている理由

GPS やシリアル番号は「消したい情報」ですが、著作権表示は「**残したい情報**」で、利用者にとっての利益の向きが逆です。同じ束に入れると「全部消すのが正解」に見えてしまい、他人の写真の権利表示を何も考えずに消す導線になります。だから危険度の並びから切り離し、第4のカテゴリとして出しています。

検出しているあいだは、除去ボタンのすぐ上に警告を出したままにします（閉じられる通知にしません）。検出した値そのものも表示して、消す前にコピーで控えられるようにしています。

**今後の候補（v2）**：「**Exif の著作権表示だけを残して、他を消す**」という選択肢。実装するときは「**Exif の分だけ残します（XMP・IPTC に入っている分は消えます）**」と容器名まで書かないと嘘になります。なお逆向きの「著作権表示だけを選択的に消す」機能は作りません。

## 実装の落とし穴（外すと機能が嘘になる）

- **APP1は2種類ある。** `Exif\0\0` と `http://ns.adobe.com/xap/1.0/\0`（XMP）が両方APP1です。マーカー番号で判別する実装は必ずXMPを取り逃すので、**署名文字列で見分けます**
- **同じ種類の区画が複数あり得る。** 64KBを超えるExif・IPTCは分割され、XMPはExtendedXMPとして複数のAPP1にまたがります。**一致したものは全部消します。最初の1つで打ち切りません**
- **知らないAPPセグメントは消しません。** 消す対象は Exif・XMP・IPTC・MPF・COM の5種類に限っています。それ以外のAPPnにメタデータが入っている可能性は残るので、画面に「完全に消せることを保証しない」と書いています

## 送信しないための実装条件

画像に由来するものは、座標もハッシュ値も「GPSの有無」フラグもファイル名も、**どんな形でも外に出しません**。例外の中身も画面に出しません（Exifの値やファイル名が混ざった文字列を、あとから外へ送る事故を防ぐため）。

このアプリを `scripts/build.mjs` の `CONNECT_BY_APP`（外部APIを許可する一覧）に**足さないでください**。`connect-src 'self'` のままにしておくことが、そのまま「送信できない」ことの技術的な保証になります。アクセス解析タグも入れません。

## サンプル写真

`sample/sample.jpg` は自作です。他人の写真も配布画像も使っていません。

表札に架空の住所が写った「全体」の絵を描き、そこを切り落とした「本体」をJPEGにして、**IFD1のサムネイルには切り落とす前の「全体」**を入れてあります。切り取ったはずの表札が縮小画像としてファイルの中に残る、という実際によくある事故の再現です。GPSは東京駅の座標で、画面にも「サンプルに書き込んだ架空の位置」と書いてあります。

## 画面に出す文言について

免責・注意書き・警告の文言は **`lib/copy.js` に集めてあります**。法務レビューの結果で差し替わる前提なので、HTMLやapp.jsに直接書かず、`data-copy="キー名"` の空要素へ流し込む形にしてあります。書き換えるときは `lib/copy.js` だけを見てください。

文言のルールは、**事実を書き、法的評価を書かない**こと（「画像はサーバーに送信されません」は書く／法律上の評価は書かない）。免責は「一切の責任を負いません」と書かず、何を保証しないのかを具体的に書きます。

## テストとサンプルの作り直し

```bash
node --test apps/day-011-photo-metadata/tests/
npx playwright test tests/e2e/day-011-photo-metadata.spec.mjs

# サンプル写真を作り直す（手で実行するときだけ走る）
PLAYWRIGHT=/path/to/playwright/index.js node apps/day-011-photo-metadata/tools/make-sample.mjs
```

ユニットテストで固定しているのは、**除去したあとのSOS以降が元と完全一致すること**（＝画素を変えていない証明）、ICCが残ること、同じ種類の区画を全部消すこと、向き1件だけのExifが正しい構造で入ること、そして**書き出したバイト列を読み直すと除去対象5種が0件・ICCが1件であること**です。

保存したときは、アプリ自身が書き出したファイルをその場で読み直して区画ごとの結果を画面に出します。免責の文章より、利用者がその場で確かめられることのほうが効くためです。

E2Eは `meta.json` が `draft` のあいだ `dist/` に入らないので、spec の中でアプリのフォルダだけを配る小さなサーバーを立てています。公開に切り替えたら通常の `baseURL` に寄せられます。
