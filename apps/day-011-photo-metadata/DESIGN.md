# Day 011 設計：この写真、まだ場所を覚えている

実装に入る前に書く（Web制作ハーネス契約テンプレート §1-1）。戦略層から書き始めて、設計判断をここから導く。

## ユーザーストーリー

| ユーザー | 欲しいことと、その理由 | 受け入れ条件 |
|---|---|---|
| **本命**：フリマやSNSに写真を上げる人 | 上げる前に「この写真から自分の生活圏がバレないか」を確かめたい。バレると実害が出るのに、確かめる手段を持っていない | 写真を置いて3秒以内に、位置情報の有無がはっきり分かる。あれば消して保存できる |
| **このアプリが救う相手**：「EXIF除去サイト」に写真をアップロードしていた人 | 消したいのに、消す過程でその写真を他人のサーバーに渡している。矛盾に気づいていない | 「この写真はどこにも送られていない」ことが、使う前と使った後の両方で分かる |
| カメラで撮った写真をブログに載せる人 | GPS以外にも何が入っているのか知りたい。機種名は平気でも、所有者名やシリアル番号は知られたくない | 何が入っているかが危険度の高い順に並び、専門用語のままで放り出されない |
| 写真を撮って売っている人 | 著作権表示は残したい。全部消えると困る | 権利表示が入っていたら、消す前に警告が出る |
| スマホしか持っていない人 | iPhoneの写真（HEIC）を置いたときに、正しく「調べられない」と言ってほしい | 「情報なし」と「調べられない」が別の答えとして表示される |

## UX5階層

### ①戦略 — 目標 × ユーザーニーズ

**作り手の目標**：Day 11–20で解禁された「4状態（空・読込中・エラー・不正入力）」を、飾りでなく必然として使い切る。加えて、AIに実装させても**際どい判断は自分でやった**と言える回にする（法務・誤検知・誤った安心感）。

**ユーザーのニーズ**：写真を公開する前の不安を、10秒で解消したい。

**差別化の源泉（ここが空なら作る意味がない）**

1. **どこにも送らない。** 既存のオンライン除去サイトは、消したい写真をアップロードさせる。目的と手段が矛盾している。このアプリはブラウザの中だけで完結し、通信を1本も出さない（E2Eテストで固定する）。
2. **画質を1ビットも変えない。** 画像を描き直して保存し直す方式（canvas再エンコード）だと、消せた代わりに劣化する。JPEGの構造を直接いじって、メタデータの区画だけを外し、画素のデータはそのまま写す。
3. **GPS以外の「気づかない情報」を名指しする。** 位置情報は誰でも知っている。知られていないのは、**カメラ本体のシリアル番号**（同じカメラで撮った他の写真と結びつく）・**所有者名**・**編集前のサムネイル**（切り取ったはずの範囲が縮小画像として残ることがある）。ここが「へえ」の中心になる。

### ②要件 — 載せるもの / 対象外にするもの

**載せる**

- JPEGをドラッグ＆ドロップ、またはファイル選択で受け取る
- 入っている情報を**危険度の高い順**に並べて表示する（場所 → 個人が結びつく情報 → 撮影の設定）
- 埋め込みサムネイルが本体と食い違う可能性を検出し、サムネイル自体を画面に出す
- 権利表示（Copyright / Artist）が入っていたら、消す前に警告する
- メタデータを外した画像をダウンロードする
- 同梱のサンプル写真（架空のGPSを自分で書き込んだもの）を1クリックで試せる
- 4状態（空・読込中・エラー・不正入力）
- シェア4点セット＋OGP（全アプリ共通ルール）

**対象外にする（やらないと決めたことを先に書く）**

| 対象外 | 理由 |
|---|---|
| PNG・WebP・HEICの解析 | 1日の枠に入らない。**黙って「情報なし」と出すのが一番危険**なので、「このツールでは調べられません」と別の答えを返す |
| 地図表示 | 地図タイルは外部依存。Day 31まで解禁されていない。座標は数値で出す |
| 住所名への変換（逆ジオコーディング） | 外部APIが要る。加えて、住所を画面に出すこと自体がリスクを増やす |
| 保存・履歴 | localStorage は Day 21 解禁 |
| 複数ファイルの一括処理 | 「1つの主要アクション」を割る |
| ICCプロファイルの削除 | 色の再現に使う情報で、個人には結びつかない。消すと色が変わる実害の方が大きい。**残すと決めて、残すと書く** |

### ③構造 — 画面遷移と、迷う分岐からの復帰路

1画面・1状態機械。

```
[空] --写真を置く--> [読込中] --+--> [結果：見つかった]  --消す--> [保存できた]
                                |
                                +--> [結果：見つからなかった]
                                |
                                +--> [対象外：調べられない形式]
                                |
                                +--> [エラー：壊れている / 読めない]
```

**迷う分岐と、その復帰路**

- **「見つからなかった」と「調べられない」は別の答えにする。** ここを一緒にすると、iPhoneのHEICを置いた人が「安全だ」と誤解して公開する。文言・アイコン・色をすべて分ける。
- **どの終端からも「別の写真を試す」で空に戻れる。** 行き止まりを作らない。
- **消したあとの画面で終わらせない。** 保存した写真をもう一度置いて「今度は何も入っていない」を確認できる導線を出す（自分の目で確かめられることが、このアプリの信頼そのもの）。

### ④骨格 — 配置と優先順位

- **いちばん大きい要素は1つに絞る。** 空状態＝ドロップゾーン。結果状態＝「いちばんまずいものは何か」の1行見出し。両方を同時に主役にしない。
- 結果は3ブロック。①場所（あるときだけ最上部）②あなたと結びつく情報（所有者名・シリアル番号・サムネイル）③撮影の設定（初期状態は畳む）
- 主要CTA「メタデータを消して保存」は結果の直下に1つだけ。ダウンロード以外のボタンは弱く見せる
- タップ領域は44px以上（Day 006で直した前例）
- 「この写真はどこにも送られていません」は**空状態と結果状態の両方**に出す。使う前の不安と、使った後の確認は別物

### ⑤表層

- **赤と緑に意味を持たせない。** 危険度は色だけでなく、必ず文字のラベル（「場所」「本人につながる」「撮影設定」）で示す（Day 006と同じ方針）
- 配色は明るい紙面＋1アクセント。直近のDay 009・010が暗い画面なので、並べたときに見分けがつく
- 本文と背景のコントラストは4.5:1以上
- 動きは最小限。写真を読み込む瞬間だけ、進行が分かる表示を出す

## この5階層を通して変わった実装判断

| # | 通す前に考えていたこと | 通した後 |
|---|---|---|
| 1 | 対応外の形式は「Exifが見つかりません」で済ませる | ③構造で分岐を書いたら、HEICを置いた人が安全だと誤解する経路が見えた。**「調べられない」を独立した状態として作る** |
| 2 | メタデータは全部消す | ②の対象外を書く段で、ICCプロファイル（色）まで消すと写真の色が変わると気づいた。**ICCは残す。残すと画面に書く** |
| 3 | GPSを主役にする | ①差別化を書いたら、GPSは既知で「へえ」がないと分かった。**シリアル番号・所有者名・埋め込みサムネイルを同格の主役にする** |
| 4 | 消したら終わり | ③で行き止まりを見つけた。**保存した写真をもう一度置いて確認する導線**を足す |
| 5 | 「送信しません」は下部に一言 | ④で優先順位を考えたら、これは機能ではなく**信頼の中心**だった。空状態と結果状態の両方に出す |
| 6 | 向きの情報も他と同じく消す | ④の受け入れ条件を書いていて、Exifを全部消すと縦写真が横倒しで表示される事故に気づいた。**向きの情報だけは作り直して残す**（消す選択肢も別に出す） |

6個変わった（0個なら形式を埋めただけなので通し直す、という契約）。
