# Day 039「足もとを掘る」

場所を選ぶと、その近くで実際に掘り出された化石の記録が、地質年代ごとの柱になって積み上がる。
いちばん近い産地から「そこが何年前、どんな場所だったか」を1行で出す。

公開URL: https://hundred-days.pages.dev/day-039-dig-below/

## なぜ作ったか

日本は地質の資料が豊富なのに、「自分がいま立っている場所」から引ける入口がない。
地質図を開いても出てくるのは地層の名前で、そこに何がいたかは書いていない。
化石のデータベースは英語で研究者に向いている。だから多くの人は「ここ昔どうだったんだろう」と
一瞬思って、そのまま流す。

地質図アプリは「地層の名前」を出す。このアプリは「そこにいた生きもの」を出す。
名前より生きもののほうが想像できる、という一点だけで勝負している。

## やらないと決めたこと

- **真下を断定しない。** 出すのは「近くで見つかった記録」であって、選んだ場所の地層の推定ではない。
  だから画面には必ず産地までの距離を出している
- **掘りに行くことを勧めない。** 産地には私有地や天然記念物があり、条例で採集が制限される場合もある
- **地質図の代わりにしない。** 地層名を網羅する方向へは伸ばさない
- **学名を主役にしない。** 日本語のグループ名を主、学名を従に置いている

## 設計の判断

### 半径で切らず、近い順に40件

全国1,741市区町村の代表点から最寄り産地までの距離を測ったところ、中央値8.5km・
50km以内に99.3%だった。ただし小笠原村は250km先。半径で切ると離島で空振りするので、
**近い順にN件**にして0件が出ないようにしてある。

**40件なのは、12件では東京が2層にしかならないため。** 40件にすると東京4層・秋田3層・
名古屋5層・札幌6層・高知9層になる。80件に増やしても層はほとんど増えない。

### 層は「世」でまとめ、高さは等間隔にする

年代の長さに比例した高さにすると、古生代の1層が画面を何十枚ぶんも占めて使えない。
かといって等間隔にすると「2億年の隔たり」と「3万年の隔たり」が同じ厚みに見えて、
時間について嘘をつく。**高さは等間隔にし、層と層の間に「ここで◯◯万年飛ぶ」と数字で書く**
ことにした。高さでは嘘をつかず、飛んだ量は正確に出す。

### 色は決めない

柱の色は国際層序委員会（ICS）の国際年代層序表の公式カラーをそのまま使っている。
地質図と同じ色であることに意味があるので、見栄えのために変えない。
ただし公式カラーは淡いものが多いので、上に載せる文字とのコントラスト比4.5:1を
ユニットテストで全56区間ぶん確かめている（満たせない2区間だけ白地に退避する）。

### 「むかしは海だった」は記録があるときだけ言う

PBDB には産地ごとに堆積環境（`env`）が入っている。日本の産地5,132か所のうち
4,294か所（84%）が海成。化石の種類から推測するのではなく、この記録を根拠にしている。
`env` が無い産地では環境に触れない。

## データ

- 化石の産出記録・産地・堆積環境・出典論文: [Paleobiology Database](https://paleobiodb.org/)
  （**CC0**。APIが応答の中で `"data_license": "Creative Commons CC0"` と返す）
- 地質年代の区分・境界・公式カラー: 国際層序委員会（ICS）国際年代層序表（PBDB経由・CC0）
- 地図タイル: [OpenFreeMap](https://openfreemap.org/)（データは ODbL 1.0）

同梱データの加工内容は [`data/SOURCES.md`](data/SOURCES.md)。

### 取りに行き方

段階展開で、産地が40件集まった段階で止める（±0.3度 → ±0.9度 → ±3.5度）。
通常2リクエスト、1段目で足りないときだけ3リクエスト。
**選んだ地点そのものではなく、小数1桁に丸めた矩形範囲を送る。**

PBDB はレート制限も User-Agent の指定も公表していない（2026-09-15時点でドキュメントを確認）。
このアプリは1回の検索で2〜3リクエストしか出さず、自動で繰り返し取りに行くこともしない。
