# Day 039「足もとを掘る」要件定義

場所を決めると、その近くで実際に掘り出された化石の記録が、古い順に縦の柱へ積み上がる。
いちばん近い記録から「ここは何年前、どんな場所だったか」を1行で出す。

データは Paleobiology Database（PBDB）。日本には産地5,132か所・産出記録30,741件ある。
ライセンスは API が応答の中で `"data_license": "Creative Commons CC0"` と自己申告する。

## 1. 絶対に守ること（破ったら作り直し）

1. **真下を断定しない。** 出すのは「近くで見つかった記録」。足もとの地層の推定ではない。
   画面には必ず産地までの距離を出し、「◯km先で見つかった」と読める形にする
2. **掘りに行くことを勧めない。** 採集の手順・場所の詳細な案内は書かない。
   私有地・天然記念物・自治体の条例に触れる可能性があるため、画面に一言注意を置く
3. **堆積環境は記録があるときだけ言う。** 「むかしは海だった」は PBDB の `env` フィールドが
   海成を示すときだけ。化石の種類から推測しない。`env` が無い産地では環境を書かない
4. **地質年代の色は ICS の公式カラーをそのまま使う。** 見栄えのために変えない。
   API が各年代区間に `col`（例 `#7FC64E`）を返すので、それを使う
5. 予想・鑑定はしない。取得できた記録をそのまま見せるだけ
6. 外部APIは PBDB の1つだけ。地図タイルは OpenFreeMap（帰属表示は常時・消さない）

## 2. 機能要件

### 2-1. 場所を決める（主要アクション）

- 地図をタップして決める／現在地ボタンで決める、の2通り
- 現在地は端末内だけで扱う。PBDB へ送るのは**丸めた矩形範囲**であって、正確な座標ではない
- 初期状態では地図だけを出し、「押して選ぶ」と分かる状態にする

### 2-2. 記録を取る

段階展開で取る。**産地が40件集まった段階で止める**。実測で全国どこでも成立する。

| 段 | 矩形の半辺 | 実測（産地の数） |
|---|---|---|
| 1 | ±0.3度（およそ60km四方） | 東京31・名古屋220・那覇165・高知52・秋田16・大館0 |
| 2 | ±0.9度 | 大館73・札幌208・青ヶ島466 |
| 3 | ±3.5度 | 父島43 |

```
GET https://paleobiodb.org/data1.2/colls/list.json
    ?lngmin=&lngmax=&latmin=&latmax=&show=loc,time,env&limit=3000
GET https://paleobiodb.org/data1.2/occs/list.json
    ?coll_id=<近い順40件のoidをカンマ区切り>&show=class,ref&limit=5000
```

- 距離は取得後にクライアントで計算し、近い順40件へ絞る（**半径で切らない**）
- 座標が日本から外れた記録が数件ある（緯度経度の取り違えとみられる）。
  緯度20〜46.5度・経度122〜154度の外は捨てる
- 通常2リクエスト。1段目で足りないときだけ3リクエストになる
- 転送量は gzip で効く（名古屋 ±0.3度の産地220件が73KB→4.9KB、化石110件が49KB→6.2KB）

> **なぜ40件か。** 12件では東京が2層にしかならず、柱が単調になる。40件にすると
> 東京4層・秋田3層・名古屋5層・札幌6層・高知9層。80件に増やしても層は増えない（高知10層・他は同数）。
> 40件のときの最も遠い産地は50km以内に収まる。

### 2-3. 答えを出す

- **1行の答えを操作より上に置く。** 「ここは◯◯万年前、海の底でした」
  （`env` が海成のとき。陸成なら「陸でした」。記録が無ければ環境に触れず年代だけ）
- 答えに使うのは**いちばん近い産地**。距離を必ず添える。
  年代はその産地自身の `eag`〜`lag` を使う（世の全範囲ではない。産地のほうが狭くて正確）
- いちばん近い記録が遠いときは、それ自体を答えにする。
  「いちばん近い記録は◯km先」と出す。「見つかりません」で終わらせない
- 3段目（±3.5度・およそ700km四方）まで広げても0件のときだけ、
  「およそ700km四方に記録がありませんでした」と出す。**距離を推測で書かない。4段目は取りに行かない**

### 2-4. 柱を見せる

**層は産地1件ごとではなく、「世(epoch)」でまとめる。** 世が取れない古い時代は紀(period)でまとめる。
同じ時代の産地が何か所も並ぶのを防ぎ、時代の幅が見えるようにするため。

- 上が現在、下へ行くほど古い。層は**古い順**に積む
- **層の高さは等間隔にする。** 年代の長さに比例させると古生代の1層が画面を占領して使えない。
  そのかわり層と層の間に「ここで◯◯万年飛ぶ」を文字で書く。
  高さで嘘をつかず、飛んだ量は数字で正確に出す
- 各層に出すもの：時代の日本語名（例「白亜紀 前期」）／何万年前か／
  その時代の産地の数といちばん近い距離／堆積環境／
  見つかった生きもののグループ（日本語・多い順）／代表的な産地名と出典論文
- 層を開いても別画面へ飛ばさない。同じ画面で展開する
- 時代の割り当ては `eag` と `lag` の**中央値**で決める（区間の端は境界にまたがるため）

### 2-5. 年数の書き方

`eag`/`lag` は百万年前の小数。そのままでは読めないので次の形に直す。

| もとの値 | 書き方 |
|---|---|
| 274.4 | 2億7,440万年前 |
| 23.04 | 2,304万年前 |
| 0.0117 | 1万1,700年前 |
| 0 | 現在 |

- 1億年を境に「◯億◯,◯◯◯万年前」と「◯,◯◯◯万年前」を切り替える
- 万の位が0のときは「2億年前」と書く（「2億0万年前」にしない）
- 層と層の隔たりも同じ書き方にそろえる

### 2-6. 日本語にするもの

英語のまま出さない。対応表は `data/` に置き、`data/SOURCES.md` に出どころを書く。

- **地質年代**：紀22種・世34種。`eag`/`lag` の数値で紀に当てる
  （`Middle Miocene` のように親をたどれない区間があるため、名前ではなく数値で照合する）
- **生きもののグループ**：綱レベルで上位30語。実測で上位20語が全体の95%を覆う
  （例 `Bivalvia`→二枚貝、`Cephalopoda`→アンモナイト・オウムガイのなかま、
  `Polycystinea`→放散虫、`Foraminifera`→有孔虫、`Rhynchonellata`→腕足類）
- 綱が `NO_CLASS_SPECIFIED` のときは門へ落とす。門も無ければ「分類が特定されていない記録」と書く
- 学名は主役にしない。日本語のグループ名を主、学名を従に置く

### 2-7. 4つの状態

- 空：場所が未選択。地図だけが出ていて、押せば始まると分かる
- 読込中：柱の位置に骨組みを出す。地図の描画を待たせない
- エラー：PBDB が落ちている・通信が切れた。**知らせは結果が出るはずだった最上部に出す**。
  取得できないと何も出せないので、押しても反応しない操作は失敗中は出さない
- 記録なし：3段目まで広げても0件。いちばん近い記録までの距離を出す

## 3. 非機能要件

- 依存なしの素のHTML/CSS/JS。地図だけ `vendor/maplibre-gl.js`（Day 025・029・030と同じ同梱ビルド）
- `scripts/build.mjs` のCSP表に3つ足す（足さないと本番だけ黙って止まる）
  - `CONNECT_BY_APP['day-039-dig-below'] = 'https://paleobiodb.org https://tiles.openfreemap.org'`
  - `WORKER_BY_APP['day-039-dig-below'] = "worker-src blob:"`（MapLibreがblob:からWorkerを起こす）
  - `IMG_BY_APP['day-039-dig-below'] = ' https://tiles.openfreemap.org'`（地図のスプライト画像）
- 出典を画面に常時出す：PBDB（CC0）、年代区分と色は国際層序委員会（ICS）、地図は OpenFreeMap
- `static/privacy.html` に追記：選んだ地点を含む**矩形範囲**が PBDB へ送られること、
  地図タイルの取得で閲覧者のIPが OpenFreeMap へ届くこと
- `THIRD_PARTY_NOTICES.md` に PBDB と ICS の行を足す
- 共有機能は `shared/share.css` と `shared/share.js` を1行ずつ足すだけ（OGPはビルドが入れる）
- ICS公式カラーは淡い色が多い。**上に載る文字のコントラスト比4.5:1を実測で確かめる**

## 4. テストで固めること

### ユニット
- 距離計算：既知の2点で誤差1%以内。日付変更線をまたぐ入力でも破綻しない
- 近い順40件：半径で切っていないこと。候補が40件未満でも落ちないこと
- 層のまとめ：同じ世の産地が1層にまとまること。世が無い時代は紀でまとまること
- 日本からの外れ値（緯度経度の取り違え）を捨てること
- 年代→紀の割り当て：`eag` の数値で決まること。境界値（66.0・2.58・251.902）の上下を固定
- 年代の日本語化：対応表に無い区間が来ても英語のまま落ちずに出ること
- グループ名の日本語化：`NO_CLASS_SPECIFIED` が門へ落ちること。門も無いときの文言
- 層の間の「◯◯万年飛ぶ」：層が隣り合っていて隔たりが無いときは書かないこと
- 環境の判定：`env` が無いとき環境を書かないこと。海成と陸成の振り分け

### E2E
- 空・読込中・エラー・記録なしの4状態が出ること
- 場所を決めると答えの1行が操作より上に出ること
- 層を開いても同じ画面にとどまること
- 産地までの距離が必ず出ていること（「真下」と読める文言が無いこと）
- 出典3つ（PBDB・ICS・OpenFreeMap）が常時出ていること
- 地図の帰属表示が消えていないこと
