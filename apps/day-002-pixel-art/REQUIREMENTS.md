# Day 002「ドット絵メーカー」要件定義

> 100日チャレンジ Day2。画像を1枚ドロップするとドット絵に変換し、PNGで保存できる単機能Webアプリ。
> ハッピーパスは1本だけ：**画像を入れる → ドット絵が出る → PNGで保存する**。

## 1. 共通制約（Day1-10フェーズ・変更禁止）

- **外部依存0個**：ライブラリ・CDN・Webフォント・外部API・アナリティクス一切禁止。ブラウザ内蔵API（Canvas 2D等）のみ。
- **画像は完全クライアントサイド処理**。サーバーへ送信しない。`fetch`/`XMLHttpRequest` を書かない。
- アカウント不要・課金なし・**localStorage等の永続化も使わない**（設定はハードコード）。
- 構成は day-001 と同じ **プレーン3ファイル**：`index.html` / `style.css` / `script.js`（`defer`読み込み）。ビルド工程なし。
- サブディレクトリ配信（`/day-002-pixel-art/`）で動くよう**相対パスのみ**使用。
- ファイル内に絶対ローカルパス・個人名・大学名・他案件名を書かない（公開リポジトリ前提）。

## 2. 機能要件

### 2-1. 画像入力
- ドロップゾーン1つ：**ドラッグ&ドロップ**と**クリックでファイル選択**（`<input type="file" accept="image/*">`）の両対応。
- 対応形式はブラウザがデコードできる画像（png / jpg / webp 等）。判定は `file.type.startsWith("image/")` 程度でよい。
- 画像以外がドロップされたら黙って無視するか、ドロップゾーン内に短い一言を出す程度（エラー状態の作り込みはしない＝Day1-10の「1状態」ルール）。
- 読み込みは `createImageBitmap` または `FileReader`＋`<img>` のどちらでもよい。EXIF回転はブラウザ既定に任せる。

### 2-2. 変換（コア）
アルゴリズムは2段階：

1. **縮小**：オフスクリーンcanvasに「横 N ドット」（縦はアスペクト比維持・四捨五入、最低1）で `drawImage` 縮小描画。
2. **拡大表示**：表示用canvasへ `imageSmoothingEnabled = false` のまま**最近傍拡大**して、ドットの境界をくっきり出す。

パラメータは2つだけ：

| パラメータ | UI | 仕様 |
|---|---|---|
| 横ドット数 N | スライダー | min 8 / max 128 / step 4 / **初期値 48**。現在値を数字で併記（例「48ドット」） |
| 減色モード | 3択（セグメントボタン or select） | ①**なし**（元の色のまま）②**レトロ8色**：固定8色パレットへ各ドットを最近傍色（RGB距離最小）でマッピング ③**緑4階調**：輝度から4段階の緑系パレットへマッピング（レトロ携帯ゲーム機風） |

- 固定パレットの具体色は実装側で決めてよいが、**ラベルと実際の色数を一致させる**こと（8色と書いたら必ず8色）。数値の誇張・不一致は禁止（公開前ファクトチェックで照合される）。
- スライダー/減色モード変更時は**即時再変換**（`input`イベント）。128ドット程度なら再計算は軽いのでデバウンス不要。
- 巨大画像対策：読み込み時に長辺2048pxを超える場合は一度2048pxに縮小してから処理してよい（品質に影響なし）。

### 2-3. 表示
- **Before/After並び表示**：元画像とドット絵を並べる（PCは横並び、スマホは縦積み）。SNSスクショ映えを意識する。
- ドット絵側が主役。表示は `image-rendering: pixelated` を併用してよい。

### 2-4. ダウンロード
- 「PNGで保存」ボタン。`canvas.toBlob("image/png")` → `<a download>` で保存。
- 出力解像度：最近傍拡大後の**長辺およそ1024px**（N×整数倍でこれに最も近いサイズ）。ドット境界がにじまないこと。
- ファイル名：`dot-art-{N}dot.png`（例 `dot-art-48dot.png`）。

## 3. UI/デザイン要件

- 単画面・日本語UI。タイトルは「ドット絵メーカー」、どこかに小さく `Day 002` 表記。
- 配色はチャレンジ一覧ページとトーンを合わせた**ダーク系**（`--bg:#14161c` / `--panel:#1d212b` / `--text:#eef1f6` / `--accent:#4f9cff` を基調に流用可）。
- day-001 の流儀に合わせる：BEM風クラス命名、`aria-*` の最低限の配慮、システムフォントスタック。
- レスポンシブ（375px幅〜PC）。タッチ操作でもファイル選択・スライダーが使えること。
- フッターに一覧へ戻るリンク `<a href="../">← 100 DAYS / 100 APPS</a>`。

## 6. 検収基準（実装者セルフチェック）

1. ローカルで `index.html` を直接開き（file://）、画像ドロップ→ドット絵表示→スライダーで粒度が変わる→減色3モード切替→PNG保存、まで一連で動く。
2. 外部リクエストが1本もない（コード上 `http` 参照なし）。
3. リポジトリルートで `npm run build` が通り、一覧に Day 002 が「制作記録のみ」として載る（draftのため）。
4. スマホ幅（375px）でレイアウト崩れなし。
5. ファイル内に絶対ローカルパス・個人情報・他案件情報がない。
