# Day096 UXレシピ

予約・購入・問い合わせ・登録・応募・参加・来店・応援。8つの目的から1つ選ぶと、その目的のページが部品の並びとして組み上がる。部品は入れ替えられ、触るたびに「UXの流れ」と、理由つきの診断が更新される。できたページは、共有リンク・HTML・画像で持ち出せる。
登録もインストールも要らない。作ったページは、このブラウザの中だけに保存する。共有を選んだときだけ、リンクや書き出したファイルを相手に渡す。

## 使い方
1. 入口で目的を選ぶ。架空のお店の下書き（9〜10部品）が組み上がる。「つづきから」と「保存を開く」もここにある。
2. 部品を押すと、「なぜこの部品か」・見た目の切り替え・文章の入力欄が出る（スマホは下のタブ）。プレビューの文字を押しても、その入力欄へ移る。見出しとボタンには、言い換えの候補がある。
3. 並べ替えは、つまみのドラッグ（指でもマウスでも）・▲▼ボタン・キーボード。キーボードでは、構成の行に ↑↓ でフォーカスを移し、Alt+↑↓ で動かし、Delete で消す（フォーカスのある行だけが対象）。パソコン幅では、▲▼・複製・削除は選んだ行に出る。「部品を足す」は、見せる・迷わせない・不安を減らす・背中を押す、の効果別。元に戻す（Ctrl/⌘+Z）もある。
4. 「診断」で、ページの流れ（気づく→わかる→信じる→動く→安心）が揃っているかと、15項目の診断を見る。「なおす」を押すと、その項目を満たすように部品を足したり動かしたりする。**点は、部品の組み立て方を見たもの**で、文章の良し悪しは見ていない。見本の文章がどれだけ残っているかは、点とは別に「自分の文章に直した部品 x / N」で出す。
5. 「見た目」で、4つのテーマ（やわらか・きりっと・にぎやか・しっとり）・6つの強調色・サイトの名前を選ぶ。サイトの名前を変えると、文章に残る見本の店名を、まとめて置き換えられる（1回の元に戻す）。パソコン幅の見え方は、プレビューの「パソコン」で見る。
6. 「共有・書き出し」で、リンク（開くと見るだけの画面）・HTML（1ファイル）・画像（PNG）にできる。「保存・開く」で、この端末に6件まで名前をつけて残せる。作業中の内容は自動で保存する。

## 下書きを失わないために
- 触った跡のある下書きがあるとき、入口で目的を選ぶ・共有を「もとに作る」と、置き換えの確認が出る。置き換えたあとも「元に戻す」で戻せる。選んだだけでは、以前の下書きを上書きしない。
- 別のタブで同じ下書きが更新されたら、自動保存を止めて知らせる。書き込みの直前にも保存先を照合し、別のタブの新しい内容を上書きしない。どちらの内容で続けるかは、本人が選ぶ。
- 端末の保存が使えない・保存された下書きが壊れているときは、黙って上書きせず、知らせて保存を止める。壊れた内容は別の場所へ退避してから、保存を始められる。
- 「元に戻す」付きの通知は、そのあとに別の操作をすると消える（古い通知が、あとの編集を戻さない）。

## 診断について
- 15項目それぞれに、理由と、出典へのリンクと、確度を出している。確度は3種。**確認済み**（出典のページに同じ内容がある）が3項目、**一部確認**（出典が支えるのは一部で、そこから広げた説明）が9項目、**独自の整理**（出典がなく、このアプリの考え方）が3項目。2026-11-21に、出典のページを開いて照合し、確度を下げた項目がある（8項目）。
- 見出し28字・フォーム4項目・部品12個などの数値は、このアプリの目安で、調査で決まった基準ではない。点は、この目安で決めている。
- 「気づく→わかる→信じる→動く→安心」は、このアプリの整理で、既存の購買行動のモデルではない。
- 期限・残り枠の「本当の数字です」は、本人が受付の記録と照らして付ける印で、アプリが代わりに付けることはしない。数字が見本のままでは、印があっても満たしたことにならない。
- 目的を伝えるとページを作ったり、設計を評価したりするサービスは、ほかにもある。このアプリは、目的を選ぶと構成が決まり、並べ替えるたびに理由つきの診断が出る、という体験に絞った。

## 仕組み
- ページは1つの状態（JSON）から作る。部品の項目・文字数・並びは `lib/contract.js` の項目表が正で、入力欄・無害化・検証・共有リンクの検査が同じ表から決まる。
- ページのCSSは `.uxr-page` の中だけで、幅は画面でなくページの幅（container query）で変わる。スマホ枠とパソコン枠で、同じCSSが効く。
- 共有リンクは `#v=` の後ろに内容を入れる。この部分はサーバーへ送られない。deflate で圧縮して base64url にし、読み込みでは長さと展開後の大きさに上限をつけ、項目表で無害化する。
- 書き出すHTMLにスクリプトは入れない。画像（PNG）は、SVGを等倍で作ってキャンバスで2倍にする（WebKit は、SVGの `viewBox` で拡大すると左上にしか描かない）。
- 日本語は文節で折り返す。描画したページのHTMLの文節の境目に `<wbr>` を入れ、CSS は `word-break: keep-all` にする（`lib/jp-wrap.js`）。WebKit（Safari・iPhone）が `word-break: auto-phrase` に未対応なため、[BudouX](https://github.com/google/budoux)（Google・Apache-2.0）の Parser と日本語モデルを、改変なしで `vendor/budoux/` に同梱している（端末の中だけで動く。許諾は [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt)）。BudouX が「売り｜場から」のように不自然に切る、漢字＋送りがな＋漢字の複合語（売り場・買い物・受け付け・申し込み）は、その境目を捨てる補正を足している。
- 外部の通信・画像・書体は使っていない。書体は端末標準。ページの絵は、文字・数字・小さなアイコンの札・背景の抽象の形だけで作り、画像が欠けた枠のように見える飾り（塗りの四角形を含む）は置かない。アイコンは、項目の文字（時給→円・時間→時計）から選ぶ。

## 既知の限界
- 2つのタブが、同じ瞬間に同じ空きの保存枠へ保存すると、片方が失われることがある（`localStorage` には排他の仕組みがなく、書いた内容を読み戻して確かめるところまで）。
- 日本語の折り返しは、BudouX の区切りに従う。文節の途中での折れは、8目的×2幅（390px・960px）×Chromium・WebKit の測定で、16ページ中 Chromium 2か所・WebKit 1か所まで減らした（残りは「」の直後の助詞）。
- 診断の点は、部品の組み立て方だけを見る（文章の良し悪しは見ない）。空欄の項目は「入口がある」「短い見出し」と数えることがある。
- 実機のスマホ（画面キーボード・日本語入力の変換中・読み上げ）は、本人の実機確認が済んでいない。実ブラウザ（Chromium・WebKit）での指のイベントの確認までを済ませている。

## まだないこと
複数画面の流れ・「ありがとう画面」・文章のトーンの切り替え・部品の自作・画像のアップロード・AIによる文章の提案・サーバーでの保存。サンプルの店と人はすべて架空で、手入れや効果の約束はしていない。書き出したHTMLの、ボタンの飛び先とフォームは見本。
