# Day096「UXレシピ」の宣伝動画

30.000秒（15小節・120 BPM・900コマ）の縦型動画（1080×1920・30fps）。公開するアプリを実際に操作して撮った画面だけで作る。
流れは、「ページに、何を載せる？」の問い → 目的を選ぶとページが組み上がる（0.5秒）→ お客さんの流れ → 文章・見た目 → 部品を消すと診断が96点から73点に → 理由と根拠 → 元に戻す → 8つの目的 → 共有・書き出し → 登録なし・無料・ブラウザだけ。
絵コンテの正本は `timeline.mjs`。映像と音楽の両方がこの表を読む。

## 再生成

リポジトリのルートで実行する。撮影にはセットアップ済みの Playwright / Chromium、書き出しには ffmpeg / ffprobe が要る。字幕の書体 Zen Kaku Gothic New（Bold・Black）は、OSにインストールしておく。
出力先はリポジトリの外にする（省略すると OS の一時フォルダの `day096-promo/`）。

```sh
promo=day-096-ux-recipe/tools/promo
node "$promo/promo-audio.mjs" --variant a --out-dir "$OUT/audio"
node "$promo/promo-audio.mjs" --variant b --out-dir "$OUT/audio"
node "$promo/verify-audio.mjs" --out-dir "$OUT/audio"
node "$promo/render-promo.mjs" --out-dir "$OUT" --audio-dir "$OUT/audio" --mux a,b
```

- 撮影だけなら約40秒。`--frames 300-420` はその範囲のコマだけを `preview-300-420/` に保存する（操作は先頭から再現する）。`--no-encode` で書き出さない。`--encode-only` は保存済みのコマから書き出し直す。
- 書き出しは `silent.mp4`・`a.mp4`・`b.mp4`・`demo.mp4`（一覧カード用・無音・540×960・16秒）・`first-frame.png`・`contact-sheet.jpg`（1秒ごと）・`capture-report.json`（操作が実際に起きたコマ・診断の点の読み取り）・`cues.json`。
- `demo.mp4` は本編の 0–6・12–18・18–20・22–24秒をつないだもの。

## 仕組み（コードを読むだけでは分からない理由）

- 画面は CSS 540×960・DPR 2。上の200pxが字幕帯、その下にアプリを入れる。字幕がアプリの上部バーと流れメーターを隠さず、文字は上下の隠れる位置（Reels などのボタン）を避けて CSS y=77〜768 に収まる。
- アプリは、実機に近い幅（415px）で動かし、1.3倍に拡大して540pxの枠いっぱいに映す。540pxのまま撮ると、実機より文字が相対的に小さく、チップや診断の理由・根拠が読みにくかった（1周目の採点で3系統が共通で指摘した）。
- ページの時計は止め（Playwright の `page.clock`）、1/30秒ずつ進めて1コマずつ撮る。トーストや自動保存の表示が、動画の時間で動く。アプリの動きを減らす設定（`reducedMotion`）で撮るので、画面の切り替えは一瞬になる。
- 本体フレームは `https://rairakku.com/100days/day-096-ux-recipe/` の住所で開くが、実際の通信はしない。Playwright の `route` で手元のファイルを返し、同じホストのほかの住所は404にする。共有ダイアログのリンクに、手元のアドレスが映らないようにするため。
- 「目的は、8つ」の8画面は、別々のポートに置いた8つの非表示フレーム。同じ保存領域だと、1つの下書きの保存が他のフレームの「別のタブで更新」の判定を動かす。
- 指・波紋・黄色の枠・札（−23／+23）・字幕・エンドカードは、ステージ（`stage.html`）の側で描く重ね物。タップは実際の押す操作（`touchscreen.tap`）で、指は押す0.42秒前から対象の位置へ向かう。

## 踏んだ罠

- 開いていないタブの中の入力欄を、先にスクロールしようとして30秒待った。タップの後に画面を動かす（指が向かう間になめらかにスクロールする）。
- 入力欄に触れる前の「全選択」は、画面全体を選ぶ（青い選択が10秒以降ずっと残った）。タップが入力欄に着いてから使う。拡大したフレームでは、キーボードの全選択が入力欄の外の語（言い換え候補）を選んだので、入力欄の中身を直接選ぶ（`select()`）。
- 部分撮影（`--frames`）は、最初の表示切り替えを飛ばすと本体フレームが押せない。初期化で本体フレームを表示する。
- 非表示（`visibility:hidden`）のフレームは押せない。8画面から本体へ戻すときは、同じコマの押す操作より先に表示を切り替える。
- JPEG のコマは全範囲（`yuvj420p`）。そのまま書き出すと範囲の指定が違う動画になるので、`scale=in_range=pc:out_range=tv` で変換する。
- 「Blocked autofocusing」はクロスオリジンのフレームのコンソールの警告で、無害。
- 診断の理由を大きく見せようと画面を1.2倍に寄せると、文章の幅が画面より広くなり、両端が切れた。寄せる代わりに、アプリを実機の幅で動かして全体を大きくした。
- 字幕の切り替えで透明度を0から上げると、切り替わりの1コマが薄く映り、採点の静止画で「途中のコマ」と指摘された。透明にせず、下から14px上がるだけにした。

## BGMと効果音

120 BPM・15小節。A案「木の粒」はニ長調のマリンバとクラップ、B案「机辺のエレピ」は変ホ長調のエレピとブラシ・丸いベース。どちらも、0.5秒の組み上がりの音から、2.0秒でキックとベースが入り、18秒から8拍のヒット、26秒で終止、最後の1.5秒でフェードする。
効果音（タップ・組み上がり・風・チップ・テーマ・削除・開く・取り消し・8拍のヒット・共有）は、絵コンテの合図（`CUES`）の時刻に置く。`--cues cues.json` で、撮影した実際の時刻に差し替えられる。
検査は、−16 LUFS ±1・真のピーク −1.5 dBTP 以下・クリップ0・合図のずれ ±5 ms・組み上がり／削除／取り消し／終止の前後100 msの音量差3 dB以上・無音の穴なし・末尾0（A・Bとも21項目に合格。スペクトログラムも出力する）。耳での試聴は未了。
