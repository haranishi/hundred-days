# Design：learning-app

## 置き場所（境界）
- `src/engine/`：出題の組み立て・正誤・経験値・連続記録・復習の間隔・実績。画面に依存しない純粋な関数だけを置き、単体試験の主対象にする
- `src/store/`：保存・形式の版と移行・書き出し/読み込み。保存できない環境ではメモリだけで動く
- `src/screens/`・`src/ui/`：画面と共通部品。`src/app/`：外枠・画面遷移・下のタブ
- `src/course/`：コースの並び（どの項目をどのレッスンで出すか）。中身のデータは `src/content/`（sign-content）を参照するだけ
- 手の表示は `src/hand/`（hand-model）の `HandView`・`renderThumbnail` だけを使う。カメラは `src/camera/`（camera-check）を動的に読み込む

## 画面遷移（URL の # 以降）
`#/`＝道すじ、`#/welcome`＝初回の案内、`#/lesson/<id>`、`#/review`、`#/practice/weak`、`#/dict`、`#/dict/<itemId>`、`#/spell`（ひらがな→指文字の再生）、`#/me`、`#/settings`、`#/about`、`#/dev/hands`（開発ビルドのみ）。レッスン中は下のタブを隠す

## コースの並び（初版）
- 指文字：ユニット1〜5（あ〜こ／さ〜と／な〜ほ／ま〜よ／ら〜ん）、ユニット6（濁音・半濁音・小さい字・のばす音）、ユニット7（自分の名前を指文字で）。1レッスンの新出は3文字まで、各ユニットの最後は総まとめ
- 数字：1〜5、6〜10、0・100・1000。各ユニットの最後に総まとめ（実装依頼で具体化）
- あいさつ：実装依頼の16項目を5ユニットに配置し、各ユニット末尾に総まとめ。全コースで未収録・confidence low を除外する。指文字ユニット7は46文字の総復習とし、名前の入力は画面側の担当
- 各コースの最初のユニットは最初から開く。案内の「どこから始めるか」のおすすめは指文字（自分の手で1文字できる体験が最短で来るため）

## 出題（`buildLesson(lesson, progress, { rng, cameraEnabled, items, vocab })`）
- 新出項目ごとに「紹介」→ 直後に「手→文字の4択」。続けて「文字→手の4択」「ペア合わせ（4組）」、覚えた文字が3つ以上なら「指文字で読む」（単語リストから、覚えた文字だけでできた語）と「指文字で綴る」。単語は「手話の意味を選ぶ」。カメラ問題は設定が有効で静止形がある時だけ1問
- 4択のまちがい選択肢は、見間違えやすい項目を優先して選ぶ（confusables → 同じユニット → 同じ種類）
- 1レッスン10〜14問。まちがえた問題は最後に回し、全問正解するまで続ける。乱数は種を渡せるようにして試験で固定する

## 記録の計算
- 経験値：レッスン完了10、全問一度で正解なら+5、復習1回5
- 連続記録：端末の日付（年月日）で数える。その日の最初のレッスン完了で、前回が昨日なら+1、今日なら据え置き、それ以外は1。開いた時に前回が一昨日以前なら表示は0。最長記録は別に持つ
- 復習の間隔（箱の段）：段0〜5、間隔は0・1・3・7・14・30日。正解で1段上げ、まちがいで段1へ。紹介した時点で段0。復習は期日の来た項目を古い順に最大12問
- 実績：初めてのレッスン・全問正解・3日/7日/30日連続・各コース修了・指文字46文字・カメラで初成功・100/500経験値

## 保存（`tekotoba:v1`）
- 1つのJSON：`version`・`settings`（利き手・目標・効果音・振動・カメラ・動きを減らす・案内済み）・`items`（項目ごとの段・期日・正誤回数）・`lessons`（完了回数）・`xpByDay`・`streak`・`achievements`
- 変更は300msまとめて保存、タブが隠れた時にも保存。読み込み時に版を見て移行する。壊れていたら退避用のキーに写してから初期化し、画面で知らせる
- 書き出し：`tekotoba-progress-YYYYMMDD.json`。読み込みは形式を検査し、確認の後に置き換える

## 見た目（独自）
- 色の基本：文字 #1F2544、背景 #FFF9F0、主ボタン #4C5FD5、強調（連続記録の炎）#FF8A3D、正解 #138A6E＋✓、まちがい #D64545＋✗、指文字 #4C5FD5・数字 #13A39A・あいさつ #E8604C。文字と背景のコントラストは 4.5:1 以上
- 書体：Zen Maru Gothic（500・700）。問題の大きな文字は56px以上
- 案内役「てまる」：SVG で描く丸い体と大きな手。表情を3種（にっこり・応援・考え中）
- 効果音は Web Audio で合成（素材ファイルなし）。振動は対応端末のみ

## シェア・OGP・オフライン（100日の Day92 として）
- 共有：100日の共通部品 `shared/share.js` を index.html の `<dialog>` 内 `<footer id="share">` に置く。入口ボタン（読み上げ名「このアプリを共有する」）は読み込み前から静的に置く。結果画面の「記録をシェア」は、進み具合の文（例：「指文字のか行を覚えた／3日連続」）を載せた自前の4点（端末の共有・X・LINE・コピー）で、共通部品と同じ注記を出す
- OGP と canonical：100日のサイトの組み立てが meta.json から入れる。OGP 画像（1200×630）は開発用のHTMLを Playwright で撮って Day のフォルダに置く
- vite-plugin-pwa：範囲は `./`。画面・データ・書体を事前に保存。MediaPipe の大きいファイルは初回使用時に保存

## 公開ゲート
- こちら側（`npm run publish:check`）：文書相対の住所だけか（`/` で始まる参照が無い）、`THIRD_PARTY_NOTICES.txt`、`source/` に写す物に絶対パス・個人の情報が無いか、組み立てた物が `/100days/day-092-…/` の下で開けるか（Playwright で、下の階層に置いて道すじ→レッスン完了まで）
- 100日側（`npm run publish:check -- --day 92`）：共有・OGP・ヘッダーなど、全アプリ横断の検査。PRの前に必ず通す

## 学習計算・保存の実装補足（2026-11-13）
- `createCourses(items?)` でデータの追加を反映できる。名前ユニット以外のレッスンIDは項目の除外前に確定し、収録数が変わっても保存記録との対応を保つ。
- 項目・語が4つに満たない場合は存在する選択肢だけを使う。ペアは2〜4組、1項目だけなら出さない。出題対象皆無なら空配列を返す。
- 指文字の語は文字単位に元の文字と変化へ分解する。紹介日は暦日で保存し、日付は呼び出し側から渡す。
- `evaluate` のスナップショットは保存用Progressに任意の `firstTryPerfect`・`cameraSuccess`・`courses` を加えた型。保存形式に完了イベントの履歴がないため、呼び出し側が完了時の結果を渡し、取得した実績を日付付きで保存する。
- v1が初版のため既定の旧版移行は無い。`createPersistence` は版別の移行関数を注入でき、変換後もv1の検査を通す。
- DOMイベントは登録しない。画面側が非表示・離脱時に `flush()` を呼ぶ。300ms保存の完了後の可否は `getSnapshot()` で取得する。
- 検証証拠は `tasks.md` のタスク2と `.agent-harness/runs/impl-engine/notes.md` を参照。
