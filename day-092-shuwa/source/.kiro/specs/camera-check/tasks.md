# Implementation Plan：camera-check

担い手：特徴と判定は Codex（ブラウザ不要の単体試験で確かめられる）、画面と通信の確認はメインループ。

- [x] 1. 特徴の計算・一致の判定・ヒントの選び方と単体試験
  - hand-model の `landmarks()` で作った21点を使い、全静止形が自分自身と一致・見間違えやすい形と不一致（右手・左手・±2%のノイズ）
  - _Requirements: 2.3, 2.4, 4.1, 4.2, 4.3_

- [x] 2. カメラの画面
  - 初回の説明（端末内で処理・保存しない・読み込みの大きさ）→ 許可 → 鏡の映像と骨組み・目標の小さな手・ヒント・成功。15秒で「できた（自分で判断）」「スキップ」。離れたらカメラを止める
  - 許可されない・カメラが無い・読み込み失敗の時は、手本を見て自分でやってみる問題に切り替える
  - モデル取得のスクリプト（SHA-256 の確認）と、wasm をビルド時に写す設定
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.2, 2.5, 3.1, 3.2_

- [x] 3. 通信とプライバシーの確認（メインループ）
  - 偽カメラの Chromium で、カメラ使用中の通信先が自サイトだけであること、CSP で外部が止まっても判定が動くことを記録する。結果に合わせて「このアプリについて」の文を決める
  - _Requirements: 1.2_

## 進み具合の記録（2026-11-13）
- 1・2：静止形は自分自身と一致し、見間違えやすい形とは不一致になる（右手・左手・±2%のノイズ）。動く混同形（数字の10・100、を など）は比べる相手から外す。止まった形のうち、判定できない「ら」は対象外にした。記録は `.agent-harness/runs/impl-camera/`
- 3：偽カメラの Chromium で、カメラの使用中の通信先が自サイトだけであること、CSP があってもなくても判定が動くこと、問題を離れるとカメラが止まることを確かめた（`tests/e2e/camera.spec.ts`）。MediaPipe の利用状況の送信は、仕掛けと CSP の二重で止まる。結果に合わせて「このアプリについて」の文を書いた
