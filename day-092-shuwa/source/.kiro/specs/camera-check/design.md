# Design：camera-check

## 方針
- 判定は「手の形の特徴」を比べる。生の座標の近さでは比べない（体格・カメラの距離で変わるため）
- 目標の特徴は、hand-model の `landmarks()` が返す目標の形の21点から、学習者の手と**同じ関数**で計算する。表示と判定の基準が食い違わない
- 読み込みは、カメラの問題を初めて開いた時だけ（動的な読み込み）。@mediapipe/tasks-vision の wasm は node_modules からビルド時に `dist/mediapipe/wasm/` へ写す。モデル（hand_landmarker.task・float16・版1）は取得用のスクリプトで SHA-256 を確かめて `public/mediapipe/` に置き、リポジトリに含める
- 通信：CSP の connect-src を自サイトだけにする。カメラ使用中の通信を Playwright で記録し、自サイト以外への通信が無いこと・判定が動くことを確かめる。確かめた結果だけを「このアプリについて」に書く（product.md の原則）

## 特徴（`features(points21, handedness)`）
- 指（人差し指〜小指）：付け根・第2関節の曲がりの角度から `extended`・`bent`・`curled` の3段階
- 親指：伸びているか、親指の先と各指先の距離（手のひらの大きさで割る）、親指の先が手のひらの面より前か後ろか
- 向き：手のひらの面の向き（手首・人差し指の付け根・小指の付け根の3点から）と、指先の向き（手首→中指の付け根）。カメラから見た向きに直して、`toViewer` などの6方向との角度で比べる
- 鏡写し：画面の映像は鏡のように反転して見せるが、判定は反転前の座標で行う。左右の判定結果は使わず、利き手の設定で右手か左手かを決める（左利きは X を反転してから右手として比べる）

## 一致の判定とヒント
- 目標ごとに「必ず合っていてほしい特徴」を自動で選ぶ：その形と、見間違えやすい形（sign-content の confusables）とで値が違う特徴。ほかの特徴は緩く見る
- 必須の特徴がすべて合った状態が 0.5 秒続いたら成功
- ヒントは、外れている必須の特徴のうち、優先度（向き → 指の状態（人差し指から順に）→ 親指）の最初の1つを、決まった文例で出す。例：「手のひらをカメラに向けましょう」「中指をまっすぐ伸ばしましょう」「親指の先を人差し指の先につけましょう」
- 15秒で一致しなければ「できた（自分で判断）」と「スキップ」を出す。どちらも✗にはしない（自分で判断は正解扱い・スキップは記録に影響しない）

## 画面
- 前面カメラの映像（鏡のように反転）、骨組みの重ね描き、目標の小さな手（自分から見た視点）、ヒントの帯、成功の動き
- 初回だけ説明の画面：映像は端末内で処理し保存しない／最初に約10MBを読み込む／許可を求めるのは「カメラで確かめる」を押した後
- 問題を離れる・レッスンを閉じる・タブが隠れると、カメラのトラックを止める

## 検証
- 単体試験：hand-model の21点で、全ての静止形が「自分自身とは一致」「見間違えやすい形とは不一致」になる（左手でも同じ）。ノイズ（±2%）を加えても自分自身とは一致する。ヒントの文が想定どおりに選ばれる
- 画面試験：Chromium の偽カメラで、許可・拒否・手が写っていない時の表示、離れた時にカメラが止まること、通信先が自サイトだけであることを確かめる
- 実際の手での精度は機械では確かめきれないので、最終報告で本人の実機確認を頼む
