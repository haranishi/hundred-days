# Design：hand-model

## 方針と、捨てた案
- three.js で、指の骨ごとのカプセル形・手のひら・親指の付け根のふくらみを組み合わせた手を描く。輪郭線（裏面を少し太らせて黒っぽく塗る方式）を付け、教材のイラストに近い見た目にする
- 深さは描画の深度で決める。2Dの重ね描きは、親指が握った指の前か後ろかを取り違えるので捨てた。人の手の3Dモデル（スキン付き）は、許諾の確認と、形の数だけ関節を合わせる手間が大きいので、初版では使わない
- 1つの仕様データから「表示」「小さな画像」「21点の関節位置」を作る。表示と判定の基準を同じにするため

## 座標の決まり（ここを取り違えると全部の形が鏡写しになる）
- **手の座標**（右手）：原点＝手首の中心。+Y＝指先の方向、+Z＝手のひらの面の外向き、+X＝親指の側。左手は X を反転する
- **場の座標**：見る人（相手）は +Z 側にいて、表す人と向かい合う。+X＝見る人から見て右、+Y＝上。表す人の右手は、見る人から見て左（−X 側）にある
- 向きの言葉（相手から見て）：`toViewer`（+Z）・`toSigner`（−Z）・`up`・`down`・`viewerLeft`（−X）・`viewerRight`（+X）。斜めは数値の3要素で書く
- 長さの単位は「手のひらの長さ＝1」。手首から中指の付け根まで

## 仕様データの形（sign-content が書き、camera-check が読む）
- `HandshapeSpec`：形。指（index/middle/ring/pinky）ごとに `extended`（伸ばす）・`bentMcp`（付け根だけ直角に曲げる）・`hooked`（付け根は伸ばし、第2・第1関節を曲げる）・`curled`（握り込む）・`half`（軽く曲げる）。親指は `alongside`（握った人差し指の横に添える）・`acrossFront`（握った指の前を横切る）・`tuckedUnder`（曲げた指先の下に入れる）・`extendedOut`（横に開く）・`extendedUp`・`foldedPalm`（手のひら側に折る）・`betweenIndexMiddle`・`touch`（指定の指の指先・関節に触れる）。ほかに `spread`（そろえる／開く）・`cross`（交差の前後）・`contacts`（指先どうしの接触）・`adjust`（関節角度の個別上書き。例外の形だけに使う）
- `Orientation`：`palm`（手のひらの向き）と `fingers`（指先の向き）。2つから手の回転を一意に決める
- `Keyframe`：`t`（秒）・`shape`・`orient`・`pos`（体の位置の名前＋ずらし、または場の座標）・`ease`
- `SignSpec`：`hands.dominant` と任意の `hands.nonDominant` の Keyframe 列、`body`（上半身を描くか）、`trace`（空中に字を書く軌跡。指先が通る点の列。`relativeTo: 'tipStart'` なら動き出しの指先からのずれで書ける）
- 交差 `cross` の前後は**相手から見た前後**。例：ら は手のひらが相手向きで、中指の腹を人差し指の背に当てるので、相手側からは人差し指が手前（`front: 'index'`）

## 形から関節角度へ
1. 指と親指の状態を、関節角度の表（付け根の曲げ・開き、第2関節、第1関節）に置き換える。第1関節は第2関節の約2/3に連動させる
2. `touch`・`contacts` は、表の角度から始めて、親指（必要なら相手の指も）を逆運動学（関節の可動域つき）で寄せる。接触の判定は「指の太さの球どうしの隙間が 0.02 以下」（指先の点の距離ではない）
3. `adjust` があれば最後に上書きする
4. 可動域を超える角度は丸める。丸めが起きた形は開発時に警告を出す

## 描画と再生
- 体の位置の名前：`neutral`（利き手側の胸の前）・`forehead`・`temple`・`eye`・`nose`・`mouth`・`chin`・`cheek`・`chest`・`belly`・`shoulder`。上半身つきの時は、肩から手首までを2つの骨の逆運動学で腕として描く
- 再生：関節角度は線形補間、回転は球面補間、位置の軌跡は曲線補間。止まる区間（同じ位置が続く所）の両端は曲線の接線を0にする（行き過ぎて体にめり込むのを防ぐ）。速さは 1 倍と 0.5 倍。最後の形で止まる。動きを減らす設定では自動再生しない。表情とうなずきは `faceTimeline` で時刻を指定できる
- 視点：`viewer` は見る人の位置から。`self` は手だけなら手の真後ろ・上40°から（指先が相手の方へ向く形だけ目の側へ35°回り込む）、上半身つきなら利き手の肩の後ろ上から、頭と胴を薄く透かして見る。手だけを自分から見る時は袖を先に描き、袖が手を隠さないようにする。鏡写しにはしない（自分の右手は自分から見ても右手）（2026-11-13 第2周。袖と胴に隠れる絵が出たため）
- 指の操作：横の払いで左右に回す。縦の払いはページのスクロールに渡す（図鑑で手の上を払ってもスクロールできるように）。上下の回転はマウスとペンだけ。戻すボタンで初期の視点へ
- 利き手が左：場全体を X で反転して描く（形のデータは右手のまま）

## 部品の使い方（learning-app との約束）
- `<HandView sign spec perspective dominant autoplay loop speed interactive controls size label />`。`replay()` を持つ。`controls` は `full`（既定）・`view`（視点の切り替えだけ。画面が自分で再生を操る時）・`none`。3D描画が使えなければ `label`（形の説明文）を表示する
- 枠は形ごとに、手の外形（指の太さ込み）が収まるように合わせる（下限あり）。上半身つきは両手と顔が入る範囲に寄せる
- `renderThumbnail(sign, { perspective, dominant, size, at }) => Promise<string>`（画像のURL）。同じ引数ならキャッシュを返す。`at` を省くと、上半身つきの単語は最初の止まる区間の真ん中（あいさつで終わる語どうしが同じ絵にならないように）、それ以外は最後の形
- 小さな画像の枠は、描く時点の絵だけを収める（2026-11-13 見た目の採点 第2周の指摘で変更）。手だけの形は、その時点の手を動かない形と同じ決まりで収める。空中に書く跡は、跡の2/3が見えるまで枠を最大1.3倍に広げる（の・り・ん・のばす音）。上半身つきは大きな表示と同じ枠
- 小さな画像では、袖・腕・胴・空中の跡・休めている反対の手を、画像の縁から一辺の0.2の幅でぼかして消す。白い札の中で袖が直線に切れて見えないようにするため。手と頭はぼかさない。大きな表示（HandView）はぼかさない
- 描画器（WebGL の文脈）は**全体で1つを共有**し、各表示の 2D キャンバスへ写す（2026-11-13 実装時の判断）。表示がいくつあっても文脈は1つなので、スマホの上限に当たらない。同時に再生するのは2つまでで、3つ目が始まると最も古い再生が最後の形で止まる
- `landmarks(shape, orient, dominant) => Vec3[21]`。並びは MediaPipe と同じ（0＝手首、1〜4＝親指、5〜8＝人差し指、…、17〜20＝小指）

## 検証
- 単体試験（ブラウザ不要）：仕様→角度→関節位置の計算、`touch` の接触距離、手のひらと指先の向きが指定から10度以内、左手の反転、21点の並び、キャッシュの鍵
- 画面試験：開発用の一覧ページ（`dev-hands.html`。本番のビルドに入らない）で全形を相手側と自分側から描き、Playwright で撮影する。小さな画像は、札に置いた見え方（`dev-hands.html?set=cards`）でも撮る。形の正しさは sign-content の目視検証で確かめる
- 性能：スマホ相当の CPU 4倍遅延で、再生が毎秒30コマ以上
