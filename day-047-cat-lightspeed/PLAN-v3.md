# 「ねこ、光になる」v3 改善計画

## 戦略・ユーザーストーリー・UX5階層

**戦略：指を動かすたび猫が世界を置き去りにし、最後に光の姿と時間差を持ち帰れる、約1分の遊びにする。** 数字の増加より「自分の操作で景色と猫が変わる」を優先する。

- 初めて遊ぶ人として、説明を読み込まず猫を動かしたい。開始後3秒以内に上下操作と推力の関係が分かる。
- スマホで遊ぶ人として、一往復ごとに手応えが欲しい。入力から100ms以内の表示反応と、最初の2秒以内の衝突で確かめられる。
- 加速する人として、遠くまで来た実感が欲しい。6世界を文字なしでも区別でき、速さに応じ流れ方が変わる。
- 完走する人として、「光になった」と感じて記録を共有したい。終了前の変身を見届け、結果から1操作で再挑戦できる。

| 階層 | 設計判断への接続 |
| --- | --- |
| 戦略 | 手応え→景色の拡張→変身の順で報酬を作る。冒頭の待ち時間と終盤の平板さを先に直す。 |
| 要件 | 指の移動量による推力・衝突・録音の鳴き声・同梱GLB猫・6世界・20通過＋光速の壁を保持する。 |
| 構造 | 開始→加速と追い越し→光の姿→自動結果の1本道。失敗画面・分岐・強化購入を増やさない。 |
| 骨格 | 猫と風景を主領域、速度と次の相手を1組のHUDにする。再挑戦を主ボタン、共有を副操作とする。 |
| 表層 | 暖色の猫、世界ごとの大きな象徴、白青の光。黄緑は推力・進捗に限定し、常時の緑の板・輪をなくす。 |

## 診断と範囲

- 提供された実時間証拠では4秒0.2、8秒0.9、20秒30km/h。`realtime-contact.png`の冒頭6コマは牧場のまま。現行`physics.js`をNodeで1/60秒刻みに進めても街23.77秒・完走90.78秒。衝突は低速でも発生しており、「20秒何も起きない」ではなく報酬の変化が遅い。
- `mobile-06-sky-3340.png`は青地、`mobile-08-orbit-66899.png`と`mobile-09-solar-446681.png`は暗地と小物が主。`scene.js`には雲・地球・太陽・惑星が既にあるが、この撮影構図では象徴として見えない。素材追加より配置・投影サイズを直す。
- `mobile-03-farm-33.png`〜星間、`desktop-12-interstellar-1075724020.png`で物体群・緑の板・輪が猫に重なる。`impacts.js`の3列、最大64破片、`impact-view.js`の常時輪が密度を増やしている。
- `mobile-11-interstellar-996628909.png`でも通常の猫が中心、`mobile-99-result-full.png`は数字表で終わる。`cat-light.js`は白化18%・発光0.16を上限としており、見せ場を抑えている。
- `mobile-00-start.png`の上下の装飾、プレイ画像の薄い操作説明で優先順位が曖昧。提供E2Eは12/14合格、猫の高さ16.6%・17.96%で2件失敗。`catScreen`は投影箱なので、顔の視認性は画像で別判定する。
- 本工程は本書と評価表だけを作成。次工程は受け入れテスト→実装→実ブラウザ証拠→独立採点。画像・ブラウザ計測は提供証拠、今回の再計測はNodeの進行のみ。添付の「046」は旧撮影で、現行HTMLは047。

## P0：既存構成の調整に限定し、1〜2セッションで実装する

以下のファイル名は、特記以外`day-047-cat-lightspeed/`からの相対パス。秒数は開始後のゲーム経過時間、画面寸法はCSS px。1回目はP0-1/2/4、2回目はP0-3/5と統合確認を目安にし、P0完了まではP1/P2を足さない。

### P0-1 序盤から変化が続く加速曲線

- 仕様：最大推力で最初の通過0.3〜1.5秒、歩く速さまで4秒以内、自転車まで6秒以内。街8〜12秒、空14〜18秒、軌道19〜24秒、太陽系24〜29秒、星間29〜34秒、完走45〜60秒。定数表・世界境界は維持し、加速式だけを連続につなぐ。
- 仕様：各世界に最低4秒、光速比90%以降に8〜15秒を割り当てる。入力なしの自動加速は加えない。指移動量の蓄積を保持し、離した後450ms以内に推力0、以降減速。冒頭の所要時間表記も更新する。
- ファイル：`lib/physics.js`、必要時`lib/input.js`、`app3d.js`、`index.html`、`README.md`、`REQUIREMENTS.md`。
- 受入：最大推力の時刻が上記範囲、20通過の順序・光速未満・99.999%終了を維持。180pxを0.6秒で上下各1回、折返し休止0.1秒の反復でも75秒以内に完走する。実タッチで移動中だけ推力が増えることを録画する。

### P0-2 猫を主役にした1画面と入力案内

- 仕様：390×844・390×664では主領域を100svh内、上部の見出し＋HUDは計160px以下、描画域は60svh以上。猫の投影高は18〜38%（目標22〜30%）、中心xは40〜60%、耳・尾・足先を含む箱は四辺2%内側。PCにも同じ猫の条件を適用する。
- 仕様：常設情報は速度・通過数・次の相手・世界名を1組に集約。操作説明は初回入力成功後2秒で畳み、推力バーは残す。右端44pxのページ移動帯は保持し「↕」を小さく表示。ボタンは44px以上、本文12px以上、通常文字のコントラスト4.5:1以上。速報は「フィクション」付きの1行、注記・出典・既存共有は下へ置く。
- ファイル：`index.html`、`app.css`、`app3d.js`、`lib/scene.js`。共有スクリプトとGLB自体は保持。
- 受入：3画面サイズで開始・猫の全域・結果の再挑戦と共有入口がスクロールなしで収まり、ページ移動帯から下部にも到達できる。全6世界×走り12位相の投影箱を検査し、実画像で耳・顔・尾が背景から判別できる。

### P0-3 世界を示す大きな背景と速度の流れ

- 仕様：牧場は道＋樹木2群、街は道路＋奥の建物3棟、空は高さの違う雲3群を配置。軌道は画面幅70%以上の地球の弧を下部に、太陽系は直径が画面幅18〜28%の太陽＋12〜20%の環付き惑星、星間は斜めの星の帯を置く。手続き生成と既存形状だけを使い、猫の顔の背後は低密度にする。
- 仕様：近景の流れを遠景の2〜4倍にして視差を作る。空から星間へ流線を12→最大120本まで増やす（星点との合計180以下）。衝突時の揺れは最大2px・120ms、カメラ周回・連続ズームはしない。世界切替は背景色の0.4〜0.8秒遷移、形状は1世界だけ描画する。
- ファイル：`lib/scene.js`、配置の必要分のみ`lib/models.js`。
- 受入：各世界へ入って1秒後と3秒後、3画面サイズで象徴が画面内にある。ラベルを隠した6枚で世界を識別できる。2秒の動画で近景が遠景より速く流れ、牧場と星間の速さの印象が異なる。

### P0-4 一つずつ読める衝突

- 仕様：未破壊の可視対象は通常3〜5個、同時に飛ぶ本体4個以下・破片12個以下。最初の接触は最大推力で2秒以内、以降の主な衝突は0.6〜1.2秒間隔を目安に距離から配置。中央1列を主体とし、0.6〜1秒で画面外へ弾く。接触時だけ0.1〜0.2秒の白い小さな衝撃を出し、常時輪・不透明な緑の尾を廃止する。
- 仕様：録音の衝撃音とニャーを残す。物体・破片は顔を避けて左右下方へ。尾は猫の後ろに接続する白青の半透明1本（不透明度0.35以下）にし、末端を透明にする。音速で1回の衝撃音、既存の音声遅延、軌道速度以降の無音を維持する。
- ファイル：`lib/impacts.js`、`lib/impact-view.js`、`lib/scene.js`、必要時`lib/sound.js`。
- 受入：接触前→接触→飛散の連続コマで原因を追える。代表衝突の前1秒〜後1秒を100ms刻みで確認し、顔を隠す物体が2コマ連続しない。入力なし・速度0では勝手に衝突せず、減速・再加速でも同一物体の二重計上や破片の増殖がない。

### P0-5 「光の猫」と二つの時計で終える

- 仕様：90%から白青の縁光、99%から白化を進め、99.9%で毛色が80%以上白へ寄る猫のシルエットに連続変化。耳・頭・尾を残し、99.999%到達時に即resultへ。結果にも80〜112px高の光の猫を静止表示し、全画面フラッシュ・演出待ち・追加クリックを挟まない。
- 仕様：90%以降は「猫の経過秒／地球の経過秒」を並べ、瞬間のγと累積値を区別。結果は光の猫→「あなたの1秒／地球の223.6秒」→所要時間・20/20→再挑戦・共有入口。到達速度と累積地球秒は詳細に残す。「物理は簡略モデル・変身は演出」を読める位置に置く。
- ファイル：`lib/cat-light.js`、`lib/scene.js`、`app3d.js`、`app.css`、`index.html`。
- 受入：90%・99%・99.9%・99.99%の同構図画像で変化が明瞭。白い猫を終了前に1秒以上見られる。γは最後223.6（小数1桁）、累積値は実際の進行の積分値。結果を待たず操作でき、再挑戦で色・時計・衝突・入力が初期化される。

## P1・P2：P0採点後の追加候補

- **P1／相手の可視化**：カタツムリ・新幹線・旅客機・軌道施設の4種だけを手続き形状で作り、幅64〜110px・同時1体、通過前後計1.5〜2.5秒の並走→後退で見せる。衝突対象と区別する。候補ファイルは`lib/scene.js`、追加`lib/rivals.js`、`app3d.js`。受入：対応する閾値通過と退場の順序が一致し、文字なしで4種を区別、顔を隠さない。他の相手は既存HUDを使う。
- **P2／遠景の質感**：星間の遠景画像を必要な場合だけ1枚、1024×512・200KB以下で本作用にAI生成し同梱。文字・主役を焼き込まず、読込失敗時は手続き背景へ戻す。候補は`assets/`、`lib/scene.js`、`data/SOURCES.md`。受入：権利表に「本作のためにAI画像生成で作成」、外部通信0、P0と同じ猫の視認性・性能予算を維持。生成しなくても合格可能。

## テストAPI契約

- `window.__day047`の`state()`、`snapshot()`、`setManual(boolean)`、`advance(ms)`、`start()`、`inputSample(sample)`と既存snapshot欄は名前・型・意味を保持。入力sampleは既存の`time:number`（開始後秒）、`distance?:number`（正規化距離）、`held?:boolean`、`stroke?:boolean`等を維持する。
- snapshotに`contractVersion:3`と`experience:{reducedMotion:boolean,events:Event[],landmarks:Landmark[],light:{phase:'coat'|'glow'|'light',amount:number},motion:{shakePx:number,speedLineCount:number}}`を追加。amountは実表示の光への変化量0〜1、shakePxは現在の画面変位の大きさ、speedLineCountは現在描いた流線数。
- `Event={seq:number,type:'milestone'|'world'|'light'|'finish',id:string,elapsed:number,speed:number}`。milestoneのidは元配列indexの文字列`'0'`〜`'19'`、worldは既存6種のid、lightは`'glow'`/`'light'`、finishは`'result'`。実際の初通過・初到達を記録し、描画から架空イベントを発生させない。
- eventsは1プレイのメモリ内のみ、startで空にして牧場worldを時刻0で追加。seqは1始まり、elapsedは非減少、通過は昇順で重複なし、finishは1回かつlight到達後。同時刻の種類間順序は不問。減速後の再通過は増やさない。保存・外部送信しない。
- `Landmark={id:'pasture'|'street'|'clouds'|'earth'|'sun'|'ringedPlanet'|'starfield',rect:{x:number,y:number,w:number,h:number}}`。現在描画する象徴だけを返す。rectは実形状の投影を描画域でクリップした矩形、canvas左上原点・幅高を各1とする。投影面積は見た目の合格を代替しない。
- 光のphaseは90%未満coat、90%以上99.9%未満glow、99.9%以上light。減速で戻り、resultではlight保持。通常進行とmanualの値を一致させ、テスト専用の成功状態を作らない。
- 撮影専用の状態書換APIは増やさない。既存manualでstart→入力→1/60秒ずつadvance→snapshot条件成立時に撮影。速度・イベントを待つ方式にして旧曲線の逆算時刻をテストに埋め込まない。manualでは音を評価せず実時間録画を使う。
- 次工程のテストは境界・範囲・因果順序を検査。旧「可視対象6個以上」「白化18%固定」「32秒で音速帯」は新仕様へ置換し、光速上限・数値表・入力量依存・時間分割の安定性・保存制限は弱めない。対象は`tests/`とリポジトリ直下`tests/e2e/day-047.spec.mjs`。

## 性能・動きを減らす設定・検証

- 実描画で全世界・衝突ピーク・終了を含め48 draw calls以下、18,000三角形以下、星点＋流線180以下。描画倍率はmin(端末DPR,1.5)、必要時1.0へ落とす。影マップ・多段ポスト処理・毎フレームの形状生成を追加しない。
- 60fpsを目標、実機で可視中のフレーム間隔p95≤33.3ms・200ms以上の停止0を合格条件とする。GLB準備完了後から完走まで計測し、機種・ブラウザ・DPRを記録。幾何予算やPC上のエミュレーションだけでスマホの滑らかさを合格にしない。
- reduced-motionは揺れ0・流線0・急な拡大0、視差速度を通常の20%以下、破片4個以下。入力・速度式・世界順・時計・到達条件は同じ。変身は静かな色変化に置換し、設定をプレイ中に変えても反映する。
- 実装後に関連単体・E2E・buildと`EVAL-v3.md`の証拠を提出。最大3周、同一失敗2周で原因と残件を返す。機械テストの成功と面白さの評価は分ける。
