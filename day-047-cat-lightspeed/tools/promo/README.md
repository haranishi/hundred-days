# Day 047 紹介動画

34秒・1080×1920・30fps の縦型動画を作るツール。本物のアプリを iframe で動かして1コマずつ撮り、1020枚の連番PNGと BGM（`promo-audio.mjs` のA案）を ffmpeg でまとめる。依存パッケージは足さない。

## 使い方：試し描きで確かめてから本番を描く

リポジトリのルートで実行する。ffmpeg・ffprobe と Playwright の Chromium が要る。アプリのフォルダはツール自身が空きポートで配信するので、`npm run build` も `dist/` も使わない。

```sh
export PLAYWRIGHT='<playwright の index.js>'
node day-047-cat-lightspeed/tools/promo/render-promo.mjs --preview      # 540×960で撮って拡大する
node day-047-cat-lightspeed/tools/promo/render-promo.mjs                # 1080×1920で撮る
node day-047-cat-lightspeed/tools/promo/render-promo.mjs --variant b    # BGMをB案にする
node day-047-cat-lightspeed/tools/promo/promo-audio.mjs --variant b --mp3 --measure   # BGMだけ書き出して測る
```

作成環境では試し描きが約1分、本番が約2分かかった。書き出すのは既定でこのフォルダの `promo.mp4`・`promo-first-frame.png`・`preview-contact.jpg`（上3段が2秒おき、下3段が奇数秒）で、どれも gitignore 済み。1コマ目と一覧は mp4 と同じフォルダに書くので、試し描きを `--out` で外へ出せば本番の分を上書きしない。連番PNGとWAVは OS の一時フォルダに置き、終われば消す。

## 撮り方：最大推力の1回の走りから、場面ごとの窓を切り出す

入力は `inputSample({ held: true })` で最大推力を1回かけたまま、手動の時計で 1/30 秒ずつ0秒から通しで進める。場面ごとに映すゲーム内の時刻（`GAME_FROM`）だけを撮り、窓の外は撮らずに進める。巻き戻しも走り直しもしない。

走り直さないのは、アプリの色の補間が壊れるからだ。`start()` の中の `resize()` が前の走りの最後の画を描き直すとき、時計は0に戻っているのに補間の起点は前の走りの時刻のまま残る。すると次に世界が変わってからの0.6秒間、画面が黄色と白に飛ぶ。遊んでいる人が「もう一度」を押した直後にも同じことが起きうる（アプリは変えていない）。一気に進めて撮るのも避けた。追い越しの一言が溜まって古い順に出てしまい、色の補間の起点も古いまま残る。

窓は `snapshot()` の実測（最大推力）で選んだ。

| 秒 | ゲーム内の窓 | 写る出来事 |
| --- | --- | --- |
| 0–4 | 3.13–7.13秒 | 牧場を7→44km/h。的を弾き、0.3秒に「ニャー」が出る |
| 4–8 | 9.0–13.0秒 | 街に入った瞬間から。新幹線が10.43秒に見え、12.03秒（動画7.0秒）に抜く |
| 8–12 | 13.0–17.0秒 | 上空の旅客機を14.73秒（動画9.7秒）に抜き、15.0秒（動画10.0秒）に雲海へ |
| 12–16 | 21.0–25.0秒 | 地球の弧。22.22秒（動画13.2秒）に宇宙ステーションを抜き、下に「真空では音が伝わらない」 |
| 16–20 | 25.0–29.0秒 | 太陽系に入った瞬間から。環のある惑星が右から左へ動く |
| 20–24 | 36.0–40.0秒 | 37.02秒（動画21.0秒）に光速の90%。二つの時計が出て、縁が光りだす |
| 24–28 | 40.0–44.0秒 | 99.0%→99.95%。猫の時計が4秒進むあいだに地球の時計は50.0→117秒。43秒から白い猫 |
| 28–30 | 49.0秒〜 | 結果画面（光の猫の写真・223.6秒・20/20） |
| 30–34 | なし | エンド画面（promo.html が描く。写真は結果画面の canvas を写したもの） |

S0 を3.13秒からにしたのは、動画0.3秒に「ニャー」が出る窓だからだ。同じ時刻にアプリと同じ録音（meow-a・同じ再生速度）を小さく重ね、結果の場面にも meow-b を1回重ねる。ほかの「ニャー」の文字はアプリの実表示なので残したが、音は鳴らない。

## アプリの仕様から来る制約

- 旅客機を抜くのは 900km/h で、まだ街の世界にいる（空は 1,000km/h から）。「雲海の上で抜く」画は撮れないので、字幕どおり「抜いて、空へ」の順に写る。
- 旅客機は13.13秒から見えるので、新幹線の窓は13.0秒で切る。延ばすと次の場面の相手が写る。
- 光速比の表示は小数3桁に丸める。完走の直前を撮ると、同じ「99.999%」の下に γ 184.6 が出て、0.5秒後の結果は 223.6 になる。S7 は結果画面から撮る。
- 40.0秒ちょうどの光速比は浮動小数で 0.98999999999999948 になる（画面は「99.0%」）。検査はこの誤差を許す。
- 90%で縁の光が付くが、はっきり見えるのは99%（動画24秒）前後から。

## 撮影用の見た目：iframe に CSS を差し込み、アプリのソースは変えない

見出し・猫速報（フィクション）・操作説明・ページ移動帯・音のボタンを隠した。結果画面の「もう一度」・共有・ベスト（日付が入る）・くわしい記録も隠した。一言・二つの時計・下の注記・結果の写真は、スマホで読める大きさへ上げた。CSS のトランジションとアニメーションは止める。実時間で動くので、機械の混み具合で画がずれる。

追い越しの一言は、字幕の出来事に当たるものだけを見せる（S1 は新幹線と「街へ」、S2 は旅客機と「空へ」など）。最大推力では1秒に2〜3個の追い越しが重なり、字幕と別の相手の名前が出てしまうからだ。下の注記は S3 の「真空では音が伝わらない」だけを見せる。BGM がこもる区間と重なる。

## 検査：落ちたら動画を見て直し、検査は外さない

- 書き出した動画から字幕の札だけを切り出し、コマ差分で切り替わりを測る。4・8・12・16・20・24・28・30秒の8回と照合し、回数違いか0.4秒超のずれで失敗にする。元の30fpsのまま測る
- 1コマ目は、プレイ中・最大推力・牧場・時速1km超で、的が3個以上見えるか飛んでいて、猫が画面内にいること
- 撮った全コマの状態で各場面を確かめる。牧場で加速して3回以上弾く／新幹線を窓の中で抜く／旅客機を抜いて空へ出る／下半分に幅7割以上の地球の弧と宇宙ステーション／惑星が画面幅15%以上左へ動く／90%の瞬間が窓の0.5秒以降にある／全コマ99%以上で時計の差が30秒以上広がる／写真の入った結果が1秒以上写る
- 寸法1080×1920・音声あり・尺34秒±0.15秒・配信元以外への通信0件・ページのエラー0件（コンソールのエラーも数える）
- AAC にした後の音を測り、−17±0.5 LUFS かつ真のピーク −1.5 dBTP 以下でなければ失敗にする

## BGM：4/4拍子・120 BPM・E マイナー、結果の28秒で E メジャーへ

場面の `music` に合わせて編成を変える。0–4秒は軽い拍と動機、8–12秒がいちばん走る。12–16秒は真空で、全体を 600Hz まで閉じてドラムを抜き、パッドと鼓動だけを残す。20–24秒は3度ずつ上がる旋律とスネアのロール、24–28秒が頂点、30秒から余韻で消える。A案はシンセ、B案はピアノと弦が主役で、楽譜は同じ。

測り方は ffmpeg。統合ラウドネスと真のピークは `ebur128`、帯域は 120Hz の4次ローパスと 8kHz の4次ハイパスを通した `astats` の RMS、場面ごとの明るさは `aspectralstats` のスペクトル重心で見る。作成時の実測は下のとおり。

| 案 | 統合 | 真のピーク | 低域の全体比 | 高域 | フックと本編の差 | 重心 疾走／真空／立て直し |
| --- | --- | --- | --- | --- | --- | --- |
| A | −17.0 LUFS | −2.8 dBTP | −7.1 dB | −39.0 dBFS | 4.1 dB | 4607／431／1270 Hz |
| B | −17.0 LUFS | −3.0 dBTP | −8.6 dB | −39.0 dBFS | 0.9 dB | 4605／472／1348 Hz |

低域は最初 −1.9 dB で、キックがほぼ占めていた。キックの胴を短く小さくし、ベースに 85Hz のハイパスを掛けて基準に入れた。スマホで聞こえるよう、キックは2倍音と打点の音を強めてある。

## 既知の限界

- 人の耳での聴取と、X・Instagram に上げた後の再圧縮の見え方は、このツールでは確かめていない
- 3D はアプリが描画倍率を1.5に抑えるので、1080×1920 では少し甘い。結果の写真は 240×160 の canvas を拡大している
- フォントは OS に依存する（作成環境は macOS のヒラギノ）。描画は headless Chromium のソフトウェア描画（SwiftShader）
