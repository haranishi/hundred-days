# Day 032「いま干していい？」要件定義

**いまの空気にどれだけ洗濯物を乾かす力があるか。**それを1つの判定と3つの所要時間で出す。使うのは気温・湿度・風・日射を1つにまとめた「大気の乾かす力」で、そこに洗濯物が持っている水の量を割ると時間になる。**将来の時刻は出さない。**

> 2026-09-13 改訂。初版は「15:40に乾く／18:00までに取り込む」という将来の時刻と、この先の雨を並べた24時間の帯を出していた。§「気象業務法への対応」のとおり作り直した。

## 背景と狙い

- 100日チャレンジ Day 32。S2（Lv.2）の2日目で、解禁表のとおり**外部API（無料・認証不要）を1個**だけ使う。その1個が Open-Meteo（`https://api.open-meteo.com/v1/forecast`）
- 題材は「需要ベースWebアプリ100案」042「洗濯物の乾き予測」。困りごとは**干す作業ではなく「いつ・どこに干すかの判断」**。面倒な家事の3位が洗濯
- 天気アプリは既視感が強い。差がつくのは**「降水確率を見せる」ことではなく「乾かす力を時間に翻訳すること」**。降水確率60%と言われても洗濯物を干すかは決まらないが、「いまの勢いなら厚手で4.5時間ぶん」なら決まる
- 地名から座標を引く外部サービスは**使わない**。APIを1個に収めるため、市区町村の代表点（1,741件）を同梱する

## 気象業務法への対応（この版の前提）

- **気象業務法17条**は、気象の**予報業務**（観測の成果に基づく現象の予想の発表を、反復・継続して行うこと）に気象庁長官の許可を要求する。気象庁の手引きは、許可の要否は**発表手段や営利か非営利かを問わない**と明記している。無料の個人アプリでも対象になる
- **19条の2**が気象予報士の設置を義務づけるため、許可を取る道は個人の100日チャレンジでは現実的でない
- したがって**将来の時刻の気象の値を取得も表示もしない**。初版が出していた乾き上がり時刻・取り込み締切・24時間の帯・翌日の提案・降水確率にもとづく判定は、すべて取りやめる
- 出すのは**いまの観測値**と、そこからの**単純な割り算**だけ。割り算の結果には「ぶん」を付け、「いまの勢いが続くと仮定したら」と画面に明記する

## UX5階層

- **戦略**: 天気アプリではなく**「いま干す・干さない」を決める1問**。成功＝開いて1タップで「いまどれくらい乾くか」が出て、洗濯機の前で迷いが終わること。失敗＝降水確率や気温の数字を並べてしまい、結局ユーザーが自分で判断させられること。**将来を予想しないことが制約でなく前提**で、そのぶん「いま」を言い切ることに寄せる
- **要件**: 載せるもの＝現在地または市区町村の選択、干し場所2つ（日なた・日かげ／軒下）、いまの判定、いまのET0、薄手・ふつう・厚手の所要時間3つ、乾かない理由、生乾きの注意、計算根拠の開示、出典。対象外＝**乾き上がりの時刻・取り込み締切・24時間の帯・翌日の提案・降水確率**（上の§のとおり）、室内干しの時間計算、通知、複数地点の保存、地図
- **構造**: 単一画面で `start → loading → ready` の3状態＋ `error`（通信失敗）。位置は「現在地」「選んだ市区町村」「未選択」の3値。干し場所を変えても**再通信せず**、取得済みの1時点から計算し直す
- **骨格**: いちばん大きい要素は**いまの判定**（「よく乾きます」を最大級）。その下にET0の1行。次に3つの所要時間を縦に並べた一覧（干す物の名前は左、時間は右揃え・等幅数字）。干し場所の切り替えは一覧の下（44px以上）。根拠と出典は折りたたみの中とフッター
- **表層**: 晴れた日の物干し。地は空色に寄せた白（`#f4f8fb`）、文字は紺墨（`#1b2b3a`）。乾かないときだけ雨色（`#3f7ec4`）に寄せる。色だけで意味を伝えず必ず文字を添える。動きは読み込みバーの1つだけ。`prefers-reduced-motion` では止める

### UX5階層を通したことで決まった実装（6件）

1. **主役は「いまの判定」1つだけ**（戦略層）。気温・湿度・風速は最初の画面に出さず、折りたたんだ「計算の根拠」の中に入れる。天気アプリに見えた時点で負け
2. **干すものは選ばせず3つ同時に出す**（要件層）。選択式だったのは「選んだ1つの時刻」を大きく出すためで、時刻をやめた以上は選ぶ理由が無い。1画面で終わるほうが速い
3. **数字に「ぶん」を付け、仮定を結果のすぐ上に書く**（骨格層）。「約2.5時間」は予想に読まれる。「約2.5時間ぶん」＋「いまの勢いが続くと仮定して」なら分量の話だと分かる
4. **干し場所の変更で再通信しない**（構造層）。1回の取得で1時点を持ち、切り替えは計算のやり直しだけ。API呼び出しを最小に保つ（利用条件の上限に対しても誠実）
5. **乾かないときは時間を出さず、理由を出す**（要件層）。0で割った数字に意味はない。「夜だから」「雨だから」まで書かないと次の行動が決まらない
6. **計算式を画面から開ける**（戦略層）。「なぜその時間なのか」を隠すと天気アプリと区別がつかない。使った値と係数、そして**いつの値か**をその場で見せる

## 乾きの計算（`lib/dry.js`・純関数・DOMに触れない）

### 考え方

大気が水を蒸発させる力を **ET0（FAO-56 基準蒸発散量・mm/h）** で受け取る。ET0 は気温・湿度・風速・日射を1つの式にまとめた値で、Open-Meteo が**いまの値**として返す。洗濯物が持っている水の量を「面積あたりの水の厚み（mm）」で表し、いまの速さで割る。

```
いまの速さ R[mm/h] = いまのET0 × C(干し場所)   ただし いま雨(≥0.1mm/h)なら R = 0
布ごとの所要時間[h] = W(布) ÷ R               ただし R = 0 なら「出せない」(null)
```

時系列を回さない。ループも状態も無く、割り算1回で終わる。

### 係数

| 記号 | 値 | 根拠 |
|---|---|---|
| W 薄手（Tシャツ・下着・シャツ） | 0.35 mm | 下の較正 |
| W ふつう（タオル・ズボン） | 0.65 mm | 下の較正 |
| W 厚手（ジーンズ・パーカー・バスタオル） | 1.20 mm | 下の較正 |
| C 日なた | 0.55 | 下の較正 |
| C 日かげ・軒下 | 0.33（日なたの6割） | 日射が無いぶん遅くなることの目安 |

⚠️ **この係数は実測ではない。** ET0 は芝生を基準にした値で、物干しに掛かった布の蒸発量そのものではない。次の3つの体感に合うよう決めた**目安**であることを README と画面の「計算の根拠」に明記する。

| 較正に使った体感 | この式での結果 |
|---|---|
| 真夏の晴れた日、Tシャツは1時間ちょっと | ET0 0.6 → 0.35 / (0.6×0.55) ≈ 1.1時間ぶん |
| 秋の晴れた日の昼なら、ジーンズは4〜5時間ぶん | 秋田 2026-09-13 12:00 の実データ（ET0 0.48）で約4.5時間ぶん |
| 冬の晴れた日でも厚手は1日ぶんでは足りない | ET0 0.08 → 1.20 / (0.08×0.55) ≈ 27時間ぶん＝数字を出さない |

### 出力

```
estimate({ current, place })
→ {
    observedAt,   // いつの値か（Open-Meteoが返した「いまの時刻」。ここより先の時刻は戻り値のどこにも入れない）
    place, placeLabel, factor,
    et0PerHour,   // いまのET0（mm/h）
    precipPerHour,// いまの雨（mm/h）
    rate,         // いまの乾く速さ（mm/h）
    raining, isDay,
    items,        // [{ key, label, examples, water, hours, tooLong }] 薄手・ふつう・厚手の3件
    verdict,      // 'good' | 'fair' | 'slow' | 'rain' | 'none'
    smell         // ふつうが5時間ぶんを超えるか
  }
```

### 判定

いまの速さで「ふつう」が何時間ぶんになるかで決める。**降水確率は使わない**（将来の予想のため）。

| verdict | 条件 | 文言 |
|---|---|---|
| `good` | ふつうが5時間ぶん以内 | 「よく乾きます」 |
| `fair` | ふつうが10時間ぶん以内 | 「ゆっくりなら乾きます」 |
| `slow` | それ以上 | 「いまはほとんど乾きません」 |
| `rain` | いま雨（≥0.1mm/h） | 「いま雨が降っています」 |
| `none` | 速さが0（夜など） | 「いまは乾きません」 |

## 機能要件

### 画面と状態

- `<main id="app" data-state="start|loading|ready|error" data-place="sun|shade">`
- **start**: 見出し「いま干していい？」、説明1行（「出すのはいまの時点だけ／◯時に乾くは出さない」を含む）、`#use-location`「現在地で調べる」（主要ボタン）と `#pick-place`「市区町村から選ぶ」
- **loading**: `aria-busy="true"`。300ms 未満なら出さない
- **ready**:
  - `#place-name`（「秋田県秋田市」または「現在地（◯◯あたり）」）＋ `#change-place`「場所を変える」
  - `#observed-at` 「（12:00時点）」＝いつの値か
  - `#verdict` いまの判定を最大級で
  - `#rate-line` 「ET0 0.48 mm/h（日なた）」
  - `#no-dry` 乾かない理由（速さが0のときだけ）
  - `#smell` 生乾きの注意（該当時のみ）
  - `#spans` 「この勢いなら、乾くのに要る時間」＋仮定の但し書き＋ `#dry-list`（薄手・ふつう・厚手の3行。24時間ぶんを超えるものは数字を出さない）。速さが0のときは丸ごと隠す
  - `#place-kind` 2ボタン（`role="radiogroup"`）
  - `#why` `<details>`「計算の根拠」＝いつの値か・使った値（気温・湿度・風速・日射・ET0・いまの雨）と係数、較正の但し書き、**「いまの値1時点だけを使っている」旨**
- **error**: `role="alert"`「天気を取れませんでした」＋ `#retry`「もう一度」＋場所の選び直しは残す
- **場所選び**（`<dialog id="place-dialog">`）: 都道府県 `<select>` → 市区町村 `<select>` → 「この場所にする」。`places.json` はここを開いたときに初めて読む

### API（`lib/weather.js`）

- `https://api.open-meteo.com/v1/forecast` に1回だけ。パラメータは `latitude` `longitude` `timezone=Asia/Tokyo` と
  `current=temperature_2m,relative_humidity_2m,precipitation,cloud_cover,wind_speed_10m,shortwave_radiation,et0_fao_evapotranspiration,is_day` の**4つだけ**
- ⚠️ **`current` の積算値は mm/h ではない。** 直前の `interval` 秒ぶんの積算で、実測（2026-09-13・6地点）では常に 900 秒＝15分ぶん。同じ時刻の `minutely_15` と一致し `hourly` とは一致しない。`perHour()` で `3600 ÷ interval` を掛けて mm/h に直す。直さないと4分の1に見積もる
- 座標は小数3桁に丸めて送る（現在地の精度をそのまま渡さない）
- 8秒で諦める。失敗・欠測は `error` 状態へ
- 同じ座標の応答は10分だけメモリに持つ（`current` は15分ごとの更新なので古い値を見せることにはならない）

### 保存

- `localStorage` に最後に選んだ市区町村コードと、干す場所。使えない環境でも動く。**古い端末に残っている `fabric` は読み捨てる**

## 非機能・共通ルール

- 外部APIは Open-Meteo の1個だけ。CSP の `connect-src` は `https://api.open-meteo.com`（`scripts/build.mjs` の `CONNECT_BY_APP`・**ホストは変わらないので変更不要**）
- 依存ライブラリなし。`app.js` は ES モジュール
- 共通のシェア部品（`shared/share.css` / `shared/share.js`）を入れる
- 4状態（loading・empty・error・ready）を全部持つ
- 44px 以上のタップ領域、キーボード操作、`prefers-reduced-motion`
- フッターに出典2つ（Open-Meteo・国勢調査/e-Stat）と「天気予報ではありません」
